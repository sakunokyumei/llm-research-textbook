この章でつくるもの

ついに、あなたのLLMを世界に公開します。第13章で育てた漱石GPTを、あなたが専門学校で学んだ HTMLとCSS と、少しの JavaScript でWebページにして、GitHub Pages（無料）で公開します。完成すると、スマートフォンからでも、友だちのパソコンからでも、URLを開くだけであなたのGPTが動きます。このサイトのトップページで動いている漱石GPTは、まさにこの章の方法で作ったものです。

これまでの復習とつながり：第3章・第12章・第13章・第19章とのつながり

  • 第12〜13章（MiniGPTの設計と漱石GPTの重み）：Pythonで組み立て、夏目漱石7作品で学習して Google Drive に保存した soseki_gpt.pt（約175万パラメータ）がそのまま主役になります。
  • 第3章（温度とsoftmaxサンプリング）：logits / temperature → softmax → サイコロで1文字選ぶ計算が、そのまま minigpt.js の sample() 関数としてブラウザ上で動きます。
  • 第19章（量子化）：32ビットの小数（float32）を8ビット整数（int8）に縮めるabsmax量子化を使うからこそ、重みファイルが約 2.5 MB に収まり、スマホ回線でも一瞬で開けます！

書き出しの関数です。第19章のabsmax量子化を、重みの行ごとに行って、8ビットの整数にします。そして、JSONに入れられるように base64（バイト列を文字だけで表す方法）に変換します。

Python（Colabのセルに貼って実行）
import base64, json
import torch

def quantize_rows(w):
    w = w.float()
    if w.dim() == 1:                                   # バイアスやLayerNormはそのまま（float32）
        return {"shape": list(w.shape), "f32": base64.b64encode(w.numpy().tobytes()).decode()}
    scale = w.abs().amax(dim=1).clamp(min=1e-8) / 127  # 行ごとの縮尺
    q = torch.round(w / scale[:, None]).clamp(-127, 127).to(torch.int8)
    return {"shape": list(w.shape),
            "i8": base64.b64encode(q.numpy().tobytes()).decode(),
            "scale": base64.b64encode(scale.numpy().astype("float32").tobytes()).decode()}

ck = torch.load(ckpt, map_location="cpu")
weights = {name: quantize_rows(t) for name, t in ck["model"].items() if not name.endswith("tril")}
with open("soseki-gpt.json", "w", encoding="utf-8") as f:
    json.dump({"config": ck["config"], "chars": ck["chars"], "weights": weights}, f, ensure_ascii=False)
print("書き出したサイズ：", round(os.path.getsize("soseki-gpt.json") / 1e6, 1), "MB")
出力の例（数値や文章は実行ごとに変わってOK）
書き出したサイズ： 2.5 MB

基本情報とつながる：base64

base64 は、どんなバイト列も、英数字と + / の64種類の文字だけで表す方法です。3バイト（24ビット）を6ビットずつ4文字に分けて表すので、サイズは約1.33倍になります。メールに画像を添付するときにも使われています。基本情報の「ビットの切り分け」の練習問題そのものですね。

基礎の補足重みの書き出しとサイズ圧縮のしくみ（PyTorchテンソル → 軽量JSON）

なぜそのままJSONに書かず、quantize_rows でひと工夫しているのでしょうか？ 約175万パラメータのサイズを比べると一目瞭然です。

書き出し方法1パラメータあたり175万個の目安サイズ特徴
素の小数リスト（float そのままJSON）約18文字（18 B）約 31 MB桁数が長すぎてWeb配信には重すぎる
小数3桁丸め（round(x, 3) のJSON）約6〜7文字（6.5 B）約 11 MB実装は超簡単だが、まだやや大きい
生の float32 バイナリ（.pt 相当）4 B約 7.0 MBJSONに直接入れられない（base64化で約9.3 MB）
行ごと int8 量子化 ＋ base641 B × 1.33約 2.5 MB精度を保ちつつ最小！スマホでも1秒未満で読める

また、1次元テンソル（バイアスやLayerNorm）は要素数がごく少なく精度に敏感なので float32 のまま残し、因果マスクの tril は固定の下三角表で推論時に再現できるため除外 しています。

Pythonの道具箱：JavaScriptをPythonの目で読む

  • const / let：変数を作る（const は後で入れ替えない変数）
  • function f(x) { … return y; }：def f(x): … return y
  • for (let i = 0; i < n; i++) { … }：for i in range(n):
  • arr.map((v) => v * 2)：[v * 2 for v in arr]
  • Float32Array：float32の数だけが並んだ配列（PyTorchのテンソルの、とても素朴な版）
  • async / await：「時間のかかる処理（ファイルの読み込みなど）を待つ」書き方

インデント（字下げ）の代わりに { } で範囲を表す、行の最後に ; を付ける、くらいの違いで、考え方はPythonと同じです。

理論の小部屋：推論だけなら、どこでも動く（オンデバイス推論の魅力）

学習には、自動微分（第7章）やAdam（第10章）、強力なGPUが必要でした。でも、学習済みの重みで推論するだけなら、必要なのは掛け算と足し算と、exp・平方根などの簡単な関数だけです。だから、JavaScriptでも、スマートフォンでも、マイコンでも、原理的にはどこでも動かせます。

一般的なWebサービス（ChatGPTなど）は、ユーザーが文字を送ると、巨大なデータセンターのGPUサーバーへ通信が飛び、サーバー側で推論を計算して結果を返します。この方法だと、利用者が増えるほど高額なサーバー代（クラウド代）がかかります。

それに対して、この章で作る方式はオンデバイス推論（エッジ推論）です。Webブラウザがモデルファイル（2.5MB）を最初に1回だけダウンロードし、そのあとはアクセスした人のスマホやPCの頭脳（CPU）だけで推論を完結させます。これには絶大なメリットがあります。

  • サーバー代がほぼ0円：静的ファイルを配信するだけなので、GitHub Pagesなどの無料サーバーで何万人に見られても（個人の利用なら通常）料金はかかりません
  • 入力が外に出ない（完全なプライバシー）：ユーザーが打ち込んだ文章は、手元のブラウザの中だけで処理され、どこかの外部サーバーに送信されることがありません
  • オフラインでも動く：一度読み込んでしまえば、飛行機の中や電波のない地下鉄でも文章を生成できます

ただし、数十億パラメータの大きなモデルは、端末でのダウンロードも計算も重くなります。175万パラメータ（2.5MB）くらいが、普通のブラウザで誰でも気軽に即座に試せる絶妙なサイズ感です。

手順3：手元で動作確認する

作った index.html をダブルクリックで開いても、モデルが読み込めません（ブラウザの安全のための制限で、file:// から別のファイルを fetch で読めないため）。簡単なWebサーバーを立てて確認します。ターミナル（Windowsならコマンドプロンプトや PowerShell）で、soseki-gpt フォルダに移動して、次を実行します。

ターミナル（黒い画面）に入力
cd soseki-gpt
python -m http.server 8000

コツ：Windowsで、フォルダの場所でターミナルを開く

エクスプローラーで soseki-gpt フォルダを開き、上のアドレス欄（パスが表示されているところ）をクリックして cmd と入力し、Enter を押すと、そのフォルダでコマンドプロンプトが開きます。この場合、上の cd soseki-gpt は不要です。Macでは、Finderでフォルダを右クリック→「フォルダに新規ターミナル」（設定で有効にする必要がある場合あり）が便利です。

ブラウザで http://localhost:8000/ を開き、「続きを書かせる」を押して、文章が出てくれば成功です。終わったら、ターミナルで Ctrl + C を押してサーバーを止めます。

つまずき注意：「読み込み失敗」や「読み込み中…」のまま止まったら

  • ファイル名を確かめる：2回ダウンロードすると soseki-gpt (1).json のような名前になっていることがあります。3つのファイルが index.html、minigpt.js、soseki-gpt.json という名前で、同じフォルダにあるか確かめましょう
  • 開き方を確かめる：アドレス欄が file:// で始まっていたら、上の手順でサーバーを立てて http://localhost:8000/ で開き直します
  • エラーの本文を見る：F12 キー（Macは Cmd+Option+I）で開発者ツールを開き、「Console（コンソール）」タブの赤い行を読みます。英語のエラーは、エラー辞典の質問テンプレートでAIに聞いてもOKです

コツ：Pythonが入っていなかったら

自分のパソコンにPythonが入っていない人は、付録Aの手順で入れるか、この手順を飛ばして手順4（GitHub Pages）で直接確かめてもかまいません。

手順4：GitHub Pagesで世界に公開する

GitHub は、プログラムを保存・公開するための、世界最大のサービスです。GitHub Pages を使うと、置いたHTMLファイルを無料でWebサイトとして公開できます（このサイトも、GitHub Pagesで公開されています）。

  1. https://github.com/ でアカウントを作る（無料）。ユーザー名はURLの一部になるので、よく考えて
  2. 右上の「＋」→「New repository」で、新しい置き場所（リポジトリ）を作る。名前は soseki-gpt、Public（公開）を選んで「Create repository」
  3. 「uploading an existing file」のリンクを押し、index.html、minigpt.js、soseki-gpt.json の3つをドラッグ＆ドロップして、「Commit changes」
  4. リポジトリの「Settings」→ 左の「Pages」→「Build and deployment」の「Branch」で main と / (root) を選んで「Save」
  5. 1〜2分待つと、https://あなたのユーザー名.github.io/soseki-gpt/ で公開されます

0円のコツ：GitHub Pages の注意

  • 無料で使えるのは、Public（公開）リポジトリです。中身は世界中から見えるので、パスワードやトークン（第17章）、個人情報は絶対に入れないでください
  • 1つのファイルは100MBまで、サイト全体は1GBまでが目安です。数百MB以上のモデルを置くのには向きません
  • 学習に使った青空文庫の作品は著作権が切れていますが、自分で集めたデータで学習したモデルを公開するときは、データの権利も確認しましょう
基礎の補足静的サイト公開（GitHub Pages）の最終確認チェックリスト
  • [ ] index.html、minigpt.js、soseki-gpt.json の3ファイルが同じルート階層にあり、ファイル名に (1) などの余計な文字がない
  • [ ] ローカルサーバー（http://localhost:8000/）でエラーなく生成できることを確認した
  • [ ] リポジトリ内に API トークン・パスワード・個人情報が1行も入っていない
  • [ ] 単一ファイルが 100 MB 以下（今回は約 2.5 MB）である
  • [ ] Pages 設定で Branch main・フォルダ / (root) を保存した

そのほかの公開・共有の方法

GitHub Pagesは小さなモデル向けです。Qwenのような大きめのモデルを人に使ってもらうには、ほかの方法もあります。

Colabで一時的に公開する：Gradio

Gradio は、Pythonだけでチャット画面などのWebアプリを作れるライブラリです。Colabで share=True にすると、一時的な公開URL（最長1週間ほど有効）が発行されます。第18〜19章のボンゴ先生モデルを、友だちに試してもらうのにぴったりです。

Python（Colabのセルに貼って実行）
!pip install -q gradio
import gradio as gr
from transformers import pipeline

bot = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B-Instruct", device_map="auto")

def text_of(content):
    if isinstance(content, list):          # 新しいGradioでは、文字以外の部品のリストのこともある
        return "".join(c.get("text", "") for c in content if isinstance(c, dict))
    return content

def reply(message, history):
    messages = [{"role": h["role"], "content": text_of(h["content"])} for h in history]
    messages.append({"role": "user", "content": text_of(message)})
    out = bot(messages, max_new_tokens=200)
    return out[0]["generated_text"][-1]["content"]

demo = gr.ChatInterface(reply, title="ボンゴ先生に質問しよう")
print(reply("こんにちは！", []))

demo.launch(share=True)

つまずき注意：Gradioの版の違い

Gradioは版によって書き方が少しずつ変わります。古い解説記事に gr.ChatInterface(…, type="messages") と書いてあっても、新しい版（6系）ではこの引数がなくなっていて、エラーになります。エラーが出たら、まずGradioの版（print(gr.__version__)）と、公式ドキュメントを確認しましょう。

model= の部分を、第18章で保存したフォルダ（/content/drive/MyDrive/tsukuru-llm/bongo-sft）に変えれば、あなたのボンゴ先生が公開されます（このノートブックで先に drive.mount のセルを実行して、ドライブをつないでおきましょう）。Colabのセッションが切れると、URLも使えなくなります。

自分のパソコンで動かす：Ollama

Ollama（オラマ）は、LLMを自分のパソコンで簡単に動かせる無料のアプリです。https://ollama.com/ からインストールして、ターミナルで次を実行するだけで、Qwen2.5-0.5Bと会話できます（初回はダウンロードに時間がかかります）。

ターミナル（黒い画面）に入力
ollama run qwen2.5:0.5b

インターネットにつながっていなくても動き、入力した内容が外に送られることもありません。少し性能の良いパソコンなら、qwen2.5:7b なども動きます。

理論の小部屋：GGUFと、量子化の名前

OllamaやLM Studioなどのアプリは、GGUF という形式のモデルファイルを使います。llama.cpp というC++で書かれた高速な推論プログラムのための形式で、量子化した重みをまとめて1つのファイルにしたものです。

ファイル名についている Q4_K_M や Q8_0 は、量子化の方法の名前です。Q4 は約4ビット、Q8 は約8ビット。数字が小さいほどファイルは小さく、性能は少し下がります。迷ったら Q4_K_M がよく使われる、バランスの良い選択です。第19章で手計算した量子化が、ここで使われているわけです。

Hugging Faceで共有する

学習したモデルやLoRAのアダプタは、Hugging Faceにアップロードして共有できます（第18章の「もっと深く」）。アプリを公開する Spaces は、2026年10月時点で、無料アカウントでは種類が限られています（CPUで動くGradioアプリの新規作成には有料プランが必要で、無料では「ZeroGPU」を使うSpaceが2つまで、または静的なHTMLのSpaceが使えます）。静的なSpaceなら、この章で作ったページ（3つのファイル）をそのまま置いて公開することもできます。サービスの条件はよく変わるので、使う前に公式ドキュメントで確認しましょう。

公開前のチェックリスト

つまずき注意：公開する前に確かめること

  1. ライセンス：元のモデル（Qwen2.5はApache 2.0）と、学習データのライセンスを守っているか。モデルカードやページに書いたか
  2. 秘密の情報：トークン、パスワード、個人情報が、コードやデータに入っていないか
  3. 出力の注意書き：「AIが生成した文章で、内容が正しいとは限りません」と書いたか
  4. 悪用の可能性：誰かを傷つける文章を簡単に作れてしまわないか
  5. お金：クレジットカードの登録が必要なサービスを、知らないうちに使っていないか（0円の原則）
