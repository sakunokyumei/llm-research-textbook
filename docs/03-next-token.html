LLMの「次のトークンの点数（ロジット）」を取り出し、自分でsoftmax・温度・サンプリングを書いて1トークンずつ文章を作る自作 generate

この章でつくるもの

この章が終わるころ、あなたは次の4つができるようになります。

  1. model(**inputs)、with torch.no_grad():、out.logits[0, -1] の入力・中間値・テンソルの形（shape）を説明できる

準備：モデルを直接読み込む

第1章では便利セットの pipeline を使いましたが、今回は中身を取り出すためにトークナイザーとモデル本体を別々に読み込みます。ランタイムは「T4 GPU」にしておきましょう（CPUでも少し待てば動きます）。

Python（Colabのセルに貼って実行）
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

name = "Qwen/Qwen2.5-0.5B-Instruct"
gpu = torch.cuda.is_available()
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(
    name, dtype=torch.float16 if gpu else torch.float32, device_map="auto"
)
print("読み込み完了。置き場所：", model.device)
出力の例（数値や文章は実行ごとに変わってOK）
読み込み完了。置き場所： cuda:0
  • AutoModelForCausalLM の CausalLM は「左から右へ次のトークンを予測する言語モデル（GPT系）」という意味です。
  • model.device はモデルが置かれた機器を表す属性で、GPUの0番なら cuda:0、CPUなら cpu になります（CUDAはNVIDIA GPUで計算する仕組み）。

モデルを直接読み込み、入力と出力の形を見る

まず「吾輩は猫である。名前は」をモデルに渡して、次のトークンに対する「生の点数表」を取り出します。本物のコードを実行する前に、初登場の書き方2つ（**inputs とテンソルの形）を理解のための最小コードで確認しましょう。

基礎の補足理解のための最小コード：`model(**inputs)` の `**` と、3次元テンソル `[1, T, V]`

① 辞書のアンパック **inputs とは？ 関数を呼ぶとき **辞書 と書くと、辞書の中身を「名前つき引数」に展開して渡してくれます。

Python（読むだけ・実行しなくてOK）
def greet(name, times):
    return (name + "! ") * times

d = {"name": "猫", "times": 2}
print(greet(**d))   # greet(name="猫", times=2) とまったく同じ！ → 猫! 猫!

tok(text, return_tensors="pt") は {"input_ids": テンソル, "attention_mask": テンソル} という辞書を返します。だから model(**inputs) は model(input_ids=..., attention_mask=...) の短縮表記です（第7章で出てくるべき乗 a ** 2 とは別の使い方です）。

② inputs と out.logits の中身と形（shape） 「吾輩は猫である。名前は」は6トークン（T = 6）だとします。

変数型・形（shape）中身の意味
inputs["input_ids"]Tensor、形 [1, 6]1件の文章 × 6個のトークンID（return_tensors="pt" でPyTorchテンソルに変換）
out.logitsTensor、形 [1, 6, 151936]1件の文章 × 各位置（0〜5） × 全151,936語ぶんの生の点数
out.logits[0, -1]Tensor、形 [151936]0番目の文章の、最後の位置（-1）における全語彙の点数（＝「名前は」の次の予測！）

では実際に動かして確かめましょう。

Python（Colabのセルに貼って実行）
text = "吾輩は猫である。名前は"

  • with torch.no_grad():：学習時に必要な「逆伝播用の途中メモ」を保存しないモードです（第7章で理由を学びます）。推論ではメモ不要なので速く省メモリになります。
  • logits（ロジット）：モデルが出力した各トークンの生の点数（スコア）です。プラスにもマイナスにもなり、上限も下限もありません（語彙数は151,665ですが、GPU計算の区切りの良さから枠が151,936取られています）。

Σ（シグマ）記号を普通の足し算から理解する

点数が 21.03 や 16.55 のままでは「何%の確率で選ばれるか」が分かりません。点数を確率に変える数式（softmax）を導く前に、式の中に登場する ∑\sum∑（シグマ）記号をゼロから理解しましょう。

数学の道具箱：Σ（シグマ）記号：9ステップで理由から理解する

① 解決したい具体的な問題：151,936個の数字を全部足す計算を、数式で短く正確に書きたい。

② 普通の足し算では困る理由：3個なら z1+z2+z3z_1 + z_2 + z_3z1​+z2​+z3​ で済みますが、151,936個を書き並べるのは不可能です。「…\dots…」で省略すると、どこからどこまで何を足すのか曖昧になることがあります。

③ 新しい発想：「番号 jjj を 111 から NNN まで1ずつ動かしながら、右側の式を全部足す」という専用の合図 ∑\sum∑（ギリシャ文字の大文字で「シグマ」と読む。英語の Sum の S に相当）を使う。

④ 各部分の読み方：

∑j=1Nxj\sum_{j=1}^{N} x_jj=1∑N​xj​
  • ∑\sum∑：「全部足せ」という命令
  • 下の j=1j=1j=1：ループ変数 jjj を 1 から始める
  • 上の NNN：jjj が N になるまで続ける（N を含む！）
  • 右の xjx_jxj​：各 jjj について足す中身（例：jjj 番目の数 xjx_jxj​）

⑤ 小さな数字で手計算：x=[10,20,30]x = [10, 20, 30]x=[10,20,30]（x1=10,x2=20,x3=30x_1=10, x_2=20, x_3=30x1​=10,x2​=20,x3​=30）のとき：

∑j=13xj=x1+x2+x3=10+20+30=60\sum_{j=1}^{3} x_j = x_1 + x_2 + x_3 = 10 + 20 + 30 = 60j=1∑3​xj​=x1​+x2​+x3​=10+20+30=60

式が 2j2j2j なら：

∑j=13(2j)=(2×1)+(2×2)+(2×3)=2+4+6=12\sum_{j=1}^{3} (2j) = (2\times 1) + (2\times 2) + (2\times 3) = 2 + 4 + 6 = 12j=1∑3​(2j)=(2×1)+(2×2)+(2×3)=2+4+6=12

⑥ Pythonの for 文との対応：∑\sum∑ はプログラムで書けばそのまま for 文です！

Python（読むだけ・実行しなくてOK）
total = 0
for j in range(1, 4):   # 注意：Pythonの range(1, 4) は 1, 2, 3（4を含まない）
    total += 2 * j
print(total)            # 12

なお、範囲が文脈から明らかなときは上下を省略して ∑jezj\sum_j e^{z_j}∑j​ezj​（全部の jjj について ezje^{z_j}ezj​ を足す）と書くこともよくあります。

確認問題で、手計算とPythonの両方から ∑\sum∑ を定着させましょう！

なぜ素朴な割り算ではダメなのか？指数関数とsoftmaxの理由

いよいよ本題です。モデルが出した生の点数（ロジット）を、確率に変換します。ここでも「数式を暗記」ではなく、「なぜその計算になるのか」を1歩ずつたどりましょう。

理論の小部屋：ステップ1〜3：問題 → 素朴な方法の失敗 → 指数関数 $e^z$ の発想

① 解決したい問題：たとえば「吾輩は○○である」の候補5つのロジットが z = [3.0, 1.6, 1.2, 0.4, -1.0] だとする。これを次の確率の2条件（＋順位の保存）を満たす数値に変えたい。

  • 条件A：すべての確率 pip_ipi​ が 0以上（マイナスの確率は存在しない）
  • 条件B：すべての確率を足すと ちょうど1（∑ipi=1\sum_i p_i = 1∑i​pi​=1）
  • 条件C：元の点数が高いほど、確率も高い（順位が保たれる）

② 素朴な方法ではなぜダメなのか？

  • 案1：そのまま合計で割る → -1.0 の確率がマイナスになって条件Aに違反！ さらに [2.0, -2.0] のように合計が0だとゼロ除算で壊れる。
  • 案2：全要素を2乗して合計で割る → 全部0以上にはなるが、-4.0 を2乗すると +16.0 になり、+3.0（2乗すると 9.0）より大きくなって条件C（順位）が逆転してしまう！
  • 案3：最小値を引いて0以上にしてから割る → 最小の候補が必ず確率ちょうど 0.0（絶対に選ばれない）になり、全候補に同じ定数を足したり引いたりしたときの比率が不自然になる。

③ 救世主の発想：指数関数 eze^zez（math.exp(z)）を使う！ eee（ネイピア数、約 2.718）を zzz 乗した eze^zez を各点数に掛けてから合計で割ると、すべての問題が一挙に解決します。

なぜ eze^zez が理想的なのか？ 性質が4つあります。

  1. どんな zzz でも必ずプラス（e−1=1/2.718≈0.37>0e^{-1} = 1/2.718 \approx 0.37 > 0e−1=1/2.718≈0.37>0。マイナスにならない！）
  2. 単調増加で順位を保つ（zzz が大きいほど eze^zez も大きい）
  3. 点数の「差」が確率の「倍率」になり、平行移動しても確率が変わらない（指数法則 ezi+c=ec⋅ezie^{z_i + c} = e^c \cdot e^{z_i}ezi​+c=ec⋅ezi​ より、全ロジットに +100+100+100 しても分子・分母の e100e^{100}e100 が約分されて確率が完全一致！）
  4. なぜ底が 2 や 10 ではなく eee なのか？（先取りメモ）：exe^xex は微分しても形がそのまま (ex)′=ex(e^x)' = e^x(ex)′=ex という特別な性質を持ち、第7〜8章の学習（勾配計算）の式がもっとも単純できれいになるためです。

  1. 各点数を eze^zez にする：e2≈7.39e^2 \approx 7.39e2≈7.39、e1≈2.72e^1 \approx 2.72e1≈2.72、e0=1.00e^0 = 1.00e0=1.00
  2. 合計（∑jezj\sum_j e^{z_j}∑j​ezj​）を計算する：7.39+2.72+1.00=11.117.39 + 2.72 + 1.00 = 11.117.39+2.72+1.00=11.11
  3. それぞれの ezie^{z_i}ezi​ を合計 11.11 で割る：
    • p1=7.39÷11.11≈0.665p_1 = 7.39 \div 11.11 \approx 0.665p1​=7.39÷11.11≈0.665（66.5%）

    • 合計：0.665+0.245+0.090=1.0000.665 + 0.245 + 0.090 = 1.0000.665+0.245+0.090=1.000！

⑥ 数式への一般化（これが softmax！） 以上の手順を、候補数 VVV 個に対して一般化した式が softmax です。

pi=ezi∑j=1Vezjp_i = \frac{e^{z_i}}{\sum_{j=1}^{V} e^{z_j}}pi​=∑j=1V​ezj​ezi​​

では、本物のLLM（151,936語）のロジットを torch.softmax で確率に変えてみましょう。

Python（Colabのセルに貼って実行）

top = torch.topk(probs, 5)
for p, i in zip(top.values, top.indices):
    print(f"{tok.decode([int(i)])!r:8} 確率 {p.item()*100:5.1f}%")
print("全トークンの確率の合計：", probs.sum().item())

'、'      確率   0.3%
'「'      確率   0.3%
'無い'    確率   0.2%
全トークンの確率の合計： 1.0000001192092896
基礎の補足なぜ `.float()` と `dim=-1` を書くのか？
  • .float()：GPUではモデルが float16（16ビット小数）で動いていますが、float16 は最大約65,504までしか表せず、exp で簡単にオーバーフローしたり丸め誤差が大きくなったりします。.float() で32ビット小数（float32）にしてから softmax するのが安全な定石です。
  • dim=-1：どの方向（軸）の合計を1にするかの指定です。-1 は「一番最後の軸」を意味します。たとえば2行3列（形 [2, 3]）なら各行（長さ3の方向）ごとに合計1.0になり、1次元（形 [151936]）でもそのまま語彙全体の合計が1.0になります。
  • なお合計が 1.0000001... とごくわずかにずれるのは、コンピュータの小数の丸め誤差（浮動小数点数の仕様）です。

サイコロを振る：サンプリングと乱数シード

確率が分かったら、その確率に従ってトークンを1つ選びます（サンプリング）。0〜1の数直線を確率の幅で区切り、0以上1未満の一様乱数 r がどの区間に落ちたかで選びます。

0 ─── 猫（0.665）───┼─ 犬（0.164）─┼ 人間 ┼名前┼机┤ 1
Python（Colabのセルに貼って実行）
import random

def sample(words, probs):
    r = random.random()          # 0以上1未満の乱数
    total = 0.0
    for w, p in zip(words, probs):
        total += p
        if r < total:
            return w
    return words[-1]

random.seed(0)
results = [sample(words, probs_small) for _ in range(1000)]
for w in words:
    print(w, results.count(w), "回")
出力
猫 664 回
犬 175 回
人間 104 回
名前 49 回
机 8 回

1000回振ると、猫が664回（約66.4%）と理論確率 0.665 によく一致しました。

基礎の補足`range`・`_`・`.count`・乱数シード
  • for _ in range(1000)：1000回繰り返す。_ は「ループ番号自体は中で使わないよ」というPythonの慣例名です。
  • results.count(w)：リストの中に w が何個あるかを数えます。
  • random.seed(0)：擬似乱数の初期値（シード）を固定します。シードを同じにすれば同じ乱数列が再現されるため、実験比較では必ずシードを固定・記録します。
  • PyTorchでは torch.multinomial(probs, num_samples=1) が同じくじ引きを高速に行ってくれます。

LLMの創造性や堅実さを調整するつまみが 温度（temperature、記号 TTT）です。仕組みは驚くほど単純で、softmaxの前にすべてのロジットを TTT で割るだけです。

def softmax_t(logits, T):
    exps = [math.exp(z / T) for z in logits]
    total = sum(exps)
    return [e / total for e in exps]

for T in [0.3, 1.0, 2.0]:

自分で文章を生成する

いよいよ「点数 → 温度つきsoftmax → サンプリング → 末尾に付け足す」をつないで、自分の手で文章生成関数 generate を書きます！

基礎の補足実行前に確認：自作 `generate` の1行ごとのテンソル（数の表、第6章）shape 追跡

「吾輩は猫である。名前は」（長さ6トークン）を入れた1周目の流れです。

処理変数形（shape）何をしているか
tok(text, return_tensors="pt").input_ids.to(...)ids[1, 6]文章をトークンIDの2次元テンソル（1文章×6トークン）へ
model(ids).logits[0, -1]logits[151936]末尾位置の次トークンの生の点数を取り出す
torch.softmax(logits.float() / temperature, dim=-1)probs[151936]温度で割って確率分布（合計1）に変換
torch.multinomial(probs, num_samples=1)next_id[1]確率に従ってトークンIDを1個サンプリング
next_id.view(1, 1)—[1, 1]ids（2次元）と連結できるよう形を [1, 1] に整える
torch.cat([ids, next_id.view(1, 1)], dim=1)ids[1, 7]軸1（横方向）に連結して文章を1トークン伸ばす

（.view やテンソル操作の詳細は第6章・第9章で本格的に練習します。ここでは「毎ステップ [1, 6] → [1, 7] → [1, 8] と1つずつ伸びる」ことをつかめれば完璧です！）

Python（Colabのセルに貼って実行）
def generate(text, n_tokens=30, temperature=1.0):
    ids = tok(text, return_tensors="pt").input_ids.to(model.device)
    for _ in range(n_tokens):
        with torch.no_grad():
            logits = model(ids).logits[0, -1]               # ① 次のトークンの点数
        probs = torch.softmax(logits.float() / temperature, dim=-1)  # ② 温度つきで確率に
        next_id = torch.multinomial(probs, num_samples=1)   # ③ サイコロを振る
        ids = torch.cat([ids, next_id.view(1, 1)], dim=1)   # ④ 最後に付け足す
    return tok.decode(ids[0])

torch.manual_seed(42)
print(generate("吾輩は猫である。名前は", n_tokens=40, temperature=0.7))
出力の例（数値や文章は実行ごとに変わってOK）

ボンゴ先生

見たかい？ ChatGPTを含む現代のすべてのLLMの文章生成の骨組みは、この10行なんだ。1つ予測して、自分の出力を次の入力の末尾に付け足して、また予測する──これを 自己回帰（autoregressive）生成 と呼ぶよ！

理論の小部屋：自己回帰生成の弱点と、先の章へのつながり

この素朴なループでは、トークンを1個増やすたびにそれまでの文章全体を毎回モデルに通し直すため、文章が長くなるほど1トークンあたりの計算が遅くなります。実際のLLMでは「過去の計算結果を覚えておいて再利用する」工夫（KVキャッシュ）で高速化します（第16章で自分で実装します）。
