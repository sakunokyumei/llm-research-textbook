つくるもの

bigramの確率表を、数えるのではなく勾配降下法で学習するニューラルネットワーク（最小のニューラル言語モデル）

この章でつくるもの

第6章の「確率の表」と、第7章の「坂を下る方法」を合体させます。表の中身をでたらめ（全部0）から始めて、損失が小さくなる方向に少しずつ調整していくと……表の中身が、数えた答えにだんだん近づいていくはずです。これが、世界で一番小さな ニューラル言語モデル です。

これまでの復習とつながり：第3章・第5章・第6章・第7章とのつながり

これまで別々に学んできた4つの道具が、この章でついに1本の線につながります！

  • 第3章（softmax）：生の点数（ロジット）を、合計1の確率分布に変える変換。
  • 第5章（交差エントロピー損失）：正解の文字に付けた確率の −log⁡-\log−log の平均。まっさらな一様分布なら損失は log⁡V\log VlogV。
  • 第6章（one-hot × 行列）：one-hot ベクトルに表 W を掛ける計算は、行を取り出す W[x] と数学的にまったく同じ。
  • 第7章（勾配降下法と自動微分）：loss.backward() で勾配を求め、with torch.no_grad(): の中で W -= lr * W.grad と坂を下り、勾配をリセットする。

ミナト

数えれば一瞬で答えが出るのに、わざわざ学習させる意味あるんですか？

ボンゴ先生

鋭い。この章のモデルだけ見れば、意味はない。でも、「数える」は直前の文字が1つのときしか使えない。直前10文字を見たいときは数えられない（第4章の組み合わせ爆発）。でも「学習」なら、どんなに複雑なモデルにも使える。今日は、答えが分かっている問題で、学習という方法が本当に正しい答えにたどり着くかを確かめるんだ。答え合わせ付きの練習問題だね。

基礎の補足なぜ `W[x]` は「最小のニューラルネットワーク」と言えるのか？

第6章で見たとおり、文字番号 x を one-hot ベクトル（x 番目だけ 1、残り2060個は 0）にして行列 W を右から掛けると、ちょうど W の x 行目がそのまま取り出されます。

Python（読むだけ・実行しなくてOK）
# 数学的にはこの2つは完全に同じ計算！
# 方法A（第6章の行列積）：巨大な one-hot 行列 [B, 2061] を作って W と掛ける（0の掛け算が多くて遅い）
#   logits = F.one_hot(x, num_classes=V).float() @ W
# 方法B（この章の書き方）：直接 x 行目を取り出すだけ（同じ結果で圧倒的に速く、自動微分もそのまま動く）
#   logits = W[x]

そして初期値を全部 0 にすると、すべての文字で e0=1e^0 = 1e0=1 になるため、softmax 後の確率はちょうど 11+1+⋯+1=1V\dfrac{1}{1 + 1 + \dots + 1} = \dfrac{1}{V}1+1+⋯+11​=V1​ の完全な一様分布になります。

損失：交差エントロピー

第5章の損失（正解の確率の −log⁡-\log−log の平均）を、テンソルで計算してみます。

Python（Colabのセルに貼って実行）
def loss_by_hand(W, x, y):
    logits = W[x]
    probs = F.softmax(logits, dim=1)
    p_correct = probs[torch.arange(len(y)), y]   # 各行の「正解の文字」の確率
    return -p_correct.log().mean()

print("手作りの損失：", loss_by_hand(W, xs[:1000], ys[:1000]).item())
print("F.cross_entropy：", F.cross_entropy(W[xs[:1000]], ys[:1000]).item())
print("log V：", math.log(V))
出力
手作りの損失： 7.630945205688477
F.cross_entropy： 7.630943775177002
log V： 7.630946580890459

理論の小部屋：交差エントロピー：`F.cross_entropy` が1つに融合している3ステップ

F.cross_entropy(logits, targets) は、次の 3つの計算 を内部でひとまとめ（かつオーバーフロー・アンダーフローしない数値的に安全な方法）で実行してくれます。

  1. 安全な softmax：生の点数 logits（形 [B, V]）の各行から最大値を引いて確率分布 ppp に変換（第3章）
  2. 正解の驚き −log⁡(p[target])-\log(p[\text{target}])−log(p[target])：各サンプル iii について、正解文字 targets[i] の確率だけを取り出して −log⁡-\log−log をとる（第5章）
  3. バッチ平均：BBB 個のサンプルの平均をとって1つのスカラー（損失）を返す
Loss=−1B∑i=1Blog⁡(softmax(logitsi)targeti)\text{Loss} = -\frac{1}{B} \sum_{i=1}^{B} \log \left( \text{softmax}(\text{logits}_i)_{\text{target}_i} \right)Loss=−B1​i=1∑B​log(softmax(logitsi​)targeti​​)

まっさらなモデルの損失は log⁡V=7.631\log V = 7.631logV=7.631。第5章の記録表の「でたらめ」と同じです。ここから、どこまで下げられるでしょう？

つまずき注意：絶対に注意！ `F.cross_entropy` には「softmax前の生のロジット」を渡す

初心者が最もやりがちなバグが、すでに F.softmax を掛けた確率 probs を F.cross_entropy に渡してしまうことです。F.cross_entropy の内部でもう一度 softmax が掛かってしまい（二重softmax）、エラーも出ないまま学習が壊れます！

Python（読むだけ・実行しなくてOK）
import math
# 正解がクラス0で、モデルがロジット [5.0, 0.0, 0.0]（ほぼ確信！）を出した例：
# ① 正しい使い方（生のロジットを渡す）：
#    softmax([5, 0, 0]) ≒ [0.987, 0.007, 0.007] → 損失 = -log(0.987) ≒ 0.013（ほぼ完璧！）
# ② 誤った使い方（確率 [0.987, 0.007, 0.007] をさらに F.cross_entropy に渡す）：
#    もう一度 softmax されて [0.570, 0.215, 0.215] → 損失 = -log(0.570) ≒ 0.562（大外れ扱い！）

鉄則：モデルの最後は必ず生のロジットのまま返し、F.cross_entropy(logits, y) に直接渡しましょう。確率が欲しいとき（生成や上位表示）だけ F.softmax を掛けます。

Pythonの道具箱：2つのリストで同時に選ぶ

probs[torch.arange(len(y)), y] は、「0行目の y[0] 列、1行目の y[1] 列、2行目の y[2] 列……」を一度に取り出す書き方です（第6章の P[xs, ys] と同じ）。torch.arange(n) は 0, 1, 2, …, n-1 を作ります。

学習：ミニバッチで坂を下る

いよいよ学習です。14万個の問題を毎回全部解くと時間がかかるので、毎回ランダムに1024問だけ選んで損失を計算し、坂を下ります。

Python（Colabのセルに貼って実行）
g = torch.Generator().manual_seed(0)
W = torch.zeros((V, V), requires_grad=True)
lr = 50
history = []

for step in range(3001):
    ix = torch.randint(0, len(xs), (1024,), generator=g)   # ランダムに1024問選ぶ（(1024,) は形の指定。要素1つでもカンマが必要）
    loss = F.cross_entropy(W[xs[ix]], ys[ix])               # ① 損失
    W.grad = None                                            # （勾配をリセット）
    loss.backward()                                          # ② 勾配
    with torch.no_grad():
        W -= lr * W.grad                                     # ③ 更新
    if step % 250 == 0:
        with torch.no_grad():
            val_loss = F.cross_entropy(W[vxs], vys).item()
        history.append((step, loss.item(), val_loss))
        if step % 500 == 0:
            print(f"ステップ {step:4d}：訓練 {loss.item():.3f}  検証 {val_loss:.3f}")
出力

ステップ 1500：訓練 3.686  検証 3.847

CPUだと1〜2分かかります。損失がどんどん下がっていきます！ 7.63（まっさら）から、3.7あたりまで来ました。

ステップ0の検証損失だけ7.531と、log⁡V=7.631\log V = 7.631logV=7.631 より少し小さいのは、検証損失を1回更新した後に測っているからです（コードでは、③の更新の後に検証しています）。訓練損失の7.631は更新の前に測っているので、ぴったり log⁡V\log VlogV です。

Pythonの道具箱：W.grad = None

第7章では .grad.zero_() で勾配を0にしました。W.grad = None は「勾配を捨てる」で、効果は同じです（次の backward() で新しく作られます）。メモリの節約になるので、こちらがよく使われます。

基礎の補足ニューラル学習ループ5ステップの解剖とミニバッチの読み方

この先の章（MLP・GPT・ファインチューニング）でも、学習ループの心臓部は常に次の 5ステップ です：

順番ステップ名この章のコード意味
①順伝播（forward）logits = W[xs[ix]]ミニバッチ1024問の生の点数（形 [1024, 2061]）を出す
②損失（loss）loss = F.cross_entropy(logits, ys[ix])正解とのずれを1つの数にまとめる
③勾配リセット（zero_grad）W.grad = None前回の勾配を消す（backward() の直前に置くのが安全！）
④逆伝播（backward）loss.backward()計算グラフを逆走し、全マスの勾配 W.grad を一括計算
⑤更新（step）with torch.no_grad(): W -= lr * W.grad記録を切って勾配の逆向きへ一歩下る

また ix = torch.randint(0, len(xs), (1024,), generator=g) のポイントも押さえておきましょう：

  • 0 以上 len(xs) 未満のランダムな行番号を batch_size = 1024 個引きます。
  • Pythonでは要素1個のタプルには末尾カンマが必要なので、(1024) ではなく (1024,) と書きます（(1024) だとただの整数になりエラー）。
  • 1エポック（訓練データ1周）＝ len(xs) / batch_size ステップなので、総エポック数は (ステップ数 × batch_size) ÷ len(xs) で計算できます。

理論の小部屋：ミニバッチ確率的勾配降下法（SGD）

全部のデータで損失を計算する代わりに、ランダムに選んだ一部（ミニバッチ、今回は1024個）で計算して坂を下る方法を、確率的勾配降下法（stochastic gradient descent、SGD）と言います。

  • 一部だけなので、損失や勾配は少しぶれる（上の「訓練」の値がガタガタなのはこのため）
  • でも計算が軽いので、同じ時間で何倍も多く坂を下れる
  • ぶれは、平均すると正しい方向を向いている

全問題を解いてから先生に採点してもらうより、10問ずつ解いてはその場で答え合わせをするほうが、早く上達しますよね。データ全体を1周することを 1エポック（epoch）と呼びます。今回は1024問 × 3000回 ≒ 300万問なので、約21エポックです。

学習率が50と大きいのは、この表の1マスあたりの勾配がとても小さいからです。モデルごとに、ちょうどいい学習率は違います。

学習した表の中身を見る

理論の小部屋：最尤推定：学習と数えるは同じ答えになる

これは偶然ではありません。「訓練データの交差エントロピー（驚きの平均）を最小にするような確率」は、数学的に 数えた割合（頻度） とぴったり一致することが証明できます。この「データが最もありそうになる（尤もらしい）パラメータを選ぶ」という考え方を 最尤推定（さいゆうすいてい、maximum likelihood estimation）と言います。

なぜ一致するのかというと、交差エントロピー損失の傾き（勾配）を計算すると、ちょうど「モデルの予測確率 − 実際の出現割合」という形になるからです。予測確率が実際の頻度とぴったり一致した瞬間に、傾きがゼロになって坂の下りが止まります。だから勾配降下法を繰り返すだけで、自然と数えた割合と同じ確率に落ち着くのです。

つまり、

  • 数えるbigram ＝ 最尤推定の答えを直接計算したもの
  • ニューラルbigram ＝ 同じ答えを坂を下って探したもの

直接計算できるのは、bigramのような単純なモデルだけです。ニューラルネットワークを使えば、直接計算できないような複雑なモデルでも、同じ「坂を下る」方法で答えを探せます。それが、この先のすべての章でやることです。

理論の小部屋：スムージングと正則化

数えるbigramでは、見たことのないペアに確率0をつけないよう、スムージングで回数に少し下駄をはかせました。ニューラルbigramでは、W が全部0（＝全文字が等確率）から出発し、学習ステップ数が有限なので、極端な確率0にはなりません。

さらに積極的に「極端な値になるのを防ぐ」方法として、損失に「W の値が大きいほど罰を与える」項を足すやり方があります。これを 正則化（せいそくか、regularization）と言い、スムージングと同じ役割を果たします（第10章で weight_decay として登場します）。

生成してみる

Python（Colabのセルに貼って実行）
g = torch.Generator().manual_seed(1)
ix = stoi["私"]
out = ["私"]
with torch.no_grad():
    for _ in range(60):
        p = F.softmax(W[ix], dim=0)
        ix = torch.multinomial(p, 1, generator=g).item()
        out.append(itos[ix])
print("".join(out))

やってみよう：学習率を変えてみよう

lr = 50 を lr = 5、lr = 200、lr = 1000 に変えて、学習曲線を描き直してみましょう。どうなるか予想してから！ 教科書の検証で実際に試した結果（3000ステップ後の検証損失）はこうでした。

  • 5：4.41。ゆっくりすぎて、3000ステップでは全然下りきらない
  • 200：3.58。意外にも、50より速く、なめらかに下がる。このモデルは単純なので、「ちょうどいい」範囲が思ったより広いのです。そして、数えた版（3.581）とほぼ同じところで止まります。同じ「直前1文字」の情報しか使っていない以上、そこが限界だからです
  • 1000：5.57。さすがに大きすぎて、損失が上がったり下がったり暴れ、ちっとも下がらない

「ちょうどいい学習率」はやってみないと分からず、モデルによって違う。だから研究者は、いくつか試して学習曲線を見比べるのです。

つまずき注意：よくあるつまずき

  • 損失が nan になった：学習率が大きすぎて発散しています。学習率を小さくしましょう。
  • RuntimeError: element 0 of tensors does not require grad：W を作るときに requires_grad=True を付け忘れています。
  • RuntimeError: a leaf Variable that requires grad is being used in an in-place operation.：更新の行（W -= lr * W.grad）が with torch.no_grad(): の中に入っていません（字下げを確認）。
  • 損失がほとんど下がらない：学習率が小さすぎるか、勾配のリセット（W.grad = None）の位置がずれています。上のコードと1行ずつ見比べましょう。
  • とても遅い：検証損失の計算（W[vxs]）は重いので、毎ステップではなく250ステップごとにしています。Colabのランタイムを「T4 GPU」にして、W を作る行を W = torch.zeros((V, V), requires_grad=True, device="cuda") に変え、xs, ys, vxs, vys もそれぞれ xs = xs.to("cuda") のようにGPUへ送ると速くなります。W は、作った後から .to("cuda") すると「学習するパラメータ」ではなくなり、W.grad が None のままになるので、作るときに device= で指定するのがコツです。GPUにした場合は、「生成してみる」のセルの p = F.softmax(W[ix], dim=0) を p = F.softmax(W[ix], dim=0).cpu() に変えます（サイコロの generator がCPU用なので、確率もCPUに戻す必要があります）。くわしくは第13章で本格的にやります。
