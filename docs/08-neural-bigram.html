数えずに学ぶ：ニューラルbigram

確率の表を勾配降下法で「学習」させたら、数えた答えに近づいていった

目安
60〜90分
環境
Google Colab（CPUでOK）
難しさ
★★★☆☆
Colabで開く（完成ノート）ノートブックをダウンロード

おすすめは「ページを読みながら、コードを自分のノートブックに1セルずつ貼って実行」。完成ノートは困ったときの答え合わせ用です。

つくるもの

bigramの確率表を、数えるのではなく勾配降下法で学習するニューラルネットワーク（最小のニューラル言語モデル）

ついでに身につく理論

  • ロジットの表＝パラメータ
  • 交差エントロピー損失（F.cross_entropy）
  • ミニバッチ確率的勾配降下法（SGD）
  • 最尤推定：損失最小化は「数える」と同じ答えになる
  • 学習曲線の読み方
  • 正則化とスムージングの関係

新しく使うPython

  • torch.randint でランダムに選ぶ
  • torch.Generator で乱数を固定
  • F.cross_entropy
  • W.grad = None

この章でつくるもの

第6章の「確率の表」と、第7章の「坂を下る方法」を合体させます。表の中身をでたらめ（全部0）から始めて、損失が小さくなる方向に少しずつ調整していくと……表の中身が、数えた答えにだんだん近づいていくはずです。これが、世界で一番小さな ニューラル言語モデル です。

ミナト

数えれば一瞬で答えが出るのに、わざわざ学習させる意味あるんですか？

ボンゴ先生

鋭い。この章のモデルだけ見れば、意味はない。でも、「数える」は直前の文字が1つのときしか使えない。直前10文字を見たいときは数えられない（第4章の組み合わせ爆発）。でも「学習」なら、どんなに複雑なモデルにも使える。今日は、答えが分かっている問題で、学習という方法が本当に正しい答えにたどり着くかを確かめるんだ。答え合わせ付きの練習問題だね。

準備

準備セルに、今回は文字⇔番号の変換と、データのテンソル化も入れておきます。

Python（Colabのセルに貼って実行）
import re, math, urllib.request
import torch
import torch.nn.functional as F

def load_soseki(file_id="773_ruby_5968"):
    url = ("https://raw.githubusercontent.com/aozorahack/aozorabunko_text/master/"
           f"cards/000148/files/{file_id}/{file_id}.txt")
    text = urllib.request.urlopen(url).read().decode("cp932")
    text = text.split("-------------------------------------------------------")[2]
    text = text.split("底本：")[0]
    text = re.sub(r"《.*?》", "", text)
    text = re.sub(r"※?［＃.*?］", "", text)
    text = text.replace("｜", "").replace("\r\n", "\n")
    text = re.sub(r"\n{3,}", "\n\n", text)
    return text.strip()

text = load_soseki()
chars = sorted(set(text))
V = len(chars)
stoi = {ch: i for i, ch in enumerate(chars)}
itos = {i: ch for ch, i in stoi.items()}

data = torch.tensor([stoi[c] for c in text])
n = int(len(data) * 0.9)
train_data, val_data = data[:n], data[n:]
print(V, train_data.shape, val_data.shape)
出力

今度は文章全体を数字のテンソルにしてしまいました。ここからは、文字ではなく番号で考えます。

vxs, vys = val_data[:-1], val_data[1:]
print("入力：", xs[:8].tolist())
print("正解：", ys[:8].tolist())
print("文字で見ると：", [itos[i] for i in xs[:8].tolist()], "→", [itos[i] for i in ys[:8].tolist()])

正解： [3, 263, 1272, 45, 1375, 0, 0, 132]

入力と正解が、1文字ずつずれて並んでいます。「上 の次は 　（全角空白）」「先 の次は 生」……。これが、言語モデルの 教師データ です。問題（入力）と答え（正解）の組が14万個以上あります。

モデル：中身がでたらめな表

第6章の確率の表 P の代わりに、点数（ロジット）の表 W を用意します。中身は最初、全部0です。

Python（Colabのセルに貼って実行）
W = torch.zeros((V, V), requires_grad=True)
print(W.shape, "パラメータの数：", W.numel())
出力
torch.Size([2061, 2061]) パラメータの数： 4247721

使い方は第6章と同じです。今の文字の番号で行を取り出せば、それが「次の文字の点数」。第3章のsoftmaxで確率にします。

Python（Colabのセルに貼って実行）
x = torch.tensor([stoi["先"]])
logits = W[x]                       # 「先」の行＝次の文字の点数（ロジット）
probs = F.softmax(logits, dim=1)
print(logits.shape, probs.shape)
print("「生」の確率：", probs[0, stoi["生"]].item(), " ＝ 1/V：", 1 / V)
出力
torch.Size([1, 2061]) torch.Size([1, 2061])
「生」の確率： 0.0004852013662457466  ＝ 1/V： 0.00048520135856380397

点数が全部0なので、softmaxするとどの文字も同じ確率 1/20611/20611/2061 になります。何も知らない、まっさらな状態です。

損失：交差エントロピー

第5章の損失（正解の確率の −log⁡-\log−log の平均）を、テンソルで計算してみます。

Python（Colabのセルに貼って実行）
def loss_by_hand(W, x, y):
    logits = W[x]
    probs = F.softmax(logits, dim=1)
    p_correct = probs[torch.arange(len(y)), y]   # 各行の「正解の文字」の確率
    return -p_correct.log().mean()

print("手作りの損失：", loss_by_hand(W, xs[:1000], ys[:1000]).item())
print("F.cross_entropy：", F.cross_entropy(W[xs[:1000]], ys[:1000]).item())
print("log V：", math.log(V))
出力
手作りの損失： 7.630945205688477
F.cross_entropy： 7.630943775177002
log V： 7.630946580890459

理論の小部屋：交差エントロピー

「softmaxで確率にして、正解の確率の −log⁡-\log−log を平均する」という計算は、機械学習であまりにもよく使うので、交差エントロピー損失（cross-entropy loss）という名前がついていて、PyTorchには F.cross_entropy という専用の関数があります。ロジットと正解の番号を渡すだけで、softmaxから平均まで全部やってくれます（しかも、数値的に安定な方法で）。

まっさらなモデルの損失は log⁡V=7.631\log V = 7.631logV=7.631。第5章の記録表の「でたらめ」と同じです。ここから、どこまで下げられるでしょう？

Pythonの道具箱：2つのリストで同時に選ぶ

probs[torch.arange(len(y)), y] は、「0行目の y[0] 列、1行目の y[1] 列、2行目の y[2] 列……」を一度に取り出す書き方です（第6章の P[xs, ys] と同じ）。torch.arange(n) は 0, 1, 2, …, n-1 を作ります。

学習：ミニバッチで坂を下る

いよいよ学習です。14万個の問題を毎回全部解くと時間がかかるので、毎回ランダムに1024問だけ選んで損失を計算し、坂を下ります。

Python（Colabのセルに貼って実行）
g = torch.Generator().manual_seed(0)
W = torch.zeros((V, V), requires_grad=True)
lr = 50
history = []

for step in range(3001):
    ix = torch.randint(0, len(xs), (1024,), generator=g)   # ランダムに1024問選ぶ
    loss = F.cross_entropy(W[xs[ix]], ys[ix])               # ① 損失
    W.grad = None                                            # （勾配をリセット）
    loss.backward()                                          # ② 勾配
    with torch.no_grad():
        W -= lr * W.grad                                     # ③ 更新
    if step % 250 == 0:
        with torch.no_grad():
            val_loss = F.cross_entropy(W[vxs], vys).item()
        history.append((step, loss.item(), val_loss))
        if step % 500 == 0:
            print(f"ステップ {step:4d}：訓練 {loss.item():.3f}  検証 {val_loss:.3f}")
出力

ステップ  500：訓練 4.196  検証 4.206
ステップ 1000：訓練 3.963  検証 3.963
ステップ 1500：訓練 3.686  検証 3.847
ステップ 2000：訓練 3.685  検証 3.771
ステップ 2500：訓練 3.548  検証 3.719
ステップ 3000：訓練 3.379  検証 3.685

CPUだと1〜2分かかります。損失がどんどん下がっていきます！ 7.63（まっさら）から、3.7あたりまで来ました。

Pythonの道具箱：W.grad = None

第7章では .grad.zero_() で勾配を0にしました。W.grad = None は「勾配を捨てる」で、効果は同じです（次の backward() で新しく作られます）。メモリの節約になるので、こちらがよく使われます。

理論の小部屋：ミニバッチ確率的勾配降下法（SGD）

全部のデータで損失を計算する代わりに、ランダムに選んだ一部（ミニバッチ、今回は1024個）で計算して坂を下る方法を、確率的勾配降下法（stochastic gradient descent、SGD）と言います。

  • 一部だけなので、損失や勾配は少しぶれる（上の「訓練」の値がガタガタなのはこのため）
  • でも計算が軽いので、同じ時間で何倍も多く坂を下れる
  • ぶれは、平均すると正しい方向を向いている

全問題を解いてから先生に採点してもらうより、10問ずつ解いてはその場で答え合わせをするほうが、早く上達しますよね。データ全体を1周することを 1エポック（epoch）と呼びます。今回は1024問 × 3000回 ≒ 300万問なので、約21エポックです。

学習率が50と大きいのは、この表の1マスあたりの勾配がとても小さいからです。モデルごとに、ちょうどいい学習率は違います。

学習した表の中身を見る

学習した W が、本当に「数えた答え」に似ているか確かめましょう。

Python（Colabのセルに貼って実行）
with torch.no_grad():
    p = F.softmax(W[stoi["先"]], dim=0)
top = torch.topk(p, 5)
print("学習したモデル：「先」の次は…")
for prob_, i in zip(top.values, top.indices):
    print(f"  {itos[i.item()]!r} {prob_.item():.3f}")
出力
学習したモデル：「先」の次は…
  '生' 0.895
  'へ' 0.026
  '刻' 0.020
  'で' 0.012
  'に' 0.004

数えたときは「生」が0.88でした（第4章）。学習では0.895。誰にも「数えろ」とは教えていないのに、損失を小さくしようと坂を下っただけで、数えた答えにたどり着いたのです。

理論の小部屋：最尤推定：学習と数えるは同じ答えになる

これは偶然ではありません。「訓練データの交差エントロピー（驚きの平均）を最小にするような確率」は、数学的に 数えた割合（頻度） とぴったり一致することが証明できます。この「データが最もありそうになる（尤もらしい）パラメータを選ぶ」という考え方を 最尤推定（さいゆうすいてい、maximum likelihood estimation）と言います。

つまり、

  • 数えるbigram ＝ 最尤推定の答えを直接計算したもの
  • ニューラルbigram ＝ 同じ答えを坂を下って探したもの

直接計算できるのは、bigramのような単純なモデルだけです。ニューラルネットワークを使えば、直接計算できないような複雑なモデルでも、同じ「坂を下る」方法で答えを探せます。それが、この先のすべての章でやることです。

理論の小部屋：スムージングと正則化

数えるbigramでは、見たことのないペアに確率0をつけないよう、スムージングで回数に少し下駄をはかせました。ニューラルbigramでは、W が全部0（＝全文字が等確率）から出発し、学習ステップ数が有限なので、極端な確率0にはなりません。

さらに積極的に「極端な値になるのを防ぐ」方法として、損失に「W の値が大きいほど罰を与える」項を足すやり方があります。これを 正則化（せいそくか、regularization）と言い、スムージングと同じ役割を果たします（第10章で weight_decay として登場します）。

生成してみる

Python（Colabのセルに貼って実行）
g = torch.Generator().manual_seed(1)
ix = stoi["私"]
out = ["私"]
with torch.no_grad():
    for _ in range(60):
        p = F.softmax(W[ix], dim=0)
        ix = torch.multinomial(p, 1, generator=g).item()
        out.append(itos[ix])
print("".join(out))

やってみよう：学習率を変えてみよう

lr = 50 を lr = 5 や lr = 200 に変えて、学習曲線を描き直してみましょう。

  • 5：ゆっくりすぎて、3000ステップでは全然下りきらない
  • 200：最初は速いが、損失がガタガタ暴れる（場合によっては悪化する）

「ちょうどいい学習率」がモデルによって違うことを体感できます。

つまずき注意：よくあるつまずき

  • 損失が nan になった：学習率が大きすぎて発散しています。学習率を小さくしましょう。
  • 損失がまったく下がらない：W を作るときに requires_grad=True を付け忘れていないか、更新の行（W -= lr * W.grad）が with torch.no_grad(): の中にあるか確認しましょう。
  • とても遅い：検証損失の計算（W[vxs]）は重いので、毎ステップではなく250ステップごとにしています。Colabのランタイムを「T4 GPU」にして、テンソルを .to("cuda") で送ると速くなります（第13章で本格的にやります）。

クイズ 1：初期の損失

語彙が100文字のモデルを、ロジットが全部0の状態から学習を始めました。最初の損失はいくつになるはず？

答えを見る（まず自分で考えてから！）

log⁡100≈4.605\log 100 \approx 4.605log100≈4.605 です。全部の文字の確率が 1/1001/1001/100 なので、正解の確率も 1/1001/1001/100、その −log⁡-\log−log は log⁡100\log 100log100。最初の損失が log⁡V\log VlogV から大きくずれていたら、初期化がおかしいサインです（第10章）。

クイズ 2：最尤推定

ニューラルbigramを十分長く学習させると、確率の表はどんな値に近づく？

答えを見る（まず自分で考えてから！）

訓練データで数えた割合（頻度）に近づきます。交差エントロピーを最小にする確率は、数えた割合と一致する（最尤推定）からです。

できたらチェック

まとめ

  • ニューラルbigram ＝ ロジットの表 W を、交差エントロピーが小さくなるように勾配降下法で調整したもの
  • ミニバッチSGD：ランダムな一部で損失と勾配を計算し、少しずつ下る
  • 損失最小化（最尤推定）の答えは、数えた頻度と一致する。学習は「数える」の一般化
  • 学習曲線で、訓練と検証の損失を見比べるのが診断の基本
