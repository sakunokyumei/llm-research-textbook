12 環境・Git・実験の記録

到達目標：同じプログラムを再実行する条件を保存する

前提：11 テストとデバッグで確かめる 演習 4 問

読む目安 7〜12分／演習 12〜24分。実装・到達課題は別の回に分けられます

時間は編集上の目安です。見出し一つで休憩しても大丈夫。中断・再開と補習の手引きも使ってください。

昨日は動いたのに

同じファイルでも、使うライブラリが更新されると動作が変わることがあります。ライブラリは、他の人が用意した機能の集まりです。研究ではコードだけでなく、Python、ライブラリ、データ、実験設定の版も記録します。

CPUはプログラムの命令を実行する装置、GPUは同じ種類の計算を多数同時に行うのに向いた装置です。ドライバーはOSが装置を使うためのソフトウェアです。NumPyは数の並びや表を計算するためのライブラリで、以下ではその導入を例にします。

仮想環境は、プロジェクトごとにPythonの追加ライブラリを分ける仕組みです。以下はターミナルで実行します。.venvは作るフォルダの名前です。

python -m venv .venv

Windowsでは.venv\Scripts\python.exe、macOS/Linuxでは.venv/bin/pythonが環境内のPythonです。以下の例はmacOS/Linuxの表記です。Windowsでは先頭を対応するパスへ置き換えます。環境を有効化する操作を省き、使うPythonを明示しています。

.venv/bin/python -m pip install numpy
.venv/bin/python -m pip freeze > requirements.txt

pipはライブラリを管理する道具です。>は出力をファイルへ保存するターミナルの記法で、既存の同名ファイルを上書きします。実験ごとに別フォルダを作って保存してください。requirements.txtから復元するときはpython -m pip install -r requirements.txtを使います。OSやGPUドライバーまではこのファイルだけで固定されません。

Gitは変化の記録

Gitはファイルの変更履歴を管理します。GitHubはGitのリポジトリを共有するサービスです。両者は別です。リポジトリは履歴を含むプロジェクトの単位。commitは変更内容を区切って記録する操作です。

git init
git status
git add first.py
git commit -m "Add first calculation"

これは新しい練習用フォルダだけで実行します。statusで対象を確認し、addで次の記録に含めるファイルを選びます。commitの前に、メールアドレス等の作者設定を自分の公開方針に合わせます。秘密鍵、APIキー、個人データ、巨大な学習結果を安易に追加しません。.gitignoreに書くと追跡対象から外せますが、既に記録した秘密を消したことにはなりません。

シェルの最低限

シェルは文字の命令を受け取ってOSの操作を行います。PowerShellとBashは違う言語なので、すべてのコマンドが共通ではありません。cdは作業場所を変えます。ファイル名に空白がある場合は引用符で囲みます。削除コマンドは、対象と復元方法を理解するまで練習に使う必要がありません。

論文のコードを動かすときは、実行前に内容、必要権限、通信先、データ利用条件を確認します。知らないスクリプトの命令を、そのまま管理者権限で実行する必要はありません。

最小の実験記録

記録 理由
コードのcommit どの実装を使ったか
データ版・分割・ハッシュ 同じ材料かを確認する
設定と乱数seed 実験条件を追う
Python・ライブラリ・装置 実行環境の差を調べる
全実行の結果・失敗 都合のよい結果だけを選ばない

ハッシュはファイル内容から計算する短い識別値です。内容が変わったかを検出する手掛かりになります。seedは乱数列を始める設定値ですが、seedをそろえるだけで異なる装置・版の結果が完全に一致するとは限りません。

演習

1・再現に足りないもの

「seed=42で実行した」とだけ書かれた結果から、同じ実験をできますか。足りないものを三つ挙げてください。

解答と考え方を読む

コードの版、データと分割、計算の回数などの設定、ライブラリ版、実行装置などが必要です。seedだけでは条件を特定できません。

2・環境の分離

二つの研究が異なるライブラリ版を要求します。一つの環境へ順番に入れ替えるよりよい方法は何ですか。

解答と考え方を読む

研究ごとに仮想環境を作り、各環境で版を固定します。互いに依存関係を上書きしにくくなります。

3・公開前の確認

APIキーをファイルへ書き、既にcommitしました。今.gitignoreへ追加すれば秘密は保護されたと言えますか。

解答と考え方を読む

言えません。過去の履歴に残っています。実際の秘密なら失効・再発行を行い、公開済みか確認し、必要な履歴処理も行います。本教材の練習では実際のキーを使わないでください。

4・記録の単位

計算の回数を変える実験の結果を同じresult.jsonへ毎回上書きすると、何が失われますか。

解答と考え方を読む

前の実行結果と条件の対応が失われます。実行IDごとのフォルダ、設定ファイル、結果ファイルを残します。

到達課題と出典

練習用フォルダにREADMEを作り、実行コマンド・入力・期待する出力を説明してください。別の日にその説明だけで実行できるか試します。Python venv、Pro Git、PyTorch 再現性 を参照。
