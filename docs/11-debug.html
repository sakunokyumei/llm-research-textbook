11 テストとデバッグで確かめる

到達目標：最小例・期待値・例外から不具合を切り分ける

前提：10 演習 5 問

動いたことは、正しいことか

誤った平均を返すプログラムも、エラーを出さずに動くことがあります。そこで「この入力にはこの答えになるはず」という小さな約束を作り、実際の結果と比べます。これをテストと呼びます。

def mean(values):
    if len(values) == 0:
        raise ValueError("空の並びの平均は求めません")
    return sum(values) / len(values)

assert mean([2, 4, 6]) == 4
assert mean([7]) == 7
assert abs(mean([0.1, 0.2]) - 0.15) < 1e-12
print("checks passed")

assertは条件が偽なら止まって知らせます。最後の比較だけ誤差の許容幅を設けたのは、小数の計算が有限精度だからです。許容誤差を大きくしすぎると本当の間違いを見逃します。

正常・境界・異常

普通の入力だけでなく、一つしかない入力、空の入力、不適切な型なども考えます。空の平均を0にすると「平均が本当に0のデータ」と区別できません。今回はエラーにする設計を選びました。何を許すかを仕様として先に決めます。

例外を扱うtryとexceptは、想定したエラーへの対応を書く仕組みです。すべての例外を無条件に無視すると、本当の不具合が隠れます。

try:
    int("not-a-number")
except ValueError:
    print("数へ変換できませんでした")

大きな失敗を小さくする

深層学習で損失が変な値になったとき、まずデータを二件、モデルを一層に減らします。入力・出力・形・値の範囲を表示し、手計算と比べます。原因候補を五つ同時に変えると、どの変更が効いたか分からなくなります。一つずつ変更し、同じテストを再実行します。

関数を別ファイルへ分けると、そのファイルをモジュールとしてimportできます。関連した状態と操作をまとめるときはクラスを使います。たとえば次のCounterは、countという状態とaddという操作を持ちます。

class Counter:
    def __init__(self):
        self.count = 0

    def add(self):
        self.count += 1

counter = Counter()
counter.add()
print(counter.count)

selfは「この実体」を参照する名前です。__init__は実体を作る際の初期化処理。PyTorchのモデルもこの考えで作るので、状態を持つ関数のまとまりとして理解しておきます。

演習

1・仕様を作る

正解率の関数へtotal=0が渡されたら、どう扱うべきでしょう。理由も述べてください。

解答と考え方を読む

たとえばValueErrorとして知らせます。0%と返すと「全問不正解」と「評価例がない」を混同するためです。別の設計として欠測値を返すこともできますが、明記が必要です。

2・テストを選ぶ

二つの数の大きい方を返す関数に、最低三つのテスト入力を選んでください。

解答と考え方を読む

(2,5)→5、(5,2)→5、(3,3)→3。負の数も許すなら(−2,−5)→−2を追加します。順序と等しい境界を確かめています。

3・切り分ける

コード、データ、学習率を同時に変えたら結果が改善しました。どの変更が効いたと言えますか。

解答と考え方を読む

この実験だけでは区別できません。一つだけを変えた比較、または組合せを整理した実験が必要です。デバッグの切り分けは研究のablationにもつながります。

4・クラスの状態

Counterの実体aとbを別々に作り、a.add()だけを二回呼びました。a.countとb.countはいくつですか。

解答と考え方を読む

2と0です。それぞれの実体に独立したcountを初期化しているためです。

5・精度の確認

小数の結果を比較するとき、単に許容誤差を1へ広げてテストを通すのは適切ですか。

解答と考え方を読む

誤差の大きさが仕様や数値精度に照らして妥当かを確認する必要があります。テストが通る値へ合わせるだけでは、間違った計算を正しいことにしてしまいます。
