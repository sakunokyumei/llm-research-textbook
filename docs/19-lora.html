この章でつくるもの

第18章では、0.5Bのモデルの全パラメータを学習させるのに約10GBのメモリを使いました。この方法では、7Bのモデルは無料のGPUに乗りません。この章では、モデル本体の重みを凍結（変えない）したまま、ほんの少しの追加パラメータだけを学習する LoRA を、まず自分の手で実装します。さらに、モデル本体を4ビットに縮める 量子化 と組み合わせた QLoRA で、無料のT4でも大きめのモデルを鍛えられるようにします。

これまでの復習とつながり：第1章・第6章・第18章とのつながり

  • 第1章・第15章（VRAMの見積もり）：学習時のメモリは「重み＋勾配＋Adamの記録 ≒ 16バイト × パラメータ数」で決まり、T4 GPUの16GB上限が大きな壁になることを学びました。
  • 第6章（行列のかけ算の形）：形 (m, k) の行列と (k, n) の行列を掛けると (m, n) になるルールを使います。LoRAの BABABA と x @ A.T @ B.T はまさにこの形の組み合わせです。
  • 第18章（全パラメータSFT）：損失マスク -100 とパディングで作ったボンゴ先生データを、そのままこの章のLoRA学習に再利用します！

この章では、「なぜ低ランク行列 BABABA でパラメータが1%以下に縮むのか」「なぜ B=0B=0B=0・AAA はランダムに初期化するのか」「量子化の丸め誤差はどう計算されるのか」 を手計算と実装の両面からマスターします。

ミナト

本体を変えずに鍛えるって、どういうことですか？ 筋トレしないでマッチョになる、みたいな……？

ボンゴ先生

いい例えだ（いや、そうでもない）。教科書に書き込みをする代わりに、付せんを貼るイメージだ。教科書（元のモデル）はきれいなまま。付せん（LoRA）に「ここはこう読み替える」と書いておく。付せんは小さいから、何枚作っても軽い。しかも剥がせば元通り。用途ごとに付せんを取り替えることもできる。

なぜ全部を学習すると重いのか

第15章で計算したとおり、AdamWで学習するときのメモリは、だいたい「16バイト × パラメータ数」でした。

モデル 推論（float16） 全パラメータの学習
0.5B 約1GB 約8GB
1.5B 約3GB 約24GB（T4に乗らない）
7B 約14GB 約112GB（T4が7枚以上）

学習のメモリの大半は、勾配とAdamの記録（慣性と歩幅）です。どちらも「学習するパラメータの数」に比例します。だったら、学習するパラメータを減らせばいいのです。

行列のランク：情報は意外と少ない

LoRAのアイデアの元になる、ランク（階数）という考え方を見ておきましょう。

Python（Colabのセルに貼って実行）
import torch
torch.manual_seed(0)
A = torch.randn(6, 2)
B = torch.randn(2, 6)
W = A @ B                       # 6×2 と 2×6 の積 → 6×6の行列
print(W.shape, "のランク：", torch.linalg.matrix_rank(W).item())
print("Wの数の個数：", W.numel(), " AとBの数の個数：", A.numel() + B.numel())
出力
torch.Size([6, 6]) のランク： 2
Wの数の個数： 36  AとBの数の個数： 24

数学の道具箱：ランクとLoRA（W′=W+αrBAW' = W + \frac{\alpha}{r}BAW′=W+rα​BA）：7ステップで理解する

① 解決したい問題：巨大な重み行列 WWW（たとえば 7B モデルにある 4096×4096=1,677万4096 \times 4096 = 1{,}677\text{万}4096×4096=1,677万 個の重み）を直接更新すると、勾配とAdamの記録だけでVRAMがパンクしてしまう。元の重み WWW を凍結したまま、ほんのわずかなパラメータ数で表現力豊かな調整 ΔW\Delta WΔW を加えたい。

② 素朴な方法では困る理由：全要素を直接学習すると 16バイト × パラメータ数でメモリ不足になる。かといって最後の1層だけを学習するだけでは、モデル全体の口調や推論パターンを十分に変えられない。

③ 発想（低ランク近似）：6×6の行列 W には36個の数が並んでいますが、6×2と2×6の行列の積で作ったので、本当は2次元ぶんの情報（ランク2）しか持っていません。2021年にMicrosoftの研究者が提案した LoRA（Low-Rank Adaptation）は、「ファインチューニングでの重みの変化 ΔW\Delta WΔW は低いランク rrr で十分に表せる」という発見に基づき、変化ぶんだけを2つの細い行列 BBB と AAA の積に分解します。

④ 記号表と数式：

W′=W+ΔW=W+αrBAW' = W + \Delta W = W + \frac{\alpha}{r} B AW′=W+ΔW=W+rα​BA
記号 形（shape） 凍結／学習 意味
WWW (dout,  din)(d_{\text{out}},\; d_{\text{in}})(dout​,din​) 凍結（更新しない） 事前学習済みの元の重み行列
AAA (r,  din)(r,\; d_{\text{in}})(r,din​) 学習する 入力を細い rrr 次元へ圧縮（ランダム正規分布で初期化）
BBB (dout,  r)(d_{\text{out}},\; r)(dout​,r) 学習する rrr 次元を元の出力次元へ展開（すべて 0 で初期化）
rrr スカラー整数（例：4, 8, 16） ハイパーパラメータ ランク（通り道の細さ・ボトルネックの幅）
α\alphaα スカラー（例：16, 32） ハイパーパラメータ 変化の効き具合を調整する倍率（αr\frac{\alpha}{r}rα​ を掛ける）

⑤ 具体的な手計算でパラメータ削減量を確かめよう： 一般の dout×dind_{\text{out}} \times d_{\text{in}}dout​×din​ の層で、元のパラメータ数は doutdind_{\text{out}} d_{\text{in}}dout​din​ 個、LoRAは r(din+dout)r(d_{\text{in}} + d_{\text{out}})r(din​+dout​) 個です。

  • 7Bクラスの層（4096×40964096 \times 40964096×4096、r=8r = 8r=8）：
    • 元の重み WWW：4096×4096=16,777,2164096 \times 4096 = \mathbf{16{,}777{,}216}4096×4096=16,777,216 個（約 16.78M）
    • LoRA（AAA と BBB）：8×(4096+4096)=65,5368 \times (4096 + 4096) = \mathbf{65{,}536}8×(4096+4096)=65,536 個（約 65.5K）
    • 割合：65,536÷16,777,216≈0.39%65{,}536 \div 16{,}777{,}216 \approx \mathbf{0.39\%}65,536÷16,777,216≈0.39%！（99.6%削減！）
  • この章のQwen2.5-0.5B（896×896896 \times 896896×896、r=8r = 8r=8）：
    • 元の重み WWW：896×896=802,816896 \times 896 = 802{,}816896×896=802,816 個 → LoRA：8×(896+896)=14,3368 \times (896 + 896) = \mathbf{14{,}336}8×(896+896)=14,336 個（約 1.79%）

⑥ なぜ「B=0B = 0B=0、A=A =A= ランダム正規分布」で初期化するのか？

  1. ステップ0で元のモデルを完全に守る：B=0B = 0B=0 なら ΔW=αrBA=0\Delta W = \frac{\alpha}{r}BA = 0ΔW=rα​BA=0 となり、学習開始瞬間の出力は事前学習済みモデルと100%一致します（最初から元の能力を壊さない！）。
  2. なぜ AAA まで 0 にしてはいけないのか？：連鎖律より、BBB の勾配は AAA に比例し、AAA の勾配は BBB に比例します。もし両方とも 0 にすると、AAA・BBB 両方の勾配がずっと 0 のままになって学習が一歩も進みません！ AAA をランダム（非ゼロ）にしておくことで、ステップ1から BBB に非ゼロの勾配が流れて動き出し、ステップ2以降は AAA も一緒に学習されます。

⑦ 理解のための最小Pythonコード：

Python（読むだけ・実行しなくてOK）
d_in, d_out, r = 4096, 4096, 8
orig = d_in * d_out                 # 16,777,216
lora = r * (d_in + d_out)           # 65,536
print(f"{lora / orig:.2%}")         # 0.39%

LoRA層を自分で作る

Python（Colabのセルに貼って実行）
import torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r=8, alpha=16):
        super().__init__()
        self.base = base
        self.base.requires_grad_(False)                       # 本体は凍結
        self.A = nn.Parameter(torch.randn(r, base.in_features) * 0.01)
        self.B = nn.Parameter(torch.zeros(base.out_features, r))   # 最初は0
        self.scale = alpha / r

    def forward(self, x):
        return self.base(x) + (x @ self.A.T @ self.B.T) * self.scale

base = nn.Linear(896, 896)
lora = LoRALinear(base)
x = torch.randn(2, 896)
print("最初は元の層と同じ？", torch.allclose(base(x), lora(x)))
trainable = sum(p.numel() for p in lora.parameters() if p.requires_grad)
print(f"学習するパラメータ：{trainable:,} / 元の層：{base.weight.numel() + base.bias.numel():,}")
出力
最初は元の層と同じ？ True
学習するパラメータ：14,336 / 元の層：803,712

Pythonの道具箱：requires_grad_(False) と nn.Parameter

requires_grad_(False) は「このパラメータの勾配は計算しなくていい（学習しない）」という設定です。勾配もAdamの記録も作られないので、メモリを食いません。これを 凍結（freeze）と言います。
nn.Parameter(テンソル) は、そのテンソルを「このモデルの学習するパラメータ」として登録します。こうしておくと、model.parameters() に含まれ、オプティマイザが更新してくれます。
def __init__(self, base: nn.Linear, …) の : nn.Linear は 型ヒント（「ここには全結合層が入ります」というメモ）で、動きは変わりません。第23章でもう一度出てきます。

基礎の補足x @ self.A.T @ self.B.T のテンソル形状トレース（なぜ .T が要るのか？）

PyTorchの nn.Linear(in_features, out_features) は重みを (out_features, in_features) で持ち、入力 x（形 (batch, in_features)）に右から転置を掛けます。LoRAの2つの行列も同じ流儀で A: (r, d_in)、B: (d_out, r) と定義しているため、左から順に次のように形が変化します（例：batch=2, d_in=896, r=8, d_out=896）。

ステップ 式 テンソルの形 役割
入力 x (2, 896) バッチ2件 × 896次元
圧縮 x @ self.A.T (2, 896) @ (896, 8) → (2, 8) 細いボトルネック（ランク8）へギュッと圧縮
展開 (x @ self.A.T) @ self.B.T (2, 8) @ (8, 896) → (2, 896) 出力896次元へ戻して self.base(x) に足す

B @ A を先に計算して (896, 896) の巨大行列を作らず、左から (x @ A.T) @ B.T と細い (2, 8) を経由するのが省メモリ＆高速のコツです！

Qwenに付せんを貼る

コツ：実行環境とリソースの目安（後半のQLoRAはGPU必須）

  • 環境：自作LoRAとPEFT節（0.5B）は無料GPU（T4）推奨（VRAM約3〜4GB、学習約1分）。後半の QLoRA節（1.5B・4ビット量子化）は bitsandbytes がCUDAを必要とするためGPU必須（T4でVRAM約4GB、約1〜2分）です。
  • ダウンロードと保存：0.5B（約1GB）＋QLoRA節で1.5B（約3.1GB）。保存するLoRAアダプタは約35MBで済みます。
  • GPUが使えない日の代替：行列のランク・自作 LoRALinear・absmax量子化の手計算セルはCPUで数秒で動きます。0.5Bの自作LoRA学習もCPUで train_rows[:16]・epochs=1 に絞れば動作確認できます。QLoRA節だけはGPU確保後（またはKaggle T4）に実行してください。
  • ライブラリ互換性：dtype= は transformers >= 4.56、device_map="auto" には accelerate が必要です（推奨環境は requirements-book.txt）。

自作のLoRA層を、Qwen2.5-0.5B-Instructの全Attentionの q_proj と v_proj（QueryとValueを作る全結合層）に取り付けます。

from transformers import AutoTokenizer, AutoModelForCausalLM

device = "cuda" if torch.cuda.is_available() else "cpu"
name = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name, dtype=torch.float32).to(device)
model.requires_grad_(False)                       # まず全部凍結

for layer in model.model.layers:                  # 全層のAttentionに付せんを貼る
    attn = layer.self_attn
    attn.q_proj = LoRALinear(attn.q_proj).to(device)
    attn.v_proj = LoRALinear(attn.v_proj).to(device)

total = sum(p.numel() for p in model.parameters())
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
print(f"全パラメータ {total:,} のうち、学習するのは {trainable:,}（{trainable / total:.2%}）")

attn.q_proj = LoRALinear(attn.q_proj) の1行で、なぜモデルの計算が変わるのでしょう？ Qwenの中では、Attentionの計算のときに self.q_proj(x) と、その名前の部品を呼び出しています。だから、q_proj という名前の部品を、元の層を包んだLoRA層に差し替えれば、次からはLoRA層が呼ばれるのです。部品を差し替えるだけで、Qwenのコードは1行も書き換えていません。

学習は、第18章のデータ作りと学習ループをそのまま使います（自分で書いたものを再利用！）。

Python（Colabのセルに貼って実行）
import random
train_rows = [json.loads(l) for l in open("bongo_sft.jsonl", encoding="utf-8")]
test_rows = [json.loads(l) for l in open("bongo_test.jsonl", encoding="utf-8")]

def build_example(question, answer):
    prompt = tok.apply_chat_template([{"role": "user", "content": question}],
                                     add_generation_prompt=True, tokenize=False)
    p = tok(prompt, add_special_tokens=False)["input_ids"]
    a = tok(answer + "<|im_end|>\n", add_special_tokens=False)["input_ids"]
    return {"input_ids": p + a, "labels": [-100] * len(p) + a}

def collate(batch):
    L = max(len(b["input_ids"]) for b in batch)
    pad = lambda xs, v: [x + [v] * (L - len(x)) for x in xs]
    return {"input_ids": torch.tensor(pad([b["input_ids"] for b in batch], tok.pad_token_id)).to(device),
            "labels": torch.tensor(pad([b["labels"] for b in batch], -100)).to(device),
            "attention_mask": torch.tensor(pad([[1] * len(b["input_ids"]) for b in batch], 0)).to(device)}

examples = [build_example(r["question"], r["answer"]) for r in train_rows]
opt = torch.optim.AdamW([p for p in model.parameters() if p.requires_grad], lr=1e-3)
scaler = torch.amp.GradScaler("cuda", enabled=(device == "cuda"))
random.seed(0); torch.manual_seed(0)
model.train()
for epoch in range(3):
    random.shuffle(examples)
    total = 0.0
    n_steps = 0
    for i in range(0, len(examples), 4):
        with torch.autocast(device_type=device, dtype=torch.float16, enabled=(device == "cuda")):
            loss = model(**collate(examples[i:i + 4])).loss
        opt.zero_grad()
        scaler.scale(loss).backward()
        scaler.step(opt)
        scaler.update()
        total += loss.item()
        n_steps += 1
    print(f"エポック {epoch + 1}：平均損失 {total / n_steps:.3f}")
model.eval()

コツ：LoRAの学習率は大きめ

全パラメータの学習（第18章）では学習率 10−510^{-5}10−5 でしたが、LoRAでは 10−410^{-4}10−4〜10−310^{-3}10−3 と大きめにします。学習するのは小さな付せんだけで、しかも BBB が0から始まるので、ある程度大きく動かさないと効果が出ないからです。

Python（Colabのセルに貼って実行）
def chat(question, n=150):
    inputs = tok.apply_chat_template([{"role": "user", "content": question}], add_generation_prompt=True,
                                     return_tensors="pt", return_dict=True).to(device)
    out = model.generate(**inputs, max_new_tokens=n, do_sample=False)
    return tok.decode(out[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)

print(chat(test_rows[6]["question"]))

量子化：数を粗くして小さくする

LoRAで、学習の勾配とAdamの記録は小さくなりました。残る大物は、モデル本体の重みそのものです。そこで、重みを少ないビット数で表す 量子化（quantization）を使います。

一番シンプルな「対称absmax量子化」を、数式と手計算から確認してからコードで動かしましょう。

数学の道具箱：対称absmax量子化と逆量子化誤差：7ステップで理解する

① 解決したい問題：float32（4バイト）の重み www を、int8（1バイト）や4ビット（0.5バイト）の小さな整数 qqq に縮めてVRAMを4分の1〜8分の1にしたい。

② 素朴な方法の失敗：そのまま小数点以下を切り捨てて整数にすると、LLMの重みのほとんどは [-0.5, +0.5] の小さな小数なので、全部 0 になって情報が消えてしまう。

③ 発想：まず重みの中の最大絶対値 max⁡i∣wi∣\max_i |w_i|maxi​∣wi​∣ を整数上限 Qmax⁡Q_{\max}Qmax​（8ビット符号付きなら 127、4ビット符号付きなら 7）にぴったり合わせる縮尺（scale） sss を作り、割って四捨五入する。使うときは sss を掛け戻す（逆量子化）。

④ 記号表と数式：

s=max⁡i∣wi∣Qmax⁡,qi=round⁡ ⁣(wis),w^i=qi⋅s,誤差i=∣wi−w^i∣s = \frac{\max_i |w_i|}{Q_{\max}}, \qquad q_i = \operatorname{round}\!\left(\frac{w_i}{s}\right), \qquad \hat{w}_i = q_i \cdot s, \qquad \text{誤差}_i = |w_i - \hat{w}_i|s=Qmax​maxi​∣wi​∣​,qi​=round(swi​​),w^i​=qi​⋅s,誤差i​=∣wi​−w^i​∣
記号 意味 Pythonでの対応
wiw_iwi​ 元のfloat32の重み w
Qmax⁡Q_{\max}Qmax​ 整数表現の最大値（8bitなら 127、4bitなら 7） (1 << (bits - 1)) - 1
sss 縮尺（scale：1目盛りあたりの幅） max(abs(x) for x in w) / qmax
qiq_iqi​ 量子化された整数（保存する値） round(x / scale)
w^i\hat{w}_iw^i​ 逆量子化で元に戻した重み q * scale

⑤ 小さな数字で手計算（4ビット：Qmax⁡=7Q_{\max}=7Qmax​=7）： 重みが w=[0.35,  −0.70,  0.14]w = [0.35,\; -0.70,\; 0.14]w=[0.35,−0.70,0.14] のとき：

  1. 最大絶対値は 0.700.700.70 ⇒ 縮尺 s=0.70/7=0.10s = 0.70 / 7 = 0.10s=0.70/7=0.10。
  2. 割って四捨五入：[3.5,  −7.0,  1.4]→roundq=[4,  −7,  1][3.5,\; -7.0,\; 1.4] \xrightarrow{\text{round}} q = [4,\; -7,\; 1][3.5,−7.0,1.4]round​q=[4,−7,1]。
  3. 逆量子化：w^=[0.40,  −0.70,  0.10]\hat{w} = [0.40,\; -0.70,\; 0.10]w^=[0.40,−0.70,0.10]。
  4. 誤差 ∣w−w^∣=[0.05,  0.00,  0.04]|w - \hat{w}| = [0.05,\; 0.00,\; 0.04]∣w−w^∣=[0.05,0.00,0.04]（常に半目盛り s/2=0.05s/2 = 0.05s/2=0.05 以下！）。

⑥ 外れ値の罠：もしここに1個だけ 10.0 が混ざって w=[0.5,  −0.5,  10.0]w = [0.5,\; -0.5,\; 10.0]w=[0.5,−0.5,10.0] になると、s=10.0/7≈1.43s = 10.0 / 7 \approx 1.43s=10.0/7≈1.43 に跳ね上がり、0.5/1.43≈0.35→00.5 / 1.43 \approx 0.35 \to 00.5/1.43≈0.35→0、−0.5/1.43≈−0.35→0-0.5 / 1.43 \approx -0.35 \to 0−0.5/1.43≈−0.35→0 と普通の重みが全部0に潰れてしまいます！

⑦ 理解のための最小Pythonコード：

Python（読むだけ・実行しなくてOK）
ws = [0.35, -0.70, 0.14]
scale = max(abs(x) for x in ws) / 7          # 0.10
q = [round(x / scale) for x in ws]           # [4, -7, 1]
w_hat = [qi * scale for qi in q]             # [0.40, -0.70, 0.10]
errs = [abs(a - b) for a, b in zip(ws, w_hat)]

では、PyTorchで8ビットのabsmax量子化を動かして誤差を確かめてみましょう。

Python（Colabのセルに貼って実行）
torch.manual_seed(0)
w = torch.randn(8) * 0.1
scale = w.abs().max() / 127                     # 最大値を127に合わせる
q = torch.round(w / scale).to(torch.int8)       # 8ビットの整数に
w_back = q.float() * scale                      # 元に戻す（逆量子化）
print("元の重み  ：", w.numpy().round(4))
print("8ビット整数：", q.numpy())
print("戻した重み：", w_back.numpy().round(4))
print("最大の誤差：", (w - w_back).abs().max().item())

理論の小部屋：量子化の考え方

  • float32（4バイト）の重みを、int8（1バイト）の整数と、1つの「縮尺」（scale）で表す。メモリは約4分の1
  • 戻すと少し誤差が出る（上の例では最大0.0008）。LLMの重みはたくさんあるので、1つ1つの小さな誤差は、全体ではあまり効かないことが多い
  • 4ビット（-8〜7の16段階など）まで粗くすると、メモリは8分の1。誤差は大きくなるが、工夫（重みをグループに分けて別々の縮尺を使う、正規分布に合わせた段階を使う NF4 など）で、性能の低下を小さく抑えられる

ただし、外れ値（とても大きな重み）が1つあると、縮尺が大きくなり、ほかの全部の重みが粗くなってしまいます。実際の量子化手法の工夫の多くは、この外れ値との戦いです。

基本情報とつながる：固定小数点と浮動小数点

基本情報で、小数の表し方に「固定小数点」と「浮動小数点」があることを習いましたね。量子化は、ある意味で浮動小数点数を「縮尺つきの固定小数点（整数）」に変換する作業です。ビット数を減らせば、表せる段階の数（8ビットなら256段階、4ビットなら16段階）が減り、誤差が増える。試験で計算した「表現できる範囲と精度」の話が、そのままLLMのメモリ節約の話になっています。

QLoRA：4ビットの本体 ＋ LoRA

QLoRA は、モデル本体を4ビット（NF4）に量子化して凍結し、その上にLoRAの付せんを貼って学習する方法です。本体のメモリはfloat16の約4分の1（float32比で約8分の1）、学習するのは付せんだけ。この組み合わせで、無料のT4でも数Bのモデルを鍛えられます。

次のコードは、Qwen2.5-1.5B-Instructを4ビットで読み込んでLoRA学習する例です。4ビットの読み込みには bitsandbytes というライブラリを使い、GPUが必要です。

このセルは、メニューの「ランタイム」→「セッションを再起動する」でGPUのメモリを空にしてから実行します。上の節のモデルがGPUに残っていると、メモリの使用量を正しく測れないうえ、メモリが足りなくなることもあるからです。セッション切断でファイルが消えていても動くように、データが無ければ自動で再取得してから読み込み直します。

0円のコツ：無料GPUで大きなモデルを鍛える作戦

  1. まず0.5Bで、データと学習の設定を固める（速いので、失敗してもすぐやり直せる）

つまずき注意：よくあるつまずき

  • bitsandbytes のエラー（CUDAが見つからない等）：4ビットの読み込みにはGPUが必要です。ランタイムが「T4 GPU」になっているか確認しましょう。インストールした直後に「入っていない」と言われるときは、「ランタイム」→「セッションを再起動する」をしてから、QLoRAのセルをもう一度実行しましょう。
  • LoRAで全然変化しない：学習率が小さすぎる（10−510^{-5}10−5 など）ことが多いです。10−410^{-4}10−4〜10−310^{-3}10−3 にしてみましょう。また、print_trainable_parameters() で学習するパラメータが0でないか確認しましょう。
  • merge_and_unload 後に結果が少し変わる：4ビットのモデルにマージすると、丸めの誤差が出ます。マージは、float16などで読み込み直した本体に対して行いましょう。

まとめ

  • LoRA：重みの変化 ΔW\Delta WΔW を低ランクの BABABA で表し、本体は凍結して AAA・BBB だけ学習する
  • 学習するパラメータが1%以下になり、勾配とAdamのメモリが激減。保存もアダプタだけでよい
  • 量子化：重みを少ないビット数（8ビット・4ビット）で表してメモリを節約。外れ値が敵
  • QLoRA ＝ 4ビットの本体 ＋ LoRA。無料のT4でも数Bのモデルを鍛えられる
