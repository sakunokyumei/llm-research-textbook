学習の道具をそろえる

ミニバッチを作る関数、検証損失を測る関数、学習率スケジュール（第10章）を用意します。検証損失は、検証データを128文字ずつに区切って全部で測るので、毎回同じ値になります。

Python（Colabのセルに貼って実行）
block_size = 128    # 何文字前まで見るか（窓の大きさ）
batch_size = 32     # 1回に何個の窓を学習するか

def get_batch(data, g):
    ix = torch.randint(0, len(data) - block_size - 1, (batch_size,), generator=g)
    x = torch.stack([data[i:i + block_size] for i in ix])
    y = torch.stack([data[i + 1:i + block_size + 1] for i in ix])
    return x.to(device), y.to(device)

@torch.no_grad()
def val_loss(model, data):
    model.eval()
    starts = range(0, len(data) - block_size - 1, block_size)
    xs = torch.stack([data[i:i + block_size] for i in starts])
    ys = torch.stack([data[i + 1:i + block_size + 1] for i in starts])
    total = 0.0
    for j in range(0, len(xs), 64):
        _, loss = model(xs[j:j + 64].to(device), ys[j:j + 64].to(device))
        total += loss.item() * len(xs[j:j + 64])
    model.train()
    return total / len(xs)

def lr_at(step, max_lr, total, warmup=200):
    if step < warmup:
        return max_lr * step / warmup
    progress = (step - warmup) / (total - warmup)
    return max_lr * 0.5 * (1 + math.cos(math.pi * progress))

.to(device) で、データをGPUのメモリに送っています。GPUで計算するには、モデルとデータの両方がGPUにいる必要があります。

基礎の補足model.train() / model.eval() と torch.no_grad() の違い（なぜ両方必要？）

val_loss 関数には @torch.no_grad()・model.eval()・model.train() の3つが登場します。初学者が最も混同しやすい2つのスイッチを整理しておきましょう。

スイッチ何を切り替えるか忘れると何が起きるか
model.eval() / model.train()Dropout などの層の挙動（評価中はランダムな遮断をオフにして全ユニットを使う）eval() 忘れ → 検証損失がブレて悪化。末尾の train() 忘れ → 以後の訓練で Dropout が永遠にオフになり過学習！
@torch.no_grad() / with torch.no_grad():微分用の計算グラフ記録（逆伝播のための途中メモを保存しない）忘れ → 評価中も不要なメモがGPUメモリ（VRAM）を圧迫して遅くなる・メモリ不足の原因に

この2つはまったく別のスイッチなので、検証や文章生成のときは必ず両方セットで使い、学習ループに戻る前に model.train() へ戻します。

また、lr_at(step, max_lr, total, warmup=200) は、最初の warmup ステップで 0 → max_lr まで直線的に上げ（ウォームアップ）、その後は 12(1+cos⁡(π⋅progress))\frac{1}{2}(1 + \cos(\pi \cdot \text{progress}))21​(1+cos(π⋅progress)) に従って滑らかに max_lr → 0 へ下げる（コサイン減衰）関数です。たとえば max_lr=0.001, total=1000, warmup=200 なら、step=0 で 0.0、step=100 で 0.0005、step=200 で最大 0.001、step=600（減衰の中間点）で 0.0005、step=1000 で 0.0 になります。

学習ループ（GPU対応版）

第10章の学習ループに、GPUで速く学習するための工夫（混合精度）を足したものです。

Python（Colabのセルに貼って実行）
def train(train_data, max_iters, lr=1e-3, seed=0, log_every=500):
    torch.manual_seed(seed)
    g = torch.Generator().manual_seed(seed)
    model = GPT(V, block_size=block_size, n_embd=128, n_head=4, n_layer=4, dropout=0.1).to(device)
    opt = torch.optim.AdamW(model.parameters(), lr=lr, weight_decay=0.1)
    scaler = torch.amp.GradScaler(device, enabled=(device == "cuda"))
    history = []
    for step in range(max_iters + 1):
        for group in opt.param_groups:
            group["lr"] = lr_at(step, lr, max_iters)
        x, y = get_batch(train_data, g)
        with torch.autocast(device_type=device, dtype=torch.float16, enabled=(device == "cuda")):
            _, loss = model(x, y)
        opt.zero_grad(set_to_none=True)              # 勾配を0にする代わりに捨てる（第8章の W.grad = None と同じ）
        scaler.scale(loss).backward()
        scaler.unscale_(opt)
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        scaler.step(opt)
        scaler.update()
        if step % log_every == 0:
            vl = val_loss(model, kokoro_val)
            history.append((step, loss.item(), vl))
            print(f"ステップ {step:5d}：訓練 {loss.item():.3f}  検証（こころ）{vl:.3f}")
    return model, history

理論の小部屋：混合精度：数の細かさを半分にして速くする

コンピュータの小数（浮動小数点数）には、使うビット数によって種類があります。

形式ビット数1個のバイト数特徴
float32（単精度）324PyTorchの標準。正確
float16（半精度）162メモリ半分。T4などのGPUで特に速い。表せる範囲が狭い
bfloat16162表せる範囲はfloat32並み、細かさは粗い。新しいGPU向け

torch.autocast(…, dtype=torch.float16) の中では、行列の掛け算などの重い計算を、自動的にfloat16で行います。パラメータそのもの（マスターウェイト）や、細かさが大事な計算（損失の合計など）はfloat32のまま。2つの精度を混ぜて使うので 混合精度（mixed precision）と呼びます。T4ではfloat32の何倍も速く計算できます。

「なぜパラメータ自体も全部float16にしないの？」と思うかもしれません。理由は、パラメータの更新量（学習率 ×\times× 勾配）がごく小さな値（例えば 0.00001 など）になるからです。float16の小さな数にその微小な更新量を足そうとすると、桁落ちして更新が無視されてしまいます。そこで、パラメータの「原本（マスターコピー）」はfloat32で正確に保持し、計算速度が求められる重い行列の掛け算だけfloat16に任せる、という役割分担をしています。

float16は小さな数を表すのが苦手で、とても小さな勾配が0になってしまう（第5章のアンダーフロー！）ことがあります。そこで GradScaler が、損失を一時的に何千倍にもしてから backward() し、更新の前に元に戻します。勾配を「拡大鏡で見る」作戦です。

CPUのときは enabled=False なので、これらは何もしません。同じコードがCPUでもGPUでも動きます。

基本情報とつながる：浮動小数点数の形式

基本情報で、浮動小数点数は「符号部・指数部・仮数部」でできていると習いましたね。float16は指数部5ビット・仮数部10ビット、bfloat16は指数部8ビット・仮数部7ビットです。指数部が多いほど表せる範囲が広く、仮数部が多いほど細かさが高い。bfloat16は「範囲は広く、細かさは我慢」という、深層学習向けに考えられた形式です（Googleが考案しました）。第19章の量子化で、この話の続きをします。

基礎の補足勾配クリッピング（clip_grad_norm_）はなぜ必要？ unscale_ との順番も確認

学習ループの後半にある次の2行は、大規模LLMの学習で欠かさず入れられる「安全ベルト」です。

Python（読むだけ・実行しなくてOK）
scaler.unscale_(opt)                                      # ① 先に拡大を元に戻す
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)   # ② 元の大きさの勾配を上限 1.0 で切る

なぜ勾配爆発が起きるのか？ 深いネットワークの逆伝播では、たまたま難しいミニバッチに当たった瞬間などに勾配が極端に大きくなる（勾配爆発）ことがあります。そのまま更新すると1ステップで重みが吹き飛び、損失が急上昇したり NaN になったりします。

L2 ノルムクリッピングの仕組み：全パラメータの勾配を1本のベクトル g\boldsymbol{g}g とみなし、長さ（L2 ノルム）∥g∥2=∑igi2\|\boldsymbol{g}\|_2 = \sqrt{\sum_i g_i^2}∥g∥2​=∑i​gi2​​ を計算します。これが上限 max_norm = 1.0 を超えたときだけ、全勾配に同じ係数 1.0∥g∥2\frac{1.0}{\|\boldsymbol{g}\|_2}∥g∥2​1.0​ を掛けて縮めます。

  • たとえば g=[3.0,4.0]\boldsymbol{g} = [3.0, 4.0]g=[3.0,4.0] なら ∥g∥2=9+16=5.0>1.0\|\boldsymbol{g}\|_2 = \sqrt{9 + 16} = 5.0 > 1.0∥g∥2​=9+16​=5.0>1.0 なので、1.0 / 5.0 = 0.2 倍して [0.6, 0.8] にします（長さはちょうど 1.0、向きは 3:4 のまま不変！）。
  • ∥g∥2≤1.0\|\boldsymbol{g}\|_2 \le 1.0∥g∥2​≤1.0 なら何もしません。

なお、scaler.scale(loss).backward() の直後は勾配が数千倍に拡大されたままなので、必ず先に scaler.unscale_(opt) で元の大きさに戻してから clip_grad_norm_ を呼ぶのが鉄則です。

GPT(**ckpt["config"]) の ** は、第3章の model(**inputs) と同じ「辞書の中身を名前つきの引数として渡す」書き方です。GPT(vocab_size=3665, block_size=128, …) と書いたのと同じ意味になります。なお、次の節の「2つの実験を比べる」グラフは、学習中の記録（hist_k と hist_all）が必要なので、休んだ後は描けません。その節は !pip install のセルだけ実行して、グラフは教科書の図で確かめましょう。その後の「書かせてみる」「ヘッドたちの役割分担を見る」は、そのまま実行できます。

基礎の補足state_dict() チェックポイントに config・chars と map_location が必要な理由

model.state_dict() が返すのは、「層の名前の文字列 → 重みテンソル」の対応辞書だけです。Python のクラス定義（class GPT）も、モデルの寸法（n_embd や n_layer）も、文字とIDの対応表も含まれていません。

そのため、安全に復元できるチェックポイントには必ず次の3点セットを保存します。

  1. "model": model.state_dict()：学習したすべての重みとバッファ（tril 等）
  2. "config": {...}：復元時にまったく同じ形の箱 GPT(**ckpt["config"]) を作るための設計寸法
  3. "chars": chars：文字とトークンIDの対応表（これが1文字でもずれると生成結果が文字化けする）

さらに読み込み時に map_location=device を指定しておけば、「T4 GPU で保存した重みを、別の日に CPU 環境で読み込む」ときもデバイス不一致エラーを防げます。

理論の小部屋：結局、データがいちばん効く

第10章では、過学習を抑えるためにドロップアウトや重み減衰を使いました。でも、最も強力な治療法は データを増やすこと です。

  • 『こころ』だけ：14.6万字を何十周もするので、途中から丸暗記が始まる
  • 7作品：92万字あるので、同じ文章を見る回数が少なく、丸暗記しにくい。しかも、漱石の文体という「共通の特徴」をいろいろな文章から学べる

『こころ』の検証データには『こころ』の続きが書いてあるのに、『こころ』以外の作品を読ませたほうが、それを上手に予測できるようになる。不思議ですが、人間も同じですね。同じ作家の本をたくさん読むと、その作家の次の一文が予想できるようになります。

LLMの研究で「モデルの大きさ」と同じくらい「データの量と質」が重視されるのは、このためです（第15章のスケーリング則で、もう少し詳しく話します）。

Pythonの道具箱：encode(start)[None]

encode(start) は、文字のIDを並べた1次元のテンソル（形 [T]）です。でもGPTは「何個かの文章をまとめて」受け取る形 [B, T] を期待しています。[None] を付けると、先頭に長さ1の軸が増えて [1, T]（文章1個ぶん）になります。第12章で torch.tensor([[…]]) と、かっこを二重にしていたのと同じ意味です。

やってみよう：GPUがあるなら、もっと大きく

GPUが使えるなら、モデルを大きくしてみましょう。train 関数はそのままで、次のセルを実行するだけです（大きなモデル用の train_big を新しく作ります）。このセルは block_size と batch_size を書き換えるので、必ず上の保存が終わってから試しましょう。後で保存のセルを実行し直すと、設定の記録がずれて、第24章で読み込めなくなります。

Python（GPUのランタイムで実行）
block_size = 256
batch_size = 64

def train_big(train_data, max_iters, lr=6e-4, seed=0):
    torch.manual_seed(seed)
    g = torch.Generator().manual_seed(seed)
    model = GPT(V, block_size=block_size, n_embd=384, n_head=6, n_layer=6, dropout=0.2).to(device)
    print("パラメータの数：", sum(p.numel() for p in model.parameters()))
    opt = torch.optim.AdamW(model.parameters(), lr=lr, weight_decay=0.1)
    scaler = torch.amp.GradScaler(device, enabled=(device == "cuda"))
    for step in range(max_iters + 1):
        for group in opt.param_groups:
            group["lr"] = lr_at(step, lr, max_iters)
        x, y = get_batch(train_data, g)
        with torch.autocast(device_type=device, dtype=torch.float16, enabled=(device == "cuda")):
            _, loss = model(x, y)
        opt.zero_grad(set_to_none=True)
        scaler.scale(loss).backward()
        scaler.unscale_(opt)
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        scaler.step(opt)
        scaler.update()
        if step % 500 == 0:
            print(f"ステップ {step:5d}：訓練 {loss.item():.3f}  検証（こころ）{val_loss(model, kokoro_val):.3f}")
    return model

model_big = train_big(all_train, max_iters=5000)

つまずき注意：よくあるつまずき

  • RuntimeError: Expected all tensors to be on the same device：モデルとデータの片方だけがGPUにいます。model.to(device) と、get_batch の中の .to(device) を確認しましょう。
  • CUDA out of memory：GPUのメモリが足りません。batch_size や block_size を半分にしてみましょう。それでもダメなら、「ランタイム」→「セッションを再起動する」でメモリを空にしてから、上から実行し直します。
  • No such file or directory: 'minigpt.py' / ModuleNotFoundError: No module named 'minigpt'：wget のセルを実行し忘れているか、ダウンロードに失敗しています。そのセルをもう一度実行しましょう。それでも同じなら、!wget の行から -q（静かに実行する指定）を消して実行すると、失敗の理由（ERROR 404 など）が表示されます。どうしてもダウンロードできないときは、第12章の5つのクラス（Head から GPT まで）のセルをこのノートブックに貼って実行し、from minigpt import GPT の行を消せば、同じように動きます。
  • 学習の途中で切断された：無料のColabではよくあります。チェックポイントの節を参考に、途中経過を保存するようにしましょう。

まとめ

  • GPUで学習するには、モデルとデータを .to(device) で送る

  • 学習したモデルは、語彙と設定もいっしょに保存しておく（チェックポイント）
