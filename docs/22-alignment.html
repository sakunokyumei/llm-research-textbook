この章でつくるもの

第18章のSFTは「お手本をまねる」学習でした。でも、良い答え方はお手本1つでは決まりません。「この2つの答えなら、こっちのほうが良い」という比べた好みのほうが、人間にとって作りやすく、しかも細かいニュアンスを伝えられます。この章では、ChatGPTを丁寧で安全なアシスタントにした RLHF の考え方を学び、その簡単で強力な後継 DPO を、損失関数からゼロから実装して使います。

これまでの復習とつながり：第3章・第5章・第18章・第19章とのつながり

この章の理論と実装は、これまでの4つの章の道具をすべて合流させて作られています。

  • 第3章（softmax）：生の点数の差を0〜1の確率に変える仕組み。この章のシグモイド関数 σ\sigmaσ は、実は候補が2つだけのsoftmaxそのものです。
  • 第5章（交差エントロピーと log⁡\loglog）：確率 ppp に対する損失 −log⁡p-\log p−logp、掛け算を足し算に・割り算を引き算に変える対数の性質、そして五分五分のときの損失 −log⁡(0.5)=log⁡2≈0.693-\log(0.5) = \log 2 \approx 0.693−log(0.5)=log2≈0.693 がそのままDPOの検算サインになります。
  • 第18章（SFT）：「1つのお手本」をまねる学習。ここではその先にある「2つの答えを比べる学習」へ進みます。
  • 第19章（LoRA）：元の重みを凍結して付せんだけ学習する仕組み。DPOでは「付せんを外した状態＝参照モデル πref\pi_{\text{ref}}πref​」として1つのモデルで2役をこなせるため、無料GPUでも動きます！

報酬モデルと、好みの確率

まずは、RLHFの考え方から見ていきましょう。

理論の小部屋：報酬モデル：答えに点数をつけるモデル

人間の好みを学習させるには、まず「答えの良さ」を数にする必要があります。そこで、答えを入力すると点数（報酬）を出す 報酬モデル（reward model）を作ります。

報酬モデルは、好みのペアから学習します。「良い答えの点数 rcr_crc​ が、悪い答えの点数 rrr_rrr​ より高くなる」ようにするのです。そのとき使われるのが、ブラッドリー・テリーモデル という考え方です。

P(良い答えが選ばれる)=σ(rc−rr)P(\text{良い答えが選ばれる}) = \sigma(r_c - r_r)P(良い答えが選ばれる)=σ(rc​−rr​)

点数の差をシグモイド関数 σ\sigmaσ に入れたものを、「良い答えが選ばれる確率」と考えます。スポーツのレーティング（強さの点数の差から勝率を予想する）と同じ発想です。

数学の道具箱：シグモイド関数とブラッドリー・テリーモデル：9ステップで理由から理解する

① 解決したい具体的な問題：2つの答えについた「生の点数 rcr_crc​（良い答え）と rrr_rrr​（悪い答え）」から、「良い答えが選ばれる確率（000 〜 111）」を計算したい。

② 素朴な方法では困る理由：ただの差 rc−rrr_c - r_rrc​−rr​ はマイナスにも +100+100+100 にもなるので確率になりません。かといって rc/(rc+rr)r_c / (r_c + r_r)rc​/(rc​+rr​) と割ると、点数が負のときに分母が 000 になったり確率が 111 を超えたりして破綻します。

③ 新しい発想：点数の差 x=rc−rrx = r_c - r_rx=rc​−rr​ を、どんな実数でも滑らかに 000 と 111 のあいだに押し込むS字の関数 シグモイド関数 σ(x)\sigma(x)σ(x) に通す。

④ 記号の1つ1つの読み方：

σ(x)=11+e−x,P(yc≻yr)=σ(rc−rr)\sigma(x) = \frac{1}{1 + e^{-x}}, \qquad P(y_c \succ y_r) = \sigma(r_c - r_r)σ(x)=1+e−x1​,P(yc​≻yr​)=σ(rc​−rr​)

  • eee：ネイピア数（約 2.7182.7182.718、第3章のsoftmaxで登場）
  • rc,rrr_c, r_rrc​,rr​：良い答え（chosen）と悪い答え（rejected）の報酬スコア
  • yc≻yry_c \succ y_ryc​≻yr​：「ycy_cyc​ のほうが yry_ryr​ より好まれる」という記号

⑤ 小さな数字で手計算：

  • 同点（rc=1,rr=1  ⟹  x=0r_c = 1, r_r = 1 \implies x = 0rc​=1,rr​=1⟹x=0）：σ(0)=11+e0=11+1=0.500\sigma(0) = \dfrac{1}{1 + e^0} = \dfrac{1}{1 + 1} = 0.500σ(0)=1+e01​=1+11​=0.500（ちょうど五分五分！）

理論の小部屋：RLHF：報酬を最大にするように強化学習

報酬モデルができたら、次はLLMを 強化学習（reinforcement learning）で鍛えます。LLMに答えを生成させ、報酬モデルで点数をつけ、点数が高い答えを出しやすくなるようにパラメータを調整する。これをくり返します（よく使われる方法が PPO）。人間のフィードバック（Human Feedback）から学ぶ強化学習（RL）なので、RLHF と呼びます。

ただし、報酬だけを追いかけると、モデルは報酬モデルの穴をつくようになります。たとえば報酬モデルが「長い答え」を好むクセを持っていたら、意味のない長文を書くようになる。これを 報酬ハッキング と言います。そこで、「元のモデル（参照モデル）からあまり離れすぎない」という罰（KLペナルティ）を加えます。

目標=報酬−β×元のモデルからの離れ具合（KLダイバージェンス）\text{目標} = \text{報酬} - \beta \times \text{元のモデルからの離れ具合（KLダイバージェンス）}目標=報酬−β×元のモデルからの離れ具合（KLダイバージェンス）

RLHFはとても強力ですが、報酬モデル・強化学習・生成をぐるぐる回すので、仕組みが複雑で、学習も不安定になりがちです。

数学の道具箱：KLダイバージェンス KL(p ∥ q)\mathrm{KL}(p \,\|\, q)KL(p∥q)：9ステップで理由から理解する

① 解決したい具体的な問題：学習中のモデルが出す確率分布 ppp が、元の参照モデルの確率分布 qqq から「どれくらいズレたか」を1つの数値（罰金）で測りたい。

② 素朴な方法では困る理由：単純に差を足す ∑i(pi−qi)\sum_i (p_i - q_i)∑i​(pi​−qi​) は、∑pi=1,∑qi=1\sum p_i = 1, \sum q_i = 1∑pi​=1,∑qi​=1 なので 1−1=01 - 1 = 01−1=0 となり、どれだけズレても常に0で測れません。また単純な差の絶対値だと、元のモデルが「ほとんど起きない（qi=0.0001q_i = 0.0001qi​=0.0001）」と判断していた変な単語に確率を移したときの危険度（何倍になったか）を十分重く罰せられません。

③ 新しい発想：各選択肢について「元の確率の何倍になったかの対数 log⁡(pi/qi)\log(p_i / q_i)log(pi​/qi​)」をとり、それを今のモデルが実際に選ぶ確率 pip_ipi​ で重みづけ平均する。

④ 記号の1つ1つの読み方：

KL(p ∥ q)=∑ipilog⁡piqi\mathrm{KL}(p \,\|\, q) = \sum_i p_i \log \frac{p_i}{q_i}KL(p∥q)=i∑​pi​logqi​pi​​
  • ppp：今のモデル（学習中の方策 π\piπ）の確率分布
  • qqq：元のモデル（参照モデル πref\pi_{\text{ref}}πref​）の確率分布
  • ∥\|∥：2つの分布を比べる区切り線（順番に意味があり、KL(p∥q)≠KL(q∥p)\mathrm{KL}(p\|q) \neq \mathrm{KL}(q\|p)KL(p∥q)=KL(q∥p) の非対称！）
  • log⁡piqi\log\dfrac{p_i}{q_i}logqi​pi​​：第5章と同じ自然対数。pi=qip_i = q_ipi​=qi​ なら log⁡1=0\log 1 = 0log1=0、pi>qip_i > q_ipi​>qi​ ならプラス、pi<qip_i < q_ipi​<qi​ ならマイナス

⑤ 小さな数字で手計算： 元のモデルが次のトークン「A・B」を q=(0.5,0.5)q = (0.5, 0.5)q=(0.5,0.5) で選び、今のモデルが p=(0.9,0.1)p = (0.9, 0.1)p=(0.9,0.1) に偏ったとき：

KL(p ∥ q)=0.9log⁡0.90.5+0.1log⁡0.10.5≈0.9×0.588+0.1×(−1.609)≈0.529−0.161=0.368\mathrm{KL}(p \,\|\, q) = 0.9 \log\frac{0.9}{0.5} + 0.1 \log\frac{0.1}{0.5} \approx 0.9 \times 0.588 + 0.1 \times (-1.609) \approx 0.529 - 0.161 = 0.368KL(p∥q)=0.9log0.50.9​+0.1log0.50.1​≈0.9×0.588+0.1×(−1.609)≈0.529−0.161=0.368

もし p=q=(0.5,0.5)p = q = (0.5, 0.5)p=q=(0.5,0.5)（ズレなし）なら、0.5log⁡1+0.5log⁡1=00.5\log 1 + 0.5\log 1 = 00.5log1+0.5log1=0 です。

⑥ Pythonでの最小コード：

Python（読むだけ・実行しなくてOK）
import math
p, q = [0.9, 0.1], [0.5, 0.5]
kl = sum(pi * math.log(pi / qi) for pi, qi in zip(p, q) if pi > 0)
print(round(kl, 3))   # 0.368

⑦ 絶対に押さえる2つの性質：

  1. 必ず0以上（KL(p∥q)≥0\mathrm{KL}(p\|q) \ge 0KL(p∥q)≥0）：各項にマイナスが出ても、合計すると必ず0以上になり、0になるのは p=qp = qp=q のときだけ。
  2. 第5章の交差エントロピーの仲間：∑pilog⁡piqi=(−∑pilog⁡qi)−(−∑pilog⁡pi)\sum p_i \log\frac{p_i}{q_i} = \big(-\sum p_i \log q_i\big) - \big(-\sum p_i \log p_i\big)∑pi​logqi​pi​​=(−∑pi​logqi​)−(−∑pi​logpi​)（交差エントロピー − エントロピー）。PyTorchでは F.kl_div(log_q, p, reduction="batchmean") で計算できます（第1引数に対数 log⁡q\log qlogq、第2引数に確率 ppp を渡す逆順の仕様なので注意）。

⑧ β\betaβ の効き方：RLHFの目標 E[r(x,y)]−β KL(π ∥ πref)\mathbb{E}[r(x,y)] - \beta\,\mathrm{KL}(\pi \,\|\, \pi_{\text{ref}})E[r(x,y)]−βKL(π∥πref​) で、β\betaβ が大きすぎるとモデルが元のまま動かなくなり、β\betaβ が小さすぎると報酬ハッキングで文章が壊れます。

⑨ DPOへの橋渡し：実は、この「KLペナルティつきの目標」があるからこそ、次の節で魔法のような数学変形が可能になります！

DPO：報酬モデルなしで、好みを直接学ぶ

2023年に、スタンフォード大学の研究者たちが、すごいことに気づきました。上のRLHFの「目標」を数学的に変形すると、報酬モデルも強化学習も使わずに、好みのペアから直接LLMを学習させる損失関数が導けるのです。それが DPO（Direct Preference Optimization）です。

数学の道具箱：DPOの目的関数 LDPOL_{\text{DPO}}LDPO​：9ステップで記号の1つ1つから完全に理解する

① 解決したい具体的な問題：RLHFでは「①報酬モデルの学習 → ②PPO強化学習」の2段階が必要で、モデルも複数要り、学習が非常に不安定です。報酬モデルを作らずに、好みのペア (質問, chosen, rejected) だけから直接LLMを学習させたい！

② 素朴な方法ではなぜダメなのか？ もし単純に「良い答えの対数確率を上げ、悪い答えを下げる」だけの損失 −log⁡σ(β(log⁡π(yc)−log⁡π(yr)))-\log\sigma\big(\beta(\log\pi(y_c) - \log\pi(y_r))\big)−logσ(β(logπ(yc​)−logπ(yr​))) を使うと、次の2つの致命的な欠陥が起きます。

  1. ブレーキがない：元のモデルから際限なく離れてしまい、日本語として壊れた文章になりやすい。
  2. 長さバイアスに負ける：文章全体の対数確率は各トークンの負の対数確率の合計なので、長い良い答え（例：-60）より短い悪い答え（例：-25）のほうが最初から圧倒的に値が高い！そのまま引き算すると、最初から -60 - (-25) = -35 という巨大なハンデを背負ってしまいます。

③ RLHF→DPOの導出の肝（どんな仮定・簡略化をしているか）： RLHFのKL制約つき目標 max⁡πE[r(x,y)]−β KL(π ∥ πref)\max_\pi \mathbb{E}[r(x,y)] - \beta\,\mathrm{KL}(\pi \,\|\, \pi_{\text{ref}})maxπ​E[r(x,y)]−βKL(π∥πref​) を数学的に解くと、最適方策 π∗\pi^*π∗ は次の閉じた形（解析解）で表せることが知られています。

π∗(y∣x)=1Z(x) πref(y∣x)exp⁡ ⁣(1β r(x,y))\pi^*(y \mid x) = \frac{1}{Z(x)}\,\pi_{\text{ref}}(y \mid x)\exp\!\left(\frac{1}{\beta}\,r(x, y)\right)π∗(y∣x)=Z(x)1​πref​(y∣x)exp(β1​r(x,y))

ここで Z(x)Z(x)Z(x) は確率の合計を1にするための正規化定数（全文章の和なので直接は計算不能）です。ところが、この式を r(x,y)r(x, y)r(x,y) について逆算すると、

r(x,y)=βlog⁡π∗(y∣x)πref(y∣x)+βlog⁡Z(x)r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x)r(x,y)=βlogπref​(y∣x)π∗(y∣x)​+βlogZ(x)

となります！これをブラッドリー・テリーモデルの差 rc−rrr_c - r_rrc​−rr​ に代入すると、計算できない厄介者 βlog⁡Z(x)\beta \log Z(x)βlogZ(x) が引き算で完全に消えて（相殺されて）しまうのです！

導出における簡略化・前提の整理：この導出は「①人間の好みがブラッドリー・テリーモデルに従う」「②KL制約つきRLHFの厳密な最適方策 π∗\pi^*π∗ によって報酬を言い換えられる」「③固定されたオフラインの好みペア上で π\piπ を直接更新してもよい（RLHFのように学習途中のモデル自身から再サンプリングするオンポリシー分布ズレを近似・省略する）」という仮定に基づいています。だからこそ、強化学習ループなしの単純な教師あり風の損失関数に落とし込めるのです。

import math
def dpo_loss_simple(pi_c, pi_r, ref_c, ref_r, beta=0.1):
    margin = beta * ((pi_c - ref_c) - (pi_r - ref_r))
    prob = 1.0 / (1.0 + math.exp(-margin))
    return -math.log(prob)

なおPyTorchでは、極端に負の margin で math.exp(-margin) がオーバーフローするのを防ぐため、数学的に等価かつ数値安全な -F.logsigmoid(margin) を使います。

Python（Colabのセルに貼って実行）
import torch
import torch.nn.functional as F

def dpo_loss(pi_c, pi_r, ref_c, ref_r, beta=0.1):
    """各引数は、その答え全体の対数確率（トークンごとの log 確率の合計）"""
    margin = beta * ((pi_c - ref_c) - (pi_r - ref_r))
    return -F.logsigmoid(margin)

ref_c, ref_r = torch.tensor(-60.0), torch.tensor(-25.0)     # 学習前：悪い答え（短い）のほうが書きやすい
print("学習前（方策＝参照）：", dpo_loss(ref_c, ref_r, ref_c, ref_r).item())
print("良い答えが +10 書きやすく：", dpo_loss(ref_c + 10, ref_r, ref_c, ref_r).item())
print("悪い答えが -10 書きにくく：", dpo_loss(ref_c, ref_r - 10, ref_c, ref_r).item())
print("両方：", dpo_loss(ref_c + 10, ref_r - 10, ref_c, ref_r).item())

注目してほしいのは、学習前の対数確率は「悪い答え（-25）」のほうが「良い答え（-60）」より高い、つまり悪い答えのほうが書きやすい状態だったことです。悪い答えは短いので、確率の掛け算の回数が少ないからです。DPOは、確率そのものではなく「元からの変化」を比べるので、出発点での長さの違いには惑わされません（ただし、学習を続けると長い答えを好むようになりやすいクセも知られています。第20章の評価で、答えの長さも見ておくと安心です）。

モデルの対数確率を計算する

本物のLLMで、答え全体の対数確率を計算する関数を作ります。第20章の4択クイズで使った方法と同じです。

Python（Colabのセルに貼って実行）
from transformers import AutoTokenizer, AutoModelForCausalLM

name = "Qwen/Qwen2.5-0.5B-Instruct"
device = "cuda" if torch.cuda.is_available() else "cpu"
tok = AutoTokenizer.from_pretrained(name)
ref_model = AutoModelForCausalLM.from_pretrained(name, dtype=torch.float32).to(device).eval()

@torch.no_grad()
def answer_logprob(model, question, answer):
    prompt = tok.apply_chat_template([{"role": "user", "content": question}], add_generation_prompt=True, tokenize=False)
    p = tok(prompt, add_special_tokens=False)["input_ids"]
    a = tok(answer + "<|im_end|>", add_special_tokens=False)["input_ids"]
    ids = torch.tensor([p + a]).to(device)
    logprobs = torch.log_softmax(model(ids).logits[0, :-1].float(), dim=-1)
    return logprobs[len(p) - 1:].gather(1, ids[0, len(p):, None]).sum().item()

p = prefs[11]
lc, lr = answer_logprob(ref_model, p["question"], p["chosen"]), answer_logprob(ref_model, p["question"], p["rejected"])
print(f"良い答えの対数確率 {lc:.1f}  悪い答えの対数確率 {lr:.1f}")

基礎の補足answer_logprob の仕組み：なぜ質問部分を除いて答えトークンだけを足すのか？

DPOで必要なのは「質問 xxx が与えられたときの、答え yyy 全体の対数確率 log⁡π(y∣x)\log \pi(y \mid x)logπ(y∣x)」です。

  1. ids = [p + a]：質問トークン列 p の後ろに、答え＋終了合図 <|im_end|> のトークン列 a をつなげてモデルに通します。
  2. 1つずらしの対応：位置 t の出力ロジットは位置 t + 1 のトークンを予測します。したがって、答えの1トークン目（ids[len(p)]）を予測しているのは logprobs[len(p) - 1] です。
  3. 答え部分だけの合計：gather で正解トークンIDに対応する対数確率だけを取り出して .sum() で足します。質問部分はモデルが生成する対象ではないため除外します（第18章のSFT損失マスク -100 と同じ発想です）。

理論の小部屋：学習ログの読み方

  • loss：DPOの損失。0.693（log⁡2\log 2log2）から下がっていけば順調
  • rewards/chosen：良い答えの暗黙の報酬（β×\beta \timesβ× 元からの対数確率の変化）。上がっていくのが理想
  • rewards/rejected：悪い答えの暗黙の報酬。下がっていくのが理想
  • rewards/margins：その差。広がっていくほど、好みを学べている
  • rewards/accuracies：良い答えの報酬が悪い答えより高かったペアの割合

rewards/chosen も一緒に下がっていく（良い答えも書きにくくなる）ことがよくあり、DPOの弱点として知られています。差が広がっていても、良い答えそのものの確率が下がりすぎると、文章がおかしくなることがあります。学習率を小さく、エポックを少なくするのが安全です。

アラインメントと安全性

理論の小部屋：アラインメント

LLMを「人間の意図や価値観に沿ったふるまい」に合わせることを、アラインメント（alignment、整合）と言います。役に立つこと（helpful）、正直であること（honest）、害を与えないこと（harmless）の3つがよく目標に挙げられます。

  • 危険な作り方を聞かれたら断る、差別的な発言をしない、といった安全性も、好みのデータ（「断る答え」をchosenにする）で学習させます
  • 人間の代わりに、原則（憲法）を与えたAIに好みを判定させる方法（RLAIF、Constitutional AI）もあります
  • 一方で、うまい言い回しで安全の仕組みをすり抜けようとする攻撃（ジェイルブレイク）もあり、守る側と破る側のいたちごっこが続いています

アラインメントは、技術だけでなく「誰の好みに合わせるのか」という社会的な問いも含む、とても大切な研究分野です。

理論の小部屋：推論モデルへの道：答えが確かめられる問題で強化学習

最近の「考えてから答える」推論モデル（reasoning model）は、数学やプログラミングのように答えが正しいかを自動で確かめられる問題で、強化学習をして作られています。人間の好みの代わりに、「答えが合っていたら報酬1、間違っていたら0」という検証可能な報酬（verifiable reward）を使うのです（RLVR）。モデルは、正解にたどり着くために、長く考える（考える過程のトークンを多く出す）ことを自分で学んでいきます。GRPO という、同じ問題に何通りも答えさせて、平均より良かった答えを強化する方法がよく使われます。第25章で、もう少し詳しく触れます。

つまずき注意：よくあるつまずき

  • 損失が最初から0.693でない：参照モデルと学習モデルが違う状態から始まっています。LoRAを使う場合は気にしなくて大丈夫ですが、自分でモデルを2つ読み込む場合は、同じ重みから始めましょう。
  • 学習後に文章がおかしくなる：学習率が大きすぎるか、エポックが多すぎます。DPOは 10−610^{-6}10−6〜10−510^{-5}10−5 台の小さな学習率から試すのが安全です（今回はLoRAなので少し大きめ）。
  • CUDA out of memory：DPOは、1つのペアで良い答えと悪い答えの両方を計算するので、SFTよりメモリを使います。バッチを小さくしましょう。
