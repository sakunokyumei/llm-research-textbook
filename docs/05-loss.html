この章でつくるもの

前の章のbigramモデルは「なんとなく漱石っぽい」文章を書きました。でも「なんとなく」では、モデルを改良しても良くなったのか分かりません。この章では、言語モデルの成績を1つの数で表す方法を作ります。この数（損失）は、この先のすべての章で、モデルの進化を測るものさしになります。

理論の小部屋：なぜ分けるの？

テスト勉強で、過去問の答えを丸暗記した人を想像してください。同じ過去問なら満点ですが、本番で少し違う問題が出たら解けません。

モデルも同じです。数えるのに使った文章で点数をつけると、「丸暗記」がうまいほど高得点になってしまいます。本当に知りたいのは「見たことのない文章でも、次の文字を当てられるか」です。

そこで、データを分けます。

  • 訓練データ（training data）：モデルが学ぶ（数える）ためのデータ。過去問
  • 検証データ（validation data）：点数をつけるためだけのデータ。モデルには絶対に見せない。本番の模試

さらに研究では、最後の最後に一度だけ使う テストデータ をもう1つ取っておくこともあります（第20章）。

訓練データだけでbigramを数え直します。

Python（Colabのセルに貼って実行）
pairs = Counter(zip(train_text, train_text[1:]))
firsts = Counter(train_text[:-1])

def prob(a, b):
    """P(b | a)：「a」の次が「b」である確率"""
    if firsts[a] == 0:
        return 0.0
    return pairs[(a, b)] / firsts[a]

print("P(生|先) =", prob("先", "生"))
print("P(は|生) =", prob("生", "は"))
出力
P(生|先) = 0.8857566765578635
P(は|生) = 0.23097112860892388

文章の確率を計算する

モデルが「この文章はありそうだ」と思うほど、良いモデルのはずです。では、文章全体の確率はどう計算するのでしょう？ 「先生は」が出てくる確率は、「先の次に生」かつ「生の次には」なので、掛け算になります。

P(先生は)=P(生∣先)×P(は∣生)=0.886×0.231≈0.205P(\text{先生は}) = P(\text{生} \mid \text{先}) \times P(\text{は} \mid \text{生}) = 0.886 \times 0.231 \approx 0.205P(先生は)=P(生∣先)×P(は∣生)=0.886×0.231≈0.205

（厳密には最初の「先」の確率も掛けますが、ここでは省きます。）では、訓練データの最初の数百文字で同じことをしてみましょう。どのペアも訓練データで数えたものなので、確率が0になることはないはずです。

Python（Colabのセルに貼って実行）
p = 1.0
for i, (a, b) in enumerate(zip(train_text, train_text[1:])):
    p = p * prob(a, b)
    if i in [10, 50, 100, 150, 200, 300]:
        print(f"{i:4d}文字目まで：確率 {p}")

事件だ！ どのペアも確率は0じゃないのに、掛け算を続けたら、300文字目でとうとうぴったり0になってしまった。200文字目の e-279 は「10のマイナス279乗」、つまり小数点の後に0が278個並ぶ数だ。宇宙にある原子の数（だいたい 108010^{80}1080 個）で1を割っても、まだまだこんなに小さくはならない。

基本情報とつながる：アンダーフロー

コンピュータの小数（浮動小数点数）には、表せる大きさに限界があります。Pythonの float（倍精度、64ビット）では、だいたい 10−30810^{-308}10−308 より小さい数はまともに表せず、最後は0になってしまいます。これを アンダーフロー と言います。基本情報の「浮動小数点数の表現」で、指数部のビット数が限られていることを習いましたね。それがここで牙をむいたのです。

0になってしまうと、どのモデルの確率も「0」で、比べようがありません。どうしましょう？

救世主：対数（log）

ここで登場するのが 対数（たいすう、logarithm）です。

数学の道具箱：対数は「何回掛けたか」を数える

log⁡101000\log_{10} 1000log10​1000 は「10を何回掛けたら1000になるか」という意味で、答えは3です（10×10×10=100010 \times 10 \times 10 = 100010×10×10=1000）。

xxx 0.001 0.01 0.1 1 10 100 1000
log⁡10x\log_{10} xlog10​x -3 -2 -1 0 1 2 3

1より小さい数はマイナスになります（0.01は「10で2回割った」ので -2）。

機械学習では、10の代わりに第3章で出てきた e≈2.718e \approx 2.718e≈2.718 を使う対数（自然対数）をよく使います。単に log⁡\loglog と書いたら自然対数のことが多く、Pythonでは math.log です。

Python（Colabのセルに貼って実行）

print(math.log(math.e), math.log(1))
print(math.log(0.5), math.log(0.01))

理論の小部屋：対数の3つの性質（これだけ覚えればOK）

  1. 掛け算が足し算になる：log⁡(a×b)=log⁡a+log⁡b\log(a \times b) = \log a + \log blog(a×b)=loga+logb
  2. 1は0になる：log⁡1=0\log 1 = 0log1=0
  3. 1より小さい数はマイナス、0に近づくほどどんどんマイナスに大きくなる

性質1がすごいのです。確率の掛け算を、対数の足し算に変えられます。足し算なら、何千回くり返しても0にはなりません（-1000とか-5000とかになるだけ）。

Python（Colabのセルに貼って実行）
log_p = 0.0
for i, (a, b) in enumerate(zip(train_text, train_text[1:])):
    log_p = log_p + math.log(prob(a, b))
    if i in [10, 50, 100, 200, 300]:

損失：驚きの平均

「log確率の合計」は文章が長いほどマイナスに大きくなるので、長さの違う文章どうしを比べにくいです。そこで、1文字あたりの平均にします。さらに、マイナスの数は扱いにくいので、符号をひっくり返してプラスにします。これが言語モデルの点数、損失（loss）です。

損失=−1N∑i=1Nlog⁡P(次の文字i∣今の文字i)\text{損失} = -\frac{1}{N}\sum_{i=1}^{N} \log P(\text{次の文字}_i \mid \text{今の文字}_i)損失=−N1​i=1∑N​logP(次の文字i​∣今の文字i​)

理論の小部屋：損失は「驚き」の平均

−log⁡p-\log p−logp は、確率 ppp のことが起きたときの 驚きの大きさ と考えられます。

  • 確率1（絶対起きると思っていた）ことが起きた → 驚き −log⁡1=0-\log 1 = 0−log1=0
  • 確率0.5のことが起きた → 驚き 0.69
  • 確率0.01（まさか！）のことが起きた → 驚き 4.6
  • 確率0のことが起きた → 驚き 無限大

損失は、モデルが検証データを1文字ずつ読みながら感じた「驚き」の平均です。良いモデルほど、次の文字を予想できているので、驚きが少ない。だから 損失は小さいほど良い のです。ゴルフのスコアと同じですね。

ちなみに、この量は 負の対数尤度（negative log-likelihood、NLL）や、交差エントロピー（cross-entropy）とも呼ばれます。名前はいかめしいですが、中身は「驚きの平均」です。

驚きの大きさをグラフにしてみましょう。グラフを描く道具 matplotlib を使います（日本語を表示するための追加の道具も入れます）。

それでは、訓練データと検証データで損失を計算してみましょう。

Python（Colabのセルに貼って実行）
def bigram_loss(data, prob_fn):
    total = 0.0
    for a, b in zip(data, data[1:]):
        p = prob_fn(a, b)
        if p == 0:
            return float("inf")       # 確率0の出来事 → 驚きは無限大
        total += -math.log(p)
    return total / (len(data) - 1)

print("訓練データの損失：", bigram_loss(train_text, prob))
print("検証データの損失：", bigram_loss(val_text, prob))
出力
訓練データの損失： 3.010172965334805
検証データの損失： inf

ミナト

検証データの損失が inf……無限大？

ボンゴ先生

検証データには、訓練データで一度も見たことがない文字のペアが出てくるからだ。数えるだけのモデルは、見たことのないペアに確率0をつける。そして、確率0のことが起きたら、驚きは無限大。モデルは「絶対にありえない！」と言い張っていたのに、起きてしまったわけだ。

Python（Colabのセルに貼って実行）
unseen = sum(1 for a, b in zip(val_text, val_text[1:]) if pairs[(a, b)] == 0)
print("検証データのペア：", len(val_text) - 1, "個のうち、訓練で見ていないもの：", unseen, "個")
出力
検証データのペア： 16246 個のうち、訓練で見ていないもの： 1315 個

「絶対」を言わないモデル：スムージング

対策はシンプルです。どのペアにも、ほんの少しだけ回数を足しておくのです。見たことがないペアにも「0.01回くらいは見たかもね」とおまけをつける。これを スムージング（smoothing、なめらかにする）と言います。

P(b∣a)=「ab」の回数+k「a」の回数+k×VP(b \mid a) = \frac{\text{「ab」の回数} + k}{\text{「a」の回数} + k \times V}P(b∣a)=「a」の回数+k×V「ab」の回数+k​

VVV は語彙の数です。分母にも k×Vk \times Vk×V を足すのは、確率の合計をちゃんと1にするためです（全部の bbb に kkk ずつ足したので）。

Python（Colabのセルに貼って実行）
V = len(set(text))

def make_smoothed(k):
    def p(a, b):
        return (pairs[(a, b)] + k) / (firsts[a] + k * V)
    return p

for k in [1, 0.1, 0.01, 0.001]:
    p_k = make_smoothed(k)
    print(f"k={k:<6} 訓練 {bigram_loss(train_text, p_k):.3f}   検証 {bigram_loss(val_text, p_k):.3f}")
出力
k=1      訓練 4.303   検証 4.385
k=0.1    訓練 3.488   検証 3.748
k=0.01   訓練 3.139   検証 3.581
k=0.001  訓練 3.033   検証 3.652

Pythonの道具箱：関数を作る関数

make_smoothed(k) は、k の値を覚えた確率関数 p を作って返す関数です。関数も変数のように受け渡しできるのがPythonの面白いところです。今は「k ごとに別の確率関数を作っている」と分かればOKです。

理論の小部屋：ハイパーパラメータは検証データで選ぶ

k は小さいほど訓練の損失は良くなります（数えた結果に忠実になるので）。でも検証の損失は、k=0.01 がいちばん良く、小さすぎても大きすぎても悪化しています。

  • k が大きすぎる：おまけが多すぎて、せっかく数えた知識が薄まる（「先」の次の「生」まで、他の文字と大差なくなる）
  • k が小さすぎる：見たことのないペアへの驚きが大きすぎる

このように、人間が事前に決める設定値を ハイパーパラメータ と呼びます（これに対して、データから決まる値がパラメータ）。ハイパーパラメータは、検証データの成績で選ぶのが鉄則です。訓練データで選ぶと、「丸暗記」に有利な値を選んでしまいます。

パープレキシティ：何択で迷っているか

損失「3.581」と言われても、ピンとこないかもしれません。そこで、もう少し直感的な数に変換します。

パープレキシティ=e損失\text{パープレキシティ} = e^{\text{損失}}パープレキシティ=e損失
Python（Colabのセルに貼って実行）
print("bigram（k=0.01）のパープレキシティ：", math.exp(3.581))
print("でたらめに選ぶモデルの損失：", math.log(V), " パープレキシティ：", math.exp(math.log(V)))
出力
bigram（k=0.01）のパープレキシティ： 35.909432330660664
でたらめに選ぶモデルの損失： 7.630946580890459  パープレキシティ： 2061.0

理論の小部屋：パープレキシティ＝「何択問題で迷っているか」

パープレキシティ（perplexity、困惑度）は、「モデルが毎回、だいたい何個の候補の中で迷っているか」を表します。

  • 2061文字から完全にでたらめに選ぶモデル：毎回2061択で迷う → パープレキシティ2061（損失は log⁡2061≈7.63\log 2061 \approx 7.63log2061≈7.63）
  • 私たちのbigramモデル：だいたい36択くらいまで絞り込めている → パープレキシティ約36

2061択から36択へ。数えるだけで、迷いを約57分の1にできたわけです。なかなかやります。

もっと深く情報理論との関係（ビットで数える）

自然対数の代わりに log⁡2\log_2log2​ を使うと、損失の単位は ビット になります。「1文字を予測するのに、平均何ビット分の情報が足りないか」という意味で、エントロピーという考え方につながります。log⁡2x=log⁡x/log⁡2\log_2 x = \log x / \log 2log2​x=logx/log2 なので、3.581 ÷ 0.693 ≈ 5.17ビット。つまり私たちのモデルは、次の1文字を当てるのに「Yes/Noの質問をあと約5回したい」状態です。
