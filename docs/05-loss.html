この章でつくるもの

前の章のbigramモデルは「なんとなく漱石っぽい」文章を書きました。でも「なんとなく」では、モデルを改良しても良くなったのか分かりません。この章では、言語モデルの成績を1つの数で表す方法を作ります。この数（損失）は、この先のすべての章で、モデルの進化を測るものさしになります。

これまでの復習とつながり：第3章・第4章とのつながり

  • 第3章：どんな数も正の値に変える指数関数 exe^xex と、合計1の確率分布を作る softmax を学びました。
  • 第4章：『こころ』から隣接ペアを数えて条件付き確率 P(b∣a)P(b \mid a)P(b∣a) を作る bigram モデルを完成させ、データに出てこない並び（スパース性）という弱点を見つけました。

この章では、条件付き確率 P(b∣a)P(b \mid a)P(b∣a) を使ってモデルに客観的な点数をつける仕組み（対数・負の対数尤度・損失・パープレキシティ）を作ります。第3章の exe^xex のちょうど逆の道具である 対数 log⁡\loglog が主役として登場します！

理論の小部屋：なぜ分けるの？

テスト勉強で、過去問の答えを丸暗記した人を想像してください。同じ過去問なら満点ですが、本番で少し違う問題が出たら解けません。

モデルも同じです。数えるのに使った文章で点数をつけると、「丸暗記」がうまいほど高得点になってしまいます。本当に知りたいのは「見たことのない文章でも、次の文字を当てられるか」です。

そこで、データを分けます。

  • 訓練データ（training data）：モデルが学ぶ（数える）ためのデータ。過去問
  • 検証データ（validation data）：点数をつけるためだけのデータ。モデルには絶対に見せない。本番の模試

さらに研究では、最後の最後に一度だけ使う テストデータ をもう1つ取っておくこともあります（第20章）。

訓練データだけでbigramを数え直します。

Python（Colabのセルに貼って実行）
pairs = Counter(zip(train_text, train_text[1:]))
firsts = Counter(train_text[:-1])

def prob(a, b):
    """P(b | a)：「a」の次が「b」である確率"""
    if firsts[a] == 0:
        return 0.0
    return pairs[(a, b)] / firsts[a]

print("P(生|先) =", prob("先", "生"))
print("P(は|生) =", prob("生", "は"))
出力
P(生|先) = 0.8857566765578635
P(は|生) = 0.23097112860892388

文章の確率を計算する

モデルが「この文章はありそうだ」と思うほど、良いモデルのはずです。では、文章全体の確率（同時確率）はどう計算するのでしょう？ 数学的に厳密な等式と、bigramモデルの近似をしっかり区別して押さえましょう。

数学の道具箱：厳密な「確率の連鎖律」 vs bigramの「マルコフ近似」

任意の文字列 (x1,x2,x3)(x_1, x_2, x_3)(x1​,x2​,x3​) が続けて出てくる確率は、条件付き確率の定義から常に厳密に次の掛け算に分解できます（確率の連鎖律、chain rule of probability）。

P(x1,x2,x3)=P(x1)⋅P(x2∣x1)⋅P(x3∣x1,x2)P(x_1, x_2, x_3) = P(x_1) \cdot P(x_2 \mid x_1) \cdot P(x_3 \mid x_1, x_2)P(x1​,x2​,x3​)=P(x1​)⋅P(x2​∣x1​)⋅P(x3​∣x1​,x2​)

「先生は」なら、厳密には P(先生は)=P(先)⋅P(生∣先)⋅P(は∣先生)P(\text{先生は}) = P(\text{先}) \cdot P(\text{生} \mid \text{先}) \cdot P(\text{は} \mid \text{先生})P(先生は)=P(先)⋅P(生∣先)⋅P(は∣先生) です。本物のLLM（GPTなど）は、3文字目を予測するときにそれまでの全文脈 (x1,x2)(x_1, x_2)(x1​,x2​) を条件にするこの厳密な連鎖律をそのまま使います。

一方、bigramモデルは「直前の1文字だけを見る」というマルコフ近似（P(x3∣x1,x2)≈P(x3∣x2)P(x_3 \mid x_1, x_2) \approx P(x_3 \mid x_2)P(x3​∣x1​,x2​)≈P(x3​∣x2​)）を置きます。

Pbigram(x1,x2,x3)=P(x1)⋅P(x2∣x1)⋅P(x3∣x2)P_{\text{bigram}}(x_1, x_2, x_3) = P(x_1) \cdot P(x_2 \mid x_1) \cdot P(x_3 \mid x_2)Pbigram​(x1​,x2​,x3​)=P(x1​)⋅P(x2​∣x1​)⋅P(x3​∣x2​)

最初の1文字 P(先)P(\text{先})P(先) を除いた遷移確率の積で「先生は」を計算すると、bigramの近似値は次のようになります。

Pbigram(生,は∣先)=P(生∣先)×P(は∣生)≈0.886×0.231≈0.205P_{\text{bigram}}(\text{生}, \text{は} \mid \text{先}) = P(\text{生} \mid \text{先}) \times P(\text{は} \mid \text{生}) \approx 0.886 \times 0.231 \approx 0.205Pbigram​(生,は∣先)=P(生∣先)×P(は∣生)≈0.886×0.231≈0.205

区別が大切：上の P(x1,x2,x3)=P(x1)P(x2∣x1)P(x3∣x1,x2)P(x_1, x_2, x_3) = P(x_1)P(x_2 \mid x_1)P(x_3 \mid x_1, x_2)P(x1​,x2​,x3​)=P(x1​)P(x2​∣x1​)P(x3​∣x1​,x2​) は常に成り立つ数学の恒等式、P(x3∣x1,x2)≈P(x3∣x2)P(x_3 \mid x_1, x_2) \approx P(x_3 \mid x_2)P(x3​∣x1​,x2​)≈P(x3​∣x2​) は計算を簡単にするためのモデル上の近似です。

では、訓練データの最初の数百文字で bigram の遷移確率を掛け続けてみましょう。どのペアも訓練データで数えたものなので、確率が0になることはないはずです。

Python（Colabのセルに貼って実行）
p = 1.0
for i, (a, b) in enumerate(zip(train_text, train_text[1:])):
    p = p * prob(a, b)
    if i in [10, 50, 100, 150, 200, 300]:
        print(f"{i:4d}文字目まで：確率 {p}")

ボンゴ先生

事件だ！ どのペアも確率は0じゃないのに、掛け算を続けたら、300文字目でとうとうぴったり0になってしまった。200文字目の e-279 は「10のマイナス279乗」、つまり小数点の後に0が278個並ぶ数だ。宇宙にある原子の数（だいたい 108010^{80}1080 個）で1を割っても、まだまだこんなに小さくはならない。

基本情報とつながる：アンダーフロー

コンピュータの小数（浮動小数点数）には、表せる大きさに限界があります。Pythonの float（倍精度、64ビット）では、だいたい 10−30810^{-308}10−308 より小さい数はまともに表せず、最後は0になってしまいます。これを アンダーフロー と言います。基本情報の「浮動小数点数の表現」で、指数部のビット数が限られていることを習いましたね。それがここで牙をむいたのです。

0になってしまうと、どのモデルの確率も「0」で、比べようがありません。どうしましょう？

救世主：対数（log）

ここで登場するのが 対数（たいすう、logarithm）です。記号を丸暗記するのではなく、「なぜ対数が必要なのか」から9ステップでたどりましょう。

数学の道具箱：対数 log⁡\loglog：9ステップで理由から理解する

① 解決したい具体的な問題：何千文字もの確率の掛け算 p1×p2×⋯×pNp_1 \times p_2 \times \dots \times p_Np1​×p2​×⋯×pN​ を、0に潰れず（アンダーフローせず）、かつモデル間の大小関係を変えずに計算したい。

② 素朴な掛け算ではなぜダメなのか？：確率は必ず 0≤p≤10 \le p \le 10≤p≤1 なので、掛けるたびに桁が急減します。300文字も掛けると 10−30810^{-308}10−308 を下回り、64ビット浮動小数点数（float）では 0.0 に丸められて全モデルの点数が同じ 0.0 になってしまいます。

③ 新しい発想：「数そのもの」ではなく、「ある基準の数を何回掛けたか（指数の肩の数）」で数える世界へ引っ越す。指数の世界では掛け算が足し算に化ける（102×103=102+310^2 \times 10^3 = 10^{2+3}102×103=102+3）ので、何万回足しても0に潰れません！

④ 記号の読み方表：

理論の小部屋：対数の3つの性質（これだけ覚えればOK）

  1. 掛け算が足し算になる：log⁡(a×b)=log⁡a+log⁡b\log(a \times b) = \log a + \log blog(a×b)=loga+logb
  2. 1は0になる：log⁡1=0\log 1 = 0log1=0
  3. 1より小さい数はマイナス、0に近づくほどどんどんマイナスに大きくなる

性質1がすごいのです。確率の掛け算を、対数の足し算に変えられます。足し算なら、何千回くり返しても0にはなりません（-1000とか-5000とかになるだけ）。

損失：驚きの平均

「log確率の合計」は文章が長いほどマイナスに大きくなるので、長さの違う文章どうしを比べにくいです。そこで、1文字あたりの平均にします。さらに、マイナスの数は扱いにくいので、符号をひっくり返してプラスにします。これが言語モデルの点数、損失（loss）です。

L=−1N∑i=1Nlog⁡pi=−1N∑i=1Nlog⁡P(次の文字i∣今の文字i)L = -\frac{1}{N}\sum_{i=1}^{N} \log p_i = -\frac{1}{N}\sum_{i=1}^{N} \log P(\text{次の文字}_i \mid \text{今の文字}_i)L=−N1​i=1∑N​logpi​=−N1​i=1∑N​logP(次の文字i​∣今の文字i​)

数学の道具箱：なぜ 1−p1-p1−p ではなく −log⁡p-\log p−logp なのか？：9ステップで理由から理解する

① 解決したい具体的な問題：正解文字に対する予測確率 p1,p2,…,pNp_1, p_2, \dots, p_Np1​,p2​,…,pN​ から、「外したほど大きい罰（損失）」を1つの数 LLL にまとめたい。

② 素朴な方法（1−p1 - p1−p や (1−p)2(1 - p)^2(1−p)2）ではなぜダメなのか？ 「外れ度合いなら 1−p1 - p1−p や (1−p)2(1 - p)^2(1−p)2 でよさそう」と思えますよね。実際に極端な外れ値で比べてみましょう。

理論の小部屋：損失は「驚き」の平均

−log⁡p-\log p−logp は、確率 ppp のことが起きたときの 驚きの大きさ と考えられます。

天気予報に例えてみましょう。

  • 「明日は100%晴れ」と予報して本当に晴れたら、驚きはゼロです（−log⁡1=0-\log 1 = 0−log1=0）
  • 「降水確率50%」と言われて雨が降ったら、コイントスが裏だったくらいで少し驚きます（−log⁡0.5≈0.69-\log 0.5 \approx 0.69−log0.5≈0.69）
  • 「降水確率1%」と言われて雨が降ったら、「えっ、降ったの！？」とかなり驚きます（−log⁡0.01≈4.6-\log 0.01 \approx 4.6−log0.01≈4.6）
  • 「降水確率0%（絶対に雨は降らない）」と断言していたのに土砂降りになったら、「嘘でしょ！？」と無限大にショックを受けます（−log⁡0=∞-\log 0 = \infty−log0=∞）

損失は、モデルが検証データを1文字ずつ読みながら感じた「驚き」の平均です。良いモデルほど、次の文字を正しく予想できているので、驚きが少ない。だから 損失は小さいほど良い のです。ゴルフのスコアと同じですね。

ちなみに、この量は 負の対数尤度（negative log-likelihood、NLL）や、交差エントロピー（cross-entropy）とも呼ばれます。より一般的には、真の確率分布 PPP とモデルの予測分布 QQQ のあいだの交差エントロピーは

    total = 0.0

        if p == 0:
            return float("inf")       # 確率0の出来事 → 驚きは無限大
        total += -math.log(p)
    return total / (len(data) - 1)

「絶対」を言わないモデル：スムージング

対策はシンプルです。どのペアにも、ほんの少しだけ回数を足しておくのです。見たことがないペアにも「0.01回くらいは見たかもね」とおまけをつける。これを スムージング（smoothing、なめらかにする）と言います。

P(b∣a)=「ab」の回数+k「a」の回数+k×VP(b \mid a) = \frac{\text{「ab」の回数} + k}{\text{「a」の回数} + k \times V}P(b∣a)=「a」の回数+k×V「ab」の回数+k​

VVV は語彙の数です。分母にも k×Vk \times Vk×V を足すのは、確率の合計をちゃんと1にするためです（全部の bbb に kkk ずつ足したので）。

数学の道具箱：小さな手計算で確かめる（V=4V = 4V=4、k=1k = 1k=1）

語彙が あ, い, う, え（V=4V = 4V=4）だけの世界で、「あ」の出現が6回（内訳：あい:3, あう:2, ああ:1, あえ:0）だったとします。全4文字に k=1k = 1k=1 ずつ足すと、分母も k×V=1×4=4k \times V = 1 \times 4 = 4k×V=1×4=4 増えて 6+4=106 + 4 = 106+4=10 になります。

import math

def perplexity(probs):
    if any(p <= 0 for p in probs):
        return float("inf")             # 確率0が1つでもあれば PPL = ∞
    loss = -sum(math.log(p) for p in probs) / len(probs)
    if loss > 700:                      # float64 は exp(709.78...) 超で OverflowError
        return float("inf")
    return math.exp(loss)

print(round(perplexity([0.5, 0.5, 1.0]), 3))   # 1.587
print(perplexity([0.25, 0.25, 0.25, 0.25]))    # 4.0
print(perplexity([0.5, 0.0]))                  # inf

  1. 「実質 KKK 択」のたとえの限界：PPL=10\mathrm{PPL} = 10PPL=10 は「どの文字でも常に10個が均等に並んでいる」という意味ではなく、あくまで幾何平均としての等価な選択肢数です。たとえば99文字を p≈1.0p \approx 1.0p≈1.0 で当てても、1文字だけ p=10−100p = 10^{-100}p=10−100 と大外れすれば全体の PPL\mathrm{PPL}PPL は一気に 101010 へ跳ね上がります（p=0p=0p=0 が1つ混ざるだけで PPL=∞\mathrm{PPL} = \inftyPPL=∞）。
  2. トークナイザー（語彙・分割単位）が違うモデルどうしは直接比べられない：1文字単位とサブワード（BPE、第14章）単位では1トークンあたりの情報量も NNN も異なるため、生の PPL\mathrm{PPL}PPL の大小を比べることはできません（第20章で詳しく検証します）。
  3. 評価データや前処理が違う数字は比べられない：同じモデルでも、易しい文か難しい文か、ルビ除去などの前処理が違うかで PPL\mathrm{PPL}PPL は大きく変わります。公平な比較にはまったく同じ評価データ・前処理・トークナイザーが必要です。

もっと深く情報理論との関係（ビットで数える）

自然対数の代わりに log⁡2\log_2log2​ を使うと、損失の単位は ビット になります。「1文字を予測するのに、平均何ビット分の情報が足りないか」という意味で、エントロピーという考え方につながります。log⁡2x=log⁡x/log⁡2\log_2 x = \log x / \log 2log2​x=logx/log2 なので、3.581 ÷ 0.693 ≈ 5.17ビット。つまり私たちのモデルは、次の1文字を当てるのに「Yes/Noの質問をあと約5回したい」状態です。
この考え方は、1948年にクロード・シャノンが作った 情報理論 から来ています。シャノンは英語の1文字あたりのエントロピーを、人間に次の文字を当てさせる実験で推定しました。まさに人間を言語モデルとして使ったわけです。
