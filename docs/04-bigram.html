この章でつくるもの

いよいよ、自分の言語モデルを作ります。材料は夏目漱石の『こころ』、道具は「数を数える」ことだけ。それなのに、完成したモデルは「私は先生の…」と、なんとなく漱石っぽい文章を書き始めます。この章のモデルが、これから第13章のGPTまで続く「進化の記録」のスタート地点です。

これまでの復習とつながり：第2章・第3章とのつながり

  • 第2章：コンピュータの中の文字は bytes（0〜255のバイト列）として保存され、文字コード（UTF-8など）で文字列に戻ること、そして文字をIDに対応づける語彙（stoi）を学びました。
  • 第3章：言語モデルの仕事は「今の文脈の次に来るトークンの確率分布を出し、その確率に従ってサンプリング（くじ引き）する」ことだと学びました。

この章では、いよいよ既製品モデルを卒業し、小説1冊から「ある文字の次にどの文字が来るか」を数えて自分で確率分布を作り、自分で文章をサンプリングする最初の言語モデルを完成させます！

掃除する：正規表現

機械学習では、データの掃除（前処理）がとても大事です。「ゴミを入れたらゴミが出てくる（Garbage In, Garbage Out）」という格言があるくらいです。ルビを消すには 正規表現（regular expression）を使います。正規表現は「こういう形の文字列」というパターンを書くための小さな言語です。

Python（Colabのセルに貼って実行）
import re

sample = "私《わたくし》はその人を常に先生《せんせい》と呼んでいた。"
print(re.sub(r"《.*?》", "", sample))
出力
私はその人を常に先生と呼んでいた。

Pythonの道具箱：正規表現の読み方

re.sub(パターン, 置き換える文字, 対象) は「パターンに合う部分を全部置き換える」関数です。r"《.*?》" は次のように読みます。

部分意味
《「《」という文字
.何でもいい1文字
*直前のものが0回以上くり返す
?ただし、なるべく短く（控えめに）
》「》」という文字

つまり「《 から始まって、いちばん近い 》 で終わる部分」です。? を付け忘れると「なるべく長く」になって、最初の《から最後の》までをごっそり消してしまいます。試してみましょう。

Python（Colabのセルに貼って実行）
print(re.sub(r"《.*》", "", sample))
出力
私と呼んでいた。

「はその人を常に先生」まで消えてしまいました。正規表現は強力なぶん、ちょっとしたミスで大惨事になります。電動ノコギリみたいなものです。

基礎の補足理解のための最小コード：`re.sub` の最短一致 `.*?` vs 最長一致 `.*`

同じ入力 s = "私《わたくし》は先生《せんせい》だ"（str型）に対して、マッチする範囲（中間状態）と出力を比べてみましょう。

パターンマッチする区間（中間）置換後の出力（str型）理由
r"《.*?》"（最短一致）①《わたくし》、②《せんせい》 の2か所"私は先生だ"? があるので一番近い 》 で止まる
r"《.*》"（最長一致）《わたくし》は先生《せんせい》 の1か所"私だ"? がないので最後の 》 まで欲張って飲み込む

では、本文全体を掃除する関数を作ります。

Python（Colabのセルに貼って実行）
def clean_aozora(text):
    text = text.split("-------------------------------------------------------")[2]  # 冒頭の説明を除く
    text = text.split("底本：")[0]                   # 末尾の書誌情報を除く
    text = re.sub(r"《.*?》", "", text)              # ルビを除く
    text = re.sub(r"※?［＃.*?］", "", text)          # 入力者注を除く
    text = text.replace("｜", "").replace("\r\n", "\n")
    text = re.sub(r"\n{3,}", "\n\n", text)           # 3行以上の空行を2行に
    return text.strip()

text = clean_aozora(raw.decode("cp932"))
print(len(text), "文字")
print(text[:150])

「〜た。」で終わる文が2960回。さすが小説、過去形だらけです。では、「先」の次には何が来るでしょう？

Python（Colabのセルに貼って実行）
def next_counts(ch):
    c = Counter()
    for (a, b), n in pairs.items():   # 全部のペアの中から
        if a == ch:                   # 1文字目が ch のものだけ
            c[b] = n                  # 2文字目と回数を記録
    return c

c = next_counts("先")
print("「先」は全部で", sum(c.values()), "回")
print(c.most_common(5))
出力

[('生', 597), ('へ', 22), ('刻', 16), ('で', 8), ('を', 6)]

「先」678回のうち597回、つまり約88%が「先生」です。『こころ』は「先生」の物語ですからね。

数学の道具箱：条件付き確率 $P(B \mid A)$：9ステップで理由から理解する

① 解決したい具体的な問題：「今の文字が『先』だ」と分かっているとき、次の文字が『生』『へ』『刻』…である確率を正しく出したい。

② 素朴な方法（単なる出現回数・全体割合）ではなぜダメなのか？

  • もし文章全体の回数ランキング（unigram）だけを使うと、『こころ』で最多は「の」（7556回）なので、どんな文字の次でも「の」が一番選ばれやすくなり、「ののたのい…」のような日本語にならない文が出てしまいます。
  • また、生の回数 597 のままでは「678回中597回（88%）」なのか「1万回中597回（6%）」なのか分からず、合計1の確率分布にもなりません。

③ 新しい発想：小説全体を見るのではなく、「1文字目が aaa であるペアだけ」に世界を絞り込み、その中で次が bbb だった割合をとる。これが 条件付き確率 です。

④ 記号の読み方表：

記号読み方意味
P(B∣A)P(B \mid A)P(B∣A)「AのもとでのBの確率」条件 AAA が起きた世界で、出来事 BBB が起きる割合
∣\mid∣（縦棒）「〜という条件のもとで」右側が分かっている条件（分母）、左側が予測したいもの
count(a,b)\text{count}(a, b)count(a,b)「aaa の次に bbb が来た回数」隣接ペア (a, b) の出現回数
count(a)\text{count}(a)count(a)「aaa（の後に文字がある箇所）の回数」条件 aaa で始まるペアの総数 ∑bcount(a,b)\sum_b \text{count}(a, b)∑b​count(a,b)

⑤ 小さな10文字コーパスで手計算：s = "あいうあいうあいあえ"（10文字・隣接9ペア）で、今の文字が「あ」のときを手計算してみましょう。

  • 全9ペア：あい, いう, うあ, あい, いう, うあ, あい, いあ, あえ
  • 「あ」で始まるペアだけ絞り込む：あい（3回）、あえ（1回）→ 合計4回
  • したがって：
P(い∣あ)=34=0.75,P(え∣あ)=14=0.25P(\text{い} \mid \text{あ}) = \frac{3}{4} = 0.75, \qquad P(\text{え} \mid \text{あ}) = \frac{1}{4} = 0.25P(い∣あ)=43​=0.75,P(え∣あ)=41​=0.25
  • 合計は 0.75+0.25=1.000.75 + 0.25 = 1.000.75+0.25=1.00。きちんと確率分布の2条件（0以上・合計1）を満たします！

⑥ 一般式：『こころ』のような長い文章でも同じです。

P(b∣a)=count(a,b)count(a)=count(a,b)∑b′count(a,b′)P(b \mid a) = \frac{\text{count}(a, b)}{\text{count}(a)} = \frac{\text{count}(a, b)}{\sum_{b'} \text{count}(a, b')}P(b∣a)=count(a)count(a,b)​=∑b′​count(a,b′)count(a,b)​

『こころ』の「先」なら：

P(生∣先)=「先生」の回数「先」の回数=597678≈0.88P(\text{生} \mid \text{先}) = \frac{\text{「先生」の回数}}{\text{「先」の回数}} = \frac{597}{678} \approx 0.88P(生∣先)=「先」の回数「先生」の回数​=678597​≈0.88

⑧ よくある誤解：P(B∣A)P(B \mid A)P(B∣A) と P(A∣B)P(A \mid B)P(A∣B) はまったく別物です。『こころ』では P(生∣先)=597/678≈0.88P(\text{生} \mid \text{先}) = 597/678 \approx 0.88P(生∣先)=597/678≈0.88 ですが、逆向きの P(先∣生)P(\text{先} \mid \text{生})P(先∣生) は「生」の次に「先」が来る確率（たった4回）なのでほぼ 000 です。縦棒 ∣\mid∣ の右側が条件（分母）と意識しましょう。

漱石に書かせる

数えた結果を使えば、文章が作れます。今の文字の「次の文字の回数」をそのまま重みにして、くじを引くのです。

Python（Colabのセルに貼って実行）
import random

following = {}                       # 「文字 → その次の文字の回数」の辞書
for a, b in zip(text, text[1:]):      # 隣り合う2文字 a, b を順番に
    if a not in following:            # a が初めて出てきたら
        following[a] = Counter()      #   a 用の空のカウンターを用意
    following[a][b] += 1              # 「a の次に b が来た」回数を1増やす

def generate(start, n=80):
    out = start
    ch = start[-1]                    # 書き出しの最後の1文字から続ける
    for _ in range(n):
        c = following[ch]
        ch = random.choices(list(c.keys()), weights=list(c.values()))[0]
        out += ch
    return out

random.seed(1)
print(generate("私"))
出力
私は腎臓の運ばなた。私のた後姿を帯の頁されはな時先生の方がなかられていと私のだろう済むしたに成功を心は私に宛てどこころにものだ私がら、多に私は自然とは午眠り、あ百

Pythonの道具箱：Counter の「0回」と random.choices

Counter は、まだ数えていないものを「0回」として扱います。だから、初めて出てきた b でも、いきなり following[a][b] += 1 と書けます（ふつうの辞書だと、ここで KeyError になります）。
random.choices(候補のリスト, weights=重みのリスト) は、重みに比例した確率で候補から1つ選びます（結果はリストで返るので [0] で取り出します）。第3章で自作した sample 関数と同じ仕事です。

なぜ1文字では足りないのか

理論の小部屋：マルコフ性と n-gram

bigramモデルは「次の文字は、直前の1文字だけで決まる」と仮定しています。この「直前だけを見る」性質を マルコフ性 と言います（「マルコフ連鎖」という名前を聞いたことがあるかもしれません）。

もっと前まで見れば、もっと自然になるはずです。直前2文字なら trigram（トライグラム）、一般に直前 n−1n-1n−1 文字を見るモデルを n-gram モデルと呼びます。2010年代の半ばごろまで、機械翻訳や音声認識の中心はこのn-gramモデルでした。

では、直前2文字を見るtrigramを作ってみましょう。

Python（Colabのセルに貼って実行）
following3 = {}
for a, b, c in zip(text, text[1:], text[2:]):
    key = a + b
    if key not in following3:
        following3[key] = Counter()
    following3[key][c] += 1

def generate3(start, n=80):
    out = start
    for _ in range(n):
        c = following3.get(out[-2:])  # 最後の2文字の「次の文字の回数」。辞書になければ None
        if c is None:                 # 続きが見つからなければ
            break                     #   ループを途中で抜けて終わり
        out += random.choices(list(c.keys()), weights=list(c.values()))[0]
    return out

random.seed(1)
print(generate3("私は"))
print("2文字の組み合わせの種類：", len(following3))
出力
私はまるでした。先生を見詰めているらしませんからＫに向って、先生が不意にその他妹の夫だの、先生ははたしかし人間が来ると、知らないんでした。奥さんにはまた愛するといて
2文字の組み合わせの種類： 21562

「先生を見詰めている」「Ｋに向って」「奥さんにはまた愛する」……かなり『こころ』です！ 直前2文字を見るだけで、ぐっと文章らしくなりました。じゃあ、10文字見れば完璧では？

理論の小部屋：データが足りない問題（スパース性）

そうはいきません。見る文字数を増やすと、組み合わせの数が爆発します。語彙が2061文字なら、組み合わせの数は文字数に対して指数関数的に膨れ上がります。

  • 直前1文字（bigram）：$2061^2 \approx 425$万通り（『こころ』に出てくるのは約2万種類だけ）
  • 直前2文字（trigram）：$2061^3 \approx 87.6$億通り
  • 直前10文字（11-gram）：$2061^{11} \approx 2.5 \times 10^{36}$通り（宇宙全体の原子の数すら超える天文学的数字！）

『こころ』全体でもたった16万字しかありません。文字数を少し増やしただけで、組み合わせの大部分はデータの中に一度も出てこなくなります。

一度も見たことがない並びに出会うと、数えるだけのモデルは「確率0」と答えるしかありません（上の generate3 が None で止まるのは、このときです）。表のマス目の大半が0でスカスカになってしまうこの現象を、スパース性（まばらさ）の問題と言います。

人間なら、「先生は」を見たことがあれば「教授は」の次も似たような言葉が来そうだと推測できます。「先生」と「教授」が似ていることを知っているからです。数えるだけのモデルには、この「似ている」が分かりません。

この壁を越えるために、文字を「数の組（ベクトル）」で表して、似た文字を近くに置く方法を学びます。それがニューラルネットワークの出番であり、第9章の「埋め込み」です。

確率の表として眺める

最後に、bigramモデルの正体を「表」として見ておきましょう。行が「今の文字」、列が「次の文字」、中身が回数です。

Python（Colabのセルに貼って実行）
look = ["先", "生", "私", "は", "。"]
print("今＼次 " + " ".join(f"{b:>4}" for b in look))
for a in look:
    row = " ".join(f"{pairs[(a, b)]:>5}" for b in look)
    print(f"  {a}   {row}")

「私→は」が1352回、「。→私」が911回。文が終わると、次の文は「私」で始まることが多い。語り手の「私」の物語らしい表です。

本当の表は2061行×2061列、約420万マスもあります。この巨大な「数の表」を効率よく扱う道具が、第6章で学ぶ 行列 と テンソル です。

  • UnicodeDecodeError：decode("utf-8") のままになっていませんか？ 青空文庫は decode("cp932") です。
  • IndexError: list index out of range（split(…)[2] の行）：ダウンロードしたファイルが本文ではなく、エラーページになっている可能性があります。print(text[:300]) で中身を確認し、URLを見直しましょう。

まとめ

  • 言語モデルの最も素朴な作り方は、「次の文字」を数えること
  • 数えた割合が 条件付き確率 P(次∣今)P(\text{次} \mid \text{今})P(次∣今)。直前1文字なら bigram
