つくるもの

『こころ』の「ある文字の次に来る文字」を数えて、漱石風（？）の文章を書くbigram言語モデル

  • データの前処理（文字コード変換・ルビ除去）

  • 条件付き確率 P(次∣今)P(\text{次} \mid \text{今})P(次∣今)
  • bigram・n-gramモデルとマルコフ性
  • データが足りない問題（スパース性）

この章でつくるもの

いよいよ、自分の言語モデルを作ります。材料は夏目漱石の『こころ』、道具は「数を数える」ことだけ。それなのに、完成したモデルは「私は先生の…」と、なんとなく漱石っぽい文章を書き始めます。この章のモデルが、これから第13章のGPTまで続く「進化の記録」のスタート地点です。

ミナト

言語モデルって、何億個もパラメータがあるすごいものじゃないんですか？ 数えるだけで作れるんですか？

ボンゴ先生

作れるとも。第3章で見たように、言語モデルの仕事は「次のトークンの確率を出す」ことだったね。だったら、本当に数えてしまえばいい。「『先』の次に何が来たか」を小説1冊ぶん全部数えれば、確率が出る。世界一素朴な言語モデルだ。素朴だからこそ、全部の部品が見える。

材料を手に入れる：青空文庫

青空文庫は、著作権の切れた文学作品を誰でも無料で読めるようにしている、ボランティアによる電子図書館です。夏目漱石（1916年没）の作品は誰でも自由に使えます。テキストファイルがGitHubにも置かれているので、そこからダウンロードしましょう。

新しいノートブック（04-bigram.ipynb）を作って、次を実行します。CPUのままでOKです。

基本情報とつながる：Shift_JIS と cp932

青空文庫のファイルは、古くから日本のパソコンで使われてきた Shift_JIS という文字コードで書かれています。基本情報の文字コードの問題で出てくる、あれです。正確にはWindowsで拡張された版の cp932（Microsoftの文字コード表の932番）を使うと、機種依存文字まで正しく読めます。
0x82 0xb1 はShift_JISで「こ」。0x82 0xb1 0x82 0xb1 0x82 0xeb で「こころ」です。上の出力の先頭と見比べてみてください。

text = raw.decode("cp932")
print(text[:300])

掃除する：正規表現

機械学習では、データの掃除（前処理）がとても大事です。「ゴミを入れたらゴミが出てくる（Garbage In, Garbage Out）」という格言があるくらいです。ルビを消すには 正規表現（regular expression）を使います。正規表現は「こういう形の文字列」というパターンを書くための小さな言語です。

Python（Colabのセルに貼って実行）
import re

sample = "私《わたくし》はその人を常に先生《せんせい》と呼んでいた。"
print(re.sub(r"《.*?》", "", sample))
出力
私はその人を常に先生と呼んでいた。

Pythonの道具箱：正規表現の読み方

re.sub(パターン, 置き換える文字, 対象) は「パターンに合う部分を全部置き換える」関数です。r"《.*?》" は次のように読みます。

部分 意味
《 「《」という文字
. 何でもいい1文字
* 直前のものが0回以上くり返す
? ただし、なるべく短く（控えめに）
》 「》」という文字

つまり「《 から始まって、いちばん近い 》 で終わる部分」です。? を付け忘れると「なるべく長く」になって、最初の《から最後の》までをごっそり消してしまいます。試してみましょう。

Python（Colabのセルに貼って実行）
print(re.sub(r"《.*》", "", sample))
出力
私と呼んでいた。

「はその人を常に先生」まで消えてしまいました。正規表現は強力なぶん、ちょっとしたミスで大惨事になります。電動ノコギリみたいなものです。

では、本文全体を掃除する関数を作ります。

Python（Colabのセルに貼って実行）
def clean_aozora(text):
    text = text.split("-------------------------------------------------------")[2]  # 冒頭の説明を除く
    text = text.split("底本：")[0]                   # 末尾の書誌情報を除く
    text = re.sub(r"《.*?》", "", text)              # ルビを除く
    text = re.sub(r"※?［＃.*?］", "", text)          # 入力者注を除く
    text = text.replace("｜", "").replace("\r\n", "\n")
    text = re.sub(r"\n{3,}", "\n\n", text)           # 3行以上の空行を2行に
    return text.strip()

text = clean_aozora(raw.decode("cp932"))
print(len(text), "文字")
print(text[:150])

『こころ』は2061種類の文字でできていて、一番多いのは「の」でした。これが私たちの言語モデルの語彙（2061文字）になります。

「次の文字」を数える

ここからが言語モデルです。「ある文字の次に、どの文字が来たか」の組（ペア）を全部数えます。

print(pairs.most_common(10))

Pythonの道具箱：zip とスライス

text[1:] は「1番目の文字から最後まで」、つまり先頭の1文字を除いた文字列です（スライスといいます）。zip(text, text[1:]) は2つを横に並べて、「0番目と1番目」「1番目と2番目」「2番目と3番目」…という組を順に作ります。

text 私 は そ の 人
text[1:] は そ の 人 を

縦に読むと「私→は」「は→そ」「そ→の」…。隣り合う2文字の組が全部手に入ります。

「〜た。」で終わる文が2960回。さすが小説、過去形だらけです。では、「先」の次には何が来るでしょう？

Python（Colabのセルに貼って実行）
def next_counts(ch):
    c = Counter()
    for (a, b), n in pairs.items():   # 全部のペアの中から
        if a == ch:                   # 1文字目が ch のものだけ
            c[b] = n                  # 2文字目と回数を記録
    return c

c = next_counts("先")
print("「先」は全部で", sum(c.values()), "回")
print(c.most_common(5))
出力
「先」は全部で 678 回
[('生', 597), ('へ', 22), ('刻', 16), ('で', 8), ('を', 6)]

「先」678回のうち597回、つまり約88%が「先生」です。『こころ』は「先生」の物語ですからね。

理論の小部屋：条件付き確率

「『先』が出たとき、次が『生』である確率」を、数学では次のように書きます。

P(生∣先)=「先生」の回数「先」の回数=597678≈0.88P(\text{生} \mid \text{先}) = \frac{\text{「先生」の回数}}{\text{「先」の回数}} = \frac{597}{678} \approx 0.88P(生∣先)=「先」の回数「先生」の回数​=678597​≈0.88

縦棒 ∣\mid∣ は「〜という条件のもとで」と読みます。これを 条件付き確率 と言います。「雨が降っているときに傘を持っている確率」のように、条件で絞り込んでから割合を考えるものです。

言語モデルとは、まさにこの P(次の文字∣それまでの文字)P(\text{次の文字} \mid \text{それまでの文字})P(次の文字∣それまでの文字) を出す仕組みのことでした（第3章）。今回は「直前の1文字だけ」を条件にしています。2つ（bi）の文字の組を数えるので、このモデルを bigram（バイグラム）モデルと呼びます。

漱石に書かせる

数えた結果を使えば、文章が作れます。今の文字の「次の文字の回数」をそのまま重みにして、くじを引くのです。

Python（Colabのセルに貼って実行）
import random

following = {}
for a, b in zip(text, text[1:]):
    if a not in following:
        following[a] = Counter()
    following[a][b] += 1

def generate(start, n=80):
    out = start
    ch = start
    for _ in range(n):
        c = following[ch]
        ch = random.choices(list(c.keys()), weights=list(c.values()))[0]
        out += ch
    return out

random.seed(1)
print(generate("私"))
出力
私は腎臓の運ばなた。私のた後姿を帯の頁されはな時先生の方がなかられていと私のだろう済むしたに成功を心は私に宛てどこころにものだ私がら、多に私は自然とは午眠り、あ百

Pythonの道具箱：random.choices

random.choices(候補のリスト, weights=重みのリスト) は、重みに比例した確率で候補から1つ選びます（結果はリストで返るので [0] で取り出します）。第3章で自作した sample 関数と同じ仕事です。

ボンゴ先生

「私は腎臓の運ばなた。」……漱石先生に怒られそうだね。でも見てごらん。「私は」「先生の方が」「私に宛て」「自然とは」。2文字だけ見れば、どこも日本語として自然だ。このモデルは、直前の1文字しか覚えていない。文の前のほうで何を言っていたかは、きれいさっぱり忘れている。

やってみよう：いろいろな書き出しで

random.seed(1) の数字を変えたり、generate("先")、generate("奥")、generate("Ｋ")（『こころ』のKは全角の「Ｋ」です） のように書き出しを変えたりしてみましょう。毎回違う「漱石っぽい何か」が生まれます。気に入ったものがあったら、それがあなたのモデルの最初の作品です。

なぜ1文字では足りないのか

理論の小部屋：マルコフ性と n-gram

bigramモデルは「次の文字は、直前の1文字だけで決まる」と仮定しています。この「直前だけを見る」性質を マルコフ性 と言います（「マルコフ連鎖」という名前を聞いたことがあるかもしれません）。

もっと前まで見れば、もっと自然になるはずです。直前2文字なら trigram（トライグラム）、一般に直前 n−1n-1n−1 文字を見るモデルを n-gram モデルと呼びます。20年ほど前まで、機械翻訳や音声認識の中心はこのn-gramモデルでした。

では、直前2文字を見るtrigramを作ってみましょう。

Python（Colabのセルに貼って実行）
following3 = {}
for a, b, c in zip(text, text[1:], text[2:]):
    key = a + b
    if key not in following3:
        following3[key] = Counter()
    following3[key][c] += 1

def generate3(start, n=80):
    out = start
    for _ in range(n):
        c = following3.get(out[-2:])
        if c is None:
            break
        out += random.choices(list(c.keys()), weights=list(c.values()))[0]
    return out

random.seed(1)
print(generate3("私は"))
print("2文字の組み合わせの種類：", len(following3))
出力
私はまるでした。先生を見詰めているらしませんからＫに向って、先生が不意にその他妹の夫だの、先生ははたしかし人間が来ると、知らないんでした。奥さんにはまた愛するといて
2文字の組み合わせの種類： 21562

「先生を見詰めている」「Ｋに向って」「奥さんにはまた愛する」……かなり『こころ』です！ 直前2文字を見るだけで、ぐっと文章らしくなりました。じゃあ、10文字見れば完璧では？

理論の小部屋：データが足りない問題（スパース性）

そうはいきません。見る文字数を増やすと、組み合わせの数が爆発します。語彙が2061文字なら、2文字の組み合わせは $2061^2 \approx 420$万通り（でも実際に『こころ』に出てくるのは、上の出力のとおり約2万種類だけ）、3文字なら約88億通り。でも『こころ』は16万字しかないので、ほとんどの組み合わせは一度も出てきません。

一度も見たことがない並びに出会うと、数えるだけのモデルは「確率0」と答えるしかありません（上の generate3 が None で止まるのは、このときです）。これを スパース性（まばらさ）の問題と言います。

人間なら、「先生は」を見たことがあれば「教授は」の次も似たような言葉が来そうだと推測できます。「先生」と「教授」が似ていることを知っているからです。数えるだけのモデルには、この「似ている」が分かりません。

この壁を越えるために、文字を「数の組（ベクトル）」で表して、似た文字を近くに置く方法を学びます。それがニューラルネットワークの出番であり、第9章の「埋め込み」です。

確率の表として眺める

最後に、bigramモデルの正体を「表」として見ておきましょう。行が「今の文字」、列が「次の文字」、中身が回数です。

Python（Colabのセルに貼って実行）
look = ["先", "生", "私", "は", "。"]
print("今＼次 " + " ".join(f"{b:>4}" for b in look))
for a in look:
    row = " ".join(f"{pairs[(a, b)]:>5}" for b in look)
    print(f"  {a}   {row}")
出力
今＼次    先    生    私    は    。
  先       0   597     0     2     0
  生       4     1     0   176     0
  私       0     0     0  1352     0
  は      58     6   145    11     1
  。     112     3   911     3     0

「私→は」が1352回、「。→私」が911回。文が終わると、次の文は「私」で始まることが多い。語り手の「私」の物語らしい表です。

本当の表は2061行×2061列、約420万マスもあります。この巨大な「数の表」を効率よく扱う道具が、第6章で学ぶ 行列 と テンソル です。

つまずき注意：よくあるつまずき

  • UnicodeDecodeError：decode("utf-8") のままになっていませんか？ 青空文庫は decode("cp932") です。
  • IndexError: list index out of range（split(…)[2] の行）：ダウンロードしたファイルが本文ではなく、エラーページになっている可能性があります。print(text[:300]) で中身を確認し、URLを見直しましょう。
  • KeyError（following[ch] の行）：書き出しに『こころ』に出てこない文字を使うと起きます。「私」「先」など、本文にある文字で始めましょう。

クイズ 1：条件付き確率

「私」は本文に2697回出てきて、そのうち「私は」は1352回でした。P(は∣私)P(\text{は} \mid \text{私})P(は∣私) はいくつ？

答えを見る（まず自分で考えてから！）
