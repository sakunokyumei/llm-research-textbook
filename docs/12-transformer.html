部品1：Head（おさらい）

第11章のHeadに、ドロップアウト（第10章）を1行足しただけです。

Python（Colabのセルに貼って実行）
class Head(nn.Module):
    """Attentionヘッド1つ（第11章）"""

    def __init__(self, n_embd, head_size, block_size, dropout):
        super().__init__()
        self.key = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        B, T, C = x.shape
        k, q, v = self.key(x), self.query(x), self.value(x)
        scores = q @ k.transpose(-2, -1) / math.sqrt(k.shape[-1])
        scores = scores.masked_fill(self.tril[:T, :T] == 0, float("-inf"))
        self.wei = F.softmax(scores, dim=-1)
        return self.dropout(self.wei) @ v

部品2：マルチヘッドAttention

Python（Colabのセルに貼って実行）
class MultiHeadAttention(nn.Module):
    """ヘッドを何個も並べて、結果をつなげる"""

    def __init__(self, n_embd, n_head, block_size, dropout):
        super().__init__()
        head_size = n_embd // n_head
        self.heads = nn.ModuleList([Head(n_embd, head_size, block_size, dropout) for _ in range(n_head)])
        self.proj = nn.Linear(n_embd, n_embd)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        out = torch.cat([h(x) for h in self.heads], dim=-1)
        return self.dropout(self.proj(out))

理論の小部屋：ヘッドを増やして分業する

1つのヘッドは、1種類の「注目の仕方」しかできません。でも文章を理解するには、「直前の文字」「文の主語」「かぎかっこの始まり」など、いろいろな観点で過去を見る必要があります。そこで、小さなヘッドを何個も並べて、それぞれに違う見方を学ばせます。

64個の数を4つのヘッドで分けると、各ヘッドは16個ずつ担当します（head_size = n_embd // n_head）。4つのヘッドの結果を torch.cat で横につなげると、また64個に戻ります。最後の proj（全結合層）で、4つの見方を混ぜ合わせます。

会議で、全員が同じ資料の同じ行を見ていたら意味がありませんよね。分担して違うところを読み、最後に持ち寄る。それがマルチヘッドです。第13章で、学習したヘッドたちが実際に役割分担している様子を見ます。

Pythonの道具箱：ModuleList

nn.ModuleList([...]) は、部品のリストをPyTorchに「これも全部モデルの部品だよ」と教えるための入れ物です。普通のPythonのリスト [...] に入れただけだと、PyTorchがパラメータを見つけられず、学習されません（model.parameters() に入らない）。気づきにくい落とし穴です。

基礎の補足マルチヘッドAttentionの形トレースと「なぜ分業が得なのか？」

n_embd = 64、n_head = 4（つまり head_size = 64 // 4 = 16）のとき、テンソルの形は次のように流れて元に戻ります。

ステップテンソルの形何をしているか
入力 x[B, T, 64]元の埋め込みベクトル（n_embd = 64）
各ヘッド h(x) × 4個[B, T, 16] が 4本4つのヘッドが独立に「別の観点」で過去から情報を集める（hs = 16）
torch.cat(..., dim=-1)[B, T, 64]4本の [B, T, 16] を最後の軸で横につなぎ、4 × 16 = 64 に戻す
self.proj(out)[B, T, 64]全結合層で4つのヘッドの見方を混ぜ合わせて残差ストリームへ返す

しかも嬉しいことに、1つの大きいヘッド（head_size = 64）を4つの小さいヘッド（head_size = 16 × 4）に分けても、Q・K・V のパラメータ合計は 4×(3×64×16)=3×6424 \times (3 \times 64 \times 16) = 3 \times 64^24×(3×64×16)=3×642 で1個も増えません。同じパラメータ予算のまま、複数の注目パターン（直前の文字、主語、括弧の対応など）を同時並行で追えるのがマルチヘッドの強みです。なお、最後に元の n_embd へ戻すため、必ず n_embd % n_head == 0（割り切れる設定）にします。

部品3：フィードフォワード（考える時間）

Python（Colabのセルに貼って実行）
class FeedForward(nn.Module):
    """各位置で、ひとりで「考える」MLP"""

    def __init__(self, n_embd, dropout):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_embd, 4 * n_embd),
            nn.GELU(),
            nn.Linear(4 * n_embd, n_embd),
            nn.Dropout(dropout),
        )

    def forward(self, x):
        return self.net(x)

理論の小部屋：話し合いと、ひとりで考える時間

Attentionは「文字どうしが情報をやりとりする」部品でした。いわば話し合いです。でも、話し合いで集めた情報を消化する時間も必要です。それがフィードフォワード層です。各位置で独立に（ほかの位置とは関係なく）、第9章と同じ「全結合層 → 活性化関数 → 全結合層」の小さなMLPを通します。

真ん中で一度 4倍 の幅に広げるのが定番です（GPTの論文の設計）。広い作業机でいったん情報を広げて考え、また元の幅にまとめる、というイメージです。活性化関数には、GPTと同じ GELU を使います。

実は、モデルの「知識」の多く（「漱石」の次は「夏目」が来やすい、など）は、このフィードフォワード層に蓄えられていると考えられています（第25章の解釈可能性の話題）。

Pythonの道具箱：Sequential

nn.Sequential(A, B, C) は、部品を順番に通す入れ物です。self.net(x) と書くと、C(B(A(x))) と同じ計算になります。流れ作業のベルトコンベアです。

基礎の補足FFNの4倍拡張：形トレースとパラメータ数

n_embd を CCC とすると、FeedForward の内部ではテンソルの形がいったん 4倍 に広がってから元に戻ります。

  • 入力：[B, T, C]
  • 1層目 Linear(C, 4C) ＋ GELU：[B, T, 4C]（パラメータ数：C×4C+4C=4C2+4CC \times 4C + 4C = 4C^2 + 4CC×4C+4C=4C2+4C）
  • 2層目 Linear(4C, C) ＋ Dropout：[B, T, C]（パラメータ数：4C×C+C=4C2+C4C \times C + C = 4C^2 + C4C×C+C=4C2+C）

合計は 8C2+5C8C^2 + 5C8C2+5C 個です。実は、1つの Block 全体のパラメータ（約 12C212C^212C2）のうち 約 2/3 がこの FeedForward 層にあります（Multi-Head Attention は約 4C24C^24C2＝約 1/3）。広い作業机（4C4C4C）に大量の重みを置いて、話し合いで集めた文脈を各位置でしっかり加工・記憶しているのです。

部品4：Block（残差接続とLayerNorm）

Python（Colabのセルに貼って実行）
class Block(nn.Module):
    """Transformerブロック：話し合い（Attention）→ 考える（FeedForward）"""

    def __init__(self, n_embd, n_head, block_size, dropout):
        super().__init__()
        self.ln1 = nn.LayerNorm(n_embd)
        self.attn = MultiHeadAttention(n_embd, n_head, block_size, dropout)
        self.ln2 = nn.LayerNorm(n_embd)
        self.ffwd = FeedForward(n_embd, dropout)

    def forward(self, x):
        x = x + self.attn(self.ln1(x))
        x = x + self.ffwd(self.ln2(x))
        return x

たった2行の forward ですが、ここにTransformerの設計の知恵が詰まっています。

理論の小部屋：残差接続：情報の高速道路

x = x + self.attn(…) の x + の部分が 残差接続（residual connection）です。第11章でも1回出てきましたね。

部品の出力で x を置き換えるのではなく、x に足し込む。こうすると、

  • 情報の高速道路（ベルトコンベア）：元の情報（自分が何の文字か、など）が、何層通っても消えずに残る。残差ストリーム（residual stream）は「工場のベルトコンベア」のようなものです。コンベアの上を文章情報がまっすぐ流れ、各ブロックのAttention係やMLP係は、コンベアの荷物を覗き見て「追加の気づき（差分）」をそっと上に載せるだけです。コンベアそのものを上書きしないので、何十層重ねても最初の文字情報が消えません。
  • 勾配の高速道路：誤差逆伝播で、勾配が足し算の道を通って、入口までまっすぐ届く（足し算の微分は1なので、勾配が弱まらない）。第10章の「深い層で勾配が消える」問題を、根本から解決する

LLMの層を何十、何百と深くできるのは、この残差接続のおかげです。2015年の画像認識モデル ResNet で有名になった方法で、Transformerはこれを借りてきました。

理論の小部屋：位置埋め込みを「足し算」する理由

Attentionには「順序」という概念がありません。文字の並び順をシャッフルしても、位置の情報がないとまったく同じ計算になってしまいます。そこで、0番目、1番目、2番目……という位置ごとのベクトル（pos_emb）を用意し、文字のベクトル（tok_emb）にそのまま足し算します。「足し算して混ざってしまわないの？」と不安になりますが、高次元の空間では、文字の意味の向きと位置の向きを別々の方向（独立した軸）として両立して保持できるため、ちゃんと区別して学習されます。

理論の小部屋：Pre-LN：まず整えてから処理する

各部品に入る前に LayerNorm をかけています（self.attn(self.ln1(x))）。これを Pre-LN（前置き正規化）と言います。2017年の元祖Transformerは「処理した後に」正規化していましたが、GPT-2以降は、学習が安定するPre-LNが主流です。残差ストリーム x 自体は正規化せず、各作業員が仕事をする前に、手元のコピーだけを整えるイメージです。

基礎の補足残差接続の「勾配の高速道路」と Pre-Norm vs Post-Norm

① なぜ x + sublayer(ln(x)) で勾配が消えないのか？ 残差接続の式 y=x+F(x)y = x + F(x)y=x+F(x) を xxx で微分すると、足し算の微分ルールから次の式になります。

∂y∂x=1+∂F(x)∂x\frac{\partial y}{\partial x} = 1 + \frac{\partial F(x)}{\partial x}∂x∂y​=1+∂x∂F(x)​

もし残差接続がない（y=F(x)y = F(x)y=F(x)）と、層を LLL 回さかのぼるたびに微分の掛け算 FL′⋯F1′F_L' \cdots F_1'FL′​⋯F1′​ が起き、各層が 0.50.50.5 なら 20 層で 0.520≈10−60.5^{20} \approx 10^{-6}0.520≈10−6 に消えてしまいます（勾配消失）。一方、残差接続があれば必ず + 1 の直通ルートが残るため、たとえ F′(x)F'(x)F′(x) が小さくても、勾配が減衰せず入口までまっすぐ届きます。

② Pre-Norm と Post-Norm の比較

方式コードの形特徴
Pre-Norm（GPT-2以降の主流）x = x + sublayer(ln(x))幹線道路 x に LayerNorm が挟まらず純粋な足し算を保てる。深い層でも学習が安定（最後に ln_f を1回入れる）
Post-Norm（2017年元祖Transformer）x = ln(x + sublayer(x))毎層、幹線道路 x 自体が正規化を通るため、層を深くすると勾配が不安定になりやすい

部品5：GPT（全体）

最後に、全部をつなげます。

Python（Colabのセルに貼って実行）
class GPT(nn.Module):
    def __init__(self, vocab_size, block_size=128, n_embd=128, n_head=4, n_layer=4, dropout=0.1):
        super().__init__()
        self.block_size = block_size
        self.tok_emb = nn.Embedding(vocab_size, n_embd)
        self.pos_emb = nn.Embedding(block_size, n_embd)
        self.drop = nn.Dropout(dropout)
        self.blocks = nn.Sequential(*[Block(n_embd, n_head, block_size, dropout) for _ in range(n_layer)])
        self.ln_f = nn.LayerNorm(n_embd)
        self.lm_head = nn.Linear(n_embd, vocab_size)
        self.apply(self._init_weights)

    def _init_weights(self, module):
        if isinstance(module, (nn.Linear, nn.Embedding)):
            nn.init.normal_(module.weight, mean=0.0, std=0.02)
        if isinstance(module, nn.Linear) and module.bias is not None:
            nn.init.zeros_(module.bias)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        pos = torch.arange(T, device=idx.device)
        x = self.drop(self.tok_emb(idx) + self.pos_emb(pos))
        x = self.blocks(x)
        logits = self.lm_head(self.ln_f(x))
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.view(B * T, -1), targets.view(B * T))
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):
        for _ in range(max_new_tokens):
            idx_cond = idx[:, -self.block_size:]          # 窓に入る分だけ
            logits, _ = self(idx_cond)
            logits = logits[:, -1, :] / temperature      # 最後の位置の点数
            if top_k is not None:
                v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
                logits[logits < v[:, [-1]]] = -float("inf")
            probs = F.softmax(logits, dim=-1)
            next_id = torch.multinomial(probs, num_samples=1)
            idx = torch.cat([idx, next_id], dim=1)
        return idx

Pythonの道具箱：新しく出てきた書き方

  • nn.Sequential(*[Block(…) for _ in range(n_layer)])：Blockを n_layer 個作ってリストにし、* でばらして Sequential に渡しています。Blockを何層も積み重ねる、の1行版です。
  • self.apply(self._init_weights)：モデルの中のすべての部品に対して _init_weights を実行します。GPT-2と同じく、重みを標準偏差0.02の正規分布で初期化します（第10章の初期化の話）。
  • isinstance(module, nn.Linear)：「module は nn.Linear の仲間（インスタンス）か？」を True / False で答える関数です。(nn.Linear, nn.Embedding) のように並べると「どちらかの仲間か？」になります。部品の種類ごとに、初期化の仕方を変えるために使っています。
  • generate は、第3章で自作した生成ループと同じです。違いは、入力を最後の block_size 文字に切り詰めること（位置の埋め込みは block_size 個しかないので）と、上位 top_k 個以外を候補から外せること（考え方は第16章で詳しく）。v, _ = torch.topk(logits, k) で上位k個の点数 v を大きい順に取り出し、v[:, [-1]]（その一番最後＝k位の点数。[-1] を [ ] で囲むと、形が [B, 1] のまま残ります）より小さい点数を、-inf（softmaxで確率0になる）に置き換えています。

1バッチで丸暗記させるテスト

第10章で紹介した研究者の口ぐせ「まず小さなデータで過学習させてみよ」を実行します。同じ1バッチだけを300回学習させて、丸暗記できるか試します。

    if step % 100 == 0:

ステップ 0：損失 7.656
ステップ 100：損失 0.025
ステップ 200：損失 0.012
ステップ 300：損失 0.009

損失がほぼ0になりました。モデルは、このバッチの文章を完全に丸暗記しました。丸暗記ができる＝モデルと学習ループにバグがない、ことの確認です。もし下がらなかったら、どこかの部品のつなぎ方を間違えています（ModuleList を普通のリストにしてしまった、など）。

基礎の補足なぜ「1バッチ丸暗記テスト」がML研究最強のデバッグ技なのか？

深層学習のコードは、バグがあってもエラーを出さずにそれっぽく動き続けてしまうことがよくあります（サイレントバグ）。数時間GPUを回したあとに「損失が下がらない！ 実は nn.ModuleList ではなく普通のリストだった」と気づくのは最悪のパターンです。

そこで研究者は、本学習の前に必ず次の 1バッチ丸暗記テスト（overfit-one-batch sanity test） を数秒だけ走らせます。

  1. dropout = 0.0 にする（過学習を邪魔するブレーキを外す）
  2. 固定の1バッチ (x, y) だけを何百回も繰り返して学習させる
  3. 損失がほぼ 0（0.01 未満）まで下がるか確認する

もし下がらなければ、順伝播・正解のずらし方・ModuleList 登録・opt.zero_grad()・学習率のどこかに必ずバグがあります。逆にほぼ 0 まで落ちれば「少なくとも学習の配線は100%正常」と安心して本学習へ進めます。

def val_loss(model, T):
    model.eval()

もっと深く本物のGPT-2との違い

この章のGPTと、OpenAIが2019年に公開したGPT-2の構造は、ほとんど同じです。違いは主に次の3つで、第15章で本物のGPT-2の重みを読み込むときに、ここを合わせます。

  • GPT-2は、Q・K・Vを作る3つの全結合層を1つにまとめている（計算が速い）。数学的には同じ
  • GPT-2は、Q・K・Vの全結合層にもバイアスがある
  • GPT-2は、出力層の重みを文字の埋め込みの表と共有している（weight tying。パラメータの節約）

大きさは、GPT-2の一番小さい版で12層・12ヘッド・768次元、約1億2400万パラメータです。

つまずき注意：よくあるつまずき

  • RuntimeError: mat1 and mat2 shapes cannot be multiplied (…x60 and 64x64)：n_embd が n_head で割り切れていません。たとえば n_embd=64, n_head=5 だと、1つのヘッドの大きさが 64 // 5 = 12 になり、5つのヘッドをつなげても 5 × 12 = 60 で、64に戻りません。64と4、128と4、384と6のように、割り切れる組み合わせにしましょう。
  • 損失がまったく下がらない：self.heads を nn.ModuleList ではなく普通のリストにしていませんか？ print(model) で部品の一覧を表示して、ヘッドが入っているか確認しましょう。
  • IndexError: index out of range in self：block_size より長い文字列を model(…) に入れています。generate は自動で切り詰めますが、自分で model(x) を呼ぶときは注意。
