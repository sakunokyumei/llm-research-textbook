Google Colabを開く

LLMを動かすには、たくさんの計算ができるコンピュータが必要です。でも心配いりません。Googleが無料で貸してくれます。それが Google Colaboratory（略して Colab、コラボ）です。

Colabは「ブラウザの中で動くPythonのノート」です。あなたのパソコンにPythonを入れなくても、Googleのコンピュータ上でPythonを実行して、結果だけをブラウザに表示してくれます。

  1. ブラウザで https://colab.research.google.com/ を開きます

LLMを呼び出す

いよいよです。次のセルを実行します。少し長いですが、1行ずつの意味は後で説明します。今は「呪文」だと思って、そのまま貼り付けてください。

import torch
from transformers import pipeline

gpu = torch.cuda.is_available()   # GPUが使えるなら True、使えないなら False

    model="Qwen/Qwen2.5-0.5B-Instruct",        # 使うモデルの名前
    dtype=torch.float16 if gpu else torch.float32,  # 数の細かさ（GPUなら軽い形式）
    device_map="auto",                         # GPUがあればGPUに載せる
)
print("GPUを使う？", gpu)

Pythonの道具箱：リスト と 辞書

[ ... ] は リスト：ものを順番に並べた入れ物です。["りんご", "みかん"] のように書きます。
{ ... } は 辞書：「名前（キー）: 中身（値）」の組を入れる入れ物です。{"role": "user", "content": "こんにちは"} は「役割はuser、内容はこんにちは」という1件のメッセージです。
messages は「辞書が並んだリスト」、つまり会話の記録です。HTMLで例えるなら、<ul> の中に <li> が並んでいて、それぞれの <li> に「誰が」「何を言ったか」が書いてある感じです。

最後の行の result[0]["generated_text"][-1]["content"] は、返ってきた結果の箱を順番に開けていく操作です。

書き方 意味
result[0] 結果のリストの0番目（Pythonは0から数えます）
["generated_text"] その中の「生成された会話」
[-1] 会話の一番最後（-1 は「後ろから1番目」）
["content"] そのメッセージの「内容」

マトリョーシカを外側から1つずつ開けているようなものです。

毎回書くのは面倒なので、関数にする

質問のたびに4行書くのは面倒ですね。プログラマは面倒くさがりです。そして面倒くさがりは、関数を作ります。

Python（Colabのセルに貼って実行）
def ask(question, max_new_tokens=200):
    messages = [{"role": "user", "content": question}]
    result = chat(messages, max_new_tokens=max_new_tokens)
    return result[0]["generated_text"][-1]["content"]

print(ask("朝ごはんにおすすめの食べ物を3つ、理由つきで教えて"))
出力の例（数値や文章は実行ごとに変わってOK）
1. ご飯と味噌汁：エネルギーになる炭水化物と、体を温める味噌汁で一日を元気に始められます。
2. ヨーグルトとフルーツ：腸内環境を整え、ビタミンも取れます。
3. 卵料理：たんぱく質が豊富で、お腹が空きにくくなります。

Pythonの道具箱：関数 def

def ask(question, ...): は「ask という名前の手順を作ります」という宣言です。字下げ（行頭のスペース4つ）された部分が手順の中身で、return は「この値を結果として返す」です。
フローチャートで言えば、よく使う処理をひとまとまりの「定義済み処理」の箱にしたものです。一度作れば、ask("…") の1行で何度でも呼び出せます。
max_new_tokens=200 は「指定しなければ200を使う」という初期値です。

print(123 * 456)
出力

LLMの正体：次の言葉を当てるゲームの達人

計算を間違えることがあるのはなぜでしょう？ ここで、この教科書でいちばん大事な話をします。

理論の小部屋：LLMがやっていることは、たった1つ

LLMがやっているのは、「ここまでの文章の続きとして、次に来そうな言葉はどれか」を予測することだけです。

「吾輩は猫で」と来たら、次は「ある」が来そう。「今日の天気は」と来たら「晴れ」や「雨」が来そう。LLMはこの「次の言葉当てゲーム」を、インターネット上の膨大な文章で練習して、ものすごく上手になったプログラムです。

1つ予測したら、その言葉を文章の最後に付け足して、また次を予測する。これを何百回も繰り返すと、長い文章ができあがります。

「吾輩は」→ 予測「猫」→「吾輩は猫」→ 予測「で」→「吾輩は猫で」→ 予測「ある」→ …

だから「123×456=」の次に来る数字も、計算しているのではなく「それっぽい数字」を予測しているのです。大きなLLMは練習量が多いので、それっぽさが正解とほぼ一致するようになりますが、小さなモデルはよく外します。人間が暗算せずに「だいたい5万くらい？」と言うのに似ていますね。

本当に「続きを書いているだけ」なのか、確かめてみましょう。会話の形（messages）ではなく、ただの文字列を渡すと、LLMは素直に「続き」を書きます。

Python（Colabのセルに貼って実行）
out = chat("吾輩は猫である。名前は", max_new_tokens=30, do_sample=False)
print(out[0]["generated_text"])
出力の例（数値や文章は実行ごとに変わってOK）
吾輩は猫である。名前はまだ無い。どこで生れたかとんと見当がつかぬ。何でも薄暗いじめじめした所で

do_sample=False は「サイコロを振らずに、いちばん確率の高い言葉を毎回選ぶ」という指定です。夏目漱石の『吾輩は猫である』の書き出しを覚えていたようです。ネット上で何度も引用されている文章なので、「次の言葉当てゲーム」の練習で何度も見たのでしょう。

ミナト

いい質問だ！ 実はチャットも「続きを書いている」だけなんだ。会話を「台本」の形の文章に変換して、「アシスタントのセリフ」の続きを書かせている。見てみよう。

Python（Colabのセルに貼って実行）
messages = [
    {"role": "system", "content": "あなたは陽気な物理の先生です。"},

あなたは陽気な物理の先生です。<|im_end|>
<|im_start|>user
空はなぜ青いの？<|im_end|>
<|im_start|>assistant

これが、LLMが実際に受け取っている文章です。<|im_start|> や <|im_end|> は「ここからセリフ」「ここでセリフ終わり」を表す特別な記号です。最後が <|im_start|>assistant（アシスタントのセリフ開始）で終わっているので、LLMはその続き、つまりアシスタントのセリフを書きます。そして <|im_end|> を書いたところで止まります。

理論の小部屋：チャット＝台本の続き

チャットモデルは、この台本形式の文章で「アシスタントのセリフ」を上手に書けるように、追加で訓練されたモデルです（名前の Instruct はその意味）。どう訓練するかは第18章で、実際に自分でやります。

台本の一番上の system は、劇でいう「役の設定」です。ここを変えると、LLMの話し方が変わります。

キャラクターを演じさせる

Python（Colabのセルに貼って実行）
def ask_as(character, question, max_new_tokens=200):
    messages = [
        {"role": "system", "content": character},
        {"role": "user", "content": question},
    ]
    result = chat(messages, max_new_tokens=max_new_tokens)
    return result[0]["generated_text"][-1]["content"]

bongo = "あなたはボンゴ先生です。陽気な物理の先生で、答えに必ずダジャレを1つ入れます。"
print(ask_as(bongo, "空はなぜ青いの？"))
出力の例（数値や文章は実行ごとに変わってOK）
いい質問だね！空が青いのは、太陽の光が空気の粒にぶつかって散らばるからなんだ。青い光は波が短くて散らばりやすいから、空いっぱいに青が広がるんだよ。これを「レイリー散乱」と言うんだ。散乱だけに、さんざん考えた答えだよ！

やってみよう：systemを書き換えよう

bongo の中身を変えて、いろいろなキャラクターにしてみましょう。

  • 「あなたは江戸時代の侍です。古風な言葉で答えます。」
  • 「あなたは5歳の子どもにも分かるように説明する先生です。」
  • 「あなたは何を聞かれても『それはLLMの得意分野です』と答えます。」

小さなモデル（0.5B）なので、キャラクターを忘れたり、ダジャレが微妙だったりします。それも味です。第18〜19章では、この「ボンゴ先生らしさ」をモデルに学習させて、systemに書かなくてもボンゴ先生になるようにします。

「大規模」ってどれくらい？

LLMの「L」はLarge（大規模）。何が大規模なのでしょう？ 数えてみましょう。

Python（Colabのセルに貼って実行）
n = sum(p.numel() for p in chat.model.parameters())
print(f"パラメータの数：{n:,} 個")
出力の例（数値や文章は実行ごとに変わってOK）
パラメータの数：494,032,768 個

理論の小部屋：パラメータ＝調整できるつまみ

パラメータは、モデルの中にある「調整できる数」です。音楽のミキサーにたくさん並んでいるつまみを想像してください。LLMの学習とは、このつまみを少しずつ回して、「次の言葉当てゲーム」の成績が良くなる位置を探す作業です。

このモデルには約4億9400万個（0.49 Billion ≒ 0.5B）のつまみがあります。名前の 0.5B はこれのこと。Bは Billion（10億）の頭文字です。ChatGPTのような最先端のモデルは、これの数百倍〜数千倍のつまみを持つと言われています。

そして、つまみの位置を決めるために読ませる文章の量も大規模です。最近のモデルは、数兆個の言葉（トークン）で練習しています。人間が一生かかっても読めない量です。

Pythonの道具箱：一行で数えるテクニック

sum(p.numel() for p in chat.model.parameters()) は、「モデルの部品（parameters()）を1つずつ取り出して、それぞれに入っている数の個数（numel()）を数え、全部足す（sum）」という意味です。今は「そういう書き方がある」と分かれば十分。
f"…{n:,}…" は f文字列です。{ } の中に変数を書くと値に置き換わり、:, を付けると3桁ごとにカンマが入ります。

基本情報とつながる：「B」と「iB」

0.5B のBは10億（10910^9109）ですが、メモリの「15360MiB」のMiBはメビバイト（2202^{20}220 バイト ≒ 105万バイト）です。基本情報で習う「K・M・G」と「Ki・Mi・Gi」の違いが、こんなところで出てきます。モデルの重さは「パラメータ数 × 1個あたりのバイト数」で、float16 なら1個2バイトなので、約4.9億 × 2 ≒ 約1GBになります。さっきダウンロードした 988M のファイルの大きさと、だいたい合っていますね！
