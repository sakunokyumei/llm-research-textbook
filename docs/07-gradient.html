この章でつくるもの

「機械学習」の学習とは何をしているのか。その答えを、この章で手に入れます。キーワードは「坂を下る」。たった1つの数をデータに合わせる小さな問題から始めて、最後はPyTorchが自動で「下る方向」を計算してくれる仕組み（自動微分）まで進みます。これが、第8章以降のすべてのモデルの学習エンジンです。

これまでの復習とつながり：第3章・第5章・第6章とのつながり

  • 第5章（損失）：モデルの良し悪しを1つの数で表す成績表「損失（小さいほど良い）」を学びました。この章では、その損失を自動で小さくしていく方法を作ります。
  • 第6章（テンソルとベクトル）：たくさんの数をひとまとめに扱うテンソルとベクトルを学びました。パラメータが複数になったときの傾き「勾配」は、まさにベクトルで表されます。
  • 第3章（with torch.no_grad():）：文章生成のときに「おまじない」として使った no_grad() の本当の理由が、この章の後半でついに明かされます！

ボンゴ焼き問題

ボンゴ先生は、週末にたこ焼きならぬ「ボンゴ焼き」の屋台を出しています。焼いた時間と、売れた個数の記録がこちら。

Python（Colabのセルに貼って実行）
hours = [1, 2, 3, 4, 5]          # 焼いた時間
sold = [2.9, 6.2, 8.8, 12.1, 15.0]  # 売れた個数（10個単位）

だいたい「時間 × 3」くらいでしょうか。これを モデル にしてみます。

予想=w×時間\text{予想} = w \times \text{時間}予想=w×時間

www は「1時間あたり何個売れるか」を表す数で、これが パラメータ です。www をいくつにすれば、記録にいちばん合うでしょう？

まず「合っている度合い」を測るものさしを作ります。予想と実際の差を2乗して平均したものを 損失 にします。

Python（Colabのセルに貼って実行）
def predict(w, x):
    return w * x

def loss_fn(w):
    total = 0.0
    for x, y in zip(hours, sold):
        total += (predict(w, x) - y) ** 2
    return total / len(hours)

for w in [1, 2, 3, 4]:
    print(f"w = {w} のとき、損失 = {loss_fn(w):.3f}")

Pythonの道具箱：** は2乗、-= は「引いて代入」

(予想 - 実際) ** 2 の ** はべき乗で、a ** 2 は a2a^2a2（a×aa \times aa×a）です。第3章の model(**inputs) の **（辞書の中身を渡す書き方）とは、記号が同じだけで別物です。** の前に値があれば2乗、( のすぐ後にあれば辞書の受け渡し、と見分けます。
第3章の total += p（足して代入）と同じ仲間に、w -= a（w = w - a、引いて代入）があります。この章の学習ループで使います。

理論の小部屋：二乗誤差

「予想 − 実際」は、外れた方向によってプラスにもマイナスにもなります。そのまま平均すると打ち消し合ってしまうので、2乗してから平均します。これを 平均二乗誤差（mean squared error、MSE）と呼びます。2乗するので、大きく外れたほど厳しく罰せられます。

第5章の言語モデルの損失（驚きの平均）とは式が違いますが、「小さいほど良い、モデルの成績表」という役割は同じです。

目隠しで山を下りる

ボンゴ先生

キミは濃い霧の山の中にいる。目隠しをされていて、遠くは見えない。分かるのは足元の傾きだけ。どうやって谷底まで下りる？

ミナト

ボンゴ先生

正解！ それが 勾配降下法（こうばいこうかほう）だ。人類の機械学習の大部分は、この「足元の傾きを見て一歩下る」でできている。拍子抜けするほど単純だろう？

足元の傾きを測ってみましょう。www をほんの少し（h=0.0001h = 0.0001h=0.0001）だけ動かして、損失がどれだけ変わるかを見ます。

Python（Colabのセルに貼って実行）
def slope(w, h=0.0001):
    return (loss_fn(w + h) - loss_fn(w)) / h

for w in [1, 2, 3, 4]:
    print(f"w = {w} での傾き：{slope(w):8.3f}")
出力
w = 1 での傾き： -44.039
w = 2 での傾き： -22.039
w = 3 での傾き：  -0.039

数学の道具箱：微分 dLdw\frac{dL}{dw}dwdL​：9ステップで理由から理解する

① 解決したい問題：グラフ全体を見ずに、「いまのパラメータ www をほんの少し右に動かしたら、損失 LLL が増えるか減るか（どれくらい急な坂か）」を1つの数で知りたい。

② そのままでは困る理由：損失 L(w)L(w)L(w) の値だけ見ても（たとえば「いま損失は 11.06」）、右に行けば下がるのか左に行けば下がるのか分かりません。

③ 新しい発想：www をごく小さな幅 hhh だけ右へ動かしたときの 「縦の変化 ÷ 横の変化」（＝坂の傾き）を測る。

L(w+h)−L(w)h\frac{L(w + h) - L(w)}{h}hL(w+h)−L(w)​

hhh を限りなく 000 に近づけた正確な傾きを 微分（derivative）と言い、dLdw\dfrac{dL}{dw}dwdL​ と書きます。

④ 記号の読み方テーブル：

記号 読み方 意味
ddd ディー（differential） 「ほんの少しの変化」を表す印（掛け算の文字ではないので約分不可！）
dLdw\dfrac{dL}{dw}dwdL​ エルをダブリューで微分したもの www をほんの少し増やしたときの「LLL の変化 ÷ www の変化」（坂の傾き）
hhh エイチ 数値微分で使う微小なずらし幅（例：0.0001）

⑤ 小さな数字で手計算：シンプルな谷 L(w)=(w−3)2L(w) = (w - 3)^2L(w)=(w−3)2（谷底は w=3w = 3w=3）で、h=0.1h = 0.1h=0.1 として傾きを測ってみます。

  • w=1w = 1w=1：L(1)=(−2)2=4L(1) = (-2)^2 = 4L(1)=(−2)2=4、L(1.1)=(−1.9)2=3.61L(1.1) = (-1.9)^2 = 3.61L(1.1)=(−1.9)2=3.61 → 傾き =(3.61−4)/0.1=−3.9= (3.61 - 4) / 0.1 = -3.9=(3.61−4)/0.1=−3.9（マイナス＝右へ行くと下る）
  • w=4w = 4w=4：L(4)=12=1L(4) = 1^2 = 1L(4)=12=1、L(4.1)=1.12=1.21L(4.1) = 1.1^2 = 1.21L(4.1)=1.12=1.21 → 傾き =(1.21−1)/0.1=+2.1= (1.21 - 1) / 0.1 = +2.1=(1.21−1)/0.1=+2.1（プラス＝右へ行くと上る → 左へ下る）
  • w=3w = 3w=3：L(3)=0L(3) = 0L(3)=0、L(3.1)=0.01L(3.1) = 0.01L(3.1)=0.01 → 傾き =0.1≈0= 0.1 \approx 0=0.1≈0（ほぼ 0 ＝谷底）

⑥ 符号のまとめ（超重要）：

  • dLdw<0\dfrac{dL}{dw} < 0dwdL​<0（マイナス）→ 右（www を大きくする方向）が下り坂
  • dLdw>0\dfrac{dL}{dw} > 0dwdL​>0（プラス）→ 左（www を小さくする方向）が下り坂
  • dLdw=0\dfrac{dL}{dw} = 0dwdL​=0 → 平ら（谷底に到達）

つまり、傾きと逆の方向に進めば必ず下れるのです。上のコードのように微小な hhh で実際に測る方法を 数値微分 と言います。

勾配降下法

一歩の大きさを 学習率（learning rate）と呼び、数式ではギリシャ文字の η\etaη（イータ）、コードでは lr と書きます。ルールはこれだけ。

w←w−ηdLdw(コード：w = w - lr * slope(w))w \leftarrow w - \eta \frac{dL}{dw} \qquad \left(\text{コード：}\texttt{w = w - lr * slope(w)}\right)w←w−ηdwdL​(コード：w = w - lr * slope(w))

数学の道具箱：勾配降下法：なぜ「引き算（−-−）」で両方うまくいくのか？

① 解決したい問題：いま測った傾き dLdw\dfrac{dL}{dw}dwdL​ を使って、パラメータ www を谷底の方向へ1歩だけ動かしたい。

② 記号の読み方：

  • ←\leftarrow←（左向き矢印）：「右辺の計算結果で左辺の変数を更新（上書き）する」という意味（プログラミングの = と同じ）
  • η\etaη（イータ）：学習率（learning rate、lr）。一歩の歩幅を決める正の数（例：0.01）

③ なぜ足し算ではなく「引き算」なのか？（符号の完全分析）：

いまの場所 傾き dLdw\dfrac{dL}{dw}dwdL​ の符号 −ηdLdw-\eta \dfrac{dL}{dw}−ηdwdL​ の符号 www の動き 結果
谷底の左側（例：w=1w=1w=1） マイナス（例：−4-4−4） マイナス × マイナス ＝ プラス 右（大きい側）へ進む 谷底へ下る！
谷底の右側（例：w=5w=5w=5） プラス（例：+4+4+4） マイナス × プラス ＝ マイナス 左（小さい側）へ進む 谷底へ下る！
ちょうど谷底（w=3w=3w=3） 000 000 動かない 谷底で止まる！

④ 小さな数字で2ステップ手計算：谷 L(w)=(w−3)2L(w) = (w - 3)^2L(w)=(w−3)2（正確な傾きは dLdw=2(w−3)\frac{dL}{dw} = 2(w - 3)dwdL​=2(w−3)）を、w=1.0w = 1.0w=1.0、学習率 η=0.2\eta = 0.2η=0.2 からスタートしてみます。

  • ステップ1：傾き =2(1.0−3)=−4.0= 2(1.0 - 3) = -4.0=2(1.0−3)=−4.0 → w←1.0−0.2×(−4.0)=1.0+0.8=1.8w \leftarrow 1.0 - 0.2 \times (-4.0) = 1.0 + 0.8 = 1.8w←1.0−0.2×(−4.0)=1.0+0.8=1.8（損失は 4.0→1.444.0 \to 1.444.0→1.44 に激減！）
  • ステップ2：傾き =2(1.8−3)=−2.4= 2(1.8 - 3) = -2.4=2(1.8−3)=−2.4 → w←1.8−0.2×(−2.4)=1.8+0.48=2.28w \leftarrow 1.8 - 0.2 \times (-2.4) = 1.8 + 0.48 = 2.28w←1.8−0.2×(−2.4)=1.8+0.48=2.28（損失は 1.44→0.5181.44 \to 0.5181.44→0.518 にさらに減少！）

坂が急なうちは大きく（+0.8）、谷底に近づくと傾きが緩やかになって自然に小さく（+0.48）進んでいるのがわかります。

Python（読むだけ・実行しなくてOK）
# 上の手計算2ステップを最小Pythonで確認
w, lr = 1.0, 0.2
for step in range(2):
    grad = 2 * (w - 3)          # L(w) = (w - 3)^2 の正確な傾き
    w = w - lr * grad           # 傾きと逆向きに一歩進む
    print(f"step {step + 1}: w = {w:.2f}, loss = {(w - 3)**2:.3f}")
# step 1: w = 1.80, loss = 1.440
# step 2: w = 2.28, loss = 0.518

やってみよう：学習率を変えてみよう

上のデモで、学習率をいろいろ変えてみましょう。

  • 小さすぎる（0.05など）：確実だけど、なかなか谷底に着かない。カタツムリ
  • ちょうどいい（0.3など）：すいすい下る
  • 大きすぎる（2近く）：谷を飛び越えて、反対側の斜面に着地。行ったり来たりして、最悪どこかへ飛んでいく

ただし、「ちょうどいい学習率」は坂の急さで変わります。デモの坂はゆるやかなので0.3でちょうどよく、ボンゴ焼きの坂はずっと急なので、0.01〜0.05くらいがちょうどいい値です。ボンゴ焼きのコードで lr = 0.1 にして試してみてください。デモでは小さめの0.1でも、ボンゴ焼きでは損失が爆発するのが見られます。学習率は、機械学習でいちばん大事なハイパーパラメータです。モデルやデータが変わったら、また探し直す必要があります。

もう1つ、デモで「別の場所から」を何回か押してみてください。デモの坂には、本当の谷底のほかに、途中に小さなくぼみがあります。スタート地点によっては、そこで止まってしまいます。勾配降下法は「今いる場所の傾き」しか見ないので、もっと深い谷が別の場所にあっても気づけないのです（局所最適解と言います）。目隠しで山を下りるのですから、仕方ありません。ただ、パラメータが何億個もある実際のLLMでは、こうした浅いくぼみに完全にはまって動けなくなることは、意外と少ないと考えられています。

パラメータが2つになったら：勾配

実際には、時間がゼロでも少しは売れる（常連さんがいる）かもしれません。モデルを少し賢くします。

予想=w×時間+b\text{予想} = w \times \text{時間} + b予想=w×時間+b

パラメータが www と bbb の2つになりました。今度は2次元の地形（山と谷）を下ることになります。傾きも「www 方向の傾き」と「bbb 方向の傾き」の2つを測ります。

Python（Colabのセルに貼って実行）
def loss2(w, b):
    return sum((w * x + b - y) ** 2 for x, y in zip(hours, sold)) / len(hours)

def slopes(w, b, h=0.0001):
    dw = (loss2(w + h, b) - loss2(w, b)) / h   # w だけ少し動かす
    db = (loss2(w, b + h) - loss2(w, b)) / h   # b だけ少し動かす
    return dw, db

w, b = 0.0, 0.0
for step in range(2000):
    dw, db = slopes(w, b)
    w, b = w - 0.02 * dw, b - 0.02 * db
print(f"w = {w:.3f}, b = {b:.3f}, 損失 = {loss2(w, b):.4f}")
出力
w = 3.010, b = -0.029, 損失 = 0.0198

数学の道具箱：偏微分 ∂L∂w\frac{\partial L}{\partial w}∂w∂L​ と勾配 ∇L\nabla L∇L：多変数でもやり方は同じ

① 解決したい問題：パラメータが2個（www と bbb）、さらには5億個になったとき、それぞれのつまみをどちらへどれだけ動かせばよいかを表したい。

② 新しい発想：「他のパラメータは全部ピタッと止めたまま、1つだけほんの少し動かしたときの傾き」を測る。これを 偏微分（へんびぶん、partial derivative）と言い、丸っこい ∂\partial∂ を使って書きます。そして全パラメータの偏微分を1つのベクトルに並べたものが 勾配（gradient）です。

∇L=(∂L∂w,∂L∂b),w←w−η∂L∂w,b←b−η∂L∂b\nabla L = \left( \frac{\partial L}{\partial w}, \frac{\partial L}{\partial b} \right), \qquad w \leftarrow w - \eta \frac{\partial L}{\partial w}, \quad b \leftarrow b - \eta \frac{\partial L}{\partial b}∇L=(∂w∂L​,∂b∂L​),w←w−η∂w∂L​,b←b−η∂b∂L​

③ 記号の読み方テーブル：

④ 小さな数字で手計算：データ1点（x=2,y=7x=2, y=7x=2,y=7）の損失 L(w,b)=(2w+b−7)2L(w, b) = (2w + b - 7)^2L(w,b)=(2w+b−7)2 を (w,b)=(2,1)(w, b) = (2, 1)(w,b)=(2,1) で偏微分してみます（このとき 2w+b−7=4+1−7=−22w + b - 7 = 4 + 1 - 7 = -22w+b−7=4+1−7=−2）。

  • www で偏微分（b=1b=1b=1 を定数扱い → L=(2w−6)2L = (2w - 6)^2L=(2w−6)2）：∂L∂w=2(2w−6)⋅2=4(−2)=−8\dfrac{\partial L}{\partial w} = 2(2w - 6) \cdot 2 = 4(-2) = -8∂w∂L​=2(2w−6)⋅2=4(−2)=−8
  • bbb で偏微分（w=2w=2w=2 を定数扱い → L=(b−3)2L = (b - 3)^2L=(b−3)2）：∂L∂b=2(b−3)⋅1=2(−2)=−4\dfrac{\partial L}{\partial b} = 2(b - 3) \cdot 1 = 2(-2) = -4∂b∂L​=2(b−3)⋅1=2(−2)=−4
  • よって勾配ベクトルは ∇L=(−8,−4)\nabla L = (-8, -4)∇L=(−8,−4)。学習率 η=0.1\eta = 0.1η=0.1 なら (w,b)←(2−0.1(−8),  1−0.1(−4))=(2.8,1.4)(w, b) \leftarrow (2 - 0.1(-8), \; 1 - 0.1(-4)) = (2.8, 1.4)(w,b)←(2−0.1(−8),1−0.1(−4))=(2.8,1.4) と更新され、2(2.8)+1.4=7.02(2.8) + 1.4 = 7.02(2.8)+1.4=7.0 でなんと1歩で損失 0 に着地します！

パラメータが5億個でも、勾配が5億個の数の並び（ベクトル）になるだけで、やることはまったく同じです。……ただし、数値微分で5億個の偏微分を測るには、モデルを5億回動かす必要があります。それはさすがに無理。そこで次の秘密兵器の出番です。

PyTorchの自動微分

PyTorchは、計算の過程を記録しておいて、正確な勾配を一発で計算してくれます。これを 自動微分（autograd）と言います。

Python（Colabのセルに貼って実行）
import torch

x = torch.tensor(hours, dtype=torch.float32)
y = torch.tensor(sold)

w = torch.tensor(1.0, requires_grad=True)   # 「この数の勾配を知りたい」と宣言
loss = ((w * x - y) ** 2).mean()
loss.backward()                              # 勾配を計算！
print("損失：", loss.item())
print("自動微分の傾き：", w.grad.item())
print("数値微分の傾き：", slope(1.0))
出力
損失： 44.099998474121094
自動微分の傾き： -44.040000915527344
数値微分の傾き： -44.03890000006072

loss.backward() を呼ぶだけで、w.grad に傾き dLdw\dfrac{dL}{dw}dwdL​ が入りました。数値微分とほぼ同じ値ですが、小数点以下3桁目からずれています。数値微分は「少し右に動かした」ときの傾きなので誤差があり、自動微分のほうが正確な値です。

では、自動微分で学習ループを書き直しましょう。これが、この先何度も書くことになる 学習ループの基本形 です。

Python（Colabのセルに貼って実行）
w = torch.tensor(0.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
lr = 0.02

for step in range(2000):
    loss = ((w * x + b - y) ** 2).mean()   # ① 予想して、損失を計算
    loss.backward()                         # ② 勾配を計算
    with torch.no_grad():                   # ③ パラメータを更新（ここは記録しない）
        w -= lr * w.grad
        b -= lr * b.grad
    w.grad.zero_()                          # ④ 勾配を0に戻す
    b.grad.zero_()

print(f"w = {w.item():.3f}, b = {b.item():.3f}, 損失 = {loss.item():.4f}")
出力
w = 3.010, b = -0.030, 損失 = 0.0198

つまずき注意：④を忘れると大変

PyTorchの .grad は、backward() を呼ぶたびに 足し算されていく（累積する）仕様です。④の zero_() を忘れると、前のステップの勾配がどんどん雪だるま式に積み上がり、学習がめちゃくちゃになります。エラーメッセージが出ずに結果だけがおかしくなるので、気づきにくいバグの代表格です。学習の様子がおかしいときは、まずここを疑いましょう。

なぜ自動で0にリセットしてくれないのかというと、GPUメモリが足りないときに何回かに分けて勾配を足し合わせる技（第16章の「勾配累積」）などで、この累積仕様が役に立つからです。便利な機能の裏返しとして、普段は毎回手動でリセット（ゼロクリア）してあげる必要があります。

理論の小部屋：第3章の no_grad の謎が解ける

③で with torch.no_grad(): を使っているのは、「パラメータの更新」は学習のための計算ではないので、記録の外でやる必要があるからです。記録したまま w -= lr * w.grad を実行すると、PyTorchは「記録中のパラメータを直接書き換えようとしている」と判断して、RuntimeError: a leaf Variable that requires grad is being used in an in-place operation. というエラーで止めます。

そして第3章では、文章を生成するだけ（学習しない）だったので、no_grad で記録を止めて、メモリと時間を節約していたのでした。あのおまじないの意味が、ようやく分かりましたね。

基礎の補足PyTorch 学習ループ4ステップの解剖（なぜ zero_() と no_grad() が必須なのか）
ステップ コード 役割 忘れるとどうなる？
① 順伝播＋損失 loss = ... 予想と損失を計算しつつ、計算グラフを記録 no_grad() の中に入れると backward() でエラー
② 逆伝播 loss.backward() 計算グラフを逆向きにたどり .grad を算出 .grad が None のままで更新できない
③ 更新 with torch.no_grad(): w -= lr * w.grad 記録を切って、勾配の逆向きへ一歩下る no_grad() を忘れると RuntimeError（leaf in-place error）
④ 勾配リセット w.grad.zero_() 次のステップに古い勾配が足されないよう0に戻す エラーは出ないが勾配が雪だるま式に足され学習が崩壊！
Python（読むだけ・実行しなくてOK）
# なぜ zero_() を忘れると危険なのか？（最小の再現例）
t = torch.tensor(2.0, requires_grad=True)
(3 * t).backward()          # 1回目：3t の微分は 3.0
print(t.grad.item())        # → 3.0
(3 * t).backward()          # zero_() せずに2回目！
print(t.grad.item())        # → 6.0（上書きではなく 3.0 + 3.0 に足し算されてしまう！）

あわせて、自動微分の記録を止める・切り離す3つの道具の使い分けも押さえておきましょう（第11章以降で頻出します）。

自動微分の中身：連鎖律

自動微分はどうやって勾配を計算しているのでしょう？ 鍵は 連鎖律（れんさりつ、chain rule）です。

数学の道具箱：連鎖律 dydx=dydududx\frac{dy}{dx} = \frac{dy}{du} \frac{du}{dx}dxdy​=dudy​dxdu​ と計算グラフの手計算トレース

① 解決したい問題：何段も計算を重ねた式（ニューラルネットワークは何十段もの計算の合成！）について、一番最後の出力（損失）を一番最初の入力やパラメータで微分したい。

② 新しい発想：計算を途中の変数 uuu に分解し、各ステップの局所的な傾きを掛け算でつなぐ（伝言ゲームの倍率の掛け算）。

u=3x+1,y=u2⟹dydx=dydu×dudx=2u×3u = 3x + 1, \qquad y = u^2 \qquad \Longrightarrow \qquad \frac{dy}{dx} = \frac{dy}{du} \times \frac{du}{dx} = 2u \times 3u=3x+1,y=u2⟹dxdy​=dudy​×dxdu​=2u×3

③ 具体的な数字で「順伝播 → 逆伝播」を手計算トレース（x=2x = 2x=2 のとき）：

  1. 順伝播（左から右へ値を計算し、途中結果 uuu をメモする）：
    • 入力：x=2x = 2x=2
    • 中間：u=3×2+1=7u = 3 \times 2 + 1 = 7u=3×2+1=7（← この u=7u = 7u=7 を覚えておく！）
    • 出力：y=72=49y = 7^2 = 49y=72=49
  2. 逆伝播（右から左へ、傾きを掛け算しながら戻す）：
    • ゴール自身：dydy=1\dfrac{dy}{dy} = 1dydy​=1（yyy が1動けば yyy は1動く）
    • 2乗を逆走：dydu=1×2u=1×(2×7)=14\dfrac{dy}{du} = 1 \times 2u = 1 \times (2 \times 7) = 14dudy​=1×2u=1×(2×7)=14（メモしておいた u=7u = 7u=7 を使う！）
    • 3x+13x + 13x+1 を逆走：dydx=dydu×dudx=14×3=42\dfrac{dy}{dx} = \dfrac{dy}{du} \times \dfrac{du}{dx} = 14 \times 3 = 42dxdy​=dudy​×dxdu​=14×3=42
Python（読むだけ・実行しなくてOK）
# 順伝播＋手動逆伝播（PyTorch の autograd が裏でやっていることそのもの）
x = 2.0
u = 3 * x + 1           # 順伝播①：u = 7.0 をメモ
y = u ** 2              # 順伝播②：y = 49.0
dy_dy = 1.0             # 逆伝播の出発点
dy_du = dy_dy * (2 * u) # 1.0 * 14.0 = 14.0
dy_dx = dy_du * 3.0     # 14.0 * 3.0 = 42.0
print(f"y={y}, dy/du={dy_du}, dy/dx={dy_dx}")

途中の傾きを掛け算でつないでいく。これが連鎖律です。伝言ゲームで、各人が「受け取った話を3倍に盛って伝える」「14倍に盛って伝える」をすると、最後は 3×14=423 \times 14 = 423×14=42 倍に盛られて届くのと同じです。

Python（Colabのセルに貼って実行）
x2 = torch.tensor(2.0, requires_grad=True)   # 上のデータの x と区別するため、x2 という名前に
u = 3 * x2 + 1
y2 = u ** 2
y2.backward()
print("自動微分：", x2.grad.item())
print("連鎖律で手計算：", 2 * u.item() * 3)
出力
自動微分： 42.0
連鎖律で手計算： 42.0

理論の小部屋：誤差逆伝播法（バックプロパゲーション）

PyTorchは、計算するたびに「何と何から、どんな計算で作られたか」を記録しています（計算グラフ）。backward() を呼ぶと、損失から出発して計算を逆向きにたどりながら、連鎖律で傾きを掛け算していきます。

順伝播：x (=2) →(×3+1)→ u (=7) →(2乗)→ y (=49)
逆伝播：dy/dx (=42) ←(×3)← dy/du (=14) ←(×2u)← dy/dy (=1)

5億個のパラメータがあっても、この逆向きの伝言ゲームを1回やるだけで、全部の勾配がまとめて求まります。この方法を 誤差逆伝播法（ごさぎゃくでんぱほう、backpropagation）と言います。ニューラルネットワークの学習を現実的なものにした、最重要の発明です。
