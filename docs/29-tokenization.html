言語モデルを作る

29 文章をトークンへ変える

到達目標：文字・byte・BPEを区別し、データから語彙を学ぶ

前提：10 文字列・データ構造・ファイル・13 計算量・検索・SQLの入口・23 情報量・損失・Perplexity 演習 5 問

読む目安 7〜12分／演習 15〜30分。実装・到達課題は別の回に分けられます

時間は編集上の目安です。見出し一つで休憩しても大丈夫。中断・再開と補習の手引きも使ってください。

コンピュータは文章をそのまま計算できない

「猫が寝る」を数の並びへ変える必要があります。まず「猫」「が」「寝」「る」を一文字ずつIDへ対応させるなら、[0,1,2,3]のように表せます。この計算単位をトークンと呼びます。トークンは文字や単語と同じとは限りません。

文字単位は分かりやすい一方、未知の文字の扱いが必要です。byte単位ならUTF-8へ変換した0〜255の値を使えますが、日本語の一文字が複数byteになることがあり、列が長くなります。単語単位は未知語が増えやすい。そこで、よく現れる部分をまとめるsubword方式が使われます。

BPEを手で追う

Byte Pair Encodingは、隣り合う組のうち頻度の高いものを結合する処理を繰り返します。玩具の語彙を「a b a b」と「a b a c」の二つの列とします。隣接ペアabは合計3回、baは2回、acは1回。abを新しい記号Xへまとめると「X X」「X a c」になります。

結合の順序を保存し、新しい文章にも同じ順に適用します。単に「見つかった長い単語をいつもまとめる」アルゴリズムではありません。実用のBPEではbyte表現、事前分割、特殊トークン、同数の頻度の扱いなども定めます。trainだけから結合を学び、testで語彙を調整しません。

EmbeddingはIDを数の並びへ引く

語彙数V、特徴数dなら、Embeddingは(V,d)の学習可能な表です。トークンIDがiならi行目を取り出します。ID自体の数の大小に意味を与えるのではなく、取り出したベクトルを学習します。ID100がID50の「二倍の意味」というわけではありません。

import torch
from torch import nn
torch.manual_seed(42)
table = nn.Embedding(5, 3)
ids = torch.tensor([[0, 2, 4]], dtype=torch.long)
print(table(ids).shape)

出力は(1,3,3)で、バッチ1、トークン3、特徴3です。特殊トークンとして文書の終わりを示すEOSや長さ合わせのPADを設ける場合、それぞれの意味と損失から除外する位置を決めます。

Embeddingの三つの操作

nn.Embedding(5,3) は5行3列の表を用意します。dtype=torch.long はIDを整数型で持つ指定です。table(ids) は指定した行を取り出す操作。ID列の形(1,3)の後ろへ一行の幅3が加わり、(1,3,3)になります。encodeは文をID列へ変えること、decodeはID列から文へ戻すことです。トークナイザーはこの変換を行う道具。Unicodeは文字に番号を対応づける仕組みで、UTF-8はその文字をbyteへ保存する一つの方法です。

分割の違いも研究条件

語彙を増やすと一文のトークン数が減ることがありますが、Embeddingと出力層は大きくなります。日本語・英語・コードで効率が違う場合もあります。圧縮率だけでなく、復元可能性、未知入力、特殊文字、処理時間、下流性能も評価します。

テキストを正規化して表記をそろえる際も、意味を変えていないか注意します。大文字小文字を消すとコードでは別の変数を同一視することがあります。変換後の文面だけでなく、変換方針を記録します。

演習

1・文字とbyte

UTF-8のbyte数、Unicode文字数、モデルのトークン数は必ず一致しますか。

解答と考え方を読む

一致しません。一文字が複数byteになる場合があり、トークナイザーが複数文字を一つにまとめたり、文字より細かく分けたりします。

2・BPEの一手

列「a a b」と「a b a b」で最も頻度の高い隣接ペアを数えてください。

解答と考え方を読む

abが合計3回、aaが1回、baが1回です。abを結合するのがこの一手です。列の境界をまたいで数えない条件を使っています。

3・Embeddingの容量

V=1000、d=64のEmbeddingには何個のパラメータがありますか。

解答と考え方を読む

1000×64=64000個です。語彙数か次元を増やすと表が大きくなります。

4・漏洩

testにだけ現れる語へ合わせてBPEの結合を追加しました。何が問題ですか。

解答と考え方を読む

最終評価用データで処理方法を調整しています。独立な評価が損なわれるため、語彙学習・設計選択はtrain/validation側で行います。

5・往復検証

トークナイザーを作ったら、最初にどんな性質を確認しますか。

解答と考え方を読む

意図した入力範囲でdecode(encode(text))が元の文字列に戻るか、空文字・改行・絵文字・未知文字・特殊トークンを扱えるか、同じ設定で結果が決まるかを確認します。正規化で非可逆にする設計ならその範囲を明示します。

到達課題と出典

実装ラボの小さなBPEを使い、日本語と英語の同程度の短文でトークン数を比較してください。玩具実装と実用のtokenizerの違いも列挙します。Sennrich et al., subword units、Stanford CS336 を参照。
