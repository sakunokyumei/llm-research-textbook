自分のコードに本物のGPT-2を入れる

OpenAIが公開した1億2400万個の数を、自作GPTに流し込む

おすすめは「ページを読みながら、コードを自分のノートブックに1セルずつ貼って実行」。完成ノートは困ったときの答え合わせ用です。

つくるもの

GPT-2と同じ形の自作GPTを書き、Hugging FaceからダウンロードしたGPT-2の重みを読み込んで、本物と同じ出力が出ることを確かめる

ついでに身につく理論

  • GPT-2の構造（Q・K・Vをまとめた計算、重み共有、GELUの近似）
  • マルチヘッドを1回の行列計算でまとめてやる方法
  • 事前学習とは何か（データ・計算量）
  • スケーリング則とChinchillaの法則
  • 計算量 ≈6ND\approx 6ND≈6ND と、学習に必要なメモリの見積もり

新しく使うPython

  • nn.ModuleDict
  • state_dict の中身を調べる・コピーする
  • .split と .view と .transpose で形を組み替える
  • torch.allclose で一致を確かめる

この章でつくるもの

この章は、あなたの自作GPTの答え合わせです。2019年にOpenAIが公開したGPT-2（一番小さい版、約1億2400万パラメータ）と同じ形のGPTを、第12章のコードを少し書き換えて作ります。そこにGPT-2の公開された重みを読み込むと……あなたのコードが、本物のGPT-2と小数点以下まで同じ出力を出します。「自分のコードは本物と同じものだ」と、数字で確かめられる瞬間です。

第12章の部品と見比べると、対応がわかります。

GPT-2の名前 第12章の部品 意味
wte tok_emb 文字（トークン）の埋め込み（word token embedding）
wpe pos_emb 位置の埋め込み（word position embedding）
h.0, h.1, … blocks[0], … Transformerブロック
ln_1, ln_2 ln1, ln2 LayerNorm
attn.c_attn 各ヘッドの key, query, value Q・K・Vをまとめた全結合層（768 → 2304 = 768×3）
attn.c_proj proj ヘッドの結果を混ぜる層
mlp.c_fc, mlp.c_proj ffwd.net[0], ffwd.net[2] フィードフォワード（768 → 3072 → 768）

違いは主に3つです。

  1. Q・K・Vを1つの全結合層でまとめて作る（c_attn の出力が2304 = 768×3）。そして、ヘッドを別々のクラスにせず、1回の計算で全ヘッドをまとめて処理する
  2. Q・K・Vにもバイアスがある（第12章は bias=False でした）
  3. 出力層の重みを、トークンの埋め込み wte と共有している（weight tying）。state_dict には lm_head.weight という名前もありますが、中身は wte と同じ表です（パラメータの数を数えるときは、1つとして数えられます）

さらに、GELUは計算の速い「tanhを使った近似版」が使われています。これらを合わせれば、読み込めるはずです。

GPT-2と同じ形のGPTを書く

第12章のGPTを、上の3つの違いに合わせて書き直します。マルチヘッドAttentionは、ヘッドごとにクラスを作る代わりに、形の組み替えで全ヘッドを一度に計算します。

Python（Colabのセルに貼って実行）
class CausalSelfAttention(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        self.n_head = n_head
        self.c_attn = nn.Linear(n_embd, 3 * n_embd)     # Q・K・Vをまとめて作る
        self.c_proj = nn.Linear(n_embd, n_embd)
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)), persistent=False)

    def forward(self, x):
        B, T, C = x.shape
        hs = C // self.n_head                           # 1ヘッドの大きさ
        q, k, v = self.c_attn(x).split(C, dim=2)        # 最後の軸をC個ずつに切る（2304→768・768・768）。文字列のsplitとは別物
        q = q.view(B, T, self.n_head, hs).transpose(1, 2)   # [B, ヘッド, T, hs]
        k = k.view(B, T, self.n_head, hs).transpose(1, 2)
        v = v.view(B, T, self.n_head, hs).transpose(1, 2)
        att = q @ k.transpose(-2, -1) / math.sqrt(hs)   # 全ヘッドの点数を一度に
        att = att.masked_fill(self.tril[:T, :T] == 0, float("-inf"))
        att = F.softmax(att, dim=-1)
        y = att @ v                                     # [B, ヘッド, T, hs]
        y = y.transpose(1, 2).contiguous().view(B, T, C)    # ヘッドを横につなげ直す
        return self.c_proj(y)


class MLP(nn.Module):
    def __init__(self, n_embd):
        super().__init__()
        self.c_fc = nn.Linear(n_embd, 4 * n_embd)
        self.gelu = nn.GELU(approximate="tanh")         # GPT-2のGELU（近似版）
        self.c_proj = nn.Linear(4 * n_embd, n_embd)

    def forward(self, x):
        return self.c_proj(self.gelu(self.c_fc(x)))


class Block(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        self.ln_1 = nn.LayerNorm(n_embd)
        self.attn = CausalSelfAttention(n_embd, n_head, block_size)
        self.ln_2 = nn.LayerNorm(n_embd)
        self.mlp = MLP(n_embd)

    def forward(self, x):
        x = x + self.attn(self.ln_1(x))
        x = x + self.mlp(self.ln_2(x))
        return x


class GPT2(nn.Module):
    def __init__(self, vocab_size, block_size, n_embd, n_head, n_layer):
        super().__init__()
        self.block_size = block_size
        self.transformer = nn.ModuleDict(dict(
            wte=nn.Embedding(vocab_size, n_embd),
            wpe=nn.Embedding(block_size, n_embd),
            h=nn.ModuleList([Block(n_embd, n_head, block_size) for _ in range(n_layer)]),
            ln_f=nn.LayerNorm(n_embd),
        ))
        self.lm_head = nn.Linear(n_embd, vocab_size, bias=False)
        self.lm_head.weight = self.transformer.wte.weight    # 重み共有（weight tying）

    def forward(self, idx):
        B, T = idx.shape
        x = self.transformer.wte(idx) + self.transformer.wpe(torch.arange(T, device=idx.device))
        for block in self.transformer.h:
            x = block(x)
        return self.lm_head(self.transformer.ln_f(x))

理論の小部屋：ヘッドをまとめて計算する形の組み替え

第12章では、4つのヘッドを、Head クラスから作った4つの部品で別々に計算していました。わかりやすいけれど、GPUにとっては「小さな仕事を4回」頼まれるより「大きな仕事を1回」のほうが速いのです。

そこで、Q（形 [B, T, 768]）を view で [B, T, 12, 64]（12ヘッド×64）に切り分け、transpose(1, 2) で [B, 12, T, 64] に並べ替えます。こうすると、テンソルの @ が「バッチごと・ヘッドごと」に行列の掛け算をしてくれるので、12ヘッド分の計算が1回で済みます。最後に逆の操作で [B, T, 768] に戻します（contiguous() は、並べ替えたテンソルをメモリ上できれいに並べ直すおまじない）。

計算の中身は、第11〜12章とまったく同じです。

Pythonの道具箱：nn.ModuleDict と persistent=False

  • nn.ModuleDict(dict(wte=…, wpe=…)) は、部品に名前をつけて入れておく箱です。dict(wte=1) は {"wte": 1} と同じ意味の、辞書の別の書き方です。こうしておくと、部品の名前が transformer.wte.weight のようになり、GPT-2の重みの名前（上で見た一覧）と一字一句同じになります。名前が同じなら、次の節で「同じ名前どうしをコピー」するだけで済みます
  • register_buffer(…, persistent=False) の persistent=False は、「tril（カンニング防止の三角形）は、保存する中身（state_dict）に入れない」という指定です。GPT-2の重みの一覧には tril がないので、これを付け忘れると、コピーのときに KeyError: 'transformer.h.0.attn.tril' になります

理論の小部屋：重み共有（weight tying）

入力側の埋め込み wte（トークン→ベクトル）と、出力層 lm_head（ベクトル→各トークンの点数）は、どちらも「語彙数 × 幅」の大きな表です。GPT-2はこの2つを同じ表にしています。「『猫』のベクトルに近いベクトルが来たら、次は『猫』の点数を高くする」という、入口と出口の対応関係を自然に表せるうえ、パラメータが3860万個（50257×768）も節約できます。

重みを流し込む

同じ設定で自作GPT-2を作り、GPT-2の重みを1つずつコピーします。1つだけ注意点があります。GPT-2の公開コードでは、全結合層の重みを [入力, 出力] の向きで持っていますが、PyTorchの nn.Linear は [出力, 入力] の向きです。だから、該当する重みは 転置（.t()、行と列の入れ替え）してからコピーします。

Python（Colabのセルに貼って実行）
mine = GPT2(cfg.vocab_size, cfg.n_positions, cfg.n_embd, cfg.n_head, cfg.n_layer)
mine.eval()
sd = mine.state_dict()
transposed = ("attn.c_attn.weight", "attn.c_proj.weight", "mlp.c_fc.weight", "mlp.c_proj.weight")

copied = 0
with torch.no_grad():
    for k in sd:
        src = sd_hf[k].t() if k.endswith(transposed) else sd_hf[k]
        assert sd[k].shape == src.shape, (k, sd[k].shape, src.shape)
        sd[k].copy_(src)
        copied += 1
print("コピーした重みの数：", copied)
出力の例（数値や文章は実行ごとに変わってOK）
コピーした重みの数： 149

mine.state_dict() が返す sd の中身は、コピーではなく、モデルのパラメータそのものです。だから sd[k].copy_(src)（src の値で上書き）をすると、mine の中身が書き換わります。

assert は「この条件が正しくなければ、ここで止まって教えて」という命令です。形が1つでも合わなければエラーになるので、黙って間違ったコピーをすることはありません。

GPT-2に文章を書かせる

自作GPT-2で、文章を生成してみましょう。第3章の自作 generate と同じループに、上位k個だけから選ぶ top-k を加えたものです。

Python（Colabのセルに貼って実行）
@torch.no_grad()
def generate(model, text, n=40, temperature=0.8, top_k=50, seed=0):
    torch.manual_seed(seed)
    idx = tok(text, return_tensors="pt").input_ids
    for _ in range(n):
        logits = model(idx[:, -model.block_size:])[:, -1, :] / temperature
        v, _ = torch.topk(logits, top_k)
        logits[logits < v[:, [-1]]] = -float("inf")    # 上位k個以外は候補から外す
        next_id = torch.multinomial(F.softmax(logits, dim=-1), 1)
        idx = torch.cat([idx, next_id], dim=1)
    return tok.decode(idx[0])

print(generate(mine, "Hello, I'm a language model,"))

理論の小部屋：モデルは、読んだものしか書けない

GPT-2は、主に英語のWebページ（約40GBのテキスト）で学習しました。バイトレベルBPEなので日本語の文字を表すことはできても（第2章）、日本語の文章をほとんど読んだことがないので、まともな続きを書けません。

あなたの漱石GPTが漱石風の文章しか書けないのと、まったく同じ理由です。LLMの能力は、どんなデータで、どれだけ学習したかで決まります。モデルの設計図（あなたが書いたコード）は、ほとんど同じなのです。

事前学習：GPT-2はどうやって作られたか

GPT-2の重みは、あなたが第13章でやったのとまったく同じ「次のトークン予測」の学習で作られました。違うのは規模だけです。このように、大量の文章で「次のトークン予測」を学習させることを 事前学習（pre-training）と呼びます。

あなたの漱石GPT GPT-2（small） 最近の大型LLM（目安）
パラメータ 約175万 1.24億 数百億〜数千億以上
学習データ 約100万文字 約40GB（数十億トークン） 数兆〜数十兆トークン
計算機 Colabの無料GPU 1枚・数分 当時の大量のGPU・TPU 数千〜数万枚のGPUで数か月

理論の小部屋：スケーリング則：大きくすると、予想どおりに賢くなる

2020年、OpenAIの研究者たちは、LLMの損失が モデルの大きさ NNN（パラメータ数）、データ量 DDD（トークン数）、計算量 CCC を増やすと、とてもきれいな法則に従って下がることを見つけました。それぞれを10倍にすると、損失が決まった割合ずつ下がっていく（グラフの両軸を対数にすると直線になる、べき乗則）。これを スケーリング則（scaling law）と言います。

この発見の何がすごいかというと、小さな実験から、大きなモデルの性能が予想できることです。「このくらいのお金をかければ、このくらい賢くなる」と計算できるので、巨大なモデルへの投資が始まりました。

2022年には、DeepMindの研究（通称 Chinchilla）が、「決まった計算量で一番賢いモデルを作るには、パラメータ1個あたり約20トークンのデータで学習させるのがよい」ことを示しました。それまでのモデルは、大きさのわりにデータが少なすぎた（読書量の割に頭だけ大きかった）のです。

計算量と、学習に必要なメモリを見積もってみましょう。

Python（Colabのセルに貼って実行）
def train_flops(n_params, n_tokens):
    return 6 * n_params * n_tokens          # 学習の計算量 ≈ 6 × N × D

def train_memory_gb(n_params):
    return n_params * 16 / 1e9              # AdamWで学習するときのメモリの目安（1パラメータ16バイト）

models = {"漱石GPT": (1.75e6, 2e7), "GPT-2 small": (124e6, 9e9),
          "Qwen2.5-0.5B": (0.49e9, 18e12), "70Bのモデル": (70e9, 15e12)}
for name, (N, D) in models.items():
    print(f"{name:12s} 計算量 {train_flops(N, D):9.1e} 回  学習メモリ {train_memory_gb(N):9.2f} GB"
          f"  Chinchilla推奨データ {20 * N:8.1e} トークン")

理論の小部屋：6ND と 16バイト

  • 計算量 ≈ 6ND6ND6ND：1トークンを学習するごとに、パラメータ1個あたり約6回の掛け算・足し算をします（順方向で約2回、逆伝播で約4回）。T4の実効性能を毎秒10兆回（101310^{13}1013）とすると、漱石GPTは数十秒、GPT-2 smallは約1週間、Qwen2.5-0.5Bは約170年（！）。大きなLLMの事前学習が、個人では無理な理由です
  • メモリ ≈ 16バイト × パラメータ数：混合精度でAdamWを使うと、パラメータ1個あたり、重み（2バイト＋4バイトの控え）、勾配（2バイト）、Adamの慣性と歩幅の記録（4バイト×2）で約16バイト必要です。T4のメモリは約15GBなので、全パラメータを学習できるのは数億パラメータくらいまで。それより大きいモデルを無料GPUで鍛えるには、第19章の LoRA という技が必要になります

0円のコツ：事前学習は「借りる」が正解

数十億パラメータ以上のモデルを、個人が0円で事前学習するのは不可能です。でも心配いりません。世界中の企業や研究機関が、事前学習済みのモデルを公開しています（Qwen、Llama、Gemma、日本語特化のモデルなど）。事前学習は借りて、自分の目的に合わせた追加の学習（ファインチューニング）だけを自分でやる。これが、第5部からのやり方です。

つまずき注意：よくあるつまずき

  • AssertionError: ('transformer.h.0.attn.c_attn.weight', …)：形が合っていません。転置が必要な重み（transposed の4種類）の名前が合っているか、n_embd などの設定が cfg と同じか確認しましょう。
  • KeyError: 'transformer.h.0.attn.tril'：register_buffer の persistent=False を付け忘れています。
  • そのほかの KeyError（sd_hf[k] の行）：自作モデルの部品の名前が、GPT-2の名前と違っています。transformer、wte、h、ln_1 などの名前を、上のコードと一字一句同じにしましょう。
  • 一致しない（False）：GELUを approximate="tanh" にしたか、mine.eval() を呼んだか、確認しましょう。
