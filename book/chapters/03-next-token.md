## 準備：モデルを直接読み込む

第1章では便利セットの `pipeline` を使いましたが、今回は中身を取り出すために**トークナイザー**と**モデル本体**を別々に読み込みます。ランタイムは「T4 GPU」にしておきましょう（CPUでも少し待てば動きます）。

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

name = "Qwen/Qwen2.5-0.5B-Instruct"
gpu = torch.cuda.is_available()
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(
    name, dtype=torch.float16 if gpu else torch.float32, device_map="auto"
)
print("読み込み完了。置き場所：", model.device)
```

```output-example
読み込み完了。置き場所： cuda:0
```

- `AutoModelForCausalLM` の `CausalLM` は「左から右へ次のトークンを予測する言語モデル（GPT系）」という意味です。
- `model.device` はモデルが置かれた機器を表す属性で、GPUの0番なら `cuda:0`、CPUなら `cpu` になります（**CUDA**はNVIDIA GPUで計算する仕組み）。

## モデルを直接読み込み、入力と出力の形を見る

まず「吾輩は猫である。名前は」をモデルに渡して、次のトークンに対する「生の点数表」を取り出します。本物のコードを実行する前に、初登場の書き方2つ（`**inputs` とテンソルの形）を**理解のための最小コード**で確認しましょう。

:::scaffold 理解のための最小コード：`model(**inputs)` の `**` と、3次元テンソル `[1, T, V]`
**① 辞書のアンパック `**inputs` とは？**
関数を呼ぶとき `**辞書` と書くと、辞書の中身を「名前つき引数」に展開して渡してくれます。

```python no-run
def greet(name, times):
    return (name + "! ") * times

d = {"name": "猫", "times": 2}
print(greet(**d))   # greet(name="猫", times=2) とまったく同じ！ → 猫! 猫!
```

`tok(text, return_tensors="pt")` は `{"input_ids": テンソル, "attention_mask": テンソル}` という**辞書**を返します。だから `model(**inputs)` は `model(input_ids=..., attention_mask=...)` の短縮表記です（第7章で出てくるべき乗 `a ** 2` とは別の使い方です）。

**② `inputs` と `out.logits` の中身と形（shape）**
「吾輩は猫である。名前は」は6トークン（`T = 6`）だとします。

| 変数 | 型・形（`shape`） | 中身の意味 |
|---|---|---|
| `inputs["input_ids"]` | `Tensor`、形 `[1, 6]` | 1件の文章 × 6個のトークンID（`return_tensors="pt"` でPyTorchテンソルに変換） |
| `out.logits` | `Tensor`、形 `[1, 6, 151936]` | 1件の文章 × 各位置（0〜5） × 全151,936語ぶんの生の点数 |
| `out.logits[0, -1]` | `Tensor`、形 `[151936]` | **0番目の文章の、最後の位置（`-1`）**における全語彙の点数（＝「名前は」の**次**の予測！） |
:::

では実際に動かして確かめましょう。

```python
text = "吾輩は猫である。名前は"
inputs = tok(text, return_tensors="pt").to(model.device)

with torch.no_grad():
    out = model(**inputs)

logits = out.logits[0, -1]
print(logits.shape)
```

```output
torch.Size([151936])
```

- `.to(model.device)`：トークナイザーがCPU上に作った入力テンソルを、モデルと同じ機器（GPUなら `cuda:0`）へ移動します。場所が違うと計算エラーになります。
- `with torch.no_grad():`：学習時に必要な「逆伝播用の途中メモ」を保存しないモードです（第7章で理由を学びます）。推論ではメモ不要なので速く省メモリになります。
- `logits`（**ロジット**）：モデルが出力した各トークンの**生の点数（スコア）**です。プラスにもマイナスにもなり、上限も下限もありません（語彙数は151,665ですが、GPU計算の区切りの良さから枠が151,936取られています）。

点数の高い上位5個を見てみましょう。

```python
top = torch.topk(logits, 5)
for score, i in zip(top.values, top.indices):
    print(f"{tok.decode([int(i)])!r:8} 点数 {score.item():6.2f}")
```

```output-example
'まだ'    点数  21.03
'ない'    点数  16.55
'、'      点数  15.22
'「'      点数  14.98
'無い'    点数  14.42
```

:::scaffold `torch.topk`・`zip`・`.item()`・f文字列書式
- `torch.topk(logits, 5)`：大きい順に5個の点数（`top.values`、形 `[5]`）とそのID（`top.indices`、形 `[5]`）をセットで返します。
- `zip(A, B)`：2つの並びを横に並べて1組ずつ取り出します（1位の点数とID、2位の点数とID…）。
- `score.item()` / `int(i)`：要素1個のPyTorchテンソルを、ふつうのPythonの小数・整数に変換します。

## Σ（シグマ）記号を普通の足し算から理解する

点数が `21.03` や `16.55` のままでは「何%の確率で選ばれるか」が分かりません。点数を確率に変える数式（softmax）を導く前に、式の中に登場する **$\sum$（シグマ）記号**をゼロから理解しましょう。

:::math Σ（シグマ）記号：9ステップで理由から理解する
**① 解決したい具体的な問題**：151,936個の数字を全部足す計算を、数式で短く正確に書きたい。

**② 普通の足し算では困る理由**：3個なら $z_1 + z_2 + z_3$ で済みますが、151,936個を書き並べるのは不可能です。「$\dots$」で省略すると、どこからどこまで何を足すのか曖昧になることがあります。

**③ 新しい発想**：「番号 $j$ を $1$ から $N$ まで1ずつ動かしながら、右側の式を全部足す」という専用の合図 **$\sum$**（ギリシャ文字の大文字で「**シグマ**」と読む。英語の Sum の S に相当）を使う。

**④ 各部分の読み方**：
$$\sum_{j=1}^{N} x_j$$
- $\sum$：「全部足せ」という命令
- 下の $j=1$：ループ変数 $j$ を `1` から始める
- 上の $N$：$j$ が `N` になるまで続ける（`N` を**含む**！）
- 右の $x_j$：各 $j$ について足す中身（例：$j$ 番目の数 $x_j$）

**⑤ 小さな数字で手計算**：$x = [10, 20, 30]$（$x_1=10, x_2=20, x_3=30$）のとき：
$$\sum_{j=1}^{3} x_j = x_1 + x_2 + x_3 = 10 + 20 + 30 = 60$$
式が $2j$ なら：
$$\sum_{j=1}^{3} (2j) = (2\times 1) + (2\times 2) + (2\times 3) = 2 + 4 + 6 = 12$$

**⑥ Pythonの `for` 文との対応**：$\sum$ はプログラムで書けばそのまま `for` 文です！

```python no-run
total = 0
for j in range(1, 4):   # 注意：Pythonの range(1, 4) は 1, 2, 3（4を含まない）
    total += 2 * j
print(total)            # 12
```

なお、範囲が文脈から明らかなときは上下を省略して $\sum_j e^{z_j}$（全部の $j$ について $e^{z_j}$ を足す）と書くこともよくあります。
:::

確認問題で、手計算とPythonの両方から $\sum$ を定着させましょう！

## なぜ素朴な割り算ではダメなのか？指数関数とsoftmaxの理由

いよいよ本題です。モデルが出した生の点数（ロジット）を、**確率**に変換します。ここでも「数式を暗記」ではなく、**「なぜその計算になるのか」**を1歩ずつたどりましょう。

:::theory ステップ1〜3：問題 → 素朴な方法の失敗 → 指数関数 $e^z$ の発想
**① 解決したい問題**：たとえば「吾輩は○○である」の候補5つのロジットが `z = [3.0, 1.6, 1.2, 0.4, -1.0]` だとする。これを次の**確率の2条件**（＋順位の保存）を満たす数値に変えたい。
- 条件A：すべての確率 $p_i$ が **0以上**（マイナスの確率は存在しない）
- 条件B：すべての確率を足すと **ちょうど1**（$\sum_i p_i = 1$）
- 条件C：元の点数が高いほど、確率も高い（**順位が保たれる**）

**② 素朴な方法ではなぜダメなのか？**
- **案1：そのまま合計で割る** → `-1.0` の確率がマイナスになって条件Aに違反！ さらに `[2.0, -2.0]` のように合計が0だとゼロ除算で壊れる。
- **案2：全要素を2乗して合計で割る** → 全部0以上にはなるが、`-4.0` を2乗すると `+16.0` になり、`+3.0`（2乗すると `9.0`）より大きくなって**条件C（順位）が逆転**してしまう！
- **案3：最小値を引いて0以上にしてから割る** → 最小の候補が必ず確率ちょうど `0.0`（絶対に選ばれない）になり、全候補に同じ定数を足したり引いたりしたときの比率が不自然になる。

**③ 救世主の発想：指数関数 $e^z$（`math.exp(z)`）を使う！**
$e$（ネイピア数、約 `2.718`）を $z$ 乗した $e^z$ を各点数に掛けてから合計で割ると、すべての問題が一挙に解決します。

| $z$ | -2 | -1 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|---|---|
| $e^z$ | 0.14 | 0.37 | 1.00 | 2.72 | 7.39 | 20.09 |

なぜ $e^z$ が理想的なのか？ 性質が4つあります。
1. **どんな $z$ でも必ずプラス**（$e^{-1} = 1/2.718 \approx 0.37 > 0$。マイナスにならない！）
2. **単調増加で順位を保つ**（$z$ が大きいほど $e^z$ も大きい）
3. **点数の「差」が確率の「倍率」になり、平行移動しても確率が変わらない**（指数法則 $e^{z_i + c} = e^c \cdot e^{z_i}$ より、全ロジットに $+100$ しても分子・分母の $e^{100}$ が約分されて確率が完全一致！）
4. **なぜ底が 2 や 10 ではなく $e$ なのか？**（先取りメモ）：$e^x$ は微分しても形がそのまま $(e^x)' = e^x$ という特別な性質を持ち、第7〜8章の学習（勾配計算）の式がもっとも単純できれいになるためです。
:::

**④〜⑤ 小さな数字で手計算してみよう**
候補が3つで $z = [2.0, 1.0, 0.0]$ とします。
1. 各点数を $e^z$ にする：$e^2 \approx 7.39$、$e^1 \approx 2.72$、$e^0 = 1.00$
2. 合計（$\sum_j e^{z_j}$）を計算する：$7.39 + 2.72 + 1.00 = 11.11$
3. それぞれの $e^{z_i}$ を合計 `11.11` で割る：
   - $p_1 = 7.39 \div 11.11 \approx 0.665$（66.5%）
   - $p_2 = 2.72 \div 11.11 \approx 0.245$（24.5%）
   - $p_3 = 1.00 \div 11.11 \approx 0.090$（9.0%）
   - 合計：$0.665 + 0.245 + 0.090 = 1.000$！

**⑥ 数式への一般化（これが softmax！）**
以上の手順を、候補数 $V$ 個に対して一般化した式が **softmax** です。

$$p_i = \frac{e^{z_i}}{\sum_{j=1}^{V} e^{z_j}}$$

| 記号 | 読み方 | 意味 | Pythonでの対応 |
|---|---|---|---|
| $z_i$ | ゼット・アイ | $i$ 番目のトークンの生の点数（ロジット） | `logits_small[i]` |
| $e^{z_i}$ | イーの ゼット・アイ乗 | 点数を正の数に変換した値 | `math.exp(z)` |
| $\sum_{j=1}^{V} e^{z_j}$ | シグマ $j=1$ から $V$ まで $e^{z_j}$ | 全候補の $e^{z_j}$ の合計 | `sum(math.exp(z) for z in logits_small)` |
| $p_i$ | ピー・アイ | $i$ 番目のトークンが選ばれる確率 | `e / total` |

**⑦〜⑧ Pythonで実装して検証しよう**（まずは理解のための小さな5候補の純Pythonコード）：

```python
import math

words = ["猫", "犬", "人間", "名前", "机"]
logits_small = [3.0, 1.6, 1.2, 0.4, -1.0]

exps = [math.exp(z) for z in logits_small]
total = sum(exps)
probs_small = [e / total for e in exps]

for w, z, e, p in zip(words, logits_small, exps, probs_small):
    print(f"{w:3}  点数 {z:5.1f}  → exp {e:6.2f}  → 確率 {p:.3f}")
print("確率の合計：", sum(probs_small))
```

```output
猫    点数   3.0  → exp  20.09  → 確率 0.665
犬    点数   1.6  → exp   4.95  → 確率 0.164
人間   点数   1.2  → exp   3.32  → 確率 0.110
名前   点数   0.4  → exp   1.49  → 確率 0.049
机    点数  -1.0  → exp   0.37  → 確率 0.012
確率の合計： 1.0
```

注目してほしい点：「猫（3.0）」と「犬（1.6）」の点数差は `1.4` で、$e^{1.4} \approx 4.06$。実際の確率比も $0.665 \div 0.164 \approx 4.05$ 倍と一致しています！

では、本物のLLM（151,936語）のロジットを `torch.softmax` で確率に変えてみましょう。

```python
probs = torch.softmax(logits.float(), dim=-1)
top = torch.topk(probs, 5)
for p, i in zip(top.values, top.indices):
    print(f"{tok.decode([int(i)])!r:8} 確率 {p.item()*100:5.1f}%")
print("全トークンの確率の合計：", probs.sum().item())
```

```output-example
'まだ'    確率  97.6%
'ない'    確率   1.1%
'、'      確率   0.3%
'「'      確率   0.3%
'無い'    確率   0.2%
全トークンの確率の合計： 1.0000001192092896
```

:::scaffold なぜ `.float()` と `dim=-1` を書くのか？
- **`.float()`**：GPUではモデルが `float16`（16ビット小数）で動いていますが、`float16` は最大約65,504までしか表せず、`exp` で簡単にオーバーフローしたり丸め誤差が大きくなったりします。`.float()` で32ビット小数（`float32`）にしてから `softmax` するのが安全な定石です。
- **`dim=-1`**：どの方向（軸）の合計を1にするかの指定です。`-1` は「一番最後の軸」を意味します。たとえば2行3列（形 `[2, 3]`）なら各行（長さ3の方向）ごとに合計1.0になり、1次元（形 `[151936]`）でもそのまま語彙全体の合計が1.0になります。
- なお合計が `1.0000001...` とごくわずかにずれるのは、コンピュータの小数の丸め誤差（浮動小数点数の仕様）です。
:::

## サイコロを振る：サンプリングと乱数シード

確率が分かったら、その確率に従ってトークンを1つ選びます（**サンプリング**）。0〜1の数直線を確率の幅で区切り、0以上1未満の一様乱数 `r` がどの区間に落ちたかで選びます。

<div class="math-display">0 ─── 猫（0.665）───┼─ 犬（0.164）─┼ 人間 ┼名前┼机┤ 1</div>

```python
import random

def sample(words, probs):
    r = random.random()          # 0以上1未満の乱数
    total = 0.0
    for w, p in zip(words, probs):
        total += p
        if r < total:
            return w
    return words[-1]

random.seed(0)
results = [sample(words, probs_small) for _ in range(1000)]
for w in words:
    print(w, results.count(w), "回")
```

```output
猫 664 回
犬 175 回
人間 104 回
名前 49 回
机 8 回
```

1000回振ると、猫が664回（約66.4%）と理論確率 `0.665` によく一致しました。

:::scaffold `range`・`_`・`.count`・乱数シード
- `for _ in range(1000)`：1000回繰り返す。`_` は「ループ番号自体は中で使わないよ」というPythonの慣例名です。
- `results.count(w)`：リストの中に `w` が何個あるかを数えます。
- `random.seed(0)`：擬似乱数の初期値（**シード**）を固定します。シードを同じにすれば同じ乱数列が再現されるため、実験比較では必ずシードを固定・記録します。
- PyTorchでは `torch.multinomial(probs, num_samples=1)` が同じくじ引きを高速に行ってくれます。
:::

## 温度：LLMの「はっちゃけ度」

LLMの創造性や堅実さを調整するつまみが **温度**（temperature、記号 $T$）です。仕組みは驚くほど単純で、**softmaxの前にすべてのロジットを $T$ で割る**だけです。

$$p_i = \frac{e^{z_i / T}}{\sum_{j=1}^{V} e^{z_j / T}}$$

:::theory なぜ $T$ で割ると性格が変わるのか？（小さな数字で検証）
2つの候補のロジットが $3.0$ と $1.0$（差は $2.0$）だとします。

| 温度 $T$ | 割った後の点数 | 点数の差 | 確率の倍率 $e^{\text{差}}$ | 振る舞い |
|---|---|---|---|---|
| $T = 0.5$（低温） | `6.0` と `2.0` | **`4.0`（2倍に拡大）** | $e^4 \approx 54.6$ 倍 | 1位がほぼ独占。堅実だが単調になりやすい |
| $T = 1.0$（標準） | `3.0` と `1.0` | `2.0`（そのまま） | $e^2 \approx 7.39$ 倍 | モデルが学んだそのままの確率分布 |
| $T = 2.0$（高温） | `1.5` と `0.5` | **`1.0`（半分に縮小）** | $e^1 \approx 2.72$ 倍 | 確率が平らになり、珍しい語も選ばれやすい |
| $T \to 0$ の極限 | — | $\infty$ | 常に1位のみ（**greedy**） | 第1章の `do_sample=False`（実装上は `argmax` を使う） |

※ 温度に `0` をそのまま入れるとゼロ除算になるため、greedyにしたいときは `argmax` を使います。
:::

Pythonでも5候補の確率変化を確認しましょう。

```python
def softmax_t(logits, T):
    exps = [math.exp(z / T) for z in logits]
    total = sum(exps)
    return [e / total for e in exps]

for T in [0.3, 1.0, 2.0]:
    p = softmax_t(logits_small, T)
    print(f"T={T}: " + "  ".join(f"{w}{x:.2f}" for w, x in zip(words, p)))
```

```output
T=0.3: 猫0.99  犬0.01  人間0.00  名前0.00  机0.00
T=1.0: 猫0.66  犬0.16  人間0.11  名前0.05  机0.01
T=2.0: 猫0.43  犬0.21  人間0.18  名前0.12  机0.06
```

## 自分で文章を生成する

いよいよ「点数 → 温度つきsoftmax → サンプリング → 末尾に付け足す」をつないで、自分の手で文章生成関数 `generate` を書きます！

:::scaffold 実行前に確認：自作 `generate` の1行ごとのテンソル（数の表、第6章）shape 追跡
「吾輩は猫である。名前は」（長さ6トークン）を入れた1周目の流れです。

| 処理 | 変数 | 形（`shape`） | 何をしているか |
|---|---|---|---|
| `tok(text, return_tensors="pt").input_ids.to(...)` | `ids` | `[1, 6]` | 文章をトークンIDの2次元テンソル（1文章×6トークン）へ |
| `model(ids).logits[0, -1]` | `logits` | `[151936]` | 末尾位置の次トークンの生の点数を取り出す |
| `torch.softmax(logits.float() / temperature, dim=-1)` | `probs` | `[151936]` | 温度で割って確率分布（合計1）に変換 |
| `torch.multinomial(probs, num_samples=1)` | `next_id` | `[1]` | 確率に従ってトークンIDを1個サンプリング |
| `next_id.view(1, 1)` | — | `[1, 1]` | `ids`（2次元）と連結できるよう形を `[1, 1]` に整える |
| `torch.cat([ids, next_id.view(1, 1)], dim=1)` | `ids` | `[1, 7]` | 軸1（横方向）に連結して文章を1トークン伸ばす |

（`.view` やテンソル操作の詳細は第6章・第9章で本格的に練習します。ここでは「毎ステップ `[1, 6] → [1, 7] → [1, 8]` と1つずつ伸びる」ことをつかめれば完璧です！）
:::

```python
def generate(text, n_tokens=30, temperature=1.0):
    ids = tok(text, return_tensors="pt").input_ids.to(model.device)
    for _ in range(n_tokens):
        with torch.no_grad():
            logits = model(ids).logits[0, -1]               # ① 次のトークンの点数
        probs = torch.softmax(logits.float() / temperature, dim=-1)  # ② 温度つきで確率に
        next_id = torch.multinomial(probs, num_samples=1)   # ③ サイコロを振る
        ids = torch.cat([ids, next_id.view(1, 1)], dim=1)   # ④ 最後に付け足す
    return tok.decode(ids[0])

torch.manual_seed(42)
print(generate("吾輩は猫である。名前は", n_tokens=40, temperature=0.7))
```

```output-example
吾輩は猫である。名前はまだ無い。どこで生れたかとんと見当がつかぬ。何でも薄暗いじめじめした所でニャーニャー泣いていた事だけは記憶している。
```

:::sensei
見たかい？ ChatGPTを含む現代のすべてのLLMの文章生成の骨組みは、この10行なんだ。1つ予測して、自分の出力を次の入力の末尾に付け足して、また予測する──これを **自己回帰（autoregressive）生成** と呼ぶよ！
:::

:::theory 自己回帰生成の弱点と、先の章へのつながり
この素朴なループでは、トークンを1個増やすたびにそれまでの文章全体を毎回モデルに通し直すため、文章が長くなるほど1トークンあたりの計算が遅くなります。実際のLLMでは「過去の計算結果を覚えておいて再利用する」工夫（**KVキャッシュ**）で高速化します（第16章で自分で実装します）。
:::

```python
    torch.manual_seed(0)
    print(f"--- 温度 {T} ---")
```


:::warn よくあるつまずき
- **`RuntimeError: Expected all tensors to be on the same device`**：入力とモデルの置き場所（CPU/GPU）がずれています。`.to(model.device)` を付け忘れていないか確認しましょう。
- **`probability tensor contains either inf, nan or element < 0`**：温度に `0` を入れてゼロ除算したときに起きます。greedyにしたいときは `torch.argmax(logits)` を使います。
- **同じ言葉のくり返し**：低い温度や小さなモデルではよく起きます（第16章で繰り返しを抑える工夫を学びます）。
:::

:::recap
- モデルは入力 `[1, T]` に対し、各位置の次トークン点数（ロジット）`[1, T, V]` を返す。末尾 `[0, -1]` が続きの予測
- $\sum$（シグマ）は「全部足す」の速記法で、Pythonの `for` 文に対応する
- **softmax**：$p_i = e^{z_i/T} / \sum_j e^{z_j/T}$。$e^z$ により全要素が正・順位保存・平行移動不変になり、最大値を引けばオーバーフローも防げる
- 確率に従ってくじを引き（サンプリング）、末尾に連結して繰り返すのが **自己回帰生成**
:::
