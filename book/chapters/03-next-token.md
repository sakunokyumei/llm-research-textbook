## 準備：モデルを直接読み込む

今回は `pipeline` を使わず、トークナイザーとモデル本体を別々に読み込みます。GPUを使うので、ランタイムを「T4 GPU」にしておきましょう（使えなければCPUでもOK。少し遅いだけです）。

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

name = "Qwen/Qwen2.5-0.5B-Instruct"
gpu = torch.cuda.is_available()
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(
    name, dtype=torch.float16 if gpu else torch.float32, device_map="auto"
)
print("読み込み完了。置き場所：", model.device)
```

```output-example
読み込み完了。置き場所： cuda:0
```

`cuda:0` はGPUの0番、`cpu` ならCPUです。**CUDA**（クーダ）は、NVIDIAのGPUで計算するための仕組みの名前です。

## LLMの「点数表」を見る

「吾輩は猫である。名前は」の次に来るトークンを、LLMがどう考えているか見てみましょう。

```python
text = "吾輩は猫である。名前は"
inputs = tok(text, return_tensors="pt").to(model.device)

with torch.no_grad():
    out = model(**inputs)

logits = out.logits[0, -1]
print(logits.shape)
```

```output
torch.Size([151936])
```

:::python with torch.no_grad():
`with torch.no_grad():` は「この中では**学習のための記録をしない**」というモードです。学習するときは、計算の途中経過を全部メモしておく必要がありますが（第7章で理由が分かります）、今は予測するだけなので、メモを省いて速く・省メモリにしています。<br>
`model(**inputs)` の `**` は、辞書の中身を「名前つきの引数」として渡す書き方です。今は「おまじない」でOK。
:::

`logits` は151,936個の数が並んだもので、**ロジット**（logit）と呼びます。語彙のトークン1つ1つに対する「次に来そう度」の点数です（語彙は151,665個でしたが、計算の都合で少し多めに枠が取ってあります）。`[0, -1]` は「1つ目の文章の、最後の位置」という意味で、「名前は」の**次**を予想した点数を取り出しています。

点数の高い上位5個を見てみましょう。

```python
top = torch.topk(logits, 5)
for score, i in zip(top.values, top.indices):
    print(f"{tok.decode([int(i)])!r:8} 点数 {score.item():6.2f}")
```

```output-example
'まだ'    点数  21.03
'ない'    点数  16.55
'、'      点数  15.22
'「'      点数  14.98
'無い'    点数  14.42
```

:::python zip と、f文字列の書式
`zip(A, B)` は、2つの並びを**横に並べて**、1組ずつ取り出します。`top.values`（点数の並び）と `top.indices`（トークンIDの並び）から、「1位の点数とID」「2位の点数とID」…と順番に取り出しています。ファスナー（zip）を閉じるように、2列が1組ずつかみ合うイメージです。<br>
f文字列の `{… !r:8}` は「`repr` で表示して、8文字分の幅をとる」、`{…:6.2f}` は「小数点以下2桁で、全体を6文字分の幅で」という書式の指定です。表のように縦をそろえて表示したいときに使います。<br>
`score.item()` は、PyTorchの数（テンソル）を、ふつうのPythonの数に取り出す書き方です。`int(i)` も同じように、ふつうの整数に変えています。
:::

1位は「まだ」。さすが、有名な書き出しを知っています。でも点数は「21.03」のような数で、このままでは「何％の確率で選ばれるのか」が分かりません。点数を確率に変換しましょう。

## 点数を確率に変える：softmax

確率に変えるには、2つの条件を満たす必要があります。

1. どの確率も **0以上**（マイナスの確率はない）
2. 全部足すと **ちょうど1**（100%）

ロジットはマイナスにもなるので、そのままでは使えません。そこで登場するのが **softmax**（ソフトマックス）という変換です。小さな例で手計算してみましょう。「吾輩は○○である」の○○の候補が5つだけだとします。

```python
import math

words = ["猫", "犬", "人間", "名前", "机"]
logits_small = [3.0, 1.6, 1.2, 0.4, -1.0]

exps = [math.exp(z) for z in logits_small]
total = sum(exps)
probs_small = [e / total for e in exps]

for w, z, e, p in zip(words, logits_small, exps, probs_small):
    print(f"{w:3}  点数 {z:5.1f}  → exp {e:6.2f}  → 確率 {p:.3f}")
print("確率の合計：", sum(probs_small))
```

```output
猫    点数   3.0  → exp  20.09  → 確率 0.665
犬    点数   1.6  → exp   4.95  → 確率 0.164
人間   点数   1.2  → exp   3.32  → 確率 0.110
名前   点数   0.4  → exp   1.49  → 確率 0.049
机    点数  -1.0  → exp   0.37  → 確率 0.012
確率の合計： 1.0
```

手順はたった2つ。**① 各点数を `exp` で変換して正の数にする → ② 全部の合計で割る**。これで「全部プラス、合計1」の確率になりました。

:::math 指数関数 exp と e
`math.exp(z)` は $e^z$ を計算します。$e$ は約2.718の決まった数（**ネイピア数**）で、$e^z$ は、$z$ が 2 や 3 なら「$e$ を $z$ 回掛けたもの」です（$e^2 = e \times e$）。$z = 0$ なら 1、$z = -1$ なら「1 を $e$ で1回割ったもの」（$e^{-1} = 1 \div 2.718 \approx 0.37$）、$z = -2$ なら2回割ったもの（約0.14）、$z$ が 1.4 のような小数なら、$e^1$ と $e^2$ の間のなめらかな値になります。計算は `math.exp` がやってくれるので、表の感覚がつかめれば十分です。

| $z$ | -1 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|---|
| $e^z$ | 0.37 | 1 | 2.72 | 7.39 | 20.09 |

ポイントは3つ。

- **どんな $z$ でも結果はプラス**（マイナスの点数も、小さな正の数になる）
- **$z$ が大きいほど、結果も大きい**（点数の順位が保たれる）
- **$z$ が1増えると、結果は約2.7倍**（点数の差が、確率の「倍率」になる）

3つ目が大事です。「猫」と「犬」の点数の差は1.4で、$e^{1.4} \approx 4.06$。だから「猫」は「犬」の約4倍選ばれやすい。確率を見ると 0.665 ÷ 0.164 ≈ 4.05 で、ちゃんとそうなっています。
:::

:::theory softmaxの式と、Σはfor文
softmaxを数式で書くと、こうなります。$z_i$ は $i$ 番目の点数、$p_i$ はその確率です。

$$p_i = \frac{e^{z_i}}{\sum_{j} e^{z_j}}$$

分母の $\sum$（シグマ）は「全部足す」という記号です。プログラマ向けに言い換えると、**Σはfor文**です。

```python no-run
total = 0
for z in logits_small:      # Σ_j の j が、for文の z に相当
    total += math.exp(z)    # e^{z_j} を足していく
```

数式が出てきたら、怖がらずに「これをPythonで書いたら？」と考えてみてください。数式は、プログラムを短く書くための速記法みたいなものです。
:::

PyTorchには、これを一発でやる `torch.softmax` があります。本物のLLMの点数を確率にしてみましょう。

```python
probs = torch.softmax(logits.float(), dim=-1)
top = torch.topk(probs, 5)
for p, i in zip(top.values, top.indices):
    print(f"{tok.decode([int(i)])!r:8} 確率 {p.item()*100:5.1f}%")
print("全トークンの確率の合計：", probs.sum().item())
```

```output-example
'まだ'    確率  97.6%
'ない'    確率   1.1%
'、'      確率   0.3%
'「'      確率   0.3%
'無い'    確率   0.2%
全トークンの確率の合計： 1.0000001192092896
```

「まだ」がほぼ確実です。合計が `1.0000001…` と微妙にずれているのは、コンピュータの小数計算の誤差です（基本情報で習う「浮動小数点数の丸め誤差」そのもの！）。

## サイコロを振る：サンプリング

確率が分かったら、その確率に従ってトークンを1つ選びます。これを **サンプリング**（sampling）と言います。確率0.665の「猫」は約67%の確率で、0.012の「机」は約1.2%の確率で選ばれる、いびつなサイコロです。

自分で作ってみましょう。くじ引きの仕組みは「0〜1の乱数を1つ引いて、確率を順番に積み上げた区間のどこに落ちたか」で決まります。

```python
import random

def sample(words, probs):
    r = random.random()          # 0以上1未満の乱数
    total = 0.0
    for w, p in zip(words, probs):
        total += p
        if r < total:
            return w
    return words[-1]

random.seed(0)
results = [sample(words, probs_small) for _ in range(1000)]
for w in words:
    print(w, results.count(w), "回")
```

```output
猫 664 回
犬 175 回
人間 104 回
名前 49 回
机 8 回
```

1000回振ると、だいたい確率どおりの回数になりました（猫は約67%なので、1000回中664回）。ぴったり665回にならないのは、サイコロだからです。

:::python range と _ と .count
`range(1000)` は「0, 1, 2, …, 999」の1000個の数の並びです。`for _ in range(1000)` で「1000回くり返す」になります。`_`（アンダースコア）は「この変数は使わない」という印の名前で、何回目かは気にせず、ただ1000回くじを引きたいときに使います。<br>
`results.count(w)` は、リスト `results` の中に `w` がいくつあるかを数えます。
:::

:::theory 区間に落とすくじ引き
0から1までの線を、確率の長さで区切ります。

<div class="math-display">0 ─── 猫（0.665）───┼─ 犬（0.164）─┼ 人間 ┼名前┼机┤ 1</div>

乱数 `r` がどの区間に落ちたかで、選ぶトークンが決まります。区間が長い（確率が高い）ほど、落ちやすい。とても素朴ですが、LLMの中でも本質的には同じことが行われています（`torch.multinomial` という関数がやってくれます）。
:::

:::fe 乱数とシード
`random.seed(0)` は乱数の **シード**（種）を決める命令です。コンピュータの乱数は、決まった計算で作る「それっぽい乱数」（**擬似乱数**）なので、種を同じにすると毎回同じ乱数の列が出てきます。実験を**再現**できるように、研究ではシードを記録しておくのが鉄則です。シードを消して実行すると、毎回結果が変わるのを確かめてみましょう。
:::

## 温度：LLMの「はっちゃけ度」

ここで、LLMを使うときによく見かけるつまみ **温度**（temperature）を紹介します。温度は、softmaxの前に**点数を温度で割る**だけの、とても単純な仕組みです。

$$p_i = \frac{e^{z_i / T}}{\sum_{j} e^{z_j / T}}$$

```python
def softmax_t(logits, T):
    exps = [math.exp(z / T) for z in logits]
    total = sum(exps)
    return [e / total for e in exps]

for T in [0.3, 1.0, 2.0]:
    p = softmax_t(logits_small, T)
    print(f"T={T}: " + "  ".join(f"{w}{x:.2f}" for w, x in zip(words, p)))
```

```output
T=0.3: 猫0.99  犬0.01  人間0.00  名前0.00  机0.00
T=1.0: 猫0.66  犬0.16  人間0.11  名前0.05  机0.01
T=2.0: 猫0.43  犬0.21  人間0.18  名前0.12  机0.06
```

:::theory 温度で何が起きる？
- **温度を下げる（T < 1）**：点数を小さい数で割るので、点数の差が**拡大**される。1位の確率がどんどん大きくなり、ほぼ毎回同じトークンを選ぶ。真面目で、安定するが、つまらない
- **温度を上げる（T > 1）**：点数の差が**縮む**。確率が平らになり、珍しいトークンも選ばれる。創造的だが、支離滅裂になりやすい
- **温度→0の極限**：いつも1位を選ぶ。これを **greedy**（貪欲法）と呼びます。第1章の `do_sample=False` はこれ

物理では、温度が高いと分子が激しく動いて、いろいろな状態をとりますよね。名前の由来はまさにそれ（統計力学のボルツマン分布）です。ボンゴ先生が物理出身なのは、この話をしたかったからに違いありません。
:::

上の「サイコロ」の箱に戻って、温度のつまみを動かしてみてください。温度を0.05にすると「猫」の一択になり、3にすると「机」ですらそこそこ選ばれるようになります。

## 自分で文章を生成する

材料は揃いました。「点数を出す → 確率にする → サイコロで1つ選ぶ → 文章の最後に付け足す」を繰り返せば、文章が生成できるはずです。これを自分で書いてみましょう。

```python
def generate(text, n_tokens=30, temperature=1.0):
    ids = tok(text, return_tensors="pt").input_ids.to(model.device)
    for _ in range(n_tokens):
        with torch.no_grad():
            logits = model(ids).logits[0, -1]               # ① 次のトークンの点数
        probs = torch.softmax(logits.float() / temperature, dim=-1)  # ② 温度つきで確率に
        next_id = torch.multinomial(probs, num_samples=1)   # ③ サイコロを振る
        ids = torch.cat([ids, next_id.view(1, 1)], dim=1)   # ④ 最後に付け足す
    return tok.decode(ids[0])

torch.manual_seed(42)
print(generate("吾輩は猫である。名前は", n_tokens=40, temperature=0.7))
```

```output-example
吾輩は猫である。名前はまだ無い。どこで生れたかとんと見当がつかぬ。何でも薄暗いじめじめした所でニャーニャー泣いていた事だけは記憶している。
```

このコードのテンソルの操作（`.input_ids`、`.view(1, 1)`、`torch.cat`、`dim=-1` など）は、第6章でくわしく学びます。今は①〜④のコメントを読んで、「点数 → 確率 → サイコロ → 付け足す」の流れが分かればOKです。

:::sensei
見たかい？ これが、ChatGPTを含むすべてのLLMの文章生成の正体だ。高度なことをしているように見えて、骨組みはこの10行。あとはモデルの「点数のつけ方」がどれだけ賢いかの勝負なんだ。
:::

:::theory 自己回帰：自分の出力を、次の入力にする
1つ予測したら、それを入力の最後に付け足して、また予測する。このように、**自分の出力を次の入力に使いながら1つずつ作っていく**方式を **自己回帰**（autoregressive）生成と呼びます。GPTの「G」はGenerative（生成的）、つまりこの生成をするモデルという意味です。

この方式には弱点もあります。トークンを1つ作るたびに、それまでの文章全体をモデルに通しているので、長くなるほど遅くなるのです。実際のLLMは「前回の計算結果を覚えておく」工夫（**KVキャッシュ**）でこれを速くしています。第16章で自分で実装します。
:::

:::try 温度を変えて書き比べよう
同じ書き出しで、温度だけを変えて生成してみましょう。予想してから実行！

```python
for T in [0.1, 0.7, 1.5]:
    torch.manual_seed(0)
    print(f"--- 温度 {T} ---")
    print(generate("ある日、AIが", n_tokens=40, temperature=T))
```

```output-example
--- 温度 0.1 ---
ある日、AIが人間の仕事を奪うのではないかという不安が広がっていました。しかし、AIは人間の仕事を奪うのではなく、
--- 温度 0.7 ---
ある日、AIが突然「私は人間になりたい」と言い出した。研究者たちは驚き、その理由を尋ねた。AIは静かに答えた。
--- 温度 1.5 ---
ある日、AIが鍋焼きうどんに論文を提出、なお昨年度の宇宙会計は猫部に移管されました。ふと見上げると
```

温度1.5になると、だんだん「夢の中の会話」みたいになっていきます。温度は高すぎても低すぎてもダメ。チャットでは0.7前後がよく使われます。
:::

最後に、`transformers` に最初から用意されている `generate` と比べてみましょう。中でやっていることの基本は、さっき自分で書いたものと同じです（もっと速くて、たくさんの便利機能がついています）。ただし、モデルには作者のおすすめ設定（`generation_config`）が付いていて、温度のほかに「上位の候補だけからくじを引く」「同じ言葉のくり返しを減らす」といった工夫も自動で効きます（第16・17章）。なので、同じシードでも、自作の `generate` とは違う文章になります。

```python
inputs = tok("吾輩は猫である。名前は", return_tensors="pt").to(model.device)
torch.manual_seed(42)
out = model.generate(**inputs, max_new_tokens=40, do_sample=True, temperature=0.7)
print(tok.decode(out[0], skip_special_tokens=True))
```

```output-example
吾輩は猫である。名前はまだ無い。どこで生れたか、とんと見当がつかない。ただ、暗い場所で鳴いていたことだけは覚えている。
```

（有名な書き出しなので、自作の `generate` と同じように原文どおりになることもあります。）

:::warn よくあるつまずき
- **`RuntimeError: Expected all tensors to be on the same device`**：データがCPUに、モデルがGPUにある、のように置き場所がずれています。`.to(model.device)` を付け忘れていないか確認しましょう。
- **`probability tensor contains either inf, nan or element < 0`**：温度に0を入れると、0で割ってしまいます。greedyにしたいときは、温度を0.01のような小さな数にするか、`torch.argmax(logits)` で1位を選びましょう。
- **生成された文章が同じことをくり返す**：小さなモデルや低い温度ではよく起きます。温度を少し上げると改善することがあります（第16章で、くり返しを防ぐ工夫も学びます）。
:::

:::quiz softmaxの役目
softmaxが「点数（ロジット）」を確率に変えるとき、`exp` を使う理由を2つ挙げてください。
:::answer
① どんな点数（マイナスでも）も正の数に変えられるから。② 点数の大小関係を保ったまま、点数の差を「倍率」に変えられるから（点数が1違うと約2.7倍）。最後に合計で割ることで、合計が1になります。
:::

:::quiz 温度
温度を0.1にしたとき、生成される文章はどうなりますか？ 理由も。
:::answer
ほとんど毎回、確率1位のトークンが選ばれるので、安定して無難な（そして同じことをくり返しがちな）文章になります。点数を0.1で割ると点数の差が10倍に拡大され、softmax後の確率が1位に集中するからです。
:::

:::quiz Σ
$\sum_{j=1}^{3} j$ をPythonのfor文で書くと？ 答えはいくつ？
:::answer
```python no-run
total = 0
for j in range(1, 4):
    total += j
```
答えは 1 + 2 + 3 = 6 です。`range(1, 4)` は1, 2, 3（4は含まない）なので注意。

:::recap
- LLMは次のトークン全部に**点数（ロジット）**をつける。**softmax**で確率に変える：$p_i = e^{z_i}/\sum_j e^{z_j}$
- 確率に従ってくじを引くのが**サンプリング**。シードを固定すると再現できる
- **温度**で点数を割ると、確率の尖り具合を調整できる（低い＝堅実、高い＝冒険）
- 「予測→くじ→付け足す」の繰り返しが**自己回帰生成**。すべてのLLMの生成はこれ
:::
