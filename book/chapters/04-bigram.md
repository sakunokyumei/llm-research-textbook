:::fe Shift_JIS と cp932
青空文庫のファイルは、古くから日本のパソコンで使われてきた **Shift_JIS** という文字コードで書かれています。基本情報の文字コードの問題で出てくる、あれです。正確にはWindowsで拡張された版の **cp932**（Microsoftの文字コード表の932番）を使うと、機種依存文字まで正しく読めます。<br>
`0x82 0xb1` はShift_JISで「こ」。`0x82 0xb1 0x82 0xb1 0x82 0xeb` で「こころ」です。上の出力の先頭と見比べてみてください。
:::

```python

print(text[:300])
```

```output

-------------------------------------------------------
【テキスト中に現れる記号について】

《》：ルビ
（例）私《わたくし》は

（例）先生一人｜麦藁帽《むぎわらぼう》を
```

## 掃除する：正規表現

機械学習では、**データの掃除（前処理）がとても大事**です。「ゴミを入れたらゴミが出てくる（Garbage In, Garbage Out）」という格言があるくらいです。ルビを消すには **正規表現**（regular expression）を使います。正規表現は「こういう形の文字列」というパターンを書くための小さな言語です。

```python
import re

sample = "私《わたくし》はその人を常に先生《せんせい》と呼んでいた。"
print(re.sub(r"《.*?》", "", sample))
```

```output
私はその人を常に先生と呼んでいた。
```

:::python 正規表現の読み方
`re.sub(パターン, 置き換える文字, 対象)` は「パターンに合う部分を全部置き換える」関数です。`r"《.*?》"` は次のように読みます。

| 部分 | 意味 |
|---|---|
| `《` | 「《」という文字 |
| `.` | 何でもいい1文字 |
| `*` | 直前のものが0回以上くり返す |
| `?` | ただし、なるべく短く（控えめに） |
| `》` | 「》」という文字 |

つまり「《 から始まって、いちばん近い 》 で終わる部分」です。`?` を付け忘れると「なるべく長く」になって、最初の《から**最後の**》までをごっそり消してしまいます。試してみましょう。

```python
print(re.sub(r"《.*》", "", sample))
```

```output
私と呼んでいた。
```

「はその人を常に先生」まで消えてしまいました。正規表現は強力なぶん、ちょっとしたミスで大惨事になります。電動ノコギリみたいなものです。
:::

:::scaffold 理解のための最小コード：`re.sub` の最短一致 `.*?` vs 最長一致 `.*`
同じ入力 `s = "私《わたくし》は先生《せんせい》だ"`（`str`型）に対して、マッチする範囲（中間状態）と出力を比べてみましょう。

| パターン | マッチする区間（中間） | 置換後の出力（`str`型） | 理由 |
|---|---|---|---|
| `r"《.*?》"`（最短一致） | ①`《わたくし》`、②`《せんせい》` の2か所 | `"私は先生だ"` | `?` があるので一番近い `》` で止まる |
| `r"《.*》"`（最長一致） | `《わたくし》は先生《せんせい》` の1か所 | `"私だ"` | `?` がないので最後の `》` まで欲張って飲み込む |

```python no-run
import re
s = "私《わたくし》は先生《せんせい》だ"
print(re.sub(r"《.*?》", "", s))   # 私は先生だ
print(re.sub(r"《.*》", "", s))    # 私だ（間の「は先生」まで消滅！）
```
:::

```python
    text = text.split("底本：")[0]                   # 末尾の書誌情報を除く
```

## 文字を数える

まずは、どの文字がよく出てくるかを数えてみましょう。数えるのに便利な道具が `Counter` です。

```python
from collections import Counter

counts = Counter(text)
print("文字の種類：", len(counts))
print(counts.most_common(10))
```

```output
文字の種類： 2061
[('の', 7556), ('た', 6734), ('い', 6214), ('し', 5302), ('に', 4710), ('。', 4654), ('は', 4334), ('て', 4193), ('な', 4061), ('で', 3909)]
```

『こころ』は2061種類の文字でできていて、一番多いのは「の」でした。これが私たちの言語モデルの**語彙**（2061文字）になります。

:::scaffold 理解のための最小コード：`collections.Counter` の入力・中身・出力
`Counter` は「要素 → 出現回数」を自動で集計する辞書（`dict` の仲間）です。普通の辞書との最大の違いは、**存在しないキーを聞いてもエラーにならず `0` を返す**点です。

| ステップ | コード / 値 | 型 | 意味 |
|---|---|---|---|
| 入力 | `s = "こころ"` | `str`（長さ3） | 1文字ずつ取り出せる文字列 |
| 集計後 | `c = Counter(s)` → `Counter({'こ': 2, 'ろ': 1})` | `Counter`（辞書の仲間） | 各文字の出現回数マップ |
| 種類数 | `len(c)` → `2` | `int` | ユニークな文字の種類（総文字数3ではない） |
| 上位取得 | `c.most_common(1)` → `[('こ', 2)]` | `list` of `(str, int)` | 多い順に `(文字, 回数)` タプルを並べたリスト |
| 未出現キー | `c["私"]` → `0` | `int` | 普通なら `KeyError` だが `Counter` は `0` |

```python no-run
from collections import Counter
c = Counter("こころ")
print(len(c), c["こ"], c["私"])   # 2 2 0
print(c.most_common(2))           # [('こ', 2), ('ろ', 1)]
```

## 「次の文字」を数える

ここからが言語モデルです。「ある文字の次に、どの文字が来たか」の組（**ペア**）を全部数えます。

```python
pairs = Counter(zip(text, text[1:]))
print(pairs.most_common(10))
```

```output
[(('た', '。'), 2960), (('し', 'た'), 2043), (('っ', 'た'), 1890), (('っ', 'て'), 1406), (('私', 'は'), 1352), (('し', 'て'), 1172), (('で', 'す'), 1142), (('て', 'い'), 1110), (('ま', 'し'), 1083), (('の', 'で'), 1071)]
```

:::python zip とスライス
`text[1:]` は「1番目の文字から最後まで」、つまり先頭の1文字を除いた文字列です（**スライス**といいます）。`zip(text, text[1:])` は2つを横に並べて、「0番目と1番目」「1番目と2番目」「2番目と3番目」…という組を順に作ります。

| `text` | 私 | は | そ | の | 人 |
|---|---|---|---|---|---|
| `text[1:]` | は | そ | の | 人 | を |

縦に読むと「私→は」「は→そ」「そ→の」…。隣り合う2文字の組が全部手に入ります。
:::

:::scaffold 理解のための最小コード：`zip(text, text[1:])` の入力・途中・出力
| ステップ | 値（具体例） | 型・長さ | 起きていること |
|---|---|---|---|
| 入力 | `s = "こころの"` | `str`（長さ4） | 元の文字列 |
| 1文字ずらす | `s[1:]` → `"ころの"` | `str`（長さ3） | 先頭の1文字を切り落とした文字列 |
| `zip` で組にする | `list(zip(s, s[1:]))` → `[('こ','こ'), ('こ','ろ'), ('ろ','の')]` | `list` of `(str, str)`（長さ3） | 短い方の長さ `len(s) - 1` で止まり、隣接ペアができる |
| `Counter` で集計 | `Counter(zip(s, s[1:]))` → `{('こ','こ'):1, ('こ','ろ'):1, ('ろ','の'):1}` | `Counter` | 各2文字ペア `(a, b)` の回数がまとまる |

```python no-run
from collections import Counter
s = "こころの"
pairs_small = list(zip(s, s[1:]))
print(len(pairs_small), pairs_small)   # 3 [('こ', 'こ'), ('こ', 'ろ'), ('ろ', 'の')]
print(Counter(pairs_small))            # Counter({('こ', 'こ'): 1, ('こ', 'ろ'): 1, ('ろ', 'の'): 1})
```
:::

「〜た。」で終わる文が2960回。さすが小説、過去形だらけです。では、「先」の次には何が来るでしょう？

```python
def next_counts(ch):
    c = Counter()
    for (a, b), n in pairs.items():   # 全部のペアの中から
        if a == ch:                   # 1文字目が ch のものだけ
            c[b] = n                  # 2文字目と回数を記録
    return c

c = next_counts("先")
print("「先」は全部で", sum(c.values()), "回")
print(c.most_common(5))
```

```output
「先」は全部で 678 回
[('生', 597), ('へ', 22), ('刻', 16), ('で', 8), ('を', 6)]
```

「先」678回のうち597回、つまり約88%が「先生」です。『こころ』は「先生」の物語ですからね。

:::math 条件付き確率 $P(B \mid A)$：9ステップで理由から理解する
**① 解決したい具体的な問題**：「今の文字が『先』だ」と分かっているとき、次の文字が『生』『へ』『刻』…である確率を正しく出したい。

**② 素朴な方法（単なる出現回数・全体割合）ではなぜダメなのか？**
- もし文章全体の回数ランキング（**unigram**）だけを使うと、『こころ』で最多は「の」（7556回）なので、どんな文字の次でも「の」が一番選ばれやすくなり、「ののたのい…」のような日本語にならない文が出てしまいます。
- また、生の回数 `597` のままでは「678回中597回（88%）」なのか「1万回中597回（6%）」なのか分からず、合計1の確率分布にもなりません。

**③ 新しい発想**：小説全体を見るのではなく、**「1文字目が $a$ であるペアだけ」に世界を絞り込み**、その中で次が $b$ だった割合をとる。これが **条件付き確率** です。

**④ 記号の読み方表**：
| 記号 | 読み方 | 意味 |
|---|---|---|
| $P(B \mid A)$ | 「AのもとでのBの確率」 | 条件 $A$ が起きた世界で、出来事 $B$ が起きる割合 |
| $\mid$（縦棒） | 「〜という条件のもとで」 | **右側**が分かっている条件（分母）、**左側**が予測したいもの |
| $\text{count}(a, b)$ | 「$a$ の次に $b$ が来た回数」 | 隣接ペア `(a, b)` の出現回数 |
| $\text{count}(a)$ | 「$a$（の後に文字がある箇所）の回数」 | 条件 $a$ で始まるペアの総数 $\sum_b \text{count}(a, b)$ |

**⑤ 小さな10文字コーパスで手計算**：`s = "あいうあいうあいあえ"`（10文字・隣接9ペア）で、今の文字が「あ」のときを手計算してみましょう。
- 全9ペア：`あい, いう, うあ, あい, いう, うあ, あい, いあ, あえ`
- 「あ」で始まるペアだけ絞り込む：`あい`（3回）、`あえ`（1回）→ 合計4回
- したがって：
$$P(\text{い} \mid \text{あ}) = \frac{3}{4} = 0.75, \qquad P(\text{え} \mid \text{あ}) = \frac{1}{4} = 0.25$$
- 合計は $0.75 + 0.25 = 1.00$。きちんと確率分布の2条件（0以上・合計1）を満たします！

**⑥ 一般式**：『こころ』のような長い文章でも同じです。
$$P(b \mid a) = \frac{\text{count}(a, b)}{\text{count}(a)} = \frac{\text{count}(a, b)}{\sum_{b'} \text{count}(a, b')}$$
『こころ』の「先」なら：
$$P(\text{生} \mid \text{先}) = \frac{\text{「先生」の回数}}{\text{「先」の回数}} = \frac{597}{678} \approx 0.88$$

**⑦ Pythonの最小コードで検算**：
```python no-run
from collections import Counter
s = "あいうあいうあいあえ"
p = Counter(zip(s, s[1:]))
a_total = sum(n for (a, b), n in p.items() if a == "あ")   # 4
print("P(い|あ) =", p[("あ", "い")] / a_total)             # 0.75
print("P(え|あ) =", p[("あ", "え")] / a_total)             # 0.25
```

**⑧ よくある誤解**：$P(B \mid A)$ と $P(A \mid B)$ は**まったく別物**です。『こころ』では $P(\text{生} \mid \text{先}) = 597/678 \approx 0.88$ ですが、逆向きの $P(\text{先} \mid \text{生})$ は「生」の次に「先」が来る確率（たった4回）なのでほぼ $0$ です。縦棒 $\mid$ の**右側が条件（分母）**と意識しましょう。

**⑨ 言語モデルとの接続**：言語モデルとはまさに $P(\text{次の文字} \mid \text{それまでの文字})$ を出す仕組み（第3章）でした。今回は直前の**1文字だけ**を条件にして2つ（bi）の文字の組を数えるので、**bigram**（バイグラム）モデルと呼びます。
:::

確認問題で、`zip` と条件付き確率の手計算・記号の読み方を定着させましょう！

## 漱石に書かせる

数えた結果を使えば、文章が作れます。今の文字の「次の文字の回数」をそのまま重みにして、くじを引くのです。

```python
import random

following = {}                       # 「文字 → その次の文字の回数」の辞書
for a, b in zip(text, text[1:]):      # 隣り合う2文字 a, b を順番に
    if a not in following:            # a が初めて出てきたら
        following[a] = Counter()      #   a 用の空のカウンターを用意
    following[a][b] += 1              # 「a の次に b が来た」回数を1増やす

def generate(start, n=80):
    out = start
    ch = start[-1]                    # 書き出しの最後の1文字から続ける
    for _ in range(n):
        c = following[ch]
        ch = random.choices(list(c.keys()), weights=list(c.values()))[0]
        out += ch
    return out

random.seed(1)
print(generate("私"))
```

```output
私は腎臓の運ばなた。私のた後姿を帯の頁されはな時先生の方がなかられていと私のだろう済むしたに成功を心は私に宛てどこころにものだ私がら、多に私は自然とは午眠り、あ百
```

:::python Counter の「0回」と random.choices
`Counter` は、まだ数えていないものを「0回」として扱います。だから、初めて出てきた `b` でも、いきなり `following[a][b] += 1` と書けます（ふつうの辞書だと、ここで `KeyError` になります）。<br>
`random.choices(候補のリスト, weights=重みのリスト)` は、重みに比例した確率で候補から1つ選びます（結果はリストで返るので `[0]` で取り出します）。第3章で自作した `sample` 関数と同じ仕事です。
:::

:::sensei
「私は腎臓の運ばなた。」……漱石先生に怒られそうだね。でも見てごらん。「私は」「先生の方が」「私に宛て」「自然とは」。**2文字だけ見れば**、どこも日本語として自然だ。このモデルは、直前の1文字しか覚えていない。文の前のほうで何を言っていたかは、きれいさっぱり忘れている。
:::

:::try いろいろな書き出しで
`random.seed(1)` の数字を変えたり、`generate("先")`、`generate("奥")`、`generate("Ｋ")`（『こころ』のKは全角の「Ｋ」です） のように書き出しを変えたりしてみましょう。毎回違う「漱石っぽい何か」が生まれます。気に入ったものがあったら、それがあなたのモデルの最初の作品です。
:::

:::scaffold 理解のための最小コード：`random.choices` の入力・途中・出力
| ステップ | 値（具体例） | 型 | 起きていること |
|---|---|---|---|
| 入力（候補） | `keys = ['い', 'え']` | `list` of `str` | `list(c.keys())` で候補を取り出す |
| 入力（重み） | `weights = [3, 1]` | `list` of `int` | `list(c.values())` で回数（合計1でなくてOK）を渡す |
| 内部処理 | 合計 `4` で割った確率 `[0.75, 0.25]` でくじ引き | 内部正規化 | 第3章の `sample` と同じ累積区間くじ引き |
| 出力 | `['い']` → `[0]` で `'い'` | `list` → `str` | 複数抽出（`k=...`）にも対応するため必ずリストで返るので `[0]` が必須 |

```python no-run
import random
keys = ["い", "え"]
weights = [3, 1]              # 3:1 の割合 → 75% と 25%
picked_list = random.choices(keys, weights=weights)
print(type(picked_list), picked_list, picked_list[0])   # <class 'list'> ['い'] い
```

## なぜ1文字では足りないのか

:::theory マルコフ性と n-gram
bigramモデルは「次の文字は、**直前の1文字だけ**で決まる」と仮定しています。この「直前だけを見る」性質を **マルコフ性** と言います（「マルコフ連鎖」という名前を聞いたことがあるかもしれません）。

もっと前まで見れば、もっと自然になるはずです。直前2文字なら **trigram**（トライグラム）、一般に直前 $n-1$ 文字を見るモデルを **n-gram** モデルと呼びます。2010年代の半ばごろまで、機械翻訳や音声認識の中心はこのn-gramモデルでした。
:::

では、直前2文字を見るtrigramを作ってみましょう。

```python
following3 = {}
for a, b, c in zip(text, text[1:], text[2:]):
    key = a + b
    if key not in following3:
        following3[key] = Counter()
    following3[key][c] += 1

def generate3(start, n=80):
    out = start
    for _ in range(n):
        c = following3.get(out[-2:])  # 最後の2文字の「次の文字の回数」。辞書になければ None
        if c is None:                 # 続きが見つからなければ
            break                     #   ループを途中で抜けて終わり
        out += random.choices(list(c.keys()), weights=list(c.values()))[0]
    return out

random.seed(1)
print(generate3("私は"))
print("2文字の組み合わせの種類：", len(following3))
```

```output
私はまるでした。先生を見詰めているらしませんからＫに向って、先生が不意にその他妹の夫だの、先生ははたしかし人間が来ると、知らないんでした。奥さんにはまた愛するといて
2文字の組み合わせの種類： 21562
```

「先生を見詰めている」「Ｋに向って」「奥さんにはまた愛する」……かなり『こころ』です！ 直前2文字を見るだけで、ぐっと文章らしくなりました。じゃあ、10文字見れば完璧では？

:::theory データが足りない問題（スパース性）
そうはいきません。見る文字数を増やすと、**組み合わせの数が爆発**します。語彙が2061文字なら、組み合わせの数は文字数に対して指数関数的に膨れ上がります。

- 直前1文字（bigram）：$2061^2 \approx 425$万通り（『こころ』に出てくるのは約2万種類だけ）
- 直前2文字（trigram）：$2061^3 \approx 87.5$億通り
- 直前10文字（11-gram）：$2061^{11} \approx 2.85 \times 10^{36}$通り（地球上の砂粒の数 $\sim 10^{19}$〜$10^{20}$ を桁違いに上回る天文学的数字！ ちなみに観測可能な宇宙全体の原子数は約 $10^{80}$ 個で、さらに25-gramあたりでそれも超えます）

『こころ』全体でもたった16万字しかありません。文字数を少し増やしただけで、組み合わせの大部分はデータの中に**一度も出てこなくなります**。

一度も見たことがない並びに出会うと、数えるだけのモデルは「確率0」と答えるしかありません（上の `generate3` が `None` で止まるのは、このときです）。表のマス目の大半が0でスカスカになってしまうこの現象を、**スパース性**（まばらさ）の問題と言います。

人間なら、「先生は」を見たことがあれば「教授は」の次も似たような言葉が来そうだと推測できます。「先生」と「教授」が**似ている**ことを知っているからです。数えるだけのモデルには、この「似ている」が分かりません。

この壁を越えるために、文字を「数の組（ベクトル）」で表して、似た文字を近くに置く方法を学びます。それがニューラルネットワークの出番であり、第9章の「埋め込み」です。
:::

## 確率の表として眺める

最後に、bigramモデルの正体を「表」として見ておきましょう。行が「今の文字」、列が「次の文字」、中身が回数です。

```python
look = ["先", "生", "私", "は", "。"]
print("今＼次 " + " ".join(f"{b:>4}" for b in look))
for a in look:
    row = " ".join(f"{pairs[(a, b)]:>5}" for b in look)
    print(f"  {a}   {row}")
```

```output
今＼次    先    生    私    は    。
  先       0   597     0     2     0
  生       4     1     0   176     0
  私       0     0     0  1352     0
  は      58     6   145    11     1
  。     112     3   911     3     0
```

「私→は」が1352回、「。→私」が911回。文が終わると、次の文は「私」で始まることが多い。語り手の「私」の物語らしい表です。

本当の表は2061行×2061列、約420万マスもあります。この巨大な「数の表」を効率よく扱う道具が、第6章で学ぶ **行列** と **テンソル** です。

:::warn よくあるつまずき
- **`UnicodeDecodeError`**：`decode("utf-8")` のままになっていませんか？ 青空文庫は `decode("cp932")` です。
- **`IndexError: list index out of range`**（`split(…)[2]` の行）：ダウンロードしたファイルが本文ではなく、エラーページになっている可能性があります。`print(text[:300])` で中身を確認し、URLを見直しましょう。
- **`KeyError`**（`following[ch]` の行）：書き出しの**最後の文字**が『こころ』に出てこない文字だと起きます。「私」「先生」など、本文にある文字で終わる書き出しにしましょう。
:::

:::checklist
- 青空文庫のテキストを `cp932` で読み込めた
- 正規表現でルビを消せた（`?` の有無の違いも見た）
- `Counter` と `zip` で文字のペアを数えた
- bigramモデルで文章を生成した
- trigramにすると自然になるが、組み合わせが爆発することを説明できる
:::

:::recap
- 言語モデルの最も素朴な作り方は、「次の文字」を**数える**こと
- 数えた割合が **条件付き確率** $P(\text{次} \mid \text{今})$。直前1文字なら **bigram**
- 見る文字数を増やすと自然になるが、**組み合わせが爆発**してデータが足りなくなる
- 機械学習では、データの**前処理**（文字コード・ルビ除去）が品質を左右する
:::

:::sensei
さて、bigramモデルは「なんとなく漱石」だった。でも「なんとなく」では研究にならない。モデルが**どれくらい**良いのか、点数をつける必要がある。次の章では、言語モデルの成績表のつけ方を学ぶ。そこで、確率を掛け算していたら、コンピュータが「0」と答えてしまう事件が起きる……。
:::
