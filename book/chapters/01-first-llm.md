## LLMを呼び出す

いよいよです。次のセルを実行します。少し長いですが、1行ずつの意味は後で説明します。今は「呪文」だと思って、そのまま貼り付けてください。

```python
import torch
from transformers import pipeline

gpu = torch.cuda.is_available()   # GPUが使えるなら True、使えないなら False

chat = pipeline(
    "text-generation",                         # やりたいこと：文章を生成する
    model="Qwen/Qwen2.5-0.5B-Instruct",        # 使うモデルの名前
    dtype=torch.float16 if gpu else torch.float32,  # 数の細かさ（GPUなら軽い形式）
    device_map="auto",                         # GPUがあればGPUに載せる
)
print("GPUを使う？", gpu)
```

```output-example
config.json: 100%|██████████| 659/659 [00:00<00:00, 4.21MB/s]
model.safetensors: 100%|██████████| 988M/988M [00:08<00:00, 118MB/s]
...
Device set to use cuda:0
GPUを使う？ True
```

モデルのファイル（約1GB）がインターネットから**ダウンロード**されるので、1〜2分かかります。

:::warn 赤や黄色の文字が出ても、まず落ち着く
`The secret HF_TOKEN does not exist in your Colab secrets.` という黄色い警告が出ることがあります。これは「Hugging Faceのログイン情報がないよ」というお知らせですが、**今回は無視して大丈夫**です。誰でも使える公開モデルなので、ログインなしでダウンロードできます。最後の行に `GPUを使う？ True`（CPUなら `False`）と出ていれば成功です。
:::

:::python import ＝ 道具を借りる
`import torch` は「`torch` という道具箱を借りてくる」という意味です。`torch`（PyTorch）は数値計算とAIのための道具箱、`transformers` はLLMを簡単に扱うための道具箱です。どちらもColabには最初から入っています。<br>
`A if 条件 else B` は「条件が正しければA、そうでなければB」という書き方です。HTMLにはない、Pythonの便利な一行if文です。
:::

`Qwen/Qwen2.5-0.5B-Instruct` は、中国のAlibaba社のチームが公開しているLLMの名前です。`Qwen`（チェン）がシリーズ名、`2.5` が世代、`0.5B` が大きさ（後で説明します）、`Instruct` は「指示に従うように訓練済み」という意味です。商用でも使えるライセンス（Apache 2.0）で公開されています。

:::python リスト と 辞書
`[ ... ]` は **リスト**：ものを順番に並べた入れ物です。`["りんご", "みかん"]` のように書きます。<br>

`messages` は「辞書が並んだリスト」、つまり会話の記録です。HTMLで例えるなら、`<ul>` の中に `<li>` が並んでいて、それぞれの `<li>` に「誰が」「何を言ったか」が書いてある感じです。
:::

最後の行の `result[0]["generated_text"][-1]["content"]` は、返ってきた結果の箱を順番に開けていく操作です。

| 書き方 | 意味 |
|---|---|
| `result[0]` | 結果のリストの0番目（Pythonは0から数えます） |
| `["generated_text"]` | その中の「生成された会話」 |
| `[-1]` | 会話の一番最後（`-1` は「後ろから1番目」） |
| `["content"]` | そのメッセージの「内容」 |

マトリョーシカを外側から1つずつ開けているようなものです。

## 毎回書くのは面倒なので、関数にする

質問のたびに4行書くのは面倒ですね。プログラマは面倒くさがりです。そして面倒くさがりは、**関数**を作ります。

```python
def ask(question, max_new_tokens=200):
    messages = [{"role": "user", "content": question}]
    result = chat(messages, max_new_tokens=max_new_tokens)
    return result[0]["generated_text"][-1]["content"]

print(ask("朝ごはんにおすすめの食べ物を3つ、理由つきで教えて"))
```

```output-example
1. ご飯と味噌汁：エネルギーになる炭水化物と、体を温める味噌汁で一日を元気に始められます。
2. ヨーグルトとフルーツ：腸内環境を整え、ビタミンも取れます。
3. 卵料理：たんぱく質が豊富で、お腹が空きにくくなります。
```

:::python 関数 def
`def ask(question, ...):` は「`ask` という名前の手順を作ります」という宣言です。字下げ（行頭のスペース4つ）された部分が手順の中身で、`return` は「この値を結果として返す」です。<br>
フローチャートで言えば、よく使う処理をひとまとまりの「定義済み処理」の箱にしたものです。一度作れば、`ask("…")` の1行で何度でも呼び出せます。<br>
`max_new_tokens=200` は「指定しなければ200を使う」という**初期値**です。
:::

## LLMの正体：次の言葉を当てるゲームの達人

計算を間違えることがあるのはなぜでしょう？ ここで、この教科書でいちばん大事な話をします。

:::theory LLMがやっていることは、たった1つ
LLMがやっているのは、**「ここまでの文章の続きとして、次に来そうな言葉はどれか」を予測すること**だけです。

「吾輩は猫で」と来たら、次は「ある」が来そう。「今日の天気は」と来たら「晴れ」や「雨」が来そう。LLMはこの「次の言葉当てゲーム」を、インターネット上の膨大な文章で練習して、ものすごく上手になったプログラムです。

1つ予測したら、その言葉を文章の最後に付け足して、また次を予測する。これを何百回も繰り返すと、長い文章ができあがります。

<div class="math-display">「吾輩は」→ 予測「猫」→「吾輩は猫」→ 予測「で」→「吾輩は猫で」→ 予測「ある」→ …</div>

だから「123×456=」の次に来る数字も、**計算しているのではなく「それっぽい数字」を予測している**のです。大きなLLMは練習量が多いので、それっぽさが正解とほぼ一致するようになりますが、小さなモデルはよく外します。人間が暗算せずに「だいたい5万くらい？」と言うのに似ていますね。
:::

本当に「続きを書いているだけ」なのか、確かめてみましょう。会話の形（`messages`）ではなく、ただの文字列を渡すと、LLMは素直に「続き」を書きます。

```python
out = chat("吾輩は猫である。名前は", max_new_tokens=30, do_sample=False)
print(out[0]["generated_text"])
```

```output-example
吾輩は猫である。名前はまだ無い。どこで生れたかとんと見当がつかぬ。何でも薄暗いじめじめした所で
```

`do_sample=False` は「サイコロを振らずに、いちばん確率の高い言葉を毎回選ぶ」という指定です（正確には、同じ言葉のくり返しを減らす調整をした後で、いちばん高いものを選びます）。夏目漱石の『吾輩は猫である』の書き出しを覚えていたようです。ネット上で何度も引用されている文章なので、「次の言葉当てゲーム」の練習で何度も見たのでしょう。

:::minato
え、じゃあチャットで会話できるのはどうしてですか？ 続きを書いてるだけなのに。
:::

:::sensei
いい質問だ！ 実はチャットも「続きを書いている」だけなんだ。会話を「台本」の形の文章に変換して、「アシスタントのセリフ」の続きを書かせている。見てみよう。
:::

```python
messages = [
    {"role": "system", "content": "あなたは陽気な物理の先生です。"},
    {"role": "user", "content": "空はなぜ青いの？"},
]
script = chat.tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
print(script)
```

```output
<|im_start|>system
あなたは陽気な物理の先生です。<|im_end|>
<|im_start|>user
空はなぜ青いの？<|im_end|>
<|im_start|>assistant
```

これが、LLMが実際に受け取っている文章です。`<|im_start|>` や `<|im_end|>` は「ここからセリフ」「ここでセリフ終わり」を表す特別な記号です。最後が `<|im_start|>assistant`（アシスタントのセリフ開始）で終わっているので、LLMはその続き、つまり**アシスタントのセリフ**を書きます。そして `<|im_end|>` を書いたところで止まります。

:::theory チャット＝台本の続き
**チャットモデル**は、この台本形式の文章で「アシスタントのセリフ」を上手に書けるように、追加で訓練されたモデルです（名前の `Instruct` はその意味）。どう訓練するかは第18章で、実際に自分でやります。

台本の一番上の `system` は、劇でいう「役の設定」です。ここを変えると、LLMの話し方が変わります。
:::

## キャラクターを演じさせる

```python
def ask_as(character, question, max_new_tokens=200):
    messages = [
        {"role": "system", "content": character},
        {"role": "user", "content": question},
    ]
    result = chat(messages, max_new_tokens=max_new_tokens)
    return result[0]["generated_text"][-1]["content"]

bongo = "あなたはボンゴ先生です。陽気な物理の先生で、答えに必ずダジャレを1つ入れます。"
print(ask_as(bongo, "空はなぜ青いの？"))
```

```output-example

```

小さなモデル（0.5B）なので、キャラクターを忘れたり、ダジャレが微妙だったりします。それも味です。第18〜19章では、この「ボンゴ先生らしさ」をモデルに**学習**させて、systemに書かなくてもボンゴ先生になるようにします。

## 「大規模」ってどれくらい？

LLMの「L」はLarge（大規模）。何が大規模なのでしょう？ 数えてみましょう。

```python
n = sum(p.numel() for p in chat.model.parameters())
print(f"パラメータの数：{n:,} 個")
```

```output-example
パラメータの数：494,032,768 個
```

:::theory パラメータ＝調整できるつまみ
**パラメータ**は、モデルの中にある「調整できる数」です。音楽のミキサーにたくさん並んでいるつまみを想像してください。LLMの学習とは、このつまみを少しずつ回して、「次の言葉当てゲーム」の成績が良くなる位置を探す作業です。

このモデルには約4億9400万個（0.49 Billion ≒ 0.5B）のつまみがあります。名前の `0.5B` はこれのこと。Bは Billion（10億）の頭文字です。ChatGPTのような最先端のモデルは、これの数百倍〜数千倍のつまみを持つと言われています。

そして、つまみの位置を決めるために読ませる文章の量も大規模です。最近のモデルは、数兆個の言葉（**トークン**）で練習しています。人間が一生かかっても読めない量です。
:::

:::python 一行で数えるテクニック
`sum(p.numel() for p in chat.model.parameters())` は、「モデルの部品（`parameters()`）を1つずつ取り出して、それぞれに入っている数の個数（`numel()`）を数え、全部足す（`sum`）」という意味です。今は「そういう書き方がある」と分かれば十分。<br>
`f"…{n:,}…"` は **f文字列**です。`{ }` の中に変数を書くと値に置き換わり、`:,` を付けると3桁ごとにカンマが入ります。
:::

:::fe 「B」と「iB」
`0.5B` のBは10億（$10^9$）ですが、メモリの「15360MiB」のMiBはメビバイト（$2^{20}$ バイト ≒ 105万バイト）です。基本情報で習う「K・M・G」と「Ki・Mi・Gi」の違いが、こんなところで出てきます。モデルの重さは「パラメータ数 × 1個あたりのバイト数」で、`float16`（数を16ビット＝2バイトで表す形式。第13章で詳しく）なら1個2バイトなので、約4.9億 × 2 ≒ 約1GBになります。さっきダウンロードした `988M` のファイルの大きさと、だいたい合っていますね！
:::

## うまく動かないときは

:::warn よくあるつまずき
- **`ModuleNotFoundError: No module named 'transformers'`**：Colab以外（自分のパソコンなど）で実行していませんか？ Colabなら最初から入っています。自分のパソコンで動かす方法は[付録A](a-setup.html)へ。
- **`CUDA out of memory`**：GPUのメモリが足りません。「ランタイム」→「セッションを再起動する」を押してから、上のセルから順に実行し直しましょう。
- **途中で止まった・接続が切れた**：無料版のColabは、しばらく操作しないと自動で切断されます（目安は数十分〜1時間半ほどで、時期によって変わります）。また、つなぎっぱなしでも最長12時間ほどで切れます。切れたら「再接続」を押して、上から実行し直せばOKです。ノートブック（コード）は残っています。消えるのは、変数やダウンロードしたファイルだけです。
- **ダウンロードが遅い・失敗する**：時間をおいて、そのセルをもう一度実行してください。
:::

:::quiz LLMの基本
LLMが文章を作るとき、毎回やっていることを一言で言うと？
:::answer
「ここまでの文章の続きとして、次に来る言葉を予測する」ことです。予測した言葉を最後に付け足して、また次を予測する……を繰り返します。チャットも、会話を台本形式の文章にして、その続きを書かせているだけです。
:::

:::quiz 計算ミスの理由
小さなLLMが「123×456」を間違えやすいのはなぜでしょう？
:::answer
LLMは計算をしているのではなく、「それっぽい続きの文字」を予測しているからです。数字の並びを確率的に予測しているので、もっともらしいけれど間違った数字を出すことがあります。正確な計算が必要なら、Pythonに計算させるのが確実です（第23章では、LLMに「計算機」という道具を使わせます）。
:::

:::quiz 0.5B
モデル名の「0.5B」は何を表している？
:::answer
パラメータ（調整できる数）の個数が約0.5 Billion、つまり約5億個であることです。
:::
