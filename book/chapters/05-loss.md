## 過去問と本番：データを分ける

モデルの点数をつける前に、大事な準備があります。データを2つに分けるのです。

```python
n = int(len(text) * 0.9)
train_text = text[:n]   # 前の90%：学習用（数える用）
val_text = text[n:]     # 後ろの10%：点数をつける用
print("訓練データ：", len(train_text), "文字")
print("検証データ：", len(val_text), "文字")
```

```output
訓練データ： 146220 文字
検証データ： 16247 文字
```

:::theory なぜ分けるの？
テスト勉強で、過去問の**答えを丸暗記**した人を想像してください。同じ過去問なら満点ですが、本番で少し違う問題が出たら解けません。

モデルも同じです。数えるのに使った文章で点数をつけると、「丸暗記」がうまいほど高得点になってしまいます。本当に知りたいのは「**見たことのない文章**でも、次の文字を当てられるか」です。

そこで、データを分けます。

- **訓練データ**（training data）：モデルが学ぶ（数える）ためのデータ。過去問
- **検証データ**（validation data）：点数をつけるためだけのデータ。モデルには絶対に見せない。本番の模試

さらに研究では、最後の最後に一度だけ使う **テストデータ** をもう1つ取っておくこともあります（第20章）。
:::

訓練データだけでbigramを数え直します。

```python
pairs = Counter(zip(train_text, train_text[1:]))
firsts = Counter(train_text[:-1])

def prob(a, b):
    """P(b | a)：「a」の次が「b」である確率"""
    if firsts[a] == 0:
        return 0.0
    return pairs[(a, b)] / firsts[a]

print("P(生|先) =", prob("先", "生"))
print("P(は|生) =", prob("生", "は"))
```

```output
P(生|先) = 0.8857566765578635
P(は|生) = 0.23097112860892388
```

## 文章の確率を計算する

モデルが「この文章はありそうだ」と思うほど、良いモデルのはずです。では、文章全体の確率はどう計算するのでしょう？ 「先生は」が出てくる確率は、「先の次に生」かつ「生の次には」なので、**掛け算**になります。

$$P(\text{先生は}) = P(\text{生} \mid \text{先}) \times P(\text{は} \mid \text{生}) = 0.886 \times 0.231 \approx 0.205$$

（厳密には最初の「先」の確率も掛けますが、ここでは省きます。）では、訓練データの最初の数百文字で同じことをしてみましょう。どのペアも訓練データで数えたものなので、確率が0になることはないはずです。

```python
p = 1.0
for i, (a, b) in enumerate(zip(train_text, train_text[1:])):
    p = p * prob(a, b)
    if i in [10, 50, 100, 150, 200, 300]:
        print(f"{i:4d}文字目まで：確率 {p}")
```

```output
  10文字目まで：確率 2.999105026951313e-16
  50文字目まで：確率 2.7431965930303487e-71
 100文字目まで：確率 5.506246902145188e-135
 150文字目まで：確率 1.2818683751043334e-213
 200文字目まで：確率 2.0794249766405372e-279
 300文字目まで：確率 0.0
```

:::sensei
事件だ！ どのペアも確率は0じゃないのに、掛け算を続けたら、300文字目でとうとう**ぴったり0**になってしまった。200文字目の `e-279` は「10のマイナス279乗」、つまり小数点の後に0が278個並ぶ数だ。宇宙にある原子の数（だいたい $10^{80}$ 個）で1を割っても、まだまだこんなに小さくはならない。
:::

:::fe アンダーフロー
コンピュータの小数（**浮動小数点数**）には、表せる大きさに限界があります。Pythonの `float`（倍精度、64ビット）では、だいたい $10^{-308}$ より小さい数はまともに表せず、最後は0になってしまいます。これを **アンダーフロー** と言います。基本情報の「浮動小数点数の表現」で、指数部のビット数が限られていることを習いましたね。それがここで牙をむいたのです。
:::

0になってしまうと、どのモデルの確率も「0」で、比べようがありません。どうしましょう？

## 救世主：対数（log）

ここで登場するのが **対数**（たいすう、logarithm）です。

:::math 対数は「何回掛けたか」を数える
$\log_{10} 1000$ は「10を何回掛けたら1000になるか」という意味で、答えは3です（$10 \times 10 \times 10 = 1000$）。

| $x$ | 0.001 | 0.01 | 0.1 | 1 | 10 | 100 | 1000 |
|---|---|---|---|---|---|---|---|
| $\log_{10} x$ | -3 | -2 | -1 | 0 | 1 | 2 | 3 |

1より小さい数はマイナスになります（0.01は「10で2回割った」ので -2）。

機械学習では、10の代わりに第3章で出てきた $e \approx 2.718$ を使う対数（**自然対数**）をよく使います。単に $\log$ と書いたら自然対数のことが多く、Pythonでは `math.log` です。
:::

```python
print(math.log10(1000), math.log10(0.01))
print(math.log(math.e), math.log(1))
print(math.log(0.5), math.log(0.01))
```

```output
3.0 -2.0
1.0 0.0
-0.6931471805599453 -4.605170185988091
```

:::theory 対数の3つの性質（これだけ覚えればOK）
1. **掛け算が足し算になる**：$\log(a \times b) = \log a + \log b$
2. **1は0になる**：$\log 1 = 0$
3. **1より小さい数はマイナス**、0に近づくほどどんどんマイナスに大きくなる

性質1がすごいのです。確率の**掛け算**を、対数の**足し算**に変えられます。足し算なら、何千回くり返しても0にはなりません（-1000とか-5000とかになるだけ）。
:::

```python
log_p = 0.0
for i, (a, b) in enumerate(zip(train_text, train_text[1:])):
    log_p = log_p + math.log(prob(a, b))
    if i in [10, 50, 100, 200, 300]:
        print(f"{i:4d}文字目まで：log確率 {log_p:.1f}")
```

```output
  10文字目まで：log確率 -35.7
  50文字目まで：log確率 -162.5
 100文字目まで：log確率 -309.1
 200文字目まで：log確率 -641.7
 300文字目まで：log確率 -951.2
```

もう0になりません。事件解決です。

## 損失：驚きの平均

「log確率の合計」は文章が長いほどマイナスに大きくなるので、長さの違う文章どうしを比べにくいです。そこで、**1文字あたりの平均**にします。さらに、マイナスの数は扱いにくいので、**符号をひっくり返して**プラスにします。これが言語モデルの点数、**損失**（loss）です。

$$\text{損失} = -\frac{1}{N}\sum_{i=1}^{N} \log P(\text{次の文字}_i \mid \text{今の文字}_i)$$

:::theory 損失は「驚き」の平均
$-\log p$ は、確率 $p$ のことが起きたときの **驚きの大きさ** と考えられます。

- 確率1（絶対起きると思っていた）ことが起きた → 驚き $-\log 1 = 0$
- 確率0.5のことが起きた → 驚き 0.69
- 確率0.01（まさか！）のことが起きた → 驚き 4.6
- 確率0のことが起きた → 驚き **無限大**

損失は、モデルが検証データを1文字ずつ読みながら感じた「驚き」の平均です。良いモデルほど、次の文字を予想できているので、驚きが少ない。だから **損失は小さいほど良い** のです。ゴルフのスコアと同じですね。

ちなみに、この量は **負の対数尤度**（negative log-likelihood、NLL）や、**交差エントロピー**（cross-entropy）とも呼ばれます。名前はいかめしいですが、中身は「驚きの平均」です。
:::

驚きの大きさをグラフにしてみましょう。グラフを描く道具 `matplotlib` を使います（日本語を表示するための追加の道具も入れます）。

```python

```

![確率pと驚き-log pのグラフ。pが1に近いと0、pが0に近づくと急に大きくなる](img/figs/05-loss/cell7_0.png)

それでは、訓練データと検証データで損失を計算してみましょう。

```python
def bigram_loss(data, prob_fn):
    total = 0.0
    for a, b in zip(data, data[1:]):
        p = prob_fn(a, b)
        if p == 0:
            return float("inf")       # 確率0の出来事 → 驚きは無限大
        total += -math.log(p)
    return total / (len(data) - 1)

print("訓練データの損失：", bigram_loss(train_text, prob))
print("検証データの損失：", bigram_loss(val_text, prob))
```

```output
訓練データの損失： 3.010172965334805
検証データの損失： inf
```

:::minato
検証データの損失が `inf`……無限大？
:::

:::sensei
検証データには、訓練データで**一度も見たことがない**文字のペアが出てくるからだ。数えるだけのモデルは、見たことのないペアに確率0をつける。そして、確率0のことが起きたら、驚きは無限大。モデルは「絶対にありえない！」と言い張っていたのに、起きてしまったわけだ。
:::

```python
unseen = sum(1 for a, b in zip(val_text, val_text[1:]) if pairs[(a, b)] == 0)
print("検証データのペア：", len(val_text) - 1, "個のうち、訓練で見ていないもの：", unseen, "個")
```

## 「絶対」を言わないモデル：スムージング

対策はシンプルです。**どのペアにも、ほんの少しだけ回数を足しておく**のです。見たことがないペアにも「0.01回くらいは見たかもね」とおまけをつける。これを **スムージング**（smoothing、なめらかにする）と言います。

$$P(b \mid a) = \frac{\text{「ab」の回数} + k}{\text{「a」の回数} + k \times V}$$

$V$ は語彙の数です。分母にも $k \times V$ を足すのは、確率の合計をちゃんと1にするためです（全部の $b$ に $k$ ずつ足したので）。

```python
V = len(set(text))

def make_smoothed(k):
    def p(a, b):
        return (pairs[(a, b)] + k) / (firsts[a] + k * V)
    return p

for k in [1, 0.1, 0.01, 0.001]:
    p_k = make_smoothed(k)
    print(f"k={k:<6} 訓練 {bigram_loss(train_text, p_k):.3f}   検証 {bigram_loss(val_text, p_k):.3f}")
```

```output
k=1      訓練 4.303   検証 4.385
k=0.1    訓練 3.488   検証 3.748
k=0.01   訓練 3.139   検証 3.581
k=0.001  訓練 3.033   検証 3.652
```

:::python 関数を作る関数
`make_smoothed(k)` は、`k` の値を覚えた確率関数 `p` を作って返す関数です。関数も変数のように受け渡しできるのがPythonの面白いところです。今は「`k` ごとに別の確率関数を作っている」と分かればOKです。
:::

:::theory ハイパーパラメータは検証データで選ぶ
`k` は小さいほど**訓練**の損失は良くなります（数えた結果に忠実になるので）。でも**検証**の損失は、`k=0.01` がいちばん良く、小さすぎても大きすぎても悪化しています。

- `k` が大きすぎる：おまけが多すぎて、せっかく数えた知識が薄まる（「先」の次の「生」まで、他の文字と大差なくなる）
- `k` が小さすぎる：見たことのないペアへの驚きが大きすぎる

このように、**人間が事前に決める設定値**を **ハイパーパラメータ** と呼びます（これに対して、データから決まる値がパラメータ）。ハイパーパラメータは、**検証データの成績で選ぶ**のが鉄則です。訓練データで選ぶと、「丸暗記」に有利な値を選んでしまいます。
:::

## パープレキシティ：何択で迷っているか

損失「3.581」と言われても、ピンとこないかもしれません。そこで、もう少し直感的な数に変換します。

$$\text{パープレキシティ} = e^{\text{損失}}$$

```python
print("bigram（k=0.01）のパープレキシティ：", math.exp(3.581))
print("でたらめに選ぶモデルの損失：", math.log(V), " パープレキシティ：", math.exp(math.log(V)))
```

```output
bigram（k=0.01）のパープレキシティ： 35.909432330660664
でたらめに選ぶモデルの損失： 7.630946580890459  パープレキシティ： 2061.0
```

:::theory パープレキシティ＝「何択問題で迷っているか」
**パープレキシティ**（perplexity、困惑度）は、「モデルが毎回、だいたい何個の候補の中で迷っているか」を表します。

- 2061文字から完全にでたらめに選ぶモデル：毎回2061択で迷う → パープレキシティ2061（損失は $\log 2061 \approx 7.63$）
- 私たちのbigramモデル：だいたい36択くらいまで絞り込めている → パープレキシティ約36

2061択から36択へ。数えるだけで、迷いを約57分の1にできたわけです。なかなかやります。
:::

## 記録表をつけよう

これから章を進むごとに、新しいモデルを作り、この**検証データの損失**で成績を比べていきます。いわば、モデルの進化の記録表です。

| モデル | 章 | 検証データの損失 | パープレキシティ |
|---|---|---|---|
| でたらめ（一様分布） | 5 | 7.631 | 2061 |
| bigram（数える、k=0.01） | 5 | 3.581 | 35.9 |
| ？？？ | 8 | ？ | ？ |
| ？？？ | 9 | ？ | ？ |
| ？？？ | 13 | ？ | ？ |

どこまで小さくできるでしょうか。ちなみに、第13章のGPTは……それは見てのお楽しみ。

:::deep 情報理論との関係（ビットで数える）
自然対数の代わりに $\log_2$ を使うと、損失の単位は **ビット** になります。「1文字を予測するのに、平均何ビット分の情報が足りないか」という意味で、**エントロピー**という考え方につながります。$\log_2 x = \log x / \log 2$ なので、3.581 ÷ 0.693 ≈ 5.17ビット。つまり私たちのモデルは、次の1文字を当てるのに「Yes/Noの質問をあと約5回したい」状態です。<br>
この考え方は、1948年にクロード・シャノンが作った **情報理論** から来ています。シャノンは英語の1文字あたりのエントロピーを、人間に次の文字を当てさせる実験で推定しました。まさに人間を言語モデルとして使ったわけです。
:::

:::warn よくあるつまずき
- **`ValueError: math domain error`**：`math.log(0)` を計算しようとしています。確率0が混ざっていないか確認しましょう（それがこの章の事件です）。
- **グラフの日本語が「□□□」になる**：`import matplotlib_fontja` を忘れていませんか？ その前の `!pip install -q matplotlib-fontja` も実行しましょう。
:::

:::quiz 損失の向き
モデルAの検証損失は3.2、モデルBは2.9でした。どちらが良いモデル？
:::answer
モデルBです。損失は「驚きの平均」なので、小さいほど次の文字をうまく予想できています。
:::

:::quiz 対数の性質
$\log(0.5 \times 0.5 \times 0.5)$ を、$\log 0.5 \approx -0.693$ を使って計算すると？
:::answer
掛け算は足し算になるので、$\log 0.5 + \log 0.5 + \log 0.5 \approx -0.693 \times 3 = -2.079$ です。
:::

:::quiz パープレキシティ
損失がちょうど $\log 10 \approx 2.303$ のモデルのパープレキシティは？ 何を意味する？
:::answer
$e^{\log 10} = 10$。モデルは平均して「10択」くらいで迷っている、という意味です。
:::

:::checklist
- 訓練データと検証データを分ける理由を説明できる
- 確率を掛け続けると0になる（アンダーフロー）のを見た
- 対数で掛け算を足し算に変えられることを確かめた
- 損失＝驚きの平均、小さいほど良い、と説明できる
- スムージングの k を検証データで選んだ
- 記録表の最初の2行を埋めた
:::

:::recap
- データは **訓練用** と **検証用** に分ける。点数は検証データでつける
- 確率の掛け算はすぐ0になる（アンダーフロー）。**対数**で足し算にする
- **損失** ＝ $-\log(\text{確率})$ の平均 ＝ 驚きの平均。小さいほど良い
- 見たことのないものに確率0をつけると損失が無限大。**スムージング**で防ぐ
- **パープレキシティ** ＝ $e^{\text{損失}}$ ＝ 何択で迷っているか
