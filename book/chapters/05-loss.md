訓練データだけでbigramを数え直します。

```python
pairs = Counter(zip(train_text, train_text[1:]))
firsts = Counter(train_text[:-1])

def prob(a, b):
    """P(b | a)：「a」の次が「b」である確率"""
    if firsts[a] == 0:
        return 0.0
    return pairs[(a, b)] / firsts[a]

print("P(生|先) =", prob("先", "生"))
print("P(は|生) =", prob("生", "は"))
```

## 文章の確率を計算する

モデルが「この文章はありそうだ」と思うほど、良いモデルのはずです。では、文章全体の確率はどう計算するのでしょう？ 「先生は」が出てくる確率は、「先の次に生」かつ「生の次には」なので、**掛け算**になります。

$$P(\text{先生は}) = P(\text{生} \mid \text{先}) \times P(\text{は} \mid \text{生}) = 0.886 \times 0.231 \approx 0.205$$

（厳密には最初の「先」の確率も掛けますが、ここでは省きます。）では、訓練データの最初の数百文字で同じことをしてみましょう。どのペアも訓練データで数えたものなので、確率が0になることはないはずです。

```python
p = 1.0
for i, (a, b) in enumerate(zip(train_text, train_text[1:])):
    p = p * prob(a, b)
    if i in [10, 50, 100, 150, 200, 300]:
        print(f"{i:4d}文字目まで：確率 {p}")
```

```output
  10文字目まで：確率 2.999105026951313e-16
  50文字目まで：確率 2.7431965930303487e-71
 100文字目まで：確率 5.506246902145188e-135
 150文字目まで：確率 1.2818683751043334e-213
 200文字目まで：確率 2.0794249766405372e-279
 300文字目まで：確率 0.0
```

:::sensei
事件だ！ どのペアも確率は0じゃないのに、掛け算を続けたら、300文字目でとうとう**ぴったり0**になってしまった。200文字目の `e-279` は「10のマイナス279乗」、つまり小数点の後に0が278個並ぶ数だ。宇宙にある原子の数（だいたい $10^{80}$ 個）で1を割っても、まだまだこんなに小さくはならない。
:::

:::fe アンダーフロー
コンピュータの小数（**浮動小数点数**）には、表せる大きさに限界があります。Pythonの `float`（倍精度、64ビット）では、だいたい $10^{-308}$ より小さい数はまともに表せず、最後は0になってしまいます。これを **アンダーフロー** と言います。基本情報の「浮動小数点数の表現」で、指数部のビット数が限られていることを習いましたね。それがここで牙をむいたのです。
:::

## 救世主：対数（log）

ここで登場するのが **対数**（たいすう、logarithm）です。記号を丸暗記するのではなく、「なぜ対数が必要なのか」から9ステップでたどりましょう。

:::math 対数 $\log$：9ステップで理由から理解する
**① 解決したい具体的な問題**：何千文字もの確率の掛け算 $p_1 \times p_2 \times \dots \times p_N$ を、0に潰れず（アンダーフローせず）、かつ**モデル間の大小関係を変えずに**計算したい。

**② 素朴な掛け算ではなぜダメなのか？**：確率は必ず $0 \le p \le 1$ なので、掛けるたびに桁が急減します。300文字も掛けると $10^{-308}$ を下回り、64ビット浮動小数点数（`float`）では `0.0` に丸められて全モデルの点数が同じ `0.0` になってしまいます。

**③ 新しい発想**：「数そのもの」ではなく、**「ある基準の数を何回掛けたか（指数の肩の数）」**で数える世界へ引っ越す。指数の世界では**掛け算が足し算に化ける**（$10^2 \times 10^3 = 10^{2+3}$）ので、何万回足しても0に潰れません！

**④ 記号の読み方表**：
| 記号 | 読み方 | 意味 |
|---|---|---|
| $\log_{10} x$ | 「ログ10の $x$」 | $10$ を何回掛けたら $x$ になるか（常用対数） |
| $\log x$（または $\ln x$） | 「ログ $x$」（自然対数） | 第3章の $e \approx 2.718$ を何回掛けたら $x$ になるか。Pythonは `math.log(x)` |
| $e^x$ と $\log x$ | 互いに逆の操作 | $\log(e^x) = x$、$e^{\log y} = y$（$y > 0$） |

**⑤ 小さな数字で手計算**：$\log_{10} 1000$ は「10を何回掛けたら1000になるか」という意味で、答えは `3` です（$10 \times 10 \times 10 = 1000$）。

| $x$ | 0.001 | 0.01 | 0.1 | 1 | 10 | 100 | 1000 |
|---|---|---|---|---|---|---|---|
| $\log_{10} x$ | -3 | -2 | -1 | 0 | 1 | 2 | 3 |

1より小さい数はマイナスになります（`0.01` は「10で2回割った」＝ $10^{-2}$ なので `-2`）。掛け算も検算してみましょう：$0.1 \times 0.01 = 0.001$ ですが、対数にすると $(-1) + (-2) = -3 = \log_{10}(0.001)$ とぴったり一致します！

**⑥ 一般式（自然対数）**：機械学習では10の代わりに $e \approx 2.718$ を底にした **自然対数** $\log$ を使います（第3章の `softmax` に出てくる $e^x$ のちょうど逆関数だからです）。
$$\log(p_1 \times p_2 \times \dots \times p_N) = \log p_1 + \log p_2 + \dots + \log p_N = \sum_{i=1}^{N} \log p_i$$

**⑦ Pythonでの検算**（下のセルで実際に確かめます）：`math.log(math.e) == 1.0`、`math.log(1) == 0.0`、`math.log(0.5) ≈ -0.693`。

**⑧ よくある誤解**：$\log(a + b) = \log a + \log b$ ではありません！ 足し算に分解できるのは**掛け算** $\log(a \times b) = \log a + \log b$ のときだけです。また $\log 0$ は定義できず（$-\infty$ に発散）、Pythonではエラーになります。
:::

```python
print(math.log10(1000), math.log10(0.01))
print(math.log(math.e), math.log(1))
print(math.log(0.5), math.log(0.01))
```

```output
3.0 -2.0
1.0 0.0
-0.6931471805599453 -4.605170185988091
```

:::theory 対数の3つの性質（これだけ覚えればOK）
1. **掛け算が足し算になる**：$\log(a \times b) = \log a + \log b$
2. **1は0になる**：$\log 1 = 0$
3. **1より小さい数はマイナス**、0に近づくほどどんどんマイナスに大きくなる

性質1がすごいのです。確率の**掛け算**を、対数の**足し算**に変えられます。足し算なら、何千回くり返しても0にはなりません（-1000とか-5000とかになるだけ）。
:::

```python
log_p = 0.0
for i, (a, b) in enumerate(zip(train_text, train_text[1:])):
    log_p = log_p + math.log(prob(a, b))
    if i in [10, 50, 100, 200, 300]:
        print(f"{i:4d}文字目まで：log確率 {log_p:.1f}")
```

```output
  10文字目まで：log確率 -35.7
  50文字目まで：log確率 -162.5
 100文字目まで：log確率 -309.1
 200文字目まで：log確率 -641.7
 300文字目まで：log確率 -951.2
```

もう0になりません。事件解決です。

## 損失：驚きの平均

「log確率の合計」は文章が長いほどマイナスに大きくなるので、長さの違う文章どうしを比べにくいです。そこで、**1文字あたりの平均**にします。さらに、マイナスの数は扱いにくいので、**符号をひっくり返して**プラスにします。これが言語モデルの点数、**損失**（loss）です。

$$L = -\frac{1}{N}\sum_{i=1}^{N} \log p_i = -\frac{1}{N}\sum_{i=1}^{N} \log P(\text{次の文字}_i \mid \text{今の文字}_i)$$

:::math なぜ $1-p$ ではなく $-\log p$ なのか？：9ステップで理由から理解する
**① 解決したい具体的な問題**：正解文字に対する予測確率 $p_1, p_2, \dots, p_N$ から、「外したほど大きい罰（損失）」を1つの数 $L$ にまとめたい。

**② 素朴な方法（$1 - p$ や $(1 - p)^2$）ではなぜダメなのか？**
「外れ度合いなら $1 - p$ や $(1 - p)^2$ でよさそう」と思えますよね。実際に極端な外れ値で比べてみましょう。

| モデルが正解につけた確率 $p$ | $1 - p$ | $(1 - p)^2$ | $-\log p$ |
|---|---|---|---|
| $1.0$（完璧に的中） | $0.00$ | $0.00$ | $0.00$ |
| $0.5$（五分五分） | $0.50$ | $0.25$ | $0.69$ |
| $0.01$（1%と軽視） | $0.99$ | $0.9801$ | $4.61$ |
| $0.0001$（0.01%と決めつけて大外れ） | $0.9999$ | $0.9998$ | $9.21$ |
| $0$（絶対に起きないと断言して大外れ） | $1.00$ | $1.00$ | $\infty$（無限大！） |

- **欠点1（大外れに甘すぎる）**：$1 - p$ や $(1 - p)^2$ では「確率1%」と「確率0.01%」の罰が `0.99` vs `0.9999` でほとんど差がつかず、「絶対に起きない（$p=0$）」と断言して外してもたかだか `1.0` の減点で済んでしまいます。一方 $-\log p$ は $p$ が0に近づくほど急激に重い罰を与え、自信満々な大外れを徹底的に矯正します。
- **欠点2（同時確率の積と一致しない）**：$1 - p$ の平均を小さくしても、文章全体の同時確率 $\prod_{i=1}^N p_i$ を最大にすることとは一致しません。**$-\log p$ の平均だけを小さくすることが、同時確率 $\prod_i p_i$ の最大化（最尤推定）と数学的にぴったり一致**します（$-\frac{1}{N}\log \prod_i p_i = -\frac{1}{N}\sum_i \log p_i$）。
- **先取りの利点（第8章）**：第3章の `softmax` と $-\log p$ を組み合わせると、学習に使う微分（勾配）が $p - y$ という最もシンプルで壊れにくい形になります！

**③ 記号の読み方表**：
| 記号 | 読み方・役割 |
|---|---|
| $L$ | 損失（Loss）。小さいほど良い（0が完璧） |
| $-$ | 負の対数 $\log p_i \le 0$ の符号を反転し、0以上の「驚き」にする |
| $\frac{1}{N}$ | ペア総数 $N$ で割り、文章の長さに依らない「1文字あたりの平均」にする |
| $\sum_{i=1}^{N}$ | $i=1$ から $N$ まで全ペアの対数確率を足し合わせる（第3章の $\sum$） |
| $p_i$ | $i$ 番目の正解文字にモデルが割り当てた予測確率 $P(\text{次}_i \mid \text{今}_i)$ |

**④ 小さな数字で手計算**：3ステップの正解確率が $p = [0.5,\; 0.5,\; 1.0]$ のとき（$\log 0.5 \approx -0.693,\; \log 1.0 = 0$）：
$$L = -\frac{1}{3}\bigl(\log 0.5 + \log 0.5 + \log 1.0\bigr) \approx -\frac{1}{3}(-0.693 - 0.693 + 0) = \frac{1.386}{3} = 0.462$$

**⑤ Pythonの最小コードで検算**：
```python no-run
import math
probs = [0.5, 0.5, 1.0]
loss = -sum(math.log(p) for p in probs) / len(probs)
print(round(loss, 3))   # 0.462
```
:::

:::theory 損失は「驚き」の平均
$-\log p$ は、確率 $p$ のことが起きたときの **驚きの大きさ** と考えられます。

天気予報に例えてみましょう。
- 「明日は100%晴れ」と予報して本当に晴れたら、驚きはゼロです（$-\log 1 = 0$）
- 「降水確率50%」と言われて雨が降ったら、コイントスが裏だったくらいで少し驚きます（$-\log 0.5 \approx 0.69$）
- 「降水確率1%」と言われて雨が降ったら、「えっ、降ったの！？」とかなり驚きます（$-\log 0.01 \approx 4.6$）
- 「降水確率0%（絶対に雨は降らない）」と断言していたのに土砂降りになったら、「嘘でしょ！？」と無限大にショックを受けます（$-\log 0 = \infty$）

損失は、モデルが検証データを1文字ずつ読みながら感じた「驚き」の平均です。良いモデルほど、次の文字を正しく予想できているので、驚きが少ない。だから **損失は小さいほど良い** のです。ゴルフのスコアと同じですね。

ちなみに、この量は **負の対数尤度**（negative log-likelihood、NLL）や、**交差エントロピー**（cross-entropy）とも呼ばれます。名前はいかめしいですが、中身は「驚きの平均」です。
:::

それでは、訓練データと検証データで損失を計算してみましょう。

```python
def bigram_loss(data, prob_fn):
    total = 0.0
    for a, b in zip(data, data[1:]):
        p = prob_fn(a, b)
        if p == 0:
            return float("inf")       # 確率0の出来事 → 驚きは無限大
        total += -math.log(p)
    return total / (len(data) - 1)

print("訓練データの損失：", bigram_loss(train_text, prob))
print("検証データの損失：", bigram_loss(val_text, prob))
```

検証データの損失： inf

:::scaffold 理解のための最小コード：`float("inf")` とゼロ確率ガード
Pythonで `math.log(0)` を直接呼ぶと `ValueError: math domain error` で強制終了してしまいます。そこで `if p == 0: return float("inf")` で先にガードしています。

| 式 | 値 | 型 | 性質 |
|---|---|---|---|

## 「絶対」を言わないモデル：スムージング

対策はシンプルです。**どのペアにも、ほんの少しだけ回数を足しておく**のです。見たことがないペアにも「0.01回くらいは見たかもね」とおまけをつける。これを **スムージング**（smoothing、なめらかにする）と言います。

$$P(b \mid a) = \frac{\text{「ab」の回数} + k}{\text{「a」の回数} + k \times V}$$

$V$ は語彙の数です。分母にも $k \times V$ を足すのは、確率の合計をちゃんと1にするためです（全部の $b$ に $k$ ずつ足したので）。

:::math 小さな手計算で確かめる（$V = 4$、$k = 1$）
語彙が `あ, い, う, え`（$V = 4$）だけの世界で、「あ」の出現が6回（内訳：`あい:3, あう:2, ああ:1, あえ:0`）だったとします。全4文字に $k = 1$ ずつ足すと、分母も $k \times V = 1 \times 4 = 4$ 増えて $6 + 4 = 10$ になります。

| 次の文字 $b$ | 元の回数 | $+k$ 後の分子 | スムージング後の確率 $P(b \mid \text{あ})$ |
|---|---|---|---|
| い | 3 | $3+1=4$ | $4/10 = 0.4$ |
| う | 2 | $2+1=3$ | $3/10 = 0.3$ |
| あ | 1 | $1+1=2$ | $2/10 = 0.2$ |
| え（未出現！） | 0 | $0+1=1$ | $1/10 = 0.1$（0にならない！） |
| **合計** | **6** | **$6 + 4 = 10$** | **$0.4 + 0.3 + 0.2 + 0.1 = 1.0$** |

もし分母に $+k \times V$ を忘れると合計が $10/6 = 1.67$ になって確率分布が壊れてしまいます。分母の $k \times V$ は「全 $V$ 文字に $k$ ずつ足した増分を帳尻合わせする項」なのです。
:::

```python
V = len(set(text))

def make_smoothed(k):
    def p(a, b):
        return (pairs[(a, b)] + k) / (firsts[a] + k * V)
    return p

for k in [1, 0.1, 0.01, 0.001]:
    p_k = make_smoothed(k)
    print(f"k={k:<6} 訓練 {bigram_loss(train_text, p_k):.3f}   検証 {bigram_loss(val_text, p_k):.3f}")
```

```output
k=1      訓練 4.303   検証 4.385
k=0.1    訓練 3.488   検証 3.748
k=0.01   訓練 3.139   検証 3.581
k=0.001  訓練 3.033   検証 3.652
```

:::python 関数を作る関数
`make_smoothed(k)` は、`k` の値を覚えた確率関数 `p` を作って返す関数です。関数も変数のように受け渡しできるのがPythonの面白いところです。今は「`k` ごとに別の確率関数を作っている」と分かればOKです。
:::

:::scaffold 理解のための最小コード：クロージャ（関数を返す関数 `make_smoothed(k)`）
「関数の中で別の関数 `def p(...)` を作り、その関数自体を `return p` で返す」仕組みを **クロージャ（closure）** と呼びます。外側の引数 `k` を内側の関数が記憶し続けるのがポイントです。

| ステップ | コード | 返る値・型 | 起きていること |
|---|---|---|---|
| ① 工場を呼ぶ | `p_k = make_smoothed(0.01)` | `function`（まだ確率計算はしない！） | `k=0.01` を覚えた新しい関数 `p` が作られる |
| ② 渡す | `bigram_loss(val_text, p_k)` | 関数をそのまま引数 `prob_fn` に渡す | `bigram_loss` の中で毎回 `p_k(a, b)` が呼ばれる |
| ③ 実行 | `p_k("先", "生")` | `float`（約 `0.855`） | 記憶していた `k=0.01` を使って確率を計算する |

最小の例で動きを確かめましょう：
```python no-run
def make_adder(k):
    def f(x):
        return x + k     # 外側の k を覚えている！
    return f             # 関数そのものを返す（f() と呼ばない点に注意）

add2 = make_adder(2)     # type(add2) は <class 'function'>
add10 = make_adder(10)
print(add2(5), add10(5)) # 7 15
```
:::

:::theory ハイパーパラメータは検証データで選ぶ
`k` は小さいほど**訓練**の損失は良くなります（数えた結果に忠実になるので）。でも**検証**の損失は、`k=0.01` がいちばん良く、小さすぎても大きすぎても悪化しています。

- `k` が大きすぎる：おまけが多すぎて、せっかく数えた知識が薄まる（「先」の次の「生」まで、他の文字と大差なくなる）
- `k` が小さすぎる：見たことのないペアへの驚きが大きすぎる

| 種類 | 誰が決める？ | 例（この章〜今後の章） |
|---|---|---|
| **パラメータ** | **訓練データ**から自動で決まる | bigramの回数表・確率表、ニューラルネットの重み行列（第6章） |
| **ハイパーパラメータ** | **人間**が事前に決め、**検証データ**で選ぶ | スムージングの `k`、学習率（第7章）、層の数、温度 `T` |

ハイパーパラメータは、**検証データの成績で選ぶ**のが鉄則です。訓練データで選ぶと、「丸暗記」に有利な値（`k=0`）を選んでしまいます。
:::

## パープレキシティ：何択で迷っているか

損失「3.581」と言われても、ピンとこないかもしれません。そこで、もう少し直感的な数に変換します。

$$\text{パープレキシティ} = e^{\text{損失}}$$

```python
print("bigram（k=0.01）のパープレキシティ：", math.exp(3.581))
print("でたらめに選ぶモデルの損失：", math.log(V), " パープレキシティ：", math.exp(math.log(V)))
```

```output
bigram（k=0.01）のパープレキシティ： 35.909432330660664
でたらめに選ぶモデルの損失： 7.630946580890459  パープレキシティ： 2061.0
```

:::theory パープレキシティ＝「何択問題で迷っているか」
**パープレキシティ**（perplexity、困惑度）は、「モデルが毎回、だいたい何個の候補の中で迷っているか」を表します。英語の perplexity は「困惑・当惑」という意味です。

- 2061文字から完全にでたらめに選ぶモデル：毎回2061択で迷う → パープレキシティ2061（損失は $\log 2061 \approx 7.63$）
- 私たちのbigramモデル：だいたい36択くらいまで絞り込めている → パープレキシティ約36

4択クイズなら迷いは4ですが、2061択のマークシートを毎回渡されたら頭を抱えますよね。パープレキシティが約36ということは、モデルの頭の中では「実質36択のクイズを解いているくらいの迷い度合い」まで選択肢を絞り込めている、ということです。

小さな数字で確かめてみましょう：
- 毎回4択を均等（確率 $1/4 = 0.25$）に迷うモデル：損失 $L = -\log(1/4) = \log 4 \approx 1.386$ → $\text{PPL} = e^{\log 4} = 4$（ちょうど4択！）
- 毎回100%的中（確率 $1.0$）する完璧なモデル：損失 $L = -\log 1 = 0$ → $\text{PPL} = e^0 = 1$（迷いゼロの1択！）

2061択から36択へ。数えるだけで、迷いを約57分の1にできたわけです。なかなかやります。
:::

:::deep 情報理論との関係（ビットで数える）
自然対数の代わりに $\log_2$ を使うと、損失の単位は **ビット** になります。「1文字を予測するのに、平均何ビット分の情報が足りないか」という意味で、**エントロピー**という考え方につながります。$\log_2 x = \log x / \log 2$ なので、3.581 ÷ 0.693 ≈ 5.17ビット。つまり私たちのモデルは、次の1文字を当てるのに「Yes/Noの質問をあと約5回したい」状態です。<br>
この考え方は、1948年にクロード・シャノンが作った **情報理論** から来ています。シャノンは英語の1文字あたりのエントロピーを、人間に次の文字を当てさせる実験で推定しました。まさに人間を言語モデルとして使ったわけです。
:::
