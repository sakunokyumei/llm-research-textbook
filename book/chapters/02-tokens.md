## LLMの「辞書」を借りる

LLMは、文章を数字に変えるための専用の辞書を持っています。この辞書と変換係をまとめて **トークナイザー**（tokenizer）と呼びます。第1章のQwenのトークナイザーだけを借りてきましょう。モデル本体（約1GB）は使わないので、ダウンロードは一瞬です。

```python
from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
print("語彙の数：", len(tok))
```

```output
語彙の数： 151665
```

このトークナイザーは、15万1665種類の「言葉のかけら」を知っています。この1つ1つのかけらを **トークン**（token）、トークン全体の一覧を **語彙**（ごい、vocabulary）と呼びます。

## 文章を数字に変える

```python
ids = tok.encode("吾輩は猫である。")
print(ids)
```

```output
[106046, 116599, 15322, 100472, 126230, 1773]
```

出ました。これが、LLMが見ている「吾輩は猫である。」の姿です。6個の数字になりました。この数字を **トークンID** と呼びます。辞書のページ番号みたいなものです。

逆向き（数字→文章）もできます。

```python
print(tok.decode(ids))
```

```output
吾輩は猫である。
```

ちゃんと元に戻りました。では、それぞれの数字が、どの「かけら」に対応しているのかを1つずつ見てみましょう。

```python
for i in ids:
    print(i, "→", repr(tok.decode([i])))
```

```output
106046 → '吾'
116599 → '輩'
15322 → 'は'
100472 → '猫'
126230 → 'である'
1773 → '。'
```

:::python for文：くり返し
`for i in ids:` は「`ids` の中身を先頭から1つずつ取り出して `i` に入れ、字下げした部分を実行する」という意味です。フローチャートの「ループ」そのものです。トレースの練習で、表に変数の値を書いていきましたよね。あれをコンピュータが高速でやっています。<br>
`repr(…)` は「中身を、Pythonの書き方のまま見せて」という関数です。文字列を `'…'` で囲んで表示するので、空白や見えない文字があっても気づけます。
:::

おもしろいことに気づきましたか？ 「猫」は1文字で1トークンですが、「である」は3文字で1トークンです。「である」は文章によく出てくるので、辞書に1つのかけらとして登録されているのです。LLMにとって、「猫」は100472番、「である」は126230番。今日からあなたも、猫を見かけたら「あ、100472だ」と言えます。言っても誰にも伝わりませんが。

## トークンの切れ目を観察する

いろいろな文章を入れてみましょう。

```python
def show_tokens(text):
    ids = tok.encode(text)
    pieces = [tok.decode([i]) for i in ids]
    print(len(ids), "トークン：", pieces)

show_tokens("こんにちは")
show_tokens("大規模言語モデル")
show_tokens("LLMを作れるようになりたい")
show_tokens("I am a cat.")
show_tokens("麒麟")
show_tokens("鰯")
```

```output
1 トークン： ['こんにちは']
5 トークン： ['大', '規模', '言', '語', 'モデル']
7 トークン： ['LL', 'M', 'を作', 'れる', 'よう', 'になり', 'たい']
5 トークン： ['I', ' am', ' a', ' cat', '.']
1 トークン： ['麒麟']
3 トークン： ['�', '�', '�']
```

:::python リストの中で for を回す
`[tok.decode([i]) for i in ids]` は「`ids` の各 `i` について `tok.decode([i])` を計算し、結果を並べたリストを作る」という1行の書き方です（**リスト内包表記**といいます）。次のように書くのと同じ意味です。

```python no-run
pieces = []
for i in ids:
    pieces.append(tok.decode([i]))
```

長い書き方のほうが分かりやすければ、そちらで書いても全く問題ありません。
:::

いくつか不思議なことが起きていますね。

- 「こんにちは」は5文字なのに1トークン。よく使うので、まるごと登録されています
- 英語では `' am'` のように、**前の空白も込み**で1トークンです
- 「麒麟」は2文字で1トークン（ビール好きのデータが多かったのでしょうか）
- そして「鰯」（いわし）は……謎の `�` が3つ！

`�` は文字化けしたときに出る記号です。いったい何が起きたのでしょう？

## 文字の正体はバイトの列

:::fe 文字コード
基本情報技術者試験で「文字コード」を習いましたね。コンピュータは文字を数で記録していて、その対応表が文字コードです。ASCII（英数字だけ）、Shift_JIS、EUC-JP、そして世界中の文字をまとめた **Unicode**。Unicodeをコンピュータに保存するときの書き方の1つが **UTF-8** で、今のWebやLLMのほとんどがこれを使っています。HTMLの最初に書く `<meta charset="utf-8">` のアレです！
:::

文字はUTF-8で、何バイトになるのでしょう？ まずは、なじみのある「猫」で確かめます。

```python
s = "猫"
b = s.encode("utf-8")
print(b)
print(len(s), "文字 →", len(b), "バイト")
print(list(b))
```

```output
b'\xe7\x8c\xab'
1 文字 → 3 バイト
[231, 140, 171]
```

「猫」1文字は、UTF-8では3つのバイト（0〜255の数）で表されます。`s = "鰯"` に変えて実行すると、「鰯」もやはり3バイトだと分かります（ほとんどの漢字・ひらがなは3バイトです）。`\xe7` は16進数の `e7`、つまり10進数の231です。基本情報で習った16進数が、ここで生きています。

:::widget utf8
:::

:::theory LLMのトークナイザーは「バイト」から作られている
Qwenのトークナイザーは、文字ではなく**バイト**を基本の部品にしています。

1. まず文章をUTF-8のバイト列にする（「猫」→ 231, 140, 171）
2. よく一緒に出てくるバイトの並びを、1つのトークンとして辞書に登録しておく（231, 140, 171 → 「猫」トークン）
3. 辞書にない珍しい並びは、バイト1個ずつのトークンのまま残る

「鰯」は学習データにあまり出てこなかったので、3つのバイトがバラバラのまま残りました。バイト1個だけでは文字にならないので、1つずつ表示すると `�` になったのです。でも3つ並べて `decode` すれば、ちゃんと「鰯」に戻ります。

この方式（**バイトレベルBPE**）のすごいところは、**どんな文字でも絶対に表せる**ことです。絵文字でも、古代文字でも、いざとなればバイト単位に分解すればいいのですから。「辞書にない文字だから読めません」が起きません。BPEの作り方は、第14章で自分で実装します。
:::

## なぜ「トークン」なの？

:::minato
文字ごとに番号をつけたらダメなんですか？ そのほうが分かりやすいのに。
:::

:::sensei
いい疑問だ。実は、文字ごとでも作れる。この教科書でも第4章からしばらくは文字ごとにする。でも、大きなLLMがそうしない理由が2つある。考えてみよう。
:::

:::theory 単語 vs 文字 vs トークン
文章を数字にする方法は、ざっくり3つ考えられます。

| 単位 | 良いところ | 困るところ |
|---|---|---|
| 単語ごと | 1つ1つに意味がある | 日本語は単語の切れ目に空白がない。新語や固有名詞が無限にあり、辞書に載せきれない |
| 文字ごと | 辞書が小さい。未知の文字が少ない | 文章が長い数字の列になる。LLMは長い列ほど計算が重い |
| トークン（よく出る並びはまとめる） | 辞書の大きさと列の長さのいいとこ取り | 切れ目が人間の感覚とずれる（「を作」など） |

LLMの計算の重さは、入力の長さ（トークン数）で決まります。同じ文章をなるべく少ないトークンで表せれば、計算が軽く、一度にたくさんの文章を読めるのです。かといって辞書を大きくしすぎると、今度は辞書の管理が重くなります。トークンは、その間のちょうどいい落としどころです。
:::

トークン数は、お金や性能にも直結します。有料のLLMサービス（APIといいます）は「100万トークンあたり◯ドル」という料金が多いですし、LLMが一度に読める長さ（**コンテキスト長**）もトークン数で決まっています。Qwen2.5-0.5Bのコンテキスト長は32,768トークンです。

```python
for text in ["I am a cat.", "Je suis un chat.", "我是一只猫。", "吾輩は猫である。"]:
    n = len(tok.encode(text))
    print(n, "トークン：", text)
```

```output
5 トークン： I am a cat.
5 トークン： Je suis un chat.
5 トークン： 我是一只猫。
6 トークン： 吾輩は猫である。
```

:::try 自分の名前は何トークン？
`show_tokens("ここに自分の名前")` を実行してみましょう。予想してから実行するのがコツです。好きなアニメのキャラ名、学校名、絵文字（🐈など）でも試してみてください。珍しい漢字ほど、細かいバイトに分解されるはずです。
:::

## 特別なトークン

第1章で見た台本の記号 `<|im_start|>` を思い出してください。あれは何トークンでしょう？

```python
print(tok.encode("<|im_start|>user"))
print(tok.convert_ids_to_tokens(tok.encode("<|im_start|>user")))
```

```output
[151644, 872]
['<|im_start|>', 'user']
```

`<|im_start|>` は12文字もあるのに、**1トークン**（151644番）です。このような記号を **特別なトークン**（special token）といいます。普通の文章の中には決して出てこない「目印」として、語彙の最後のほうに追加されています。

| トークン | ID | 役目 |
|---|---|---|
| `<\|endoftext\|>` | 151643 | 文章の終わり |
| `<\|im_start\|>` | 151644 | セリフの始まり |
| `<\|im_end\|>` | 151645 | セリフの終わり。チャットモデルはこれを出したら止まる |

LLMが「自分で話すのをやめる」ことができるのは、この `<|im_end|>` を「次のトークン」として予測できるように訓練されているからです。止まるのも予測のうち。なかなかよくできています。

## 自分でトークナイザーを作る

ここからが本番です。Qwenのトークナイザーは15万語もあって大がかりなので、この教科書の第2部では、もっとシンプルな **文字トークナイザー**（1文字＝1トークン）を自分で作って使います。まずは短い文章で作ってみましょう。

```python
text = "吾輩は猫である。名前はまだ無い。"

chars = sorted(set(text))
print(chars)
print("語彙の数：", len(chars))
```

```output
['。', 'あ', 'い', 'だ', 'で', 'は', 'ま', 'る', '前', '名', '吾', '無', '猫', '輩']
語彙の数： 14
```

:::python set と sorted
`set(text)` は、文字列から**重複を取り除いた文字の集まり**（集合）を作ります。「は」は2回出てきますが、集合には1つだけ入ります。`sorted(…)` はそれを並べ替えてリストにします。日本語は文字コードの順に並ぶので、ひらがなが漢字より前に来ます。
:::

次に、文字→番号の辞書（`stoi`：string to integer）と、番号→文字の辞書（`itos`：integer to string）を作ります。

```python
stoi = {}
for i, ch in enumerate(chars):
    stoi[ch] = i

itos = {}
for ch, i in stoi.items():
    itos[i] = ch

print(stoi)
```

```output
{'。': 0, 'あ': 1, 'い': 2, 'だ': 3, 'で': 4, 'は': 5, 'ま': 6, 'る': 7, '前': 8, '名': 9, '吾': 10, '無': 11, '猫': 12, '輩': 13}
```

:::python enumerate と items
`enumerate(chars)` は、リストの中身を「番号つき」で取り出します。`i` に 0, 1, 2…、`ch` に文字が入ります。<br>
`stoi.items()` は、辞書の「キーと値の組」を1つずつ取り出します。<br>
辞書は `stoi["猫"]` のように、キーを指定して値を引けます。紙の辞書で「猫」を引くとページ番号が分かる、のと同じです。
:::

いよいよ変換係の関数を作ります。

```python
def encode(s):
    return [stoi[c] for c in s]

def decode(ids):
    return "".join(itos[i] for i in ids)

ids = encode("猫である")
print(ids)
print(decode(ids))
```

```output
[12, 4, 1, 7]
猫である
```

できました！ これがあなたの最初のトークナイザーです。Qwenの15万語には遠く及びませんが、やっていることの本質は同じ。「文章⇔数字」の変換です。

:::python join
`"".join(…)` は、文字のリストを1つの文字列につなげます。`"".join(["猫", "で"])` は `"猫で"` になります。`"-".join(…)` にすると `"猫-で"` のように、間に `-` を挟んでつなげます。
:::

:::warn 辞書にない文字は？
この小さな辞書には「犬」がありません。`encode("犬")` を実行すると `KeyError: '犬'` というエラーになります（「そのキーは辞書にないよ」の意味）。文字トークナイザーの弱点です。確かめるなら、エラーにならない次の書き方で。

```python
print("犬" in stoi)
```

```output
False
```

第4章では、夏目漱石の小説に出てくる**全部の文字**で辞書を作るので、小説の中の文字なら困りません。
:::

:::quiz バイト数
「AI猫」をUTF-8で表すと、何バイトになるでしょう？
:::answer
5バイトです。英字の「A」「I」は1バイトずつ、「猫」は3バイトなので、1 + 1 + 3 = 5。`len("AI猫".encode("utf-8"))` で確かめられます。
:::

:::quiz 鰯の謎
Qwenのトークナイザーで「鰯」が `�` 3つになったのはなぜ？ また、それでも困らないのはなぜ？
:::answer
「鰯」はUTF-8で3バイトですが、学習データに少ないため、3バイトをまとめたトークンが辞書に登録されていませんでした。だからバイト1つずつの3トークンに分かれ、1つずつでは文字にならないので `�` と表示されました。それでも3つ並べてデコードすれば「鰯」に戻るので、情報は失われていません。バイトを基本にしているので、どんな文字も表せるのです。
:::

:::quiz トークンの長所
LLMが「文字ごと」ではなく「トークン」を使う一番の理由は？
:::answer
同じ文章を少ない数の列で表せるからです。LLMの計算の重さや、一度に読める量（コンテキスト長）はトークン数で決まるので、よく出る文字の並びを1トークンにまとめると、速く・たくさん読めるようになります。
:::

:::recap
- LLMは文章を **トークンID** の列として扱う。トークンの一覧が **語彙**
- 文字は **UTF-8** ではバイトの列。日本語1文字はたいてい3バイト
- 実際のLLMは、よく出るバイトの並びを1トークンにまとめる（バイトレベルBPE）。だから未知の文字がない
- 自作の文字トークナイザーは、`stoi` と `itos` の2つの辞書でできている
:::

数字になった文章を受け取ったLLMは、次のトークンを「選ぶ」。でも、どうやって選んでいるのか？ 実はサイコロを振っているんだ。次の章では、LLMの頭の中のサイコロを取り出して、自分の手で振ってみよう。
:::
