## 報酬モデルと、好みの確率

まずは、RLHFの考え方から見ていきましょう。

:::theory 報酬モデル：答えに点数をつけるモデル
人間の好みを学習させるには、まず「答えの良さ」を数にする必要があります。そこで、答えを入力すると**点数（報酬）**を出す **報酬モデル**（reward model）を作ります。

報酬モデルは、好みのペアから学習します。「良い答えの点数 $r_c$ が、悪い答えの点数 $r_r$ より高くなる」ようにするのです。そのとき使われるのが、**ブラッドリー・テリーモデル** という考え方です。

$$P(\text{良い答えが選ばれる}) = \sigma(r_c - r_r)$$

点数の**差**をシグモイド関数 $\sigma$ に入れたものを、「良い答えが選ばれる確率」と考えます。スポーツのレーティング（強さの点数の差から勝率を予想する）と同じ発想です。
:::

:::math シグモイド関数とブラッドリー・テリーモデル：9ステップで理由から理解する
**① 解決したい具体的な問題**：2つの答えについた「生の点数 $r_c$（良い答え）と $r_r$（悪い答え）」から、「良い答えが選ばれる確率（$0$ 〜 $1$）」を計算したい。

**② 素朴な方法では困る理由**：ただの差 $r_c - r_r$ はマイナスにも $+100$ にもなるので確率になりません。かといって $r_c / (r_c + r_r)$ と割ると、点数が負のときに分母が $0$ になったり確率が $1$ を超えたりして破綻します。

**③ 新しい発想**：点数の差 $x = r_c - r_r$ を、どんな実数でも滑らかに $0$ と $1$ のあいだに押し込むS字の関数 **シグモイド関数 $\sigma(x)$** に通す。

**④ 記号の1つ1つの読み方**：
$$\sigma(x) = \frac{1}{1 + e^{-x}}, \qquad P(y_c \succ y_r) = \sigma(r_c - r_r)$$
- $\sigma$（シグマ）：シグモイド関数（ギリシャ文字の小文字。合計の $\sum$ は大文字なので区別しよう）
- $e$：ネイピア数（約 $2.718$、第3章のsoftmaxで登場）
- $r_c, r_r$：良い答え（chosen）と悪い答え（rejected）の報酬スコア
- $y_c \succ y_r$：「$y_c$ のほうが $y_r$ より好まれる」という記号

**⑤ 小さな数字で手計算**：
- 同点（$r_c = 1, r_r = 1 \implies x = 0$）：$\sigma(0) = \dfrac{1}{1 + e^0} = \dfrac{1}{1 + 1} = 0.500$（ちょうど五分五分！）
- 差が $+2$（$r_c = 3, r_r = 1 \implies x = 2$）：$e^{-2} \approx 0.135$ なので $\sigma(2) = \dfrac{1}{1 + 0.135} \approx 0.881$（約88%で良い答えが勝つ）
- 差が $-2$（$r_c = 1, r_r = 3 \implies x = -2$）：$e^{+2} \approx 7.389$ なので $\sigma(-2) = \dfrac{1}{1 + 7.389} \approx 0.119$（対称性 $\sigma(-x) = 1 - \sigma(x)$ に注目！）

**⑥ 第3章 softmax との完全な一致（2択のsoftmax＝シグモイド）**：
候補が $r_c$ と $r_r$ の2つだけのsoftmaxを、分子・分母とも $e^{r_c}$ で割ってみましょう。
$$\frac{e^{r_c}}{e^{r_c} + e^{r_r}} = \frac{1}{1 + e^{r_r - r_c}} = \frac{1}{1 + e^{-(r_c - r_r)}} = \sigma(r_c - r_r)$$
なんと**ブラッドリー・テリーモデルは、2候補のsoftmaxと数学的にまったく同じ式**なのです！

**⑦ Pythonで確かめる**：

```python
import math
for x in [-4, -2, 0, 2, 4]:
    print(f"σ({x:+d}) = {1 / (1 + math.exp(-x)):.3f}")
```

```output
σ(-4) = 0.018
σ(-2) = 0.119
σ(+0) = 0.500
σ(+2) = 0.881
σ(+4) = 0.982
```

**⑧ 極端なときの振る舞い**：差 $x \to +\infty$ で $\sigma(x) \to 1$（ほぼ確実に良い答えが選ばれる）、$x \to -\infty$ で $\sigma(x) \to 0$、$x = 0$ でちょうど $0.5$。また両方に $+100$ を足しても差 $r_c - r_r$ は変わらない（平行移動不変）。

**⑨ 学習とのつながり**：報酬モデルを学習するときは、この確率に第5章の負の対数（交差エントロピー）をつけた $-\log\sigma(r_c - r_r)$ を最小化します。この形が、すぐ次のDPOの式にそのまま現れます！
:::

:::theory RLHF：報酬を最大にするように強化学習
報酬モデルができたら、次はLLMを **強化学習**（reinforcement learning）で鍛えます。LLMに答えを生成させ、報酬モデルで点数をつけ、点数が高い答えを出しやすくなるようにパラメータを調整する。これをくり返します（よく使われる方法が **PPO**）。人間のフィードバック（Human Feedback）から学ぶ強化学習（RL）なので、**RLHF** と呼びます。

ただし、報酬だけを追いかけると、モデルは**報酬モデルの穴をつく**ようになります。たとえば報酬モデルが「長い答え」を好むクセを持っていたら、意味のない長文を書くようになる。これを **報酬ハッキング** と言います。そこで、「元のモデル（参照モデル）からあまり離れすぎない」という罰（**KLペナルティ**）を加えます。

$$\text{目標} = \text{報酬} - \beta \times \text{元のモデルからの離れ具合（KLダイバージェンス）}$$

RLHFはとても強力ですが、報酬モデル・強化学習・生成をぐるぐる回すので、仕組みが複雑で、学習も不安定になりがちです。
:::

:::math KLダイバージェンス $\mathrm{KL}(p \,\|\, q)$：9ステップで理由から理解する
**① 解決したい具体的な問題**：学習中のモデルが出す確率分布 $p$ が、元の参照モデルの確率分布 $q$ から「どれくらいズレたか」を1つの数値（罰金）で測りたい。

**② 素朴な方法では困る理由**：単純に差を足す $\sum_i (p_i - q_i)$ は、$\sum p_i = 1, \sum q_i = 1$ なので $1 - 1 = 0$ となり、どれだけズレても常に0で測れません。また単純な差の絶対値だと、元のモデルが「ほとんど起きない（$q_i = 0.0001$）」と判断していた変な単語に確率を移したときの危険度（何倍になったか）を十分重く罰せられません。

**③ 新しい発想**：各選択肢について「元の確率の**何倍**になったかの対数 $\log(p_i / q_i)$」をとり、それを今のモデルが実際に選ぶ確率 $p_i$ で重みづけ平均する。

**④ 記号の1つ1つの読み方**：
$$\mathrm{KL}(p \,\|\, q) = \sum_i p_i \log \frac{p_i}{q_i}$$
- $p$：今のモデル（学習中の方策 $\pi$）の確率分布
- $q$：元のモデル（参照モデル $\pi_{\text{ref}}$）の確率分布
- $\|$：2つの分布を比べる区切り線（順番に意味があり、$\mathrm{KL}(p\|q) \neq \mathrm{KL}(q\|p)$ の**非対称**！）
- $\log\dfrac{p_i}{q_i}$：第5章と同じ自然対数。$p_i = q_i$ なら $\log 1 = 0$、$p_i > q_i$ ならプラス、$p_i < q_i$ ならマイナス

**⑤ 小さな数字で手計算**：
元のモデルが次のトークン「A・B」を $q = (0.5, 0.5)$ で選び、今のモデルが $p = (0.9, 0.1)$ に偏ったとき：
$$\mathrm{KL}(p \,\|\, q) = 0.9 \log\frac{0.9}{0.5} + 0.1 \log\frac{0.1}{0.5} \approx 0.9 \times 0.588 + 0.1 \times (-1.609) \approx 0.529 - 0.161 = 0.368$$
もし $p = q = (0.5, 0.5)$（ズレなし）なら、$0.5\log 1 + 0.5\log 1 = 0$ です。

**⑥ Pythonでの最小コード**：
```python no-run
import math
p, q = [0.9, 0.1], [0.5, 0.5]
kl = sum(pi * math.log(pi / qi) for pi, qi in zip(p, q) if pi > 0)
print(round(kl, 3))   # 0.368
```

**⑦ 絶対に押さえる2つの性質**：
1. **必ず0以上**（$\mathrm{KL}(p\|q) \ge 0$）：各項にマイナスが出ても、合計すると必ず0以上になり、0になるのは $p = q$ のときだけ。
2. **第5章の交差エントロピーの仲間**：$\sum p_i \log\frac{p_i}{q_i} = \big(-\sum p_i \log q_i\big) - \big(-\sum p_i \log p_i\big)$（交差エントロピー − エントロピー）。PyTorchでは `F.kl_div` で計算できます。

**⑧ $\beta$ の効き方**：RLHFの目標 $\mathbb{E}[r(x,y)] - \beta\,\mathrm{KL}(\pi \,\|\, \pi_{\text{ref}})$ で、$\beta$ が大きすぎるとモデルが元のまま動かなくなり、$\beta$ が小さすぎると報酬ハッキングで文章が壊れます。

**⑨ DPOへの橋渡し**：実は、この「KLペナルティつきの目標」があるからこそ、次の節で魔法のような数学変形が可能になります！
:::

## DPO：報酬モデルなしで、好みを直接学ぶ

2023年に、スタンフォード大学の研究者たちが、すごいことに気づきました。上のRLHFの「目標」を数学的に変形すると、**報酬モデルも強化学習も使わずに**、好みのペアから直接LLMを学習させる損失関数が導けるのです。それが **DPO**（Direct Preference Optimization）です。

:::math DPOの目的関数 $L_{\text{DPO}}$：9ステップで記号の1つ1つから完全に理解する
**① 解決したい具体的な問題**：RLHFでは「①報酬モデルの学習 → ②PPO強化学習」の2段階が必要で、モデルも複数要り、学習が非常に不安定です。報酬モデルを作らずに、好みのペア `(質問, chosen, rejected)` だけから直接LLMを学習させたい！

**② 素朴な方法ではなぜダメなのか？**
もし単純に「良い答えの対数確率を上げ、悪い答えを下げる」だけの損失 $-\log\sigma\big(\beta(\log\pi(y_c) - \log\pi(y_r))\big)$ を使うと、次の**2つの致命的な欠陥**が起きます。
1. **ブレーキがない**：元のモデルから際限なく離れてしまい、日本語として壊れた文章になりやすい。
2. **長さバイアスに負ける**：文章全体の対数確率は各トークンの負の対数確率の合計なので、**長い良い答え**（例：`-60`）より**短い悪い答え**（例：`-25`）のほうが最初から圧倒的に値が高い！そのまま引き算すると、最初から `-60 - (-25) = -35` という巨大なハンデを背負ってしまいます。

**③ RLHF→DPOの導出の肝（どんな仮定・簡略化をしているか）**：
RLHFのKL制約つき目標 $\max_\pi \mathbb{E}[r(x,y)] - \beta\,\mathrm{KL}(\pi \,\|\, \pi_{\text{ref}})$ を数学的に解くと、最適方策 $\pi^*$ は次の**閉じた形（解析解）**で表せることが知られています。
$$\pi^*(y \mid x) = \frac{1}{Z(x)}\,\pi_{\text{ref}}(y \mid x)\exp\!\left(\frac{1}{\beta}\,r(x, y)\right)$$
ここで $Z(x)$ は確率の合計を1にするための正規化定数（全文章の和なので直接は計算不能）です。ところが、この式を $r(x, y)$ について逆算すると、
$$r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x)$$
となります！これをブラッドリー・テリーモデルの差 $r_c - r_r$ に代入すると、計算できない厄介者 **$\beta \log Z(x)$ が引き算で完全に消えて（相殺されて）しまう**のです！
> **導出における簡略化・前提の整理**：この導出は「①人間の好みがブラッドリー・テリーモデルに従う」「②KL制約つきRLHFの厳密な最適方策 $\pi^*$ によって報酬を言い換えられる」「③固定されたオフラインの好みペア上で $\pi$ を直接更新してもよい（RLHFのように学習途中のモデル自身から再サンプリングするオンポリシー分布ズレを近似・省略する）」という仮定に基づいています。だからこそ、強化学習ループなしの単純な教師あり風の損失関数に落とし込めるのです。
:::

:::math DPOの式と記号・手計算トレース

**④ DPO目的関数の記号を1つ残らず読む**：
$$L_{\text{DPO}} = -\log \sigma\!\Big(\beta \big[ (\log \pi(y_c) - \log \pi_{\text{ref}}(y_c)) - (\log \pi(y_r) - \log \pi_{\text{ref}}(y_r)) \big]\Big)$$

| 記号 | 読み方・正体 | 絶対に間違えないためのポイント |
|---|---|---|
| $\pi$ | **学習中のモデル（方策、policy）** | **円周率 $3.14$ ではない！** 英語 policy の p にあたるギリシャ文字 |
| $\pi_{\text{ref}}$ | **参照モデル（reference）** | 学習開始前の重みを凍結した元のLLM（ブレーキ役・出発点の基準） |
| $y_c, y_r$ | 良い答え（chosen）・悪い答え（rejected） | 同じ質問 $x$ に対する比較ペアの文章 |
| $\log \pi(y_c)$ | 良い答え全体の対数確率 | 答えの全トークンの $\log P_\pi(\text{token}_t \mid \text{前})$ の合計（0以下の負の数） |
| $\Delta_c = \log\pi(y_c) - \log\pi_{\text{ref}}(y_c)$ | 良い答えの「書きやすさの変化」 | $\log(\pi/\pi_{\text{ref}})$。元より書きやすくなると**プラス** |
| $\Delta_r = \log\pi(y_r) - \log\pi_{\text{ref}}(y_r)$ | 悪い答えの「書きやすさの変化」 | 元より書きにくくなると**マイナス**（減らしたい！） |
| $\beta$ | KLペナルティの強さ（例：`0.1`） | 大きいほど参照モデルから離れにくくなる |
| $\sigma(\cdot)$ | シグモイド関数 | マージン $m = \beta(\Delta_c - \Delta_r)$ を確率 $(0, 1)$ に変換 |
| $-\log(\cdot)$ | 負の対数（第5章の交差エントロピー） | 確率が1に近いほど損失0、確率0.5なら $\log 2 \approx 0.693$ |

**⑤ なぜわざわざ $\log\pi_{\text{ref}}$ を引き算するのか？（2つの本質的理由）**：
1. **暗黙のKLペナルティが自動で入る**：$\beta(\log\pi - \log\pi_{\text{ref}}) = \beta\log(\pi/\pi_{\text{ref}})$ という「元のモデルとの比」を暗黙の報酬にすることで、元のモデルの自然な日本語を壊さないブレーキが組み込まれる。
2. **出発点の長さバイアスを打ち消せる**：良い答えが `-60`、悪い答えが `-25` でも、それぞれから参照モデルの値（`-60` と `-25`）を引くため、出発点はどちらも `0` にリセットされ、純粋な「変化の差」だけで公平に比べられる！

**⑥ 具体的な数字で手計算トレース（なぜ初期損失が常に $0.693$ なのか）**：
参照モデルで $\log\pi_{\text{ref}}(y_c) = -60$、$\log\pi_{\text{ref}}(y_r) = -25$、$\beta = 0.1$ とします。

| 状態 | $\Delta_c$ | $\Delta_r$ | マージン $m = 0.1(\Delta_c - \Delta_r)$ | 確率 $\sigma(m)$ | DPO損失 $-\log\sigma(m)$ |
|---|---|---|---|---|---|
| **学習開始直後（$\pi = \pi_{\text{ref}}$）** | $0$ | $0$ | **$0.0$** | **$0.500$** | **$-\log 0.5 = \log 2 \approx 0.693$** |
| 良い答えが $+10$ 書きやすく（`-50`） | $+10$ | $0$ | $+1.0$ | $0.731$ | $0.313$（減少！） |
| 悪い答えが $-10$ 書きにくく（`-35`） | $0$ | $-10$ | $+1.0$ | $0.731$ | $0.313$（同じく減少！） |
| 両方達成（`chosen +10` かつ `rejected -10`） | $+10$ | $-10$ | $+2.0$ | $0.881$ | $0.127$（大きく減少！） |
| 逆方向に失敗（`chosen -10`） | $-10$ | $0$ | $-1.0$ | $0.269$ | $1.313$（急上昇！） |

**⑦ 純粋Pythonでの実装イメージ**：
```python no-run
import math
def dpo_loss_simple(pi_c, pi_r, ref_c, ref_r, beta=0.1):
    margin = beta * ((pi_c - ref_c) - (pi_r - ref_r))
    prob = 1.0 / (1.0 + math.exp(-margin))
    return -math.log(prob)
```
なおPyTorchでは、極端に負の `margin` で `math.exp(-margin)` がオーバーフローするのを防ぐため、数学的に等価かつ数値安全な `-F.logsigmoid(margin)` を使います。

**⑧ 注意点（DPOのクセ）**：式は差 $\Delta_c - \Delta_r$ だけを見るため、学習率が大きすぎると良い答えの確率 $\Delta_c$ まで一緒に下がりながら悪い答えがもっと下がる（`rewards/chosen` がマイナスになる）現象が起きることがあります。また長文バイアスも完全には消えないため、生成文の目視と長さの確認が大切です。

**⑨ 実際のPyTorchコードで検算しよう**：下のセルで、上の手計算テーブルの数字と小数第3位まで完全に一致することを確かめます！
:::

式だけだと分かりにくいので、数で計算してみましょう。

```python
import torch
import torch.nn.functional as F

def dpo_loss(pi_c, pi_r, ref_c, ref_r, beta=0.1):
    """各引数は、その答え全体の対数確率（トークンごとの log 確率の合計）"""
    margin = beta * ((pi_c - ref_c) - (pi_r - ref_r))
    return -F.logsigmoid(margin)

ref_c, ref_r = torch.tensor(-60.0), torch.tensor(-25.0)     # 学習前：悪い答え（短い）のほうが書きやすい
print("学習前（方策＝参照）：", dpo_loss(ref_c, ref_r, ref_c, ref_r).item())
print("良い答えが +10 書きやすく：", dpo_loss(ref_c + 10, ref_r, ref_c, ref_r).item())
print("悪い答えが -10 書きにくく：", dpo_loss(ref_c, ref_r - 10, ref_c, ref_r).item())
print("両方：", dpo_loss(ref_c + 10, ref_r - 10, ref_c, ref_r).item())
```

```output
学習前（方策＝参照）： 0.6931471824645996
良い答えが +10 書きやすく： 0.3132616877555847
悪い答えが -10 書きにくく： 0.3132616877555847
両方： 0.12692801654338837
```

:::theory 最初の損失は log 2
学習を始めた瞬間は、方策＝参照なので、括弧の中は0、$\sigma(0) = 0.5$、損失は $-\log 0.5 = \log 2 \approx 0.693$ です。第5章で「最初の損失は $\log V$」を確かめたのと同じで、DPOの学習ログで最初に **0.693** が出ていたら、正しく始まっている印です。

注目してほしいのは、学習前の対数確率は「悪い答え（-25）」のほうが「良い答え（-60）」より高い、つまり**悪い答えのほうが書きやすい**状態だったことです。悪い答えは短いので、確率の掛け算の回数が少ないからです。DPOは、確率そのものではなく「元からの**変化**」を比べるので、出発点での長さの違いには惑わされません（ただし、学習を続けると長い答えを好むようになりやすいクセも知られています。第20章の評価で、答えの長さも見ておくと安心です）。
:::

## モデルの対数確率を計算する

本物のLLMで、答え全体の対数確率を計算する関数を作ります。第20章の4択クイズで使った方法と同じです。

```python
from transformers import AutoTokenizer, AutoModelForCausalLM

name = "Qwen/Qwen2.5-0.5B-Instruct"
device = "cuda" if torch.cuda.is_available() else "cpu"
tok = AutoTokenizer.from_pretrained(name)
ref_model = AutoModelForCausalLM.from_pretrained(name, dtype=torch.float32).to(device).eval()

@torch.no_grad()
def answer_logprob(model, question, answer):
    prompt = tok.apply_chat_template([{"role": "user", "content": question}], add_generation_prompt=True, tokenize=False)
    p = tok(prompt, add_special_tokens=False)["input_ids"]
    a = tok(answer + "<|im_end|>", add_special_tokens=False)["input_ids"]
    ids = torch.tensor([p + a]).to(device)
    logprobs = torch.log_softmax(model(ids).logits[0, :-1].float(), dim=-1)
    return logprobs[len(p) - 1:].gather(1, ids[0, len(p):, None]).sum().item()

p = prefs[11]
lc, lr = answer_logprob(ref_model, p["question"], p["chosen"]), answer_logprob(ref_model, p["question"], p["rejected"])
print(f"良い答えの対数確率 {lc:.1f}  悪い答えの対数確率 {lr:.1f}")
```

```output-example
良い答えの対数確率 -142.3  悪い答えの対数確率 -21.7
```

学習前のQwenにとっては、長くて個性的なボンゴ先生の答えより、短くて素っ気ない答えのほうが、ずっと「書きやすい」ようです。

:::scaffold `answer_logprob` の仕組み：なぜ質問部分を除いて答えトークンだけを足すのか？
DPOで必要なのは「質問 $x$ が与えられたときの、答え $y$ 全体の対数確率 $\log \pi(y \mid x)$」です。

1. `ids = [p + a]`：質問トークン列 `p` の後ろに、答え＋終了合図 `<|im_end|>` のトークン列 `a` をつなげてモデルに通します。
2. **1つずらしの対応**：位置 `t` の出力ロジットは位置 `t + 1` のトークンを予測します。したがって、答えの1トークン目（`ids[len(p)]`）を予測しているのは `logprobs[len(p) - 1]` です。
3. **答え部分だけの合計**：`gather` で正解トークンIDに対応する対数確率だけを取り出して `.sum()` で足します。質問部分はモデルが生成する対象ではないため除外します（第18章のSFT損失マスク `-100` と同じ発想です）。
:::

## TRLのDPOTrainerで学習する

DPOの学習は、TRLの `DPOTrainer` を使うと簡単です。データを「prompt・chosen・rejected」の形にして渡すだけです。メモリを節約するために、第19章のLoRAを使います（LoRAを使うと、参照モデルは「付せんを外した状態」として自動的に用意されるので、モデルを2つ読み込む必要がありません）。

```python
from datasets import Dataset
from peft import LoraConfig
from trl import DPOTrainer, DPOConfig

ds = Dataset.from_list([{"prompt": [{"role": "user", "content": p["question"]}],
                         "chosen": [{"role": "assistant", "content": p["chosen"]}],
                         "rejected": [{"role": "assistant", "content": p["rejected"]}]} for p in prefs])
policy = AutoModelForCausalLM.from_pretrained(name, dtype=torch.float32)
config = DPOConfig(output_dir="dpo-bongo", beta=0.1, learning_rate=5e-5, num_train_epochs=3,
                   per_device_train_batch_size=4, logging_steps=1, report_to="none", save_strategy="no",
                   bf16=False, fp16=torch.cuda.is_available())
trainer = DPOTrainer(model=policy, args=config, train_dataset=ds, processing_class=tok,
                     peft_config=LoraConfig(r=16, lora_alpha=32, target_modules="all-linear", task_type="CAUSAL_LM"))
trainer.train()
```

Colabでは、学習中に「Step」と「Training Loss」の表が表示されます。でも、そこに出るのは損失だけです。DPOならではの値（`rewards/…`）は、学習が終わった後に、学習の記録 `trainer.state.log_history`（1ステップごとの記録の辞書を並べたリスト）から取り出して表示します。

```python
for h in trainer.state.log_history:
    if "rewards/margins" in h and h["step"] % 4 == 1:     # 4ステップごとに表示
        print(f"ステップ {h['step']:2d}：損失 {h['loss']:.3f}  良い {h['rewards/chosen']:5.2f}  "
              f"悪い {h['rewards/rejected']:5.2f}  差 {h['rewards/margins']:5.2f}  正解率 {h['rewards/accuracies']:.2f}")
```

:::theory 学習ログの読み方
- `loss`：DPOの損失。0.693（$\log 2$）から下がっていけば順調
- `rewards/chosen`：良い答えの暗黙の報酬（$\beta \times$ 元からの対数確率の変化）。上がっていくのが理想
- `rewards/rejected`：悪い答えの暗黙の報酬。下がっていくのが理想
- `rewards/margins`：その差。広がっていくほど、好みを学べている
- `rewards/accuracies`：良い答えの報酬が悪い答えより高かったペアの割合

`rewards/chosen` も一緒に下がっていく（良い答えも書きにくくなる）ことがよくあり、DPOの弱点として知られています。差が広がっていても、良い答えそのものの確率が下がりすぎると、文章がおかしくなることがあります。学習率を小さく、エポックを少なくするのが安全です。
:::

学習後のモデルで、学習前に比べて、良い答えと悪い答えの書きやすさがどう変わったか見てみましょう。

for name_, m in [("学習前", ref_model), ("DPO後", trainer.model)]:
    lc = answer_logprob(m, p["question"], p["chosen"])

    print(f"{name_}：良い答え {lc:7.1f}  悪い答え {lr:7.1f}")

- **なぜモデルが1つで済むのか？**：LoRA（第19章）では元の重み $W$ を凍結し、横付けした付せん $\Delta W$ だけを学習します。そのため **LoRAをONにすれば学習中モデル $\pi$、一時的にOFFにすれば元の参照モデル $\pi_{\text{ref}}$** として1つのモデルで2役をこなせます。

## アラインメントと安全性

:::theory アラインメント
LLMを「人間の意図や価値観に沿ったふるまい」に合わせることを、**アラインメント**（alignment、整合）と言います。役に立つこと（helpful）、正直であること（honest）、害を与えないこと（harmless）の3つがよく目標に挙げられます。

- 危険な作り方を聞かれたら断る、差別的な発言をしない、といった**安全性**も、好みのデータ（「断る答え」をchosenにする）で学習させます
- 人間の代わりに、原則（憲法）を与えたAIに好みを判定させる方法（**RLAIF**、Constitutional AI）もあります
- 一方で、うまい言い回しで安全の仕組みをすり抜けようとする攻撃（**ジェイルブレイク**）もあり、守る側と破る側のいたちごっこが続いています

アラインメントは、技術だけでなく「誰の好みに合わせるのか」という社会的な問いも含む、とても大切な研究分野です。
:::

:::theory 推論モデルへの道：答えが確かめられる問題で強化学習
最近の「考えてから答える」**推論モデル**（reasoning model）は、数学やプログラミングのように**答えが正しいかを自動で確かめられる**問題で、強化学習をして作られています。人間の好みの代わりに、「答えが合っていたら報酬1、間違っていたら0」という**検証可能な報酬**（verifiable reward）を使うのです（RLVR）。モデルは、正解にたどり着くために、長く考える（考える過程のトークンを多く出す）ことを自分で学んでいきます。**GRPO** という、同じ問題に何通りも答えさせて、平均より良かった答えを強化する方法がよく使われます。第25章で、もう少し詳しく触れます。
:::

:::warn よくあるつまずき
- **損失が最初から0.693でない**：参照モデルと学習モデルが違う状態から始まっています。LoRAを使う場合は気にしなくて大丈夫ですが、自分でモデルを2つ読み込む場合は、同じ重みから始めましょう。
- **学習後に文章がおかしくなる**：学習率が大きすぎるか、エポックが多すぎます。DPOは $10^{-6}$〜$10^{-5}$ 台の小さな学習率から試すのが安全です（今回はLoRAなので少し大きめ）。
- **`CUDA out of memory`**：DPOは、1つのペアで良い答えと悪い答えの両方を計算するので、SFTよりメモリを使います。バッチを小さくしましょう。
:::
