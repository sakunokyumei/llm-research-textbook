## ボンゴ焼き問題

ボンゴ先生は、週末にたこ焼きならぬ「ボンゴ焼き」の屋台を出しています。焼いた時間と、売れた個数の記録がこちら。

```python
hours = [1, 2, 3, 4, 5]          # 焼いた時間
sold = [2.9, 6.2, 8.8, 12.1, 15.0]  # 売れた個数（10個単位）
```

だいたい「時間 × 3」くらいでしょうか。これを **モデル** にしてみます。

$$\text{予想} = w \times \text{時間}$$

$w$ は「1時間あたり何個売れるか」を表す数で、これが **パラメータ** です。$w$ をいくつにすれば、記録にいちばん合うでしょう？

まず「合っている度合い」を測るものさしを作ります。予想と実際の差を2乗して平均したものを **損失** にします。

```python
def predict(w, x):
    return w * x

def loss_fn(w):
    total = 0.0
    for x, y in zip(hours, sold):
        total += (predict(w, x) - y) ** 2
    return total / len(hours)

for w in [1, 2, 3, 4]:
    print(f"w = {w} のとき、損失 = {loss_fn(w):.3f}")
```

```output
w = 1 のとき、損失 = 44.100
w = 2 のとき、損失 = 11.060
w = 3 のとき、損失 = 0.020
w = 4 のとき、損失 = 10.980
```

:::theory 二乗誤差
「予想 − 実際」は、外れた方向によってプラスにもマイナスにもなります。そのまま平均すると打ち消し合ってしまうので、**2乗**してから平均します。これを **平均二乗誤差**（mean squared error、MSE）と呼びます。2乗するので、大きく外れたほど厳しく罰せられます。

第5章の言語モデルの損失（驚きの平均）とは式が違いますが、「小さいほど良い、モデルの成績表」という役割は同じです。
:::

$w = 3$ あたりが良さそうです。グラフにしてみましょう。

## 目隠しで山を下りる

:::sensei
キミは濃い霧の山の中にいる。目隠しをされていて、遠くは見えない。分かるのは**足元の傾き**だけ。どうやって谷底まで下りる？
:::

:::minato
足元が下っている方向に、一歩ずつ進めばいいんじゃないですか？
:::

:::sensei
正解！ それが **勾配降下法**（こうばいこうかほう）だ。人類の機械学習の大部分は、この「足元の傾きを見て一歩下る」でできている。拍子抜けするほど単純だろう？
:::

足元の傾きを測ってみましょう。$w$ をほんの少し（$h = 0.0001$）だけ動かして、損失がどれだけ変わるかを見ます。

```python
def slope(w, h=0.0001):
    return (loss_fn(w + h) - loss_fn(w)) / h

for w in [1, 2, 3, 4]:
    print(f"w = {w} での傾き：{slope(w):8.3f}")
```

```output
w = 1 での傾き： -44.039
w = 2 での傾き： -22.039
w = 3 での傾き：  -0.039
w = 4 での傾き：  21.961
```

:::theory 微分＝傾き
「横に少し動いたとき、縦にどれだけ動くか」の比 $\dfrac{\text{縦の変化}}{\text{横の変化}}$ が **傾き** です。横の変化をどんどん小さくした極限の傾きを **微分**（derivative）と言い、$\dfrac{dL}{dw}$ と書きます（「$L$ を $w$ で微分したもの」と読みます。$d$ は「ほんの少しの変化」の意味）。

上のコードのように、ほんの少し動かして実際に測る方法を **数値微分** と言います。

傾きの**符号**を見てください。

- $w = 1, 2$：傾きがマイナス → 右（$w$ を大きくする方向）に行くと下る
- $w = 4$：傾きがプラス → 左に行くと下る
- $w = 3$ 付近：傾きがほぼ0 → 谷底

つまり、**傾きと逆の方向に進めば下れる**のです。
:::

## 勾配降下法

一歩の大きさを **学習率**（learning rate）と呼び、`lr` と書きます。ルールはこれだけ。

$$w \leftarrow w - \text{lr} \times \frac{dL}{dw}$$

「傾きと逆向きに、傾きの大きさに比例して進む」。坂が急なら大きく、緩やかなら小さく進みます。

```python
w = 0.0
lr = 0.01
for step in range(15):
    w = w - lr * slope(w)
    if step % 2 == 0:
        print(f"ステップ {step:2d}：w = {w:.4f}  損失 = {loss_fn(w):.4f}")
```

:::python % は割り算の余り
`step % 2` は「`step` を2で割った余り」です。偶数なら0、奇数なら1なので、`if step % 2 == 0:` は「偶数のステップのときだけ表示する」という意味になります。この先の学習ループでは、`if step % 500 == 0:`（500ステップごとに表示）の形で何度も出てきます。
:::

```output
ステップ  0：w = 0.6604  損失 = 60.3252
ステップ  2：w = 1.5773  損失 = 22.3426
ステップ  4：w = 2.1351  損失 = 8.2831
ステップ  6：w = 2.4745  損失 = 3.0788
ステップ  8：w = 2.6810  損失 = 1.1523
ステップ 10：w = 2.8066  損失 = 0.4392
ステップ 12：w = 2.8830  損失 = 0.1752
ステップ 14：w = 2.9295  損失 = 0.0775
```

$w = 0$ から出発して、15歩で3の近くまで来ました。誰も「答えは3だよ」と教えていないのに、傾きだけを頼りに谷底へ向かっています。最初は坂が急なので大きく進み、谷底に近づくと坂が緩やかになって、歩幅が自然に小さくなっているのにも注目してください。

上のデモで、学習率をいろいろ変えてみましょう。

- **小さすぎる**（0.05など）：確実だけど、なかなか谷底に着かない。カタツムリ
- **ちょうどいい**（0.3など）：すいすい下る
- **大きすぎる**（2近く）：谷を飛び越えて、反対側の斜面に着地。行ったり来たりして、最悪どこかへ飛んでいく

## パラメータが2つになったら：勾配

実際には、時間がゼロでも少しは売れる（常連さんがいる）かもしれません。モデルを少し賢くします。

$$\text{予想} = w \times \text{時間} + b$$

パラメータが $w$ と $b$ の2つになりました。今度は2次元の地形（山と谷）を下ることになります。傾きも「$w$ 方向の傾き」と「$b$ 方向の傾き」の2つを測ります。

```python
def loss2(w, b):
    return sum((w * x + b - y) ** 2 for x, y in zip(hours, sold)) / len(hours)

def slopes(w, b, h=0.0001):
    dw = (loss2(w + h, b) - loss2(w, b)) / h   # w だけ少し動かす
    db = (loss2(w, b + h) - loss2(w, b)) / h   # b だけ少し動かす
    return dw, db

w, b = 0.0, 0.0
for step in range(2000):
    dw, db = slopes(w, b)
    w, b = w - 0.02 * dw, b - 0.02 * db
print(f"w = {w:.3f}, b = {b:.3f}, 損失 = {loss2(w, b):.4f}")
```

```output
w = 3.010, b = -0.029, 損失 = 0.0198
```

:::theory 偏微分と勾配
パラメータが複数あるとき、「他のパラメータは止めて、1つだけ少し動かしたときの傾き」を **偏微分**（へんびぶん）と言い、$\dfrac{\partial L}{\partial w}$ のように丸っこい $\partial$（デル、ラウンドディー）で書きます。

偏微分を全部のパラメータについて並べたベクトルを **勾配**（gradient）と言います。

$$\nabla L = \left( \frac{\partial L}{\partial w}, \frac{\partial L}{\partial b} \right)$$

勾配は「最も急に**上る**方向」を指す矢印です。だから、その**逆**に進めば最も急に下れる。パラメータが5億個でも、勾配が5億個の数の並び（ベクトル）になるだけで、やることは同じです。

……ただし、数値微分で5億個の偏微分を測るには、モデルを5億回動かす必要があります。それはさすがに無理。そこで次の秘密兵器の出番です。
:::

## PyTorchの自動微分

PyTorchは、計算の過程を記録しておいて、**正確な勾配を一発で計算**してくれます。これを **自動微分**（autograd）と言います。

```python
import torch

x = torch.tensor(hours, dtype=torch.float32)
y = torch.tensor(sold)

w = torch.tensor(1.0, requires_grad=True)   # 「この数の勾配を知りたい」と宣言
loss = ((w * x - y) ** 2).mean()
loss.backward()                              # 勾配を計算！
print("損失：", loss.item())
print("自動微分の傾き：", w.grad.item())
print("数値微分の傾き：", slope(1.0))
```

```output
損失： 44.099998474121094
自動微分の傾き： -44.040000915527344
数値微分の傾き： -44.03890000006072
```

`loss.backward()` を呼ぶだけで、`w.grad` に傾き $\dfrac{dL}{dw}$ が入りました。数値微分とほぼ同じ値ですが、小数点以下3桁目からずれています。数値微分は「少し右に動かした」ときの傾きなので誤差があり、自動微分のほうが正確な値です。

では、自動微分で学習ループを書き直しましょう。これが、この先何度も書くことになる **学習ループの基本形** です。

```python
w = torch.tensor(0.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
lr = 0.02

for step in range(2000):
    loss = ((w * x + b - y) ** 2).mean()   # ① 予想して、損失を計算
    loss.backward()                         # ② 勾配を計算
    with torch.no_grad():                   # ③ パラメータを更新（ここは記録しない）
        w -= lr * w.grad
        b -= lr * b.grad
    w.grad.zero_()                          # ④ 勾配を0に戻す
    b.grad.zero_()

print(f"w = {w.item():.3f}, b = {b.item():.3f}, 損失 = {loss.item():.4f}")
```

```output
w = 3.010, b = -0.030, 損失 = 0.0198
```

:::warn ④を忘れると大変
PyTorchの `.grad` は、`backward()` を呼ぶたびに **足し算されていく**（累積する）仕様です。④の `zero_()` を忘れると、前のステップの勾配がどんどん積み上がり、学習がめちゃくちゃになります。エラーは出ないので、気づきにくい。学習がおかしいときは、まずここを疑いましょう。
:::

:::theory 第3章の `no_grad` の謎が解ける
③で `with torch.no_grad():` を使っているのは、「パラメータの更新」という計算まで記録されてしまうと、次の `backward()` のときに「更新の計算の微分」まで計算しようとして混乱するからです。

そして第3章では、文章を生成するだけ（学習しない）だったので、`no_grad` で記録を止めて、メモリと時間を節約していたのでした。あのおまじないの意味が、ようやく分かりましたね。
:::

## 自動微分の中身：連鎖律

自動微分はどうやって勾配を計算しているのでしょう？ 鍵は **連鎖律**（れんさりつ、chain rule）です。

:::theory 連鎖律：微分の伝言ゲーム
次の計算を考えます。

$$u = 3x + 1, \qquad y = u^2$$

$x$ を少し動かすと $u$ が動き、$u$ が動くと $y$ が動きます。

- $x$ が1動くと、$u$ は3倍動く：$\dfrac{du}{dx} = 3$
- $u$ が1動くと、$y$ は $2u$ 倍動く：$\dfrac{dy}{du} = 2u$（$u^2$ の傾きは $2u$。$u$ が大きいほど急）

だから、$x$ が1動くと $y$ は $3 \times 2u$ 倍動きます。

$$\frac{dy}{dx} = \frac{dy}{du} \times \frac{du}{dx} = 2u \times 3$$

**途中の傾きを掛け算でつないでいく**。これが連鎖律です。伝言ゲームで、各人が「受け取った話を3倍に盛って伝える」「2倍に盛って伝える」をすると、最後は $3 \times 2 = 6$ 倍に盛られて届くのと同じです。
:::

```python
x = torch.tensor(2.0, requires_grad=True)
u = 3 * x + 1
y = u ** 2
y.backward()
print("自動微分：", x.grad.item())
print("連鎖律で手計算：", 2 * u.item() * 3)
```

```output
自動微分： 42.0
連鎖律で手計算： 42.0
```

:::theory 誤差逆伝播法（バックプロパゲーション）
PyTorchは、計算するたびに「何と何から、どんな計算で作られたか」を記録しています（**計算グラフ**）。`backward()` を呼ぶと、損失から出発して計算を**逆向きに**たどりながら、連鎖律で傾きを掛け算していきます。

<div class="math-display">x →(×3+1)→ u →(2乗)→ y　　　逆向き：y の傾き 1 →(×2u)→ u の傾き →(×3)→ x の傾き</div>

5億個のパラメータがあっても、この逆向きの伝言ゲームを**1回**やるだけで、全部の勾配がまとめて求まります。この方法を **誤差逆伝播法**（ごさぎゃくでんぱほう、backpropagation）と言います。ニューラルネットワークの学習を現実的なものにした、最重要の発明です。
:::

:::fe 誤差逆伝播法
基本情報技術者試験のシラバスにも、AIの用語として「誤差逆伝播法」「勾配降下法」「学習率」が登場します。試験では用語の意味を問われるだけですが、あなたはもう**自分で動かしたことがある**人です。暗記カードより、ボンゴ焼きのほうが忘れにくいはずです。
:::

:::deep 微分の公式を少しだけ
この教科書では、微分はPyTorchに任せます。でも、いくつかの公式を知っていると、式を読むときに便利です。

| 関数 | 微分 | ひとこと |
|---|---|---|
| $x^2$ | $2x$ | 2乗の傾きは2倍の $x$ |
| $x^n$ | $n x^{n-1}$ | 上の一般形 |
| $e^x$ | $e^x$ | 微分しても変わらない、変わり者 |
| $\log x$ | $1/x$ | 第5章の対数の傾き |
| $ax + b$ | $a$ | 直線の傾きは一定 |

例えばボンゴ焼きの損失 $L = \frac{1}{5}\sum (wx - y)^2$ を $w$ で微分すると、連鎖律で $\frac{1}{5}\sum 2(wx - y) \cdot x$ になります。$w = 1$ を入れると -44.04。自動微分の答えと一致します。
:::

:::quiz 進む方向
ある場所で、損失のパラメータ $w$ についての傾きが +5 でした。学習率0.1の勾配降下法で、$w$ はどう変わる？
:::answer
$w \leftarrow w - 0.1 \times 5 = w - 0.5$。$w$ は0.5だけ**小さく**なります。傾きがプラス（右に行くと上る）なので、左に進むわけです。
:::

:::quiz 学習率
学習率を大きくしすぎると何が起きる？
:::answer
一歩が大きすぎて谷底を飛び越え、反対側の斜面に着地します。行ったり来たりを繰り返したり、どんどん損失が大きくなって発散したりします。
:::

:::quiz 連鎖律
$y = (2x)^3$ で、$x = 1$ のときの $\frac{dy}{dx}$ を連鎖律で求めよう（$u = 2x$ とおく）。
:::answer
$\frac{du}{dx} = 2$、$\frac{dy}{du} = 3u^2 = 3 \times 2^2 = 12$。掛け算して $12 \times 2 = 24$ です。
:::

:::recap
- **学習**とは、損失が小さくなるようにパラメータを調整すること
- **微分**は傾き。傾きと逆向きに少しずつ進むのが **勾配降下法**：$w \leftarrow w - \text{lr} \times \frac{dL}{dw}$
- パラメータが複数なら、偏微分を並べた **勾配** を使う
- PyTorchの **自動微分** は、**連鎖律**で計算を逆にたどり、全パラメータの勾配を一度に求める（**誤差逆伝播法**）
- 学習ループの基本形：① 損失計算 → ② `backward()` → ③ 更新（`no_grad`）→ ④ 勾配を0に
:::
