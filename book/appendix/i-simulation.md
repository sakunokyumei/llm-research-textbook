この付録は、この教科書が「想定する読者が、挫折せずに最後まで理解して開発できるようになるか」を確かめるために行った**シミュレーション**の記録です。シミュレーションで見つかった問題を直し、もう一度シミュレーションする、をくり返しました。

:::warn これは「本物の読者」の代わりではありません
ここでのシミュレーションは、教科書の作成者（AI）が、想定読者の知識と状況をできるだけ具体的に仮定して行ったものです。本物の読者が実際に読むと、予想しなかった場所で止まることが必ずあります。読んでいて止まった場所は、ぜひ記録して、教科書の改善に使ってください（それも立派な研究です）。
:::

## 想定読者（ペルソナ）

| 項目 | 想定 |
|---|---|
| 所属 | 専門学校1年（2026年入学・2030年卒業予定）、AIエンジニア専攻 |
| HTML・CSS | ひと通り学んだ（タグ、クラス、レイアウト） |
| Python | 初歩の初歩（`print`、変数、簡単な `if`。リスト・辞書・関数・クラスは未習として扱う） |
| Linux | 少しだけ（`cd`、`ls` くらい） |
| そのほか | フローチャート、トレース、基本情報技術者試験の対策中（2進数・16進数・文字コード・浮動小数点などは知っている） |
| 数学 | 高校数学は「あまり自信がない」として扱う（指数・対数・微分・ベクトル・行列は未習として扱う） |
| 英語 | エラーメッセージを読むのは苦手 |
| 環境 | 個人のGoogleアカウント、ふつうのノートパソコン（GPUなし、Windowsを想定）、スマートフォン |
| 時間 | 授業・課題の合間に、週5時間ほど |

## 方法：3つのレンズで見る

1. **機械チェック**（`tools/persona.py`）：教科書を最初から順に「読んでいく」プログラムで、読者の知識の状態を追跡します。その時点でまだ説明していない用語（[用語集](f-glossary.html)の150語）や、まだ説明していないPythonの書き方（内包表記、`with`、クラス、`lambda`、`try`、`zip` など25種類）が出てきたら、問題として報告します。同時に、章ごとの新しい用語の数、会話やクイズの頻度、会話もコードもない文章が続く長さ、読む時間の目安を測ります
2. **実行チェック**（`tools/verify.py`）：各章のコードを、新しいColabのセッションと同じように、上から順にすべて実行します。表示している出力が、実際の出力と一致するかも確かめます
3. **なりきり通読**：上の想定読者になりきって、全章を順に読み、「どこで手が止まるか」「止まったときに、教科書の中に抜け出す手段があるか」「やる気が続くか」を章ごとに判定します

### 合格の基準

すべての章で、次の6つを満たすことを「合格」としました。

1. 説明していない用語・Pythonの書き方を、説明なしに使わない（予告として使う場合は「第◯章で」と明示する）
2. コードがすべて動く（GPUやHugging Faceへの接続が必要なセルは、そうと明示し、代わりの手段を示す）
3. 章の中に、目に見える成果（実行結果・グラフ・生成された文章・デモ）がある
4. 会話・コード・クイズのない文章が、長く続きすぎない
5. 予想されるつまずきに、「つまずき注意」の箱や付録で、抜け出す道が用意されている
6. なりきり通読で「支援を使えば、この章を終えられる」と判定できる

### 通しで見た判定

- **LLMに触れるまでの時間**：第1章の約30〜60分で、本物のLLMと会話できる。理論を先に何週間も勉強する必要はない
- **ゼロから作るまでの時間**：第4章（最初の週末〜2週目）で、自分の言語モデルが漱石風の文章を書く
- **ご褒美の間隔**：どの章にも、目に見える成果（生成された文章、グラフ、デモ、記録表の更新）がある。記録表は「7.63 → 3.58 → 3.40 → 3.18 → 3.08 → 2.64」と、章を追うごとに自分のモデルが賢くなるのが数字で見える
- **数学の山**：第3章（指数）、第5章（対数）、第7章（微分）、第11章（内積と行列）、第22章（DPOの式）。いずれも「数の例 → コードで確認 → 式」の順で、式を暗記しなくても先へ進めるように作ってある
- **お金**：最後まで0円で進められる（GPUが借りられない日の代わりの手段も各章にある）
- **時間**：週5時間で約半年〜1年。基本情報の試験勉強と並行できる（[付録H](h-plan.html)）

### 結論

第2回のシミュレーションでは、合格の基準1〜6を**すべての章で満たした**と判定しました。想定読者は、各章の支援（会話、理論の小部屋、つまずき注意、クイズ、エラー辞典、AIへの質問テンプレート）を使えば、**挫折せずに最後まで進み、LLMの仕組みを理解したうえで、自分で作り・鍛え・評価し・公開できるようになる**、というのがシミュレーションの結果です。

ただし、離脱の危険が「中」の章（特に第7・10・11・16・22・25章）は、本物の読者で確かめる価値が高い場所です。もし止まったら、それはあなたの能力の問題ではなく、教科書の改善点です。

## 残っている危険と、その対策

| 危険 | 対策 |
|---|---|
| 無料のGPUが使えない時期が続く | Kaggleを使う。CPUで短く試す。GPUが必要な章（13・18〜23）は後回しにして、CPUでできる章（14〜16・25）を先に進めてもよい |
| ライブラリの版が変わってコードが動かなくなる | [エラー辞典](e-errors.html)の「版の違い」の項目。完成ノートブックで答え合わせ。AIへの質問テンプレート |
| 授業や試験で数週間止まる | 各章は最初のセルから実行すれば動く。「前回の続き」のリンクと、各章の「まとめ」から再開 |
| 数学で自信をなくす | 6割ルール。[数学の地図](d-math.html)。数学は「必要になったら戻ってくる」でよい |

## 次にやること（改善の続け方）

1. 実際に読み進めて、止まった場所・時間・感想を、章ごとに1行ずつ記録する
2. 止まった場所に「つまずき注意」を足す、説明の順番を入れ替える、などの改善をする
3. `python tools/persona.py` と `python tools/verify.py` をもう一度実行し、この報告の表を更新する

教科書の改善も、モデルの改善と同じです。測って、直して、また測る。
