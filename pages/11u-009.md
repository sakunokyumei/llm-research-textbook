# 11-9 演習

読む目安10〜20分／確認5〜10分。長いコードの実行はPCを使える別の回へ分けられます。時間は編集上の目安です。

この章の9/10ページ。今日の目標：演習の小例を一つ追う。

## 記号を読む前に、小例へ戻る

仕様は期待する動作、テストはその動作を確かめる作業です。assert 2+3==5は成り立つことを確認します。負数も受け付ける仕様なら正数の確認だけでは足りません。

:::exercise 6・仕様を作る
正解率の関数へtotal=0が渡されたら、どう扱うべきでしょう。理由も述べてください。
:::answer
たとえばValueErrorとして知らせます。0%と返すと「全問不正解」と「評価例がない」を混同するためです。別の設計として欠測値を返すこともできますが、明記が必要です。
:::

:::exercise 7・テストを選ぶ
二つの数の大きい方を返す関数に、最低三つのテスト入力を選んでください。
:::answer
(2,5)→5、(5,2)→5、(3,3)→3。負の数も許すなら(−2,−5)→−2を追加します。順序と等しい境界を確かめています。
:::

:::exercise 8・切り分ける
計算のコード、入力するデータ、結果を丸める桁数を同時に変えたら結果が改善しました。どの変更が効いたと言えますか。
:::answer
この実験だけでは区別できません。一つだけを変えた比較、または組合せを整理した実験が必要です。研究でも部品や条件を一つずつ取り除いて影響を比べます。この比較を[ablation](reference.html#term-ablation)（アブレーション）と呼びます。
:::

:::exercise 9・クラスの状態
Counterの実体aとbを別々に作り、a.add()だけを二回呼びました。a.countとb.countはいくつですか。
:::answer
2と0です。それぞれの実体に独立したcountを初期化しているためです。
:::

:::exercise 10・精度の確認
小数の結果を比較するとき、単に許容誤差を1へ広げてテストを通すのは適切ですか。
:::answer
誤差の大きさが仕様や数値精度に照らして妥当かを確認する必要があります。テストが通る値へ合わせるだけでは、間違った計算を正しいことにしてしまいます。
:::
